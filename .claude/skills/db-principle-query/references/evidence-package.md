# 证据包规范

每个模块/协议在进入编码前产出一份证据包（总体开发方案第 22 节要求）。

**落档位置**：`doc/evidence/<模块>-<日期>/evidence.md`，原始检索输出同目录留档。

## 模板

```markdown
# 证据包：<模块/协议名>

- 编制日期：YYYY-MM-DD
- 对应阶段：P<N>
- 检索执行：<人/Agent>
- 状态：complete | partial（含未核验项）

## 结论

<3 条以内**可判定**结论。每条附证据编号。>

1. …（证据 1）
2. …（证据 2）
```

## 填写规范

| 字段 | 要求 |
| --- | --- |
| 结论 | **可判定**（能验证真假），不用"性能较好""机制合理"这类不可判定的表述 |
| 条目 ID | 必须给出，供 `detail` 复现；只写摘要不算证据 |
| 源码提交 | P0 冻结 pgvector、AGE 等源码基线后回填；未冻结时在"未核验项"注明 |
| 核验日期 | **必填**。知识库内容随时间变化，过期证据需重新核验 |
| 适用条件 | **必填**。版本、范围、前提、已知失效场景 |
| 检索范围 | 不得表述为"已穷尽全部资料" |
| 冲突 | 必记录，开 ADR |

## 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 用检索摘要直接下结论 | 未经核验的结论进入设计 | 必须 `detail` / `doc_retrieve` 下钻 |
| 采用占位条目 | 空内容当证据 | 检查"占位内容"字样，改走源码学习系列 |
| 写"已穷尽检索" | 过度声明 | 写"已检索范围，召回有界" |
| 缺核验日期 | 无法判断时效 | 必填 |
| 引用跨版本并集字段数 | 数值失真 | 落到单一版本/范围组合分节 |
| 冲突时静默择一 | 风险敞口不可见 | 记录冲突并开 ADR |
| 把知识库结论当自主决策 | 依据不可追溯 | 分开标注"来源"与"本项目自定" |
