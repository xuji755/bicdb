# 端到端场景走查（v0.1）

日期：2026-10-04　　目的：**找"分域都自洽、合起来有缝"的地方**

**为什么单做这一步**：八个规格域是分域写的，从未串起来走过一遍。
而这一小时的讨论里，"缝"出现了三次——**每次都是被问出来的，不是走出来的**。

**判据**（每步都问）：

1. **是否一次调用可完成**？还是 agent 要拼好几步胶水？
2. **是否要 agent 自己拼胶水**？
3. **是否会撞上"用错也没报错"的地方**？

---

## 场景：一个 coding agent 的一次任务

```text
0. 工作区与 agent 的建立
1. 新建任务 → 写 task_checkpoint
2. 会话开始 → 写对话消息
3. 检索装配上下文
4. 后台提取：会话 → 记忆
5. 中途中断 → 用 checkpoint 恢复
6. 用户确认两条记忆
7. 两条互相冲突
8. 撤销其中一个来源
9. 任务结束归档
```

---

## 逐步走查

### 0. 建立：`agent_id` 没有创建动作

`memory.agent_id` 已定（空 = 主体级共享，有值 = agent 私有）✓——**但没有"创建一个 agent"这个动作** ✗。

**现在它是"写了就存在"的** ✗——这**不一定是缺陷**（名字空间归 agent 自己 ✓），
但**两处没答案**：

| 问题 | 后果 |
| --- | --- |
| agent 下线后，它的记忆怎么办？ | 检索时**仍然命中它们** ✗——而那个 agent 已经不在了 |
| `agent_id` 与工作区内的其他名字空间冲突吗？ | 未知 |

**判**：**不算缝，但要在文档里标清"agent_id 是调用方自定的标签，库不管理其生命周期"** ✓。
（已在 `MEM` 的待确认汇总记过。）

---

### 1. 新建任务：**没有幂等约定** ✗

写 `task_checkpoint(task_id, checkpoint_seq=1, goal, ...)` ✓。

**问题**：agent 重试一次，就写进**两行"同一任务的目标"** ✗——而**检查点是恢复点** ✗✓，
两行会让恢复**不确定**（取哪一行？）✓✓。

**这是"友好"清单第 2 条（幂等写入）的具体落点** ✗——而它现在**只是清单上的一条，没有机制**。

**判**：**真缝** ✗。见 §修正 1。

---

### 2. 写对话：**会话表没有"属于谁"的字段** ✗✗

会话表是 `append_only + logging=none + TTL + segment_drop` ✓——**但它只有一个表，没有维度** ✗：

| 缺什么 | 后果 |
| --- | --- |
| **`agent_id`** | **提取进程无法知道这段会话属于哪个 agent** ✗✗ |
| **`task_id` / 会话标识** | 无法"把这次任务的对话拿出来" ✗ |

**第二个后果最重** ✗✓：提取进程的任务是"把会话变成记忆" ✓——
而**记忆要带 `agent_id`** ✓（否则检索时的 agent 过滤无从谈起 ✓）。
**它只能从内容里猜** ✗——**而那是策略，不该由库猜** ✓✓。

**判**：**真缝，且是最重的一处** ✗。见 §修正 2。

---

### 3. 检索装配上下文：**通** ✓

混合检索（`REQ-RET-006`：查询文本 + 可选向量 + 类型时间过滤 + 来源范围 + `top_k` + 资源预算）✓
+ 图扩展（`REQ-RET-009`，限跳数与节点预算）✓ + 过滤 ✓。

输出 `memory_id / revision / source / 检索方法 / 分数 / 证据片段` ✓——
**"拼成提示词"是策略，归 agent** ✓，而**底座给了它拼装所需的全部原料** ✓（尤其**证据片段** ✓）。
**顺序由融合（RRF）给出** ✓。

**判**：**通** ✓。**这一块是"一次调用可完成"的** ✓。

> **但有一类常被忽略的检索** ✗：**"把这个任务的全部记忆给我"**——
> 那不是相似度检索 ✗，而是**按 task 列举** ✓。
> **它依赖 §2 里缺的那个字段** ✗——与缝 2 同源。

---

### 4. 后台提取：水位有了，但**输入分不清归属** ✗

进程形态已定 ✓（可选、每工作区一个、可独立进程、无特权通道）✓；
水位存在有日志的一侧 ✓；产出走正常写路径 ✓。

**但它读到的会话"没有归属"** ✗（§2 的缝）✓——**它无法把产出挂到正确的 `agent_id` 上** ✗。

**另一处**：`source_record` 要指向"读过的会话位置" ✓——**那个位置必须稳定** ✗：
会话表的 ROWID 会随**段丢弃**而变化 ✗✓——**刻意的段丢弃**是它的设计 ✓。

**判**：**真缝（第二处较轻）** ✗。见 §修正 3。

---

### 5. 中断与恢复：**通** ✓

恢复靠 `task_checkpoint` ✓（记忆表，`logging = redo_only`，**有日志** ✓）——
而**对话原文可丢** ✓（会话表 `logging = none`）✓。**"丢掉会话，从记忆里找回"这条路是通的** ✓。

取最新检查点 = `WHERE task_id = ? ORDER BY checkpoint_seq DESC LIMIT 1` ✓——
**走 `(task_id, checkpoint_seq)` 主键** ✓，一次调用 ✓。

**判**：**通** ✓。**这是本次走查里第二块完整的** ✓。

---

### 6. 用户确认：`memory_version` 的语义**没写清** ✗

`candidate → confirmed` ✓。我给的规定是"**每次转换写一个新的 `memory_version`**" ✗——
理由是"谁在何时为什么确认"要留痕 ✓。

**但这与 `memory_version` 的定义冲突** ✗✓：

| 我定义它是 | 而状态转换 |
| --- | --- |
| "该记忆的某一版**内容**" | **不改内容** ✗ |

**于是"确认"会产出一个"内容一模一样"的版本** ✗——**读起来像冗余，实际是概念没对齐** ✓。

**判**：**真缝（概念层）** ✗。见 §修正 4。

---

### 7. 两条冲突：**通，但检索不带出来** ✓⚠

`conflicts_with` 是一条 `derived_link` ✓；**库不检测**（无模型 ✓），**由 agent 建立** ✓。
**双向只需一条 link** ✓（查询查两个方向 ✓）——但**需要反向索引** ✓（已记 ✓）。

⚠ **缺口已记**（"友好"第 4 条）：**检索结果不返回冲突关系** ✗——
agent 想"看到一条时同时知道它和谁冲突"，得**再发一次查询** ✓。

**判**：**通，但两跳** ✓。可接受，已记为缺口 ✓。

---

### 8. 撤销来源：**可见性判据漏了它** ✗

`source_record.revoked_at` ✓——同步阻止派生物返回 ✓，靠反查 `derived_link` ✓。

**但 `REQ-MEM-011` 写的是**："检索**默认排除 `expired` 与 `deleted`**" ✗——
**它没有提到"来源已撤销"** ✗✓。

**于是"不可见"现在有两个来源，而文档只写了一个** ✗✓：

```text
不可见  ⟸  status ∈ {expired, deleted}      ← REQ-MEM-011 写了
       ∨  来源已撤销（revoked_at 非空）      ← 只在 REQ-MEM-013 里，没进可见性判据
```

**判**：**真缝** ✗。见 §修正 5。

---

### 9. 归档：**记忆的 TTL 是行级还是表级？** ✗✗

任务结束 → 会话表的 `TTL + segment_drop` 生效 ✓（整段丢弃 ✓）。

**但记忆表呢？** ✗——**中期记忆要过期，长期记忆不该** ✗✓——
而 **`retention` 是表选项**（`tab$.retention`）✗，**表级** ✗✓。

**一条记忆是中期还是长期，是行级的** ✗（`kind` 字段 ✓）——
**所以它的 TTL 必须是行级的** ✗✓——**而表选项给不了** ✗✗。

**而 `REQ-MEM-003` 其实已经点破了**："中期与长期共享底层事务，
**生命周期由独立业务字段表达**" ✓✓——**"独立业务字段"就是行级 TTL** ✓——
**但我没有在 schema 里给出这个字段** ✗✓。

**判**：**真缝，且是结构性的** ✗。见 §修正 6。

## 汇总：六处缝

| # | 缝 | 性质 | 严重度 |
| --- | --- | --- | --- |
| **1** | `task_checkpoint` 无幂等约定 | 缺机制 | 中 |
| **2** | **会话表与 `memory` 缺 `agent_id` / `task_id`** | **缺字段** | **高** |
| **3** | `source_record` 指向的"会话位置"不稳定（段会丢） | 缺定义 | 中 |
| **4** | `memory_version` 是"内容版本"还是"事件"？ | **概念** | 中 |
| **5** | 可见性判据漏了"来源已撤销" | 缺条件 | 高 |
| **6** | **记忆的 TTL 是行级字段，不是表选项** | **结构性** | **高** |

**三处高**：缝 2、缝 5、缝 6。
**其中缝 2 与缝 6 是"字段/结构缺失"，缝 5 是"判据不全"** ✓。

> **一个观察**：六处里有 **四处在 `MEM` 域** ✗——
> 而 `MEM` 是唯一一个**我按"六条路线对比"来设计的域** ✓。
> **对比得出的是"概念与形状"，而字段级的东西它给不了** ✓——
> **概念对齐不等于落地完整** ✓。
