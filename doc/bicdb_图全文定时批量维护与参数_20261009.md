# 图全文定时批量维护与参数（2026-10-09）

图全文索引已支持 `manual` 与 `batch` 两种显式维护方式。两者均通过原生共享队列记录源变更，不在源写入路径执行分词；文档、倒排项、消费游标和队列清理沿用同一事务发布。此阶段没有连接或修改 Neo4j。

## 配置与 SQL

```ini
[fulltext]
fulltext_interval_ms = 5000
fulltext_batch_rows = 256
```

实例配置按现有参数机制重启装载，命令行也可使用 `-c fulltext.fulltext_interval_ms=1000`。索引显式 OPTIONS 优先于实例有效参数，未指定的值继续继承实例配置。间隔范围为 100–86400000 毫秒；批次大小范围为 1–4096 个合并事件。0、负数、小数、NULL 和未知选项均拒绝，停用自动维护选择 manual 或 PAUSE。

```sql
CREATE FULLTEXT GRAPH INDEX answers ON kg
  NODES LABEL "Entity" (name,config.question,config.answers[0])
  OPTIONS '{"update":"batch","interval_ms":5000,"batch_rows":256}';

ALTER FULLTEXT GRAPH INDEX answers ON kg
  OPTIONS '{"update":"batch","interval_ms":30000,"batch_rows":512}';
SHOW FULLTEXT GRAPH INDEXES ON kg;
ALTER FULLTEXT GRAPH INDEX answers ON kg PAUSE;
ALTER FULLTEXT GRAPH INDEX answers ON kg RESUME;
ALTER FULLTEXT GRAPH INDEX answers ON kg SYNC;
```

ALTER OPTIONS 替换完整维护策略，必须指定 update。省略的数值恢复实例继承，不保留旧覆盖值。manual 可以设置 batch_rows，供显式 SYNC 使用；interval_ms 仅适用于 batch。修改策略不重建文档或任何索引段，不改变当前暂停状态。策略以字典非键列事务更新，跨重启保留；后续 REBUILD 保留策略与暂停状态。

SHOW 保留原有列，并追加 `interval_ms`、`batch_rows`、`interval_source`、`batch_rows_source`。数值来源为 INDEX 或 INSTANCE；manual 的 interval_ms 为 NULL，表示没有定时维护。旧版未登记共享队列的全文索引不支持在线策略转换，仍保持原有维护语义。

## 调度与前台交互

当前服务支持多个连接和 SQL 执行线程。主调度循环按时间检查各工作区的维护任务；仅在目标工作区没有活动、排队或挂起的 SQL，且没有未提交事务时执行该工作区维护。其他工作区的未提交事务不阻止目标工作区追平。持续 SQL 或 STATUS 请求不再依赖接收超时才触发维护；只读或故障工作区跳过后台写入。维护批次在实例共享执行线程执行，计入 worker_threads 和执行活跃数；目标工作区在该批完成前不派发新 SQL，新 SQL 仍按正常队列上限排队，其他工作区可使用剩余线程。主循环只负责投递和接收结果，候选工作区轮转，避免线程少于工作区时固定优先前几个。STATUS 的 fulltext_active 表示活跃维护任务，fulltext_failures 累计失败次数。

服务检查粒度约 100 毫秒。每个工作区每次检查最多发布一个已到期索引的一个批次，按到期时间选择，避免一次清空全部积压而长期占据请求通道。首次发现索引或有效参数变化时，从发现时刻重新等待一个间隔。间隔表示调度间隔，不是对分词、WAL 或磁盘耗时的上限；长语句、事务、其他已到期索引和单批执行时间均可增加实际延迟。

显式 SYNC 仍固定开始时的图源水位并连续消费批次，批次大小使用索引覆盖值或实例值。后台每批覆盖当前可见源队列；部分进度只推进 cursor，未完成前 covered_source_seq 不冒充完整覆盖。PAUSE 保留积压，重启不自动解除。

读超时不返回半帧给上层，也不重新从帧头开始解析。动词、长度行和二进制载荷的已读字节保留在原解码调用内；EOF、超长或非法帧仍报错。等待输入不独占数据库；新连接受实例连接数上限约束。协议字节格式不变。

## 身份与故障

维护入口只由本机服务调用，不新增网络动词或用户 SQL 绕过权限。入口在内部维护作用域保存并恢复用户身份、执行参数和内部访问标志，包括失败返回；活动用户事务直接跳过。因此 PUBLIC 的具名用户仍只读，内部维护可更新保护文档与队列而不提升该用户后续 SQL 的权限。

失败的批次不发布、不确认事件。成功的前序批次继续可见。失败消费者按其间隔且至少间隔一秒重试，日志记录错误；有效消费者可继续推进。修正源内容后可自动追平。源队列预算耗尽仍使源语句明确失败并回滚，不丢弃积压。

新策略 descriptor 为 `bicdb-graph-fulltext-managed-v2`，包含完整 Definition 与 policy。既有 managed-v1 索引按 manual 读取，不暗中开启定时任务，重建保持原 descriptor；可通过 ALTER OPTIONS 升级策略。更早的未注册队列索引不自动转换消费者。文档和队列原生格式未变。

## 验证与边界

验证包括：指定与继承间隔/批次大小，在线策略修改不换段，空闲服务自动推进，半帧请求期间维护和后续帧边界，暂停与策略跨重启，活动事务跳过，失败事件不确认且健康消费者不饥饿，以及 PUBLIC 读用户在维护后仍被拒绝写入。

全文冷查询与单批维护仍有有界全文语料、共享队列和统计恢复开销，逻辑预算不是 RSS 上限。本阶段没有大型图谱性能验收，维护已使用共享执行任务，也尚未实现固定目标 WAIT、旧倒排/退役段回收、普通表/配置表/附件文档的统一全文 SQL。

证据见 [定时维护验证记录](evidence/bicdb-graph-fulltext-timer-20261009/README.md)，原生事务及序号定义见 [共享队列实施](bicdb_图全文共享变更队列与批量维护_20261009.md)。
