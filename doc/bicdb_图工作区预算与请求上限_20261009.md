# 图工作区预算与请求上限（2026-10-09）

此前只有 DETACH 关联边预算可配置，其余图执行限制固定。本轮将已有的节点、边、中间行、展开/表达式工作、路径深度及文本字节上限接入工作区的 `bicdb.ini`，并增加可收紧预算的 SQL `BUDGETS` 子句。超过预算仍明确报资源错误，不返回伪完整结果；显式部分结果协议尚未接入。

## 工作区配置

```ini
[graph]
max_nodes=100000
max_edges=500000
max_rows=10000
max_expansions=100000
max_edge_expansions=100000
max_elapsed_ms=60000
max_depth=16
max_text_bytes=104857600
detach_edge_limit=10000
```

| 参数 | 合法范围 | 实际作用 |
| --- | --- | --- |
| max_nodes | 0..100000 | 持久化图节点总数、完整加载及原生快照头的节点上限；0 可用于禁止新增节点 |
| max_edges | 0..500000 | 图边总数、完整加载及快照头的边上限 |
| max_rows | 1..10000 | 既有图执行器的中间/结果行上限；SEARCH 全文返回行也受约束 |
| max_expansions | 1..100000 | 既有展开与表达式工作计数；全文 provider、原生记录读取也使用该工作区/请求上限 |
| max_edge_expansions | 0..100000 | 独立邻接候选边费用，子查询及同一 SQL 的 GRAPH_TABLE 来源共享 |
| max_elapsed_ms | 1..60000 | 协作式图语句时长，子查询/物化/原生提交前检查同一时钟 |
| max_depth | 1..16 | 有界路径的深度/总路径长度检查，默认保持现有的 16 |
| max_text_bytes | 1024..104857600 | 已有图序列化、值/结果、按需记录读取和 GRAPH_TABLE 物化的字节预算 |
| detach_edge_limit | 0..500000 | 跨子句/CALL/UNION 的不同关联边删除总数，保留既有去重和失败语义 |

以上范围是当前原生实现的系统硬上限。配置文件和 `-c graph.<参数>=<值>` 使用同一校验、配置来源和渲染机制；命令行覆盖只对本次启动生效。编辑文件不改变正在运行的服务，重启后生效。

降低节点/边总数上限到已有图规模以下，会使该图的加载/查询报错，不会静默截取节点或边。它们是语料规模上限，不是某次点查的实体装载数；请求不能更改这两项。

## 请求语法

```sql
CYPHER kg 'MATCH (n:Item {name:"a"}) RETURN n.name'
  BUDGETS '{"max_rows":1,"max_text_bytes":4096}';

PROFILE CYPHER kg 'MATCH (n)-[*1..2]->(m) RETURN m.name'
  PARAMETERS '{}'
  BUDGETS '{"max_depth":2,"max_expansions":1000}';

SELECT g.title
FROM GRAPH_TABLE(kg, :query PARAMETERS :params BUDGETS :budgets
  COLUMNS (title VARCHAR2(128))) g;
```

- 顺序为 query、可选 PARAMETERS、可选 BUDGETS；GRAPH_TABLE 的 BUDGETS 位于 COLUMNS 前。CYPHER 接受 JSON 字符串字面量；GRAPH_TABLE 接受字面量或命名 SQL 参数，禁止引用外层行。
- BUDGETS 可包含 `max_rows`、`max_expansions`、`max_edge_expansions`、`max_elapsed_ms`、`max_depth`、`max_text_bytes`、`detach_edge_limit`。省略/空对象使用工作区配置；请求值必须为合法整数且不超过工作区值。未知字段、非对象、小数、负数、字符串数字、过大值及超过 4096 字节的对象明确拒绝，不自动改小。
- 图语句内的 provider 调用使用相同的请求上限，包括命名全文过程、strict 扫描与 eventual 候选/统计记录读取。该语句结束或失败都会恢复原工作区政策，不影响下一条请求和服务后台调度。
- 小的字节请求不会通过旧版全文完整缓存绕过装载上限。已发布全文 generation 的全语料预算仍按其存储格式校验，不将“整个索引大小”误当作查询加载量；v3/v4 查询继续选择统计桶和候选正文。
- SEARCH FULLTEXT GRAPH INDEX 使用工作区的行/工作预算；其调用方 OPTIONS 中的 limit 仍是主动限制，不把超出工作区预算的默认结果静默截小。

## 入口、事务与可观察性

直接 `bicdb sql`、REPL、认证服务会话、空闲/分帧等待时的维护均安装同一工作区政策。原生 STATUS 增加 `graph_max_nodes`、`graph_max_edges`、`graph_max_rows`、`graph_max_expansions`、`graph_max_edge_expansions`、`graph_max_elapsed_ms`、`graph_max_depth`、`graph_max_text_bytes`，保留旧 DETACH 字段；展示的是启动时有效配置。

受信任 `Session::set_graph_limits` 校验全部参数后才替换，非法配置保持先前有效值。既有 `set_graph_detach_edge_limit` API 保留，并更新同一政策对象。

图写语句仍先暂存再发布。预算失败丢弃本语句的图内容、索引和 journal 变更，外层显式事务中此前成功的 SQL 保持。耐久分配器允许失败语句留下 ID 跳号，避免回滚后复用；这不作为内容变更提交。维护失败不确认该批事件；此前成功的批次仍保留。

GRAPH_TABLE 各来源使用各自请求预算，整个 SQL 语句的图来源物化字节仍合计使用工作区上限。超过上限拒绝整个 SQL 结果，不给部分联查。图表 AST 装箱避免新增预算表达式放大所有 FROM 节点。

## 验证和边界

核心测试覆盖工作区硬上限、请求禁止提升、语法/类型、配置文件渲染及命令行优先级；原生测试验证重启生效、状态值、节点/边/行/路径失败、请求不泄漏、参数化 GRAPH_TABLE、全文 provider、失败写入与先前 SQL 事务保留、失败维护事件及旧全文缓存约束。CLI/REPL 另有真实入口验证，GRAPH_TABLE 多来源合计字节预算有直接 Session 验证。

测试全部使用隔离合成 bicdb 数据，没有连接或修改 Neo4j；见 [证据](evidence/bicdb-graph-budget-policy-20261009/README.md)。

本轮统一现有限制的配置和请求入口，不把其声明为 GRP-008/009 已完整验收：

- 原 `max_expansions` 仍与表达式工作共用，原生记录另有倍数预算；后续已新增独立 `max_edge_expansions`，并在同一 SQL 的 GRAPH_TABLE 来源间共享边余额，见[计账规则](bicdb_图独立展开边预算_20261009.md)。
- max_rows 也约束中间行，写了 LIMIT 仍可能先在中间态超限。同一 SQL 的不同 GRAPH_TABLE 来源现在共享 Runner 混合工作与独立边余额；来源 BUDGETS 只能降低自己的份额，不能重置语句余额。见[共享工作预算](bicdb_GRAPH_TABLE共享工作预算_20261010.md)。
- max_text_bytes 是现有逻辑/序列化/装载字节费用，不是全部执行器实际持有内存或 RSS 上限。全文内核的持久化文档/token 全局预算独立保留。
- 协作式图语句时间限制已实现，见[时钟与回滚边界](bicdb_图语句时间预算_20261009.md)；实际内存计账以及显式部分结果状态仍待继续。整体图增强目标保持进行中。
