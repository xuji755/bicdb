# 共享缓存与服务调度审计（2026-10-10）

## 已完成修复

- KCBWDS 是共享 DB Cache 分区，不是逻辑工作区。移除每个逻辑工作区至少预留 2 GiB 的准入约束。例如 6 GiB Cache 可配置 2 个 KCBWDS 分区，按分区启动 DBWR，不因绑定更多工作区增加固定缓存配额。
- 新增 `[service] max_bound_workspaces`，默认 1024，范围 1–65536，包含 PUBLIC。当前计数是已打开并驻留的工作区数，不是连接数；断开最后一个连接不会自动卸载工作区。STATUS 显示上限与当前值。
- 配置不足或资源占用导致的打开失败不再永久标记为恢复损坏。真实恢复错误仍隔离工作区，不能用取消配额绕过一致性检查。
- BIND 普通失败不再破坏已认证身份；非法 UTF-8 在移动会话状态前校验。不存在的工作区可重新选择，重复 BIND 被拒绝后原绑定仍可执行 SQL。
- 全文维护按工作区分别判断事务和 SQL 活跃状态；主循环按时间检查，避免持续 STATUS/SQL 请求使接收超时永远不发生而饿死维护。只读、故障工作区不执行后台写批次。维护采用独立目录视图，与 SQL worker 的目录使用方式一致。
- 每轮最多接收 64 个新连接，避免连续连接到达阻塞完成事件、停止请求和维护。
- CKPT/UNDO 后台线程通过稳定的工作区 ID 映射分工，新增工作区不会改变既有工作区的责任线程，避免不同时间截取的注册列表造成重叠维护。

## 验证

上一轮 CLI 库单元测试 46 项通过。BIND 既有实例回归 2 项通过，覆盖非法编码、失败重试和重复绑定后继续查询。

全文既有实例回归 1 项通过：在两个合成工作区中保持其中一个的未提交事务，在另一个创建 batch 索引和数据；持续轮询 STATUS/索引状态后，验证文档数、源水位、待处理数量及 eventual 实际检索命中。索引发现后的追平观测约 0.26 秒，不是性能承诺。

图全文测试数据需要非空字符串 `db_type`。缺少该领域字段的节点不会进入当前全文文档集合；此前文档数为 0 的失败用例缺少此字段，不能作为索引丢失数据的证据。

回归脚本为 `drivers/python/tests/test_bind_existing.py` 和 `test_fulltext_existing.py`。脚本不启动实例；全文测试必须显式设置 `BICDB_TEST_ALLOW_PROVISION=1`，创建合成工作区和随机口令用户，结束时暂停用户，保留工作区供复查。不得将真实口令写入测试文件。

## 后续优化顺序与边界

1. 全文单批已纳入实例共享执行调度，见本页追加审计。仍需大型语料下的重批次延迟与前台竞争验收，不能以小型回归代替性能测试。
2. AUTH、首次 BIND 的恢复/目录装载仍可能阻塞控制循环。应拆分阻塞 I/O 与连接状态发布，防止同一工作区重复打开；现有 `control_workers` 参数不代表这些操作已经并行。
3. 长期打开大量工作区需要安全卸载机制，必须处理引用、事务、后台注册、脏页和恢复状态；当前绑定上限明确约束驻留数量，不承诺无限绑定。
4. 继续细分恢复失败与暂时 I/O/资源错误，避免把可重试错误误判为持久损坏；PUBLIC 元数据一致性要求保持不变。

本轮未修改 Web，不恢复 Neo4j 迁移，也不修改 Neo4j 数据。当前验证不是大型图谱吞吐或全内核无缺陷证明。


## 追加审计：句柄生命周期与异步全文维护

发现并修复上一轮引入的回归：每轮全文维护打开新的 Catalog，但 FileIo 使用显式句柄表，Rust 对象离开作用域不会自动关闭文件。即使没有待维护索引也会泄漏。修复在 Session 销毁后显式关闭 Catalog，并覆盖配置失败与维护失败；目录打开失败作为维护错误上报，不再通过 `?` 退出整个 daemon。

扩大审计还发现 DataFile 的创建、临时文件重置、文件头校验，以及 Catalog 的角色、引导页、引导条目校验失败会遗留句柄，现均在失败返回前释放。保留成功路径的显式 close 契约，不改变其他模块借用底层文件句柄的生命周期。关闭自身失败的处置和全内核资源所有权统一仍需后续梳理。

全文维护现在是共享执行池中的任务：仅在目标工作区无运行、排队、挂起 SQL 且无未提交事务时占用一个执行名额，同时阻止该工作区派发新 SQL。其他工作区继续派发；完成（包括失败）后释放名额、归还全文调度状态并继续排队 SQL。已受理的维护计入停机排空。候选工作区轮转，防止固定遍历顺序在少量线程下造成长期饥饿。没有增加每工作区专用线程。

验证：CLI 50 项、storage 247 项、catalog 71 项库单元测试通过。新增故障注入覆盖创建长度/写入失败、临时重置 size/set_len/write/sync 失败、坏文件头、错误文件角色/引导内容；新增维护排队互斥、线程上限、失败后继续执行 SQL 与句柄归还用例。

部署后既有实例实测：跨工作区未提交事务不阻止全文追平，eventual 检索命中；本次追平约 0.15 秒。三个已打开工作区的空闲采样中，句柄最低值前后均为 21，STATUS 最大观测延迟约 2 毫秒。这仅是本次轻载观测，尚未覆盖大型语料与饱和负载。

增加只读脚本 `drivers/python/tests/test_maintenance_existing.py`，显式指定 BICDB_TEST_INI，观测稳定工作区数量下的句柄增长及维护指标；不启动或重启实例。

本次修复晚于 v0.3.2 Release；既有标签不可覆盖，修复记录于 Unreleased。审计仍未全部完成：认证/首次绑定恢复异步化、工作区安全卸载、恢复错误分型与更多资源持有路径继续列为未关闭项。
