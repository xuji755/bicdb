# 按需写入覆盖层与提交验证（2026-10-09）

本阶段把按需访问从只读扩展到 SQL 原生图写入。已完成当前提交序号中验证过的 v3 源图的局部更新；冷启动、提交序号变化、旧头或缺失访问树仍完整验证后写入。这个边界必须保留，不能把缓存命中或 2000 节点测试当作冷图、大型知识库和多连接并发的完整验收。

## 准入与完整源证明

事务引擎保留最多 128 个有界验证凭据。每个凭据包含工作区、图对象、事务 owner、提交序号及完整头字节；不缓存完整图，不持久保存凭据。只有完整加载且核对路由、实体、计数、规范 JSON/记录字节后的源图，或从这种源图原子提交的正确净变更，才能产生凭据。SQL 和用户参数无法传入“已验证”标记。

查询选择头时必须同时匹配 owner、当前提交序号和全部头字节。重启清空凭据；其他事务提交、无关表的提交、DDL、头变化和事务 owner 变化都会使旧凭据不能命中。源头被重新校验哈希但统计与数据不符时，仍走完整验证并原子拒绝，保留上一阶段损坏统计测试。

这是该阶段的保守运行期优化。后续已经接入[独立持久聚合证明](bicdb_独立语料聚合证明与冷图写入接入_20261009.md)，新图在冷启动及无关提交后可核对实际观察源和证明路径，不再依赖本节运行期凭据。统计字段自身的校验和从未作为全图数据证明。

## 覆盖层与预算

新增显式 `execute_with_storage_write_deadline` 接口，旧 `execute_with_storage` 接口保持只读。Source 的目录与邻接候选合并本轮缓存中新建/修改对象；删除标记阻止后续 MATCH 再从旧快照取回已删除对象。非 DETACH 删除也查询源的完整关联边，不能因为缓存没有边而允许删除仍被引用的节点。DETACH 在删除前加载关联边并核对共享边/删除预算。

失败恢复调用者的初始局部缓存；不会因为加载后再修改标签导致失败缓存留下不一致的目录。CALL/UNION 继续共享原值 journal、预算和时钟。

完整源 `GraphCorpus` 与局部缓存分开。规范 JSON 字节按首次原值/最终值计算净增减，同时调整完整节点/边数量、逗号和 ID 水位位数。原生记录字节按真实旧节点行长度与独立边规范大小计算，保留非规范节点 JSON 的兼容性。最终头保存全图数值，不能用缓存长度代替全图数值。

`StorageImage::partial_adjacency` 是预检映像，只保存已验证的原始节点记录和边大小。它必须使用变更集 patch；普通完整图 `patch` 拒绝该映像。原始节点与 journal 不符、缺失旧边大小、全图下溢/溢出或超限均拒绝。边仍独立规划，不创建第二套旧 kind-2 拓扑记录。

## 唯一键与提交

唯一性先精确探测持久树，再按源快照取回未缓存候选；未缓存不等于删除。净修改 ID 由最终值一起检查，允许键交换与释放。新增带 source resolver 的接口要求完整候选；未知/失败证明拒绝，不能在局部缓存上流式兜底。原有完整图接口保留完整图扫描兜底。

所有普通原生发布及恢复导入保存预检前的原头，在同一个引擎写上下文里取得当前 manifest 行锁，核对完整头、版本、路由后才修改拓扑。读取当前头使用最新已提交及本事务视图，既有查询快照仍描述预检源。源已经变化就报 `native graph source changed; retry the statement`；语句回滚保留此前成功事务工作。

这为原生源变化及唯一性证明提供提交前保护；不能因此宣称已完成多连接 SQL 的全部写入交错、并发 MERGE 或一般节点 Move。物理重建继续沿用其独立 idle/原子 DDL 协议，尚未做完整并发性能验收。

## 修改后的全文检索

未修改时沿用现有冷全文查询。语句已修改源之后再调用全文检索，需要完整语料排名/新鲜度语义：此时完整读取源，再应用 journal 覆盖层交给全文提供者。不能把局部缓存当成全文语料。普通局部源写入产生的全文事件仍只枚举净变更并与实体同事务提交。

邻接链预算回调此前丢失工作/字节与时间分类，本轮因提交验证增加原生工作而暴露该问题；已恢复正确错误分类，原 15 单位失败测试及回滚断言没有放宽。
