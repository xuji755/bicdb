## 0 边界（先划死）

**本设计覆盖**：`bicdb-catalog` 的**模块设计**——引导页的**字节布局**（新定，
格式永久固定）、字典表的**内核常量**清单、**打开链**、**对象缓存**、
`resolve`/`type_descriptor`/`object_version` 的**契约**、**DDL 的执行路径**
（写侧：对象号分配、对象锁、版本推进、索引构建、段回收）。

| 不在本设计 | 归属 |
| --- | --- |
| 字典表的**数据模型**（有哪些表、各列是什么、为什么这么分层） | `arch/03` §3.1——**已定，本设计只引用不重复** |
| 段/页/行的物理操作（建段、写页、行格式） | `bicdb-storage`（已实现，直接用） |
| 事务引擎（begin/commit/undo/redo/锁原语） | `bicdb-txn`（已实现；本设计只用其**行锁**与**提交序号**） |
| 名字解析的**语法面**（哪些名字算保留） | `spec/SQL.md` §0.4——已定 |
| DDL 的 SQL 语法 | `doc/SQL前端设计_v0.1.md`（S7 片） |

**一条总纪律**：**字典表就是普通表**（`arch/03` §3.1 的四条好处）——
字典的读写全部经**表引擎 + 事务 + redo**，目录模块**不发明第二套元数据机制**。

## 1 取法与纪律

| # | 纪律 | 依据 |
| --- | --- | --- |
| 1 | 字典表 = 普通表（复用页/行/索引/undo/redo/恢复） | `arch/03` §3.1——"元数据不是特例" |
| 2 | **引导页是内核常量**：格式永久固定、写一次、**不产生 redo**；靠**两份副本** + 备份 | `arch/05` 页类型 12 行 |
| 3 | **对象锁 = 对象字典行上的行锁**（`obj$` 那一行） | `arch/05` §334 |
| 4 | **版本 = `mtime`（提交序号）**；解析结果携带版本，**计划缓存失效靠比对** | REQ-SQL-009 |
| 5 | **不可区分**：找不到 = "不存在"（不区分别人的/已删的/从未存在的） | REQ-ISO-006 |
| 6 | 目录接口**只读**；写一律走 DDL 路径（独立事务 + 对象锁；活动事务中拒绝 DDL） | REQ-ENG-006；TXN REQ-TXN-016 |
| 7 | 不设 `file$` 落盘字典表——文件清单的权威在**控制文件**，查询由**固定表** `file$` 满足 | `arch/03` §3.1.2/§3.1.4 |

**与 PG/Oracle 的对照**（记档，防"为什么不像 X"）：

| | Oracle | PG | 我们 |
| --- | --- | --- | --- |
| 字典载体 | `obj$`/`tab$`/`col$`…（普通表 + 引导 `bootstrap$` 存 DDL 文本） | 系统目录（`pg_class`…，与用户表同引擎） | 同 PG 的手法、**同 Oracle 的表族**；引导页**存结构化条目、不存 DDL 文本**（`arch/03` §3.1.1 已定） |
| 缓存失效 | 依赖链 + 失效通知 | relcache/syscache invalidation 广播 | **世代号 + 精确失效**（§4.3）；跨进程不适用（V1.0 单进程引擎） |
| 对象版本 | `OBJECT_ID` + DDL 时间 | 目录行的 xmin 可见性 | **`mtime` = 最后修改的提交序号**（`arch/03` §3.1.3） |

## 2 引导页（页类型 12）——**字节布局（新定，格式永久固定）**

**位置**：`file 0` 的**块 1 与块 2**（两份副本；读时取**有效的那份**，
两份都坏 ⇒ 按 §2.4 重建）。块 0 是文件头页（类型 11，**偏移精确化已实现**）。

```text
偏移 0      标准页头 68B（page_type = 12；file_id/block_id 自证——同其它页）
偏移 68     页体头 8B
              entry_count   2B     条目数 N
              format_version 1B    当前 = 1
              保留           5B
偏移 76     条目区：entry[N]，**每项 24B**
              dataobj#      4B     数据对象号（u32 小端）
              seg_type      1B     复用 §5.11 的段类型枚举（1 堆 / 2 BTree / 3 邻接…）
              保留          1B
              seg_header    6B     段头页 ROWID（6B = file 10b │ block 28b │ row 10b）
              iniexts       4B     初始区数
              保留          8B     （凑 24B 对齐；将来扩展不破格式）
偏移 76+24N 起为**空闲区**（必须为零；页尾 4B 校验副本照常，`seal` 纪律）
```

**条目清单 = 最小自举集**（`arch/03` §3.1.1 已定；**N = 表数 + 该表的自举索引数**）：

| 工作区种类 | 条目 | N |
| --- | --- | --- |
| 普通工作区 | 7 张自举表（`obj$`/`tab$`/`col$`/`ind$`/`icol$`/`seg$`/`undo$`）+ 8 个自举索引（`obj$` 两个、其余各一，键见表） | **15** |
| `public` | 普通 15 + 其独有的三张（`user$`/`ws$`/`fs$`）+ 其 5 个唯一索引（`name` 唯一索引等） | **23** |

**不进的**：`stat$`/`seq$`（**由自举层描述**——它们的字典行在建区时经 DDL
插入，段头位置走 `seg$`，见 §5）；固定表 `file$`（不落盘，`arch/03` §3.1.4）。

**自举属性**（每条都是"为什么必须在这里"）：

- 读引导页**不依赖任何字典行**——这是自举链的起点（块 0 → 块 1 → 7 张表 → 其余一切）；
- **每个自举表至少有一个唯一索引并同样进引导页**——否则自举之后仍无法按名/按号定位字典行；
- `seg_type` 必须随条目存：读引导页时字典表还不可用（`arch/05` §1631 的同一条理由）。

**读取协议**：读块 1 → 校验（页头自证 + 页尾校验副本 + `entry_count` 与
`format_version` 合理）→ 有效即用；无效读块 2；两份都无效 ⇒ **按 §2.4 重建**
（扫 `file 0` 的段头页，交叉核对 `dataobj#`/`seg_type`）——重建是恢复路径的一部分，
不在正常打开路径上。

**写入协议**：只在**创建工作区**时写一次（§5.1）；此后**不变**。
它**不产生 redo**（"用 redo 保护它"在逻辑上不成立——它是恢复锚点之一，
`arch/05` §1360）；耐久性靠**写后 fsync**（建区路径的显式 fsync，属创建协议）。

## 3 字典表：内核常量清单

**列定义以 `arch/03` §3.1.3 为准**（本设计不重复）；这一节的用途是**把"内核
常量"钉成可编码的清单**——`bicdb-catalog` 里有一张常量表，
启动自检时与引导页/字典表交叉核对（不一致 ⇒ 打开失败，响亮）。

| 表 | 键（唯一索引） | 表选项（`arch/03` §3.1.2） | 说明 |
| --- | --- | --- | --- |
| `obj$` | `(obj#)`、`(namespace, name)` | 普通：`transactional` + `logging=full` + `update_mode=in_place` | 所有对象的根定义；`type#` 编号空间照 Oracle 预留 |
| `tab$` | `(obj#)` | 同上下 | 表专有（七项表选项在此） |
| `col$` | `(obj#, col#)` | 〃 | 列定义（`deflt` 存**物理编码**，一列装完） |
| `ind$` | `(obj#)` | 〃 | 索引专有（`bobj#`/`type#`/`is_unique`/`status`） |
| `icol$` | `(obj#, pos#)` | 〃 | 索引键列组成（`is_desc`） |
| `seg$` | `(dataobj#)` | 〃 | 持久段登记（表段/索引段；undo 段走 `undo$`、临时段不入字典） |
| `undo$` | `(seg#)` | 〃 | Undo 段本身（V1.0 单段、位置固定；**不进 `obj$`**） |
| `stat$` | `(obj#)` | **非事务表**：`logging=redo_only` | 统计可丢；**读路径不产生同步写** |
| `seq$` | `(seq#)` | 普通 | 系统序列（`object_id`/`memory_id`/…）；分配在内存、跳号无害 |
| `user$`/`ws$`/`fs$`（仅 `public`） | 见 `arch/03` | 普通 | 主体 / 工作区登记 / 文件系统池 |

**表选项驱动行为**：`tab$.transactional/logging/update_mode/retention/…`
**就是**表引擎的输入（`arch/08` 五种表类型的落地）——目录模块把选项**翻译**
成段创建参数与访问策略；**翻译表是本模块的唯一职责点**（执行器不查字典）。

## 4 打开链与对象缓存

### 4.1 打开链（`open_workspace`）

```text
① 控制文件（§2.6 已实现）→ 文件清单 + 检查点位置
② file 0 块 0（文件头页）：校验 role=0 / format_version / workspace_ref
③ 块 1（或块 2）引导页 → 15/23 个自举条目（dataobj#、seg_type、段头、iniexts）
④ 逐个 `Segment::open(file0, 段头块)` → 7 张自举表 + 索引就绪
⑤ **恢复**（WAL redo 从检查点起，含字典页——它们是普通页）
⑥ 建**对象缓存**（§4.2）：先装入自举对象（obj# ≤ 99），用户对象按需装入
⑦ 就绪：`resolve`/`type_descriptor`/`object_version` 可用
```

**打开期的读用哪个快照**：`redo` 完成后的**最新已提交序号**（打开是恢复语义，
不是语句语义）；此后每个会话的目录读用它**自己的语句快照**
（REQ-SQL-009 的版本比对因此是快照一致的）。

### 4.2 对象缓存（每工作区一份，进程内）

```text
by_obj   : HashMap<u32 /*obj#*/, ObjectEntry>
by_name  : HashMap<(u8 /*namespace*/, String /*name*/), u32 /*obj#*/>
ObjectEntry { obj#, name, namespace, type#, dataobj#, ctime, mtime, status,
              列定义（按需装入）, 表选项（按需装入） }
```

三条纪律：

1. **缓存是派生物**：任何不一致以**字典行**为准；缓存只做加速（miss 即回查
   索引——`(namespace,name)` 或 `(obj#)` 的点查）。
2. **不跨工作区**：缓存随工作区上下文生命周期，键空间里没有工作区这一维
   （一个实例的 `catalog` 每个工作区一个实例）。
3. **快照一致性**：装入/回查用**调用方给的快照**；同一会话内同一快照的
   重复解析结果稳定（不会被并发 DDL 搅动——RC 语义下快照内不变）。

### 4.3 失效：**世代号 + 精确失效**（进程内、无广播）

```text
每个工作区一个 **catalog generation**（u64，内存原子量；打开时 = 恢复后的提交序号）
- 任何 DDL 提交后 generation 自增（提交路径的一个钩子，先自增后放行）
- 缓存项记装入时的 generation；resolve 先读 generation（一次原子读）：
    generation == entry.generation  ⇒ 直接命中
    generation >  entry.generation  ⇒ **精确回查**（DDL 同时登记它改过哪些
                                       obj#/name，回查只失效那些；无登记 ⇒ 全清）
- **计划缓存**用另一套（REQ-SQL-009 的 `(obj#, mtime)` 元组比对）——
  两层各司其职：对象缓存要快，计划缓存要准
```

**前提记档**：**单进程引擎**（V1.0 一个实例一个 daemon；外部工具不写库内数据）。
跨进程失效不做——若将来出现第二个写者，本节协议必须重做（**不得**假设它已经支持）。

## 5 DDL 执行（写侧）

### 5.1 创建 / 克隆工作区（引导页的唯一写入路径）

```text
① 分配 file 0/1/2（与全局控制文件的登记，见 §2.12——不在本设计重复）
② file 0 块 0（文件头页，含位图空间头）
③ 建 15 个自举段（7 表 + 8 索引）：段头页 + 空 B+Tree（树头写扩展区）
④ **写引导页两份（块 1、块 2）→ fsync file 0**   ← 自举链成立
⑤ DDL 事务：建 stat$/seq$（普通 DDL 路径，§5.2）+ 预置业务对象（MEM 五张等，更高层驱动）
⑥ 提交；`public.ws$` 登记（§2.11/§2.12）
CLONE OF：②③④ 的文件按 reflink 复制（§2.7）——**引导页原样随文件而来**，
`seq$` 原样延续（"序号空间原样延续"，§2.12）
```

**崩溃于中途**：未在 `public.ws$` 登记的工作区按"**未完成创建**"清除
（判据 = `ws$` 行存在与否；清理 = 删除该工作区目录，含其全部文件）。
④ 之前崩溃与之后崩溃都归这一条——**登记是唯一的可见性分界**。

### 5.2 `CREATE TABLE`

```text
一个 DDL 事务（独立；活动事务中发 DDL ⇒ 拒绝，TXN REQ-TXN-016）：
① 名字检查：resolve(namespace=1, name) 命中 ⇒ "已存在"；保留名（`$` 结尾/预置名）⇒ 拒绝
② 分配 obj#（seq$ 的 object_id 序列；用户对象 ≥ 100）与 dataobj#
③ 写 obj$ 一行（type#=2、namespace=1、dataobj#、status=1）
④ 写 tab$ 一行（七项表选项：**由 `WITH` 选项与表类型翻译而来**，§3）
⑤ 写 col$ 每列一行（type#/length/precision/scale/nullable）
⑥ 建表段（`Segment::create`，SegType::Heap，obj#/dataobj# 进段头自描述）
   + 写 seg$ 一行（段头位置）
⑦ **取对象锁**：在 obj$ 该行上加行锁（排他）——DDL 互斥（§1 纪律 3）
⑧ 提交前**预约提交序号** `seq = engine.reserve_commit_seq()`，
   把 ③④⑤⑥ 写的所有行的 `mtime = seq`；`commit()` 用预约的序号落定
```

> **`reserve_commit_seq` 是本设计对事务引擎的新要求**（小增量）：
> 提交序号在提交时分配，而 `mtime` 必须在提交**前**写进字典行。
> 预约 = 原子取号并保证本事务最终以此号提交（单写者语义下无冲突；
> 其余事务的提交序号顺延）。**记档**：若评审认为不值得，替代方案是
> `mtime = 0`（未知）并让计划缓存退化为"表选项变更即全失效"——**不推荐**
> （REQ-SQL-009 的比对失效要 mtime 可用）。

### 5.3 `CREATE INDEX`（含唯一索引）与表达式索引

```text
① 名字检查 + 分配 obj#/dataobj#（同 5.2 ①②）
② 写 ind$（bobj# = 基表 obj#、type#=0 BTree、cols、is_unique）与 icol$（键列序 + is_desc）
③ 建索引段（SegType::BTree）+ 写 seg$；树头写扩展区
④ **构建**：表对象锁（排他）下——按基表语句快照扫描全表，
   逐行求键（表达式索引求表达式），**外部排序**（temp 段；REQ-RES 的 temp 配额），
   再**批量灌 B+Tree**（自底向上；不逐行随机插入）
⑤ mtime 推进与提交（同 5.2 ⑦⑧）
```

**唯一性检查**：④ 的排序阶段检出重复键 ⇒ **整个 DDL 事务回滚**并报
"唯一约束冲突（重复键）"（V1.0 无约束对象，唯一性即唯一索引，`arch/03` §3.1.2）。
**表达式索引**的键来自前端（`json_get(col,'a.b')`）；目录只存 `icol$` 的
"表达式序号"？——**否**：表达式索引的键列在 `col$` 里**没有列号**。
**定案**：`icol$.col# = 0` 表示"键是该索引的**表达式**"，表达式本身存
`ind$` 的**扩展列**（见下），求值由执行器侧的键求值器承担。

> **`icol$.col# = 0` 的表达式**：`arch/03` 的 `ind$` 列清单没有表达式列。
> 本设计**新增一列** `ind$.expr_src 字节串`（存**规范化后的表达式文本**，
> 由 Binder 侧生成、目录原样保存），`icol$.col# = 0` 时按 `pos#` 对应到
> 该文本里的第 `pos#` 个表达式。**这是对 `arch/03` 的一处追加**——
> 评审通过后同步 `arch/03` 的列定义表。**理由**：表达式键必须可重建
> （打开索引时要能重新求值），而字典表不能引用 AST（AST 是前端对象）。

### 5.4 `DROP TABLE` / `DROP INDEX`

```text
一个 DDL 事务 + 对象锁（排他）：
① 删 obj$ 行（**级联**：表 ⇒ 其全部索引的 obj$/ind$/icol$ 行一并删）
② 删 tab$/col$（或 ind$/icol$）行
③ 段回收：段的全部区归还 LMT（位图；经 redo 保护）——`seg$` 行删除
④ 表选项为 `cleanup = segment_drop` 的表（session 等）⇒ 同一路径；
   `cleanup = row_delete` ⇒ 行级清理由 TTL 维护走 DML
⑤ mtime/提交（同 5.2 ⑦⑧）——**没有 mtime 了**（行已删）；
   计划缓存的失效靠"对象不存在"这条比对（键里的 obj# 已解析不到）
```

**DROP 后的陈旧引用**：`obj#` **不回绕**（`arch/03` §3.1.3）——
陈旧计划引用已删对象时解析失败（"不存在"），不会指向新对象。

### 5.5 `Move`（数据文件搬迁）与索引失效

`Move` 后索引失效落在 **`obj$.status`（权威）与 `ind$.status`（副本）**，
同一事务一起改（`arch/03`）。**本设计的落点**：`status ≠ 1` 的索引
**不进入访问路径**（选路期排除）且**计划缓存键失配**（REQ-SQL-009 的
`(obj#, mtime, status)` 三元组）。重建由"重建索引"路径（= 5.3 的 ④ 换段）承担。

### 5.6 工作区 DDL（`CREATE/ALTER/DROP WORKSPACE`）

在 **`public` 工作区**上执行（管理元数据 `ws$` 在那里）；**仅 admin，
资格检查先于对象查找**（`spec/SQL.md` REQ-SQL-005 的三条语义）。
实现落点：本模块的 `public` 实例上跑 §5.1/`ws$` 的 DML——
**不跨工作区**（全程一个事务，REQ-ISO-005）。

## 6 接口契约（REQ-ENG-006 的落地）

```text
trait Catalog {                       // 每工作区一个实例；只读
  fn resolve(&self, snapshot, ns: Namespace, name: &str)
        -> Result<ObjectRef, CatalogError>;            // 找不到 ⇒ NotFound（不可区分）
  fn resolve_by_obj(&self, snapshot, obj#: u32) -> Result<ObjectRef, CatalogError>;
  fn columns(&self, snapshot, obj#) -> Result<Vec<ColumnDesc>, CatalogError>;
  fn indexes_of(&self, snapshot, table_obj#) -> Result<Vec<IndexRef>, CatalogError>;
  fn object_version(&self, snapshot, obj#) -> Result<ObjectVersion, CatalogError>; // = mtime
  fn fixed_table(&self, name: &str) -> Option<FixedTable>;   // file$/session$/lock$ —— 不查字典
}

ObjectRef { obj#, namespace, name, type#, dataobj#, status, ctime, mtime
            /* dataobj# = 0 ⇒ 无段（视图/过程——V1.0 不产生） */ }
ColumnDesc { col#, name, type#, length, precision, scale, nullable }
IndexRef   { obj#, bobj#, kind(BTree/ANN/邻接), is_unique, status, 键列组成 }
FixedTable = file$（内容 = 控制文件内存映像）
```

**语义要点**：

- **没有写方法**（REQ-ENG-006 的"只读"）——写只经 DDL 路径；
- `resolve` 的**不可区分**：跨区名字、已删除、从未存在 ⇒ 同一个 `NotFound`；
- `type_descriptor` 的实际形态 = `ColumnDesc` 交给 **TYP 内核**转成类型描述子
  （目录不解释类型语义——REQ-SQL-010 的"同一件事只有一个实现"）；
- **执行器的取用**：resolve 表 ⇒ `dataobj#` ⇒ `seg$.file_id/block_id` ⇒
  `Segment::open` ⇒ `data_blocks(hwm)` 得扫描边界（执行器不查字典，
  只拿"段头 + 列形状 + 表选项"三样）。

**验收要点**（照 REQ-ENG-006）：跨区名字、保留名、版本变更后缓存失效
三条各有用例；`object_version` 贯穿计划缓存判定。

## 7 实施切片（编码顺序）

| 片 | 内容 | 验收 |
| --- | --- | --- |
| **C1** | 引导页格式（类型 12 的读写 + 两份副本 + 校验与重建）+ 字典表**格式常量**（§3 清单 + 自检） | 往返：写 → 关 → 开 → 逐项一致；单副本损坏 ⇒ 用另一份；两份坏 ⇒ 按段头页重建一致 |
| **C2** | **打开链**（§4.1）+ 对象缓存与世代号（§4.2/4.3） | 真件：建区 → 关 → 开 → 7 张自举表可查；DDL 提交 ⇒ 世代自增 ⇒ 缓存精确失效 |
| **C3** | `Catalog` 只读面（§6）：resolve/columns/indexes_of/object_version/fixed_table | 不可区分三例；版本随 DDL 变更；跨工作区不共享 |
| **C4** | DDL 写侧（§5.2/5.3/5.4）：建表/建索引（含唯一性与表达式键）/删表 | 建 → 插入 → 查询闭环；唯一冲突回滚干净；DROP 后段回收（区归还位图）可观测；崩溃注入 ⇒ 字典自洽 |
| **C5** | `stat$`/`seq$` 接入 + `Move` 失效落点（§5.5） | 序列分配（内存 + 定期刷入、跳号无害）；Move 后索引不进选路 |

**依赖**：C1/C2 只依赖已实现的 `bicdb-storage`/`bicdb-wal`/`bicdb-txn`；
**C4 需要 `reserve_commit_seq`（§5.2 的记档项）**——先做该小增量；
SQL 前端 S2 依赖 C1–C3。
