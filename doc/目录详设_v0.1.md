## 0 边界（先划死）

**本设计覆盖**：`bicdb-catalog` 的**模块设计**——引导页的**字节布局**（新定，
格式永久固定）、字典表的**内核常量**清单、**打开链**、**对象缓存**、
`resolve`/`type_descriptor`/`object_version` 的**契约**、**DDL 的执行路径**
（写侧：对象号分配、对象锁、版本推进、索引构建、段回收）。

| 不在本设计 | 归属 |
| --- | --- |
| 字典表的**数据模型**（有哪些表、各列是什么、为什么这么分层） | `arch/03` §3.1——**已定，本设计只引用不重复** |
| 段/页/行的物理操作（建段、写页、行格式） | `bicdb-storage`（已实现，直接用） |
| 事务引擎（begin/commit/undo/redo/锁原语） | `bicdb-txn`（已实现；本设计只用其**行锁**与**提交序号**） |
| 名字解析的**语法面**（哪些名字算保留） | `spec/SQL.md` §0.4——已定 |
| DDL 的 SQL 语法 | `doc/SQL前端设计_v0.1.md`（S7 片） |

**一条总纪律**：**字典表就是普通表**（`arch/03` §3.1 的四条好处）——
字典的读写全部经**表引擎 + 事务 + redo**，目录模块**不发明第二套元数据机制**。

## 1 取法与纪律

| # | 纪律 | 依据 |
| --- | --- | --- |
| 1 | 字典表 = 普通表（复用页/行/索引/undo/redo/恢复） | `arch/03` §3.1——"元数据不是特例" |
| 2 | **引导页是内核常量**：格式永久固定、写一次、**不产生 redo**；**主副空间分离**（§2.1）+ 备份 | `arch/05` 页类型 12 行；证据包 `catalog-boot-20261006` |
| 3 | **锁：统一的行锁，没有"对象锁"这一新机制**（用户口径 2026-10-06）——DDL 对**对象字典行**取**排他行锁**、"锁哪一行"是约定，原语/等待/超时/死锁路径与其他行锁**同一套**；名字唯一性靠 `obj$` 的 `(namespace,name)` **唯一索引**（不是先查后插） | `arch/05` §334；§5.2 |
| 4 | **版本 = `mtime`（提交序号）**；解析结果携带版本，**计划缓存失效靠比对** | REQ-SQL-009 |
| 5 | **不可区分**：找不到 = "不存在"（不区分别人的/已删的/从未存在的） | REQ-ISO-006 |
| 6 | 目录接口**只读**；写一律走 DDL 路径（独立事务 + 对象行锁；活动事务中拒绝 DDL） | REQ-ENG-006；TXN REQ-TXN-016 |
| 7 | 不设 `file$` 落盘字典表——文件清单的权威在**控制文件**，查询由**固定表** `file$` 满足；**文件一致性靠 `文件头 file_scn` ↔ `控制文件检查点` 核对**（不靠第二张清单表） | `arch/03` §3.1.2/§3.1.4；§2.5 |
| 8 | **字典数据有独立缓冲**（`row cache` 形态；用户口径 2026-10-06）——与缓冲池、与 WMM 工作内存池**都分离** | §4.2；证据 E5–E9 |
| 9 | **格式带版本号**（文件头 `format_version`、引导页体内版本）；**不认识即拒绝**（fail-closed） | §2.4；`arch/05`（格式未冻结前可调） |

**与 PG/Oracle 的对照**（记档，防"为什么不像 X"）：

| | Oracle | PG | 我们 |
| --- | --- | --- | --- |
| 字典载体 | `obj$`/`tab$`/`col$`…（普通表 + 引导 `bootstrap$` 存 DDL 文本） | 系统目录（`pg_class`…，与用户表同引擎） | 同 PG 的手法、**同 Oracle 的表族**；引导页**存结构化条目、不存 DDL 文本**（`arch/03` §3.1.1 已定） |
| 字典数据缓存 | **row cache**（`dc_*` 按型分、在共享池、`V$ROWCACHE` 统计） | `catcache`/`relcache`（分型 + invalidation 广播） | **字典行缓存**（§4.2：按字典表分型、独立于缓冲池；单进程 ⇒ 写穿 + 世代号，无 enqueue 层） |
| 缓存失效 | 依赖链 + 失效通知；RAC 靠 `Q[A-Z]` row cache 锁 | 共享失效消息广播 | **世代号 + 精确失效**（§4.3）；跨进程不适用（V1.0 单进程引擎） |
| 对象版本 | `OBJECT_ID` + DDL 时间 | 目录行的 xmin 可见性 | **`mtime` = 最后修改的提交序号**（`arch/03` §3.1.3） |
| 文件的恢复位点 | 数据文件头记 **checkpoint SCN**（介质恢复判据） | 页 LSN + `pg_control` 检查点位点 | **文件头记 `file_scn`**（§2.4）+ 控制文件检查点（§11.7）——两处比对判"落后/不配对" |

## 2 file 0 排布与引导页（页类型 12）

### 2.1 排布：**核心元数据带 + 副本带**（评审修订 2026-10-06，用户口径）

**问题**：原草案把引导页的两份副本放在**相邻块**（块 1、块 2）——
**同一片损坏（坏块簇 / 一次误写 / 头段被覆盖）会把两份一起带走**，
"两份副本"退化为"一份"。**副本的价值在故障域分离**，不在份数。

**证据**（证据包 `catalog-boot-20261006`）：ext4 把备份超级块放在**多个块组**、
主在块 1 而备份在远处（实例：块 32768），恢复用 `e2fsck -b` / `mount -o sb=`
（E1）；Oracle 控制文件多路复用的官方推荐是**放不同磁盘**——"只要还有一份
完好就能恢复"（E3/E4）。用户评审意见与二者同向。

**file 0 专用排布**（数据文件、undo、temp 保持现行统一布局**不变**）：

```text
块 0                  文件头页（类型 11，**主**）——含位图空间头
块 1                  引导页（类型 12，**主**）
块 2 .. 255           **核心元数据带**预留（[0, 4 MiB)；**不写入**，稀疏读零）
──────────────────── 4 MiB 边界（块 256）────────────────────
块 256                引导页**副本**      ┐ 副本带（[4 MiB, 8 MiB)）
块 257                文件头**副本**      ┘ （与主相距 4 MiB；随头页更新同写）
块 258 .. 511         副本带预留（格式上允许将来放更多副本组——**不改格式即可加**）
──────────────────── 8 MiB 边界（块 512）────────────────────
块 512 .. 831         file 0 位图区（40 区 × 8 页 = 320 页；结构与现行相同）
块 832 ..             file 0 数据区（**字典表的段**从这里分配）
```

**三条性质**：

| # | 性质 |
| --- | --- |
| 1 | **主副相距 4 MiB**（块 1 ↔ 块 256）——单点损坏（坏块簇/一次误写/头段覆盖）不可能同时命中 |
| 2 | **头副本**：**文件头页也被复制**（被毁同样致命——`file_id`/`role`/当前大小/位图空间头都在里面）；**头页每次更新（扩展）⇒ 头副本同写**（扩展是低频事件） |
| 3 | **预留不写入**：两条带的未用块**保持零**（稀疏；同"扩展即 `set_len`、零搬移"的现行做法）——磁盘占用仍是"实际写过的几百 KiB"，预留的只是**地址空间** |

**常量**（内核常量，随格式版本冻结）：

```text
META_CORE_BAND_BLOCKS   = 256    （4 MiB；"4M 不够可以增加"——**增加即改格式版本**）
META_REPLICA_BAND_BLOCKS= 256    （4 MiB；组内 2 页：引导页副本 + 文件头副本）
FILE0_BITMAP_FIRST_BLOCK= 512    （= (核心带 + 副本带) / 页大小）
FILE0_DATA_AREA_FIRST   = 832    （= 512 + 320）
其它 role：现行公式不变（位图 1..320、数据区 321）
```

**代码影响**（列表化，供 C1 实施）：`datafile.rs`/`bitmap.rs` 里写死的
`DATA_AREA_FIRST_BLOCK` 换成**按 role 取的布局表**（`FileLayout{bitmap_first,
data_area_first}`）；`MIN_FILE_BLOCKS` 对 file 0 取 832 + 8；涉及变更处逐点
对表排查（§7 C1 的验收含"file 0 与数据文件各自的块公式"）。

### 2.2 引导页（类型 12）字节布局（格式永久固定）

```text
偏移 0      标准页头 68B（page_type = 12；file_id/block_id 自证——同其它页）
偏移 68     页体头 8B
              entry_count   2B     条目数 N
              format_version 1B    当前 = 1
              保留           5B
偏移 76     条目区：entry[N]，**每项 24B**
              dataobj#      4B     数据对象号（u32 小端）
              seg_type      1B     复用 §5.11 的段类型枚举（1 堆 / 2 BTree / 3 邻接…）
              保留          1B
              seg_header    6B     段头页 ROWID（6B = file 10b │ block 28b │ row 10b）
              iniexts       4B     初始区数
              保留          8B     （凑 24B 对齐；将来扩展不破格式）
偏移 76+24N 起为**空闲区**（稀疏零；页尾 4B 校验副本照常，`seal` 纪律）
```

**条目清单 = 最小自举集**（`arch/03` §3.1.1 已定；**N = 表数 + 该表的自举索引数**）：

| 工作区种类 | 条目 | N |
| --- | --- | --- |
| 普通工作区 | 7 张自举表（`obj$`/`tab$`/`col$`/`ind$`/`icol$`/`seg$`/`undo$`）+ 8 个自举索引（`obj$` 两个、其余各一，键见表） | **15** |
| `public` | 普通 15 + 其独有的三张（`user$`/`ws$`/`fs$`）+ 其 5 个唯一索引 | **23** |

**不进的**：`stat$`/`seq$`（**由自举层描述**——字典行在建区时经 DDL 插入，
段头位置走 `seg$`，见 §5）；固定表 `file$`（不落盘，`arch/03` §3.1.4）。

**自举属性**：读引导页**不依赖任何字典行**（自举链起点：块 0 → 块 1 → 7 张表 →
其余一切）；每个自举表至少一个唯一索引**同样进引导页**；`seg_type` 必须随条目
存（读引导页时字典表还不可用——`arch/05` §1631 的同一条理由）。

### 2.3 读写协议

**写**：只在**创建工作区**时写一次（§5.1）+ 头页更新时同步头副本；
**不产生 redo**（"用 redo 保护它"在逻辑上不成立——它本身就是恢复锚点；
`arch/05` §1360）；耐久性靠创建路径的显式 **fsync**。
CLONE 时随文件 reflink 复制（`arch/03` §2.7），**引导页与副本原样随文件而来**。

**读（打开链的第 ②③ 步，含自愈）**：

```text
① 主区：块 0（头）+ 块 1（引导页）——页头自证 + 页尾校验 + 与上下文互洽
      （workspace_ref / role / file_id）⇒ 有效即用（正常路径）
② 主区任一处无效 ⇒ 读**副本带**（块 256/257）：
      一律先逐页校验；有效 ⇒ **就地把主区重写回去**（自愈；记审计/告警一次）
③ 主副皆无效 ⇒ **重建**（兜底，E2）：
      · 引导页：扫 file 0 数据区的段头页（类型 7）——
        四个自举要素都能读出：dataobj#/seg_type/seg_header（即该页自身块号）/
        iniexts；与"字典表常量清单"（§3）交叉核对后重建
      · 文件头：file_id/role/workspace_ref 取控制文件与打开上下文，
        **当前大小取文件实际长度**，位图空间头按固定公式重建
      · 重建是**恢复动作**：写回主区 + 副本带，并记一次告警
```

**两份副本都坏还能重建**——这是 `arch/03` 已定的兜底（"扫 file 0 找段头页重建
引导页"）；本次改动把它的触发概率进一步压低（主副分离）。

**数据文件的文件头**（role 1/2/3+）**本次不改**：其位图区与数据区位置是
**固定公式**、头页里的 `runs[]`/当前大小可由实际文件长度与位图页反推，
重建路径比 file 0 简单；若实测发现需要，再按同一"带"手法处理（记入 §8）。

### 2.4 文件头页（类型 11）——**版本号**与**文件 SCN**（评审修订 2026-10-06，用户口径）

**布局扩展**（格式尚未冻结——`arch/05`："编号在格式冻结前仍可调整"——
**现在就做**，避免冻结后再改）：

```text
偏移 68    file_id        2B     ┐
           role           1B     │
           format_version 1B     │ 现行字段，**不动**
           flags          2B     │
           当前大小       6B     │（块数，以文件自身为权威——§2.6 的对偶）
           workspace_ref  8B     ┘（止于 88）
偏移 88    **file_scn     8B**   本文件最新**持久化位点**（LSN 原值——本库的"文件 SCN"）
偏移 96    保留           8B     （将来：检查点时刻 / 头自校验字）
偏移 104   **位图空间头**（run_count 1B │ 保留 3B │ runs[] 4B×40）——**原偏移 88，后移 16B**
```

**代码影响**：`BITMAP_SPACE_HEAD_OFFSET` 88 → **104**、`BITMAP_RUNS_OFFSET`
92 → **108**（`datafile.rs` 常量 + 写入点 + 校验 + 既有用例的断言块号）。

**三条语义**：

| # | 语义 |
| --- | --- |
| 1 | **版本号 = `format_version`**（已有 1B）：**页格式 + 文件头布局**的版本；**任何布局变化必须改版本**；打开时**严格校验——不认识即拒绝**（fail-closed，不猜测、不降级、不做"尽力解析"）。引导页体内另有自己的 `format_version`（自举条目布局）。冻结后不可变（`arch/05` 既有纪律）。 |
| 2 | **`file_scn` = 本文件最新持久化位点**。存 **LSN**（日志位置）而不是提交序号：**恢复判据的比较对象是日志位置**（本库 LSN 与 CommitSeq 同序，两者不混用——`bicdb-common` 的类型隔离）。用途与 Oracle 数据文件头的 checkpoint SCN 同形：<br>· `file_scn` **落后于**检查点起点 ⇒ 该文件来自旧备份/未跟上 ⇒ 必须从更早的日志重放或走介质恢复——**打开时告警/拒绝**（不静默）；<br>· `file_scn` **超前于**日志末尾 ⇒ 文件与日志**不配对**（配错文件/拷贝错）⇒ **拒绝**。 |
| 3 | **推进协议（写序是硬的）**：`file_scn` **只前移**；由**刷盘路径**在该文件的刷盘点之后推进——**先 fsync 数据页 → 再写头页（含 `file_scn`）→ 再写头副本 → fsync**。崩溃窗口只能落在"数据已durable、头还没更新"一侧（头**保守落后**，安全）；**头绝不声称未持久化的位点**。`role = temp`（file 2）**不推进**（打开即整体重置，`arch/03` §4.8）。 |

### 2.5 **文件一致性核对：`file_scn` ↔ 控制文件检查点**（评审修订 2026-10-06，用户口径）

**为什么"不设落盘 `file$`"仍然能判一致性**（本条的动机正是纪律 7 的对偶）：
文件清单的权威在**控制文件**；而**每个文件自己的持久化位点**记在**该文件的头**里
（§2.4 的 `file_scn`）。两者都是磁盘上**独立存在**的事实，**比对即得一致性判定**——
不依赖任何一张"文件清单字典表"（那才是"第二个真相源"）。

```text
控制文件：CheckpointProgress { checkpoint_commit_seq, checkpoint_lsn }   ← 已在实现（§2.6/§11.7）
文件头  ：file_scn（LSN）                                                 ← 本设计新增（§2.4）
```

**打开/恢复时的判定表**（对**每个非 temp 文件**逐一执行）：

| `file_scn` vs `checkpoint_lsn` | 判定 | 动作 |
| --- | --- | --- |
| **相等** | 该文件与检查点一致（干净落盘点） | 正常打开（无需重放该文件） |
| **落后**（`file_scn` < 检查点） | 该文件来自**旧备份/未跟上**，或崩溃时未刷完 | ① 若 `file_scn` ≥ **日志链起点**（未越出可重放范围）⇒ 从 `file_scn` 起重放 redo，**正常恢复**；② 越出日志链 ⇒ **介质恢复**路径（从备份 + 归档）；两者都**记告警**（不静默） |
| **超前**（`file_scn` > 检查点） | 文件**比控制文件新**——配错文件 / 换过控制文件 / 拷贝错 | **拒绝打开**（响亮）；人工介入 |
| 头**读不出/校验失败** | 头损坏 | 走 §2.3 的**副本带自愈 → 重建**路径，恢复后**再回到本表核对** |

**三处配套**：

1. **恢复收尾**：重放完成后，把各文件的 `file_scn` 推进到恢复位点（写头 + 头副本），
   与新的检查点记录**一起**发布（`write_checkpoint_and_groups` 的同一次更新）。
2. **工具面**：`db_check` / 一致性检查（`OPS` 域）用同一对位点做**离线体检**——
   "控制文件说 X、文件头说 Y"的差异报告即本表的前两行。
3. **固定表 `file$` 的核对**：`file$` 的内容取自控制文件内存映像（`arch/03` §3.1.4）；
   若将来出现二者不符（内存映像 ≠ 盘上控制文件），判据同样是"以盘上为准 + 重读"，
   与本表同一条思路。

## 3 字典表：内核常量清单

**列定义以 `arch/03` §3.1.3 为准**（本设计不重复）；这一节的用途是**把"内核
常量"钉成可编码的清单**——`bicdb-catalog` 里有一张常量表，
启动自检时与引导页/字典表交叉核对（不一致 ⇒ 打开失败，响亮）。

| 表 | 键（唯一索引） | 表选项（`arch/03` §3.1.2） | 说明 |
| --- | --- | --- | --- |
| `obj$` | `(obj#)`、`(namespace, name)` | 普通：`transactional` + `logging=full` + `update_mode=in_place` | 所有对象的根定义；`type#` 编号空间照 Oracle 预留 |
| `tab$` | `(obj#)` | 同上下 | 表专有（七项表选项在此） |
| `col$` | `(obj#, col#)` | 〃 | 列定义（`deflt` 存**物理编码**，一列装完） |
| `ind$` | `(obj#)` | 〃 | 索引专有（`bobj#`/`type#`/`is_unique`/`status`） |
| `icol$` | `(obj#, pos#)` | 〃 | 索引键列组成（`is_desc`） |
| `seg$` | `(dataobj#)` | 〃 | 持久段登记（表段/索引段；undo 段走 `undo$`、临时段不入字典） |
| `undo$` | `(seg#)` | 〃 | Undo 段本身（V1.0 单段、位置固定；**不进 `obj$`**） |
| `stat$` | `(obj#)` | **非事务表**：`logging=redo_only` | 统计可丢；**读路径不产生同步写** |
| `seq$` | `(seq#)` | 普通 | 系统序列（`object_id`/`memory_id`/…）；分配在内存、跳号无害 |
| `user$`/`ws$`/`fs$`（仅 `public`） | 见 `arch/03` | 普通 | 主体 / 工作区登记 / 文件系统池 |

**表选项驱动行为**：`tab$.transactional/logging/update_mode/retention/…`
**就是**表引擎的输入（`arch/08` 五种表类型的落地）——目录模块把选项**翻译**
成段创建参数与访问策略；**翻译表是本模块的唯一职责点**（执行器不查字典）。

## 4 打开链与对象缓存

### 4.1 打开链（`open_workspace`）

```text
① 控制文件（§2.6 已实现）→ 文件清单 + 检查点位置
② file 0 块 0（文件头页）：校验 role=0 / format_version / workspace_ref
③ 块 1（或块 2）引导页 → 15/23 个自举条目（dataobj#、seg_type、段头、iniexts）
④ 逐个 `Segment::open(file0, 段头块)` → 7 张自举表 + 索引就绪
⑤ **恢复**（WAL redo 从检查点起，含字典页——它们是普通页）
⑥ 建**字典行缓存**（§4.2）：先装入自举对象（obj# ≤ 99），用户对象按需装入
⑦ 就绪：`resolve`/`type_descriptor`/`object_version` 可用
```

**打开期的读用哪个快照**：`redo` 完成后的**最新已提交序号**（打开是恢复语义，
不是语句语义）；此后每个会话的目录读用它**自己的语句快照**
（REQ-SQL-009 的版本比对因此是快照一致的）。

### 4.2 字典行缓存（`row cache` 形态；用户口径 2026-10-06）

**取法**：照 Oracle 的 **row cache**——"最近使用的**数据字典信息**的缓存"，
**按型分**（`dc_tables`/`dc_objects`/`dc_columns`/…），**独立于缓冲池**
（Oracle 里它在共享池，参数 `SHARED_POOL_SIZE`）（证据 E5–E7）。

**我们的形态**：每工作区一份、**按字典表分型**的行缓存——

```text
型（每型一把读写锁；对应 Oracle 的 row cache objects 子锁存器——证据 E9 约束②）
  obj$   : by_obj#: u32 → ObjRow            ；by_name: (ns, name) → obj#（名字解析热路径）
  tab$   : by_obj#: u32 → TabRow            （表选项：段参数、访问策略的输入）
  col$   : by_obj#: u32 → Vec<ColRow>       （按 obj# 成组装入——一次范围扫）
  ind$   : by_obj#: u32 → IndRow ；icol$: by_obj#: u32 → Vec<IcolRow>
  seg$   : by_dataobj#: u32 → SegRow        （段头跳板）
  undo$  : by_seg#: u32 → UndoRow
每个条目：{ 行值, loaded_at: CommitSeq（装入时的提交序号）, generation }
```

**五条纪律**：

1. **缓存是派生物**：任何不一致以**字典行**为准；miss 即回查（普通索引点查/范围扫，
   经表访问服务——**CR 可见性由服务负责**，缓存层不重造可见性）。
2. **不跨工作区**：缓存随工作区上下文生命周期（每工作区一个 catalog 实例）。
3. **快照门槛**：条目记 `loaded_at`（提交序号）；**读方快照 < `loaded_at` ⇒ 不命中**、
   走存储读（CR）——RC 下不同会话快照不同，缓存只服务"快照 ≥ 装载点"的读。
   快照 ≥ `loaded_at` ⇒ 命中即正确（本进程是唯一写者，缓存里的就是最新已提交版本）。
4. **写穿**：DDL **在同一事务内**改字典行时**同改缓存**（单一写路径——没有
   "该发通知而没发"的窗口；这是单进程形态下对 Oracle enqueue 的替代，证据 E6）。
5. **不进缓冲池、不进 WMM**：独立缓冲（纪律 8）；容量 = **行数 + 字节双上限的
   LRU**（Oracle 的淘汰算法 KB 未给正文 ⇒ **自定**，默认值随 P0 数值项；
   字典行数天然有界于对象数，上限主要是防御性的）。
   **统计四件套照 `V$ROWCACHE`**：`gets` / `hits` / `misses` / `modifications`
   （Oracle 的经验线 GETMISSES/GETS < 15% **只作诊断参考，不写成阈值**——证据 E8）。

**故障模型记档**（证据 E9，Oracle 的 "row cache lock" 等待 = 高频 DDL /
共享池压力下的字典争用）——两条约束已落进设计：**失效按对象精确**（§4.3，
高频 DDL 下不做全清）+ **锁按型分把**（不与无关解析互相阻塞）。

**与对象缓存的区别**：**没有第二套"对象缓存"**——`resolve` 的产物
（obj# + 版本 + 名字）由 `obj$` 型直接服务；列/索引/段的解析各取对应型。
（原草案的"对象缓存 + by_name 映射"并入本节的 `obj$` 型，不保留两份。）

### 4.3 失效：**世代号 + 精确失效**（进程内、无广播）

```text
每个工作区一个 **catalog generation**（u64，内存原子量；打开时 = 恢复后的提交序号）
- 任何 DDL 提交后 generation 自增（提交路径的一个钩子，先自增后放行）
- 缓存项记装入时的 generation；resolve 先读 generation（一次原子读）：
    generation == entry.generation  ⇒ 直接命中
    generation >  entry.generation  ⇒ **精确回查**（DDL 同时登记它改过哪些
                                       obj#/name，回查只失效那些；无登记 ⇒ 全清）
- **计划缓存**用另一套（REQ-SQL-009 的 `(obj#, mtime)` 元组比对）——
  两层各司其职：字典行缓存要快（服务解析），计划缓存要准（服务执行）
```

**前提记档**：**单进程引擎**（V1.0 一个实例一个 daemon；外部工具不写库内数据）。
跨进程失效不做——若将来出现第二个写者，本节协议必须重做（**不得**假设它已经支持）。

## 5 DDL 执行（写侧）

### 5.1 创建 / 克隆工作区（引导页的唯一写入路径）

```text
① 分配 file 0/1/2（与全局控制文件的登记，见 §2.12——不在本设计重复）
② file 0 块 0（文件头页：含 format_version 与 file_scn=创建位点）
③ 建 15 个自举段（7 表 + 8 索引）：段头页 + 空 B+Tree（树头写扩展区）
④ **写引导页主（块 1）+ 副本带（块 256/257：引导页副本 + 文件头副本）→ fsync file 0**
   ← 自举链成立（主副相距 4 MiB，§2.1）
⑤ DDL 事务：建 stat$/seq$（普通 DDL 路径，§5.2）+ 预置业务对象（MEM 五张等，更高层驱动）
⑥ 提交；`public.ws$` 登记（§2.11/§2.12）
CLONE OF：②③④ 的文件按 reflink 复制（§2.7）——**引导页与副本原样随文件而来**，
`seq$` 原样延续（"序号空间原样延续"，§2.12）
```

**崩溃于中途**：未在 `public.ws$` 登记的工作区按"**未完成创建**"清除
（判据 = `ws$` 行存在与否；清理 = 删除该工作区目录，含其全部文件）。
④ 之前崩溃与之后崩溃都归这一条——**登记是唯一的可见性分界**。

### 5.2 `CREATE TABLE`

```text
一个 DDL 事务（独立；活动事务中发 DDL ⇒ 拒绝，TXN REQ-TXN-016）：
① 名字检查：resolve(namespace=1, name) 命中 ⇒ "已存在"；保留名（`$` 结尾/预置名）⇒ 拒绝
   （**并发同名 CREATE 的正确性不靠这一步**——靠 ③ 处 `i_obj_name` 唯一索引的插入冲突：
    后到者在唯一索引上失败 ⇒ 报"已存在"；统一的行锁/唯一性路径，§1 纪律 3）
② 分配 obj#（seq$ 的 object_id 序列；用户对象 ≥ 100）与 dataobj#
③ 写 obj$ 一行（type#=2、namespace=1、dataobj#、status=1）
④ 写 tab$ 一行（七项表选项：**由 `WITH` 选项与表类型翻译而来**，§3）
⑤ 写 col$ 每列一行（type#/length/precision/scale/nullable）
⑥ 建表段（`Segment::create`，SegType::Heap，obj#/dataobj# 进段头自描述）
   + 写 seg$ 一行（段头位置）
⑦ **锁：统一的行锁，无新机制**（§1 纪律 3）——在 obj$ 该行上取**排他行锁**
   （"对象锁"= 锁哪一行的约定）；语句对涉及的对象取**共享行锁**（S）——
   S/X 冲突走与数据行**完全相同**的等待/超时/死锁路径；**长 DDL（建索引）
   在其持续期内阻塞对该表的并发写**（V1.0 取正确性优先，代价记档）
⑧ 提交前**预约提交序号** `seq = engine.reserve_commit_seq()`，
   把 ③④⑤⑥ 写的所有行的 `mtime = seq`；`commit()` 用预约的序号落定
```

> **`reserve_commit_seq` 是本设计对事务引擎的新要求**（小增量）：
> 提交序号在提交时分配，而 `mtime` 必须在提交**前**写进字典行。
> 预约 = 原子取号并保证本事务最终以此号提交（单写者语义下无冲突；
> 其余事务的提交序号顺延）。**记档**：若评审认为不值得，替代方案是
> `mtime = 0`（未知）并让计划缓存退化为"表选项变更即全失效"——**不推荐**
> （REQ-SQL-009 的比对失效要 mtime 可用）。

### 5.3 `CREATE INDEX`（含唯一索引）与表达式索引

```text
① 名字检查 + 分配 obj#/dataobj#（同 5.2 ①②）
② 写 ind$（bobj# = 基表 obj#、type#=0 BTree、cols、is_unique）与 icol$（键列序 + is_desc）
③ 建索引段（SegType::BTree）+ 写 seg$；树头写扩展区
④ **构建**：表对象行的**排他行锁**下（并发写该表被阻塞，见 §5.2 ⑦）——按基表语句快照扫描全表，
   逐行求键（表达式索引求表达式），**外部排序**（temp 段；REQ-RES 的 temp 配额），
   再**批量灌 B+Tree**（自底向上；不逐行随机插入）
⑤ mtime 推进与提交（同 5.2 ⑦⑧）
```

**唯一性检查**：④ 的排序阶段检出重复键 ⇒ **整个 DDL 事务回滚**并报
"唯一约束冲突（重复键）"（V1.0 无约束对象，唯一性即唯一索引，`arch/03` §3.1.2）。
**表达式索引**的键来自前端（`json_get(col,'a.b')`）；目录只存 `icol$` 的
"表达式序号"？——**否**：表达式索引的键列在 `col$` 里**没有列号**。
**定案**：`icol$.col# = 0` 表示"键是该索引的**表达式**"，表达式本身存
`ind$` 的**扩展列**（见下），求值由执行器侧的键求值器承担。

> **`icol$.col# = 0` 的表达式**：`arch/03` 的 `ind$` 列清单没有表达式列。
> 本设计**新增一列** `ind$.expr_src 字节串`（存**规范化后的表达式文本**，
> 由 Binder 侧生成、目录原样保存），`icol$.col# = 0` 时按 `pos#` 对应到
> 该文本里的第 `pos#` 个表达式。**这是对 `arch/03` 的一处追加**——
> 评审通过后同步 `arch/03` 的列定义表。**理由**：表达式键必须可重建
> （打开索引时要能重新求值），而字典表不能引用 AST（AST 是前端对象）。

### 5.4 `DROP TABLE` / `DROP INDEX`

```text
一个 DDL 事务 + 对象行的排他行锁（§5.2 ⑦ 同一机制）：
① 删 obj$ 行（**级联**：表 ⇒ 其全部索引的 obj$/ind$/icol$ 行一并删）
② 删 tab$/col$（或 ind$/icol$）行
③ 段回收：段的全部区归还 LMT（位图；经 redo 保护）——`seg$` 行删除
④ 表选项为 `cleanup = segment_drop` 的表（session 等）⇒ 同一路径；
   `cleanup = row_delete` ⇒ 行级清理由 TTL 维护走 DML
⑤ mtime/提交（同 5.2 ⑦⑧）——**没有 mtime 了**（行已删）；
   计划缓存的失效靠"对象不存在"这条比对（键里的 obj# 已解析不到）
```

**DROP 后的陈旧引用**：`obj#` **不回绕**（`arch/03` §3.1.3）——
陈旧计划引用已删对象时解析失败（"不存在"），不会指向新对象。

### 5.5 `Move`（数据文件搬迁）与索引失效

`Move` 后索引失效落在 **`obj$.status`（权威）与 `ind$.status`（副本）**，
同一事务一起改（`arch/03`）。**本设计的落点**：`status ≠ 1` 的索引
**不进入访问路径**（选路期排除）且**计划缓存键失配**（REQ-SQL-009 的
`(obj#, mtime, status)` 三元组）。重建由"重建索引"路径（= 5.3 的 ④ 换段）承担。

### 5.6 工作区 DDL（`CREATE/ALTER/DROP WORKSPACE`）

在 **`public` 工作区**上执行（管理元数据 `ws$` 在那里）；**仅 admin，
资格检查先于对象查找**（`spec/SQL.md` REQ-SQL-005 的三条语义）。
实现落点：本模块的 `public` 实例上跑 §5.1/`ws$` 的 DML——
**不跨工作区**（全程一个事务，REQ-ISO-005）。

## 6 接口契约（REQ-ENG-006 的落地）

```text
trait Catalog {                       // 每工作区一个实例；只读
  fn resolve(&self, snapshot, ns: Namespace, name: &str)
        -> Result<ObjectRef, CatalogError>;            // 找不到 ⇒ NotFound（不可区分）
  fn resolve_by_obj(&self, snapshot, obj#: u32) -> Result<ObjectRef, CatalogError>;
  fn columns(&self, snapshot, obj#) -> Result<Vec<ColumnDesc>, CatalogError>;
  fn indexes_of(&self, snapshot, table_obj#) -> Result<Vec<IndexRef>, CatalogError>;
  fn object_version(&self, snapshot, obj#) -> Result<ObjectVersion, CatalogError>; // = mtime
  fn fixed_table(&self, name: &str) -> Option<FixedTable>;   // file$/session$/lock$ —— 不查字典
}

ObjectRef { obj#, namespace, name, type#, dataobj#, status, ctime, mtime
            /* dataobj# = 0 ⇒ 无段（视图/过程——V1.0 不产生） */ }
ColumnDesc { col#, name, type#, length, precision, scale, nullable }
IndexRef   { obj#, bobj#, kind(BTree/ANN/邻接), is_unique, status, 键列组成 }
FixedTable = file$（内容 = 控制文件内存映像）
```

**语义要点**：

- **没有写方法**（REQ-ENG-006 的"只读"）——写只经 DDL 路径；
- `resolve` 的**不可区分**：跨区名字、已删除、从未存在 ⇒ 同一个 `NotFound`；
- `type_descriptor` 的实际形态 = `ColumnDesc` 交给 **TYP 内核**转成类型描述子
  （目录不解释类型语义——REQ-SQL-010 的"同一件事只有一个实现"）；
- **执行器的取用**：resolve 表 ⇒ `dataobj#` ⇒ `seg$.file_id/block_id` ⇒
  `Segment::open` ⇒ `data_blocks(hwm)` 得扫描边界（执行器不查字典，
  只拿"段头 + 列形状 + 表选项"三样）。

**验收要点**（照 REQ-ENG-006）：跨区名字、保留名、版本变更后缓存失效
三条各有用例；`object_version` 贯穿计划缓存判定。
