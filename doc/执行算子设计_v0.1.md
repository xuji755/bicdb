## 1 执行模型

### 1.1 统一契约（拉取）

```text
一行一行向上拉：父在 next() 里调子；子产出 0 或 1 行。
- 短路是免费的：LIMIT 拉到第 N 行就不再调子（无 ORDER BY 时）；
- 阻塞算子（Sort/HashAgg/HashJoin 构建侧）必须在 open/首次 next 里耗尽输入；
- 阻塞 ≠ 提前终止：Top-N 只限"排序内存"，输入照扫（见 §4.1）。
```

```rust
/// 执行算子统一接口（火山拉取）。
pub trait Operator {
    /// 打开：取资源（游标、缓冲、临时段租约）；可被 rescan 重入。
    fn open(&mut self, cx: &mut ExecContext<'_>) -> Result<(), ExecError>;
    /// 取下一行（`None` = 本算子树耗尽）。**每次调用先查取消/截止**。
    fn next(&mut self, cx: &mut ExecContext<'_>) -> Result<Option<Row>, ExecError>;
    /// **参数化重扫**（NL 内表的参数变了；不重建 open 的资源）。
    fn rescan(&mut self, cx: &mut ExecContext<'_>) -> Result<(), ExecError>;
    /// 释放（临时段/游标/记账）；幂等；取消路径也必须走到。
    fn close(&mut self, cx: &mut ExecContext<'_>);
}
```

**四条纪律**（对应 ENG 不变量的落点）：

| # | 纪律 | 来源 |
| --- | --- | --- |
| ① | **执行器不碰页**——一切行经存储服务（TableAccess/IndexAccess），可见性由服务负责 | ENG 不变量 1 |
| ② | **读路径不含锁**——读算子不调锁管理器；行锁只出现在 DML 算子的写路径 | ENG 不变量 3 |
| ③ | **预算随请求**——deadline/取消/内存预算经 `ExecContext` 贯穿每个 `next()`；取消后释放锁、页引用、临时段 | ENG 不变量 10 |
| ④ | **计划不可变、状态单次新造**——算子树从不可变计划**构建**（每次执行一棵新树）；算子内部状态不属于计划 | REQ-SQL-004 |

### 1.2 执行上下文（`ExecContext`）

| 携带 | 说明 |
| --- | --- |
| 事务句柄 + **语句快照** | 语句级 RC：语句开始取快照、结束释放（REQ-TXN-001）；读算子把它传给存储服务 |
| 参数值 | 类型化参数通道（绑定期已定型；不做文本拼接） |
| deadline / 取消标志 | 每个 `next()` 查；长循环（外部归并、批量回表批次间）追加检查点 |
| 临时空间记账 | 本执行的 temp 用量；超 work_mem ⇒ **溢出**（不是报错）；超 `quota_temp` ⇒ 资源类错误 |
| 统计槽 | 每算子行数/耗时/临时字节（诊断与 EXPLAIN 形态用） |

### 1.3 行与值

- **行 = 解码后的值序列**（`TYP` 内核的类型域）；表达式求值走 `TYP`
  的三值逻辑（NULL 参与的比较结果为 NULL；`WHERE` 只放行 TRUE）。
- 算子之间传**值**，不传页/游标（纪律①）；行来源是存储服务的行字节，
  由算子按结果形状解码。

### 1.4 阻塞性分类（读计划的人先看这个）

| 类 | 算子 | 后果 |
| --- | --- | --- |
| **流水** | SeqScan / IndexScan / FastFullScan / Filter / Project / Limit / NestedLoop / IndexNL | 边读边吐；LIMIT/短路谓词能真正打断上游 |
| **阻塞** | Sort / TopN（首次输出前） / HashJoin（构建侧） / HashAgg / SortedAgg（首次输出前） / Materialize（选用时） | **首行时间 = 输入读完时间**；交互式分页查询要警惕（材料 §7 的信号之一） |

## 2 算子清单（V1.0 闭集）

命名对照（我们的名字 ↔ PG ↔ Oracle）：

| 我们 | PG | Oracle | 说明 |
| --- | --- | --- | --- |
| `SeqScan` | Seq Scan | TABLE ACCESS FULL | HWM 起止；区读批量；CR 由存储服务 |
| `IndexScan` | Index Scan | INDEX RANGE/UNIQUE SCAN + TABLE ACCESS BY INDEX ROWID | **一个节点内含回表**（PG 形态），回表**批量**（Oracle 12c BATCHED 技巧，§9.4） |
| `IndexOnlyScan` | Index Only Scan | 覆盖列/索引全扫 | 只碰索引列（键 + ROWID），不回表 |
| `FastFullScan` | （无直系） | INDEX FAST FULL SCAN | 物理序区读、不保序；只喂聚合/COUNT（§9.1.6 已落地） |
| `Filter` | Filter | FILTER | 三值逻辑；**access/filter 谓词分层**见 §4.4 |
| `Project` | Projection | VIEW | 表达式求值；只在需要的节点做 |
| `Limit` | Limit | COUNT STOPKEY | LIMIT/OFFSET；**无 ORDER BY 时真短路** |
| `NestedLoop` | Nested Loop | NESTED LOOPS | INNER/LEFT；内表参数化重扫（索引探测是常态） |
| `HashJoin` | Hash Join | HASH JOIN | INNER/LEFT；构建侧=小表；溢出分批 |
| `Sort` | Sort | SORT ORDER BY | 内存快排 → 外部归并（temp 段） |
| `TopN` | Sort+Limit（top-N 堆） | SORT ORDER BY STOPKEY | 有界堆；**输入仍全扫**（§4.1） |
| `HashAgg` | HashAggregate | HASH GROUP BY | 无排序要求；溢出按分区重扫；**含 `DISTINCT` 变体**（每组去重集，§2.4） |
| `SortedAgg` | GroupAggregate | SORT GROUP BY | 输入按分组键有序；**流式输出首组**；`DISTINCT` 变体要求输入按（组键, 去重键）有序 |
| `ScalarAgg` | （Aggregate 无 GROUP BY） | SORT AGGREGATE | 单组；空输入也输出一行 |
| `Append` | Append | UNION-ALL / CONCATENATION | 合并追加（**流水**——逐子输入拉完换下一个） |
| `Unique` | Unique | （HASH UNIQUE 的有序形态） | **相邻去重**（输入按去重键有序）；`SELECT DISTINCT`、`UNION` 去重 |
| `SetOp` | HashSetOp（哈希）/ SetOp（有序） | INTERSECT / MINUS 族 | 哈希实现（**阻塞**）；`INTERSECT [ALL]` / `EXCEPT [ALL]` 按**重数**计数 |
| `Insert` / `Update` / `Delete` | ModifyTable | INSERT/UPDATE/DELETE | 逐行经事务引擎；行锁/等待在写路径 |

**按需启用**（不在 V1.0 闭集，触发即加）：`Materialize`、
`Memoize`、`IncrementalSort`、`SkipScan`（触发条件见 §7）。

### 2.1 访问族

**`SeqScan`**——读：自表 HWM 下界起、到 HWM 止（§4.3.1 的扫描边界）；
每批一个区（≤ 8 页）区读 + 逐块 CR 重建 + 逐行提取（§9.4）；
谓词里可下推的部分（列与常量比较）在**行提取前**先判（省解码）。
**空块照扫**（HWM 语义：删除不降水位）。

**`IndexScan`**——三段式：① 索引定位（`Tree::range`/`lookup`，闭区间；
唯一扫描 = 退化为单点）；② **攒批**（默认 256 条或一个区的行数取小）；
③ 按 `(file_id, block_id, slot)` 排序 → 按块分组 → **每块一次区读 + 一次
CR** → 逐行提取。**回表行的可见性由存储服务判**（CR 重建后 `heap::row` +
快照判定）；索引项指向"死行"（并发删除后）⇒ 跳过，不报错。

**`IndexOnlyScan`**——查询只碰索引列（如 `COUNT(*)`、只选索引表达式）：
只读叶条目，不回表。**注意**：我们的索引条目 = （键, ROWID），没有 include
列 ⇒ 仅当投影/谓词列**全部**由键覆盖时才可标记（优化器判定，binder 给列集）。

**`FastFullScan`**——已落地（§9.1.6）：物理块序区读、只取叶页、**不保序**；
只喂不接受顺序的消费方（COUNT/聚合）。

### 2.2 连接族

**`NestedLoop`**（INNER/LEFT）——外层一行 ⇒ 绑定参数 ⇒ **rescan 内表** ⇒
逐行比对 `joinQual`；LEFT 在外层无匹配时补 NULL 输出。内表是 `IndexScan`
时 rescan = 参数化索引探测（我们唯一实用的形态；无索引内表的 NL 由优化器
避免）。**SEMI/ANTI 不做**（SQL 面无 `EXISTS`/`IN (子查询)`；`IN (字面量列表)`
走表达式求值，不是连接）。

**`HashJoin`**（INNER/LEFT）——构建侧（小表）建哈希表（键 = 连接键，
值 = 行副本）；探测侧流式。溢出：**分批**（batch 0 留内存，其余写 temp 段；
处理到该批时重扫构建侧物化结果）——照 PG 形态；**不做** PG18 的并行
walk-back 内存公式（单线程无共享哈希表，见证据 `988820` 的适用性说明）。
LEFT 需要跟踪"探测行是否匹配过"。

### 2.3 排序族

**`Sort`**——内存快排；超 work_mem ⇒ 生成有序 run 写 temp 段，收割时
**k 路归并**（堆）。排序键比较走 `TYP` 内核；**NULL 位置**：升序在最后、
降序在最前（Oracle 默认，`spec/SQL.md` 已定）。

**`TopN`**——`ORDER BY … LIMIT n` 合并成一个算子：维护大小 n 的最大堆
（只保留前 n 行）。**输入必须全扫**（证据 `2065263`：STOPKEY 只把排序内存
限到 n，950K 匹配行照样读完）。`OFFSET m` ⇒ 堆大小 n+m，收割时丢前 m。

### 2.4 聚合族

**`HashAgg`**——GROUP BY 键建哈希表，值 = 各聚合的**转移状态**
（不保留原始行）；输出为哈希序（无序）。溢出：按哈希分区重扫（照 PG13
形态，证据 `557030`）。

**`SortedAgg`**——输入已按分组键有序（来自索引序或 Sort）时流式：
换组即输出上一组（首组延迟小）。

**`ScalarAgg`**——无 GROUP BY：单组流式折叠；**空输入也输出一行**
（`COUNT(*)=0`、`SUM=NULL` 等零元语义）。

**HAVING** = 聚合之上的 `Filter`（不单独设算子）；`COUNT/SUM/AVG/MIN/MAX`
的初值/转移/归并三段式由 `TYP` 内核给出。

**`DISTINCT` 聚合**（`COUNT(DISTINCT x)` 等，本期范围内）——**不新增算子**，
是聚合的**修饰**：

| 形态 | 取法 | 代价 |
| --- | --- | --- |
| `HashAgg` + `DISTINCT` | 每个**组**携带一个"去重值集"（该聚合参数表达式的已见值）；命中集合即跳过转移 | 内存 = Σ组去重值（随组内基数）；溢出随 HashAgg 分区一起走 |
| `SortedAgg` + `DISTINCT` | 要求输入按 **（组键, 去重键）** 有序 ⇒ 组内相邻去重（零额外内存） | 多一次排序（或复用索引序） |

**V1.0 取法**：哈希形态为主（与 `HashAgg` 一体）；有序形态作为**按需启用**
（触发：`DISTINCT` 聚合的组内基数大、哈希内存成为实测瓶颈——PG 历史上的
首选正是有序形态，材料 §5.9 的组状态模型与之相容）。**注意**：`COUNT(DISTINCT)`
与普通聚合**可混用**（同语句不同修饰），组状态按聚合逐项各自维护。

### 2.5 流水控制族

`Filter`（谓词）、`Project`（投影 + 表达式）、`Limit`（`LIMIT/OFFSET`；
`OFFSET` 只在本地计数丢弃）。

### 2.6 DML 族

`Insert`（源 = `VALUES` 字面量列表；逐行经事务引擎插入，**先 undo 后变更**）、
`Update`/`Delete`（源 = 扫描子树；逐行加行锁 → 改行 → 记撤销）。
写路径的等待-重试（`RowLocked` → 登记 → 挂起 → 重试）由事务引擎承担
（`execute_with_wait`）；算子在**挂起前释放持有的行缓冲**（上下文纪律）。
**无 RETURNING**（SQL 面清单外）。

### 2.7 去重与集合运算族（本期）

**`Unique`**（相邻去重）——输入已按去重键有序（前置 `Sort` 或索引序）；
流式：只保留"与上一行不同"的行。`SELECT DISTINCT` = `Sort` + `Unique`
（去重键 = 全部输出列）；`UNION`（去重）= `Append` + `Sort` + `Unique`。

**`Append`**（合并追加）——按序拉各子输入；**流水**（无阻塞）；
`UNION ALL` 的直译形态（也是 `UNION` 族的前置）。**本切片不做**
`MergeAppend`（有序归并追加——需要各子输入有序，触发条件见 §8）。

**`SetOp`**（`INTERSECT [ALL]` / `EXCEPT [ALL]`）——**哈希实现**（阻塞）：
构建侧（右侧）建计数表，探测侧（左侧）按标记产出；`ALL` 变体按**重数**
（bag 语义）计数、去重形态每键至多产一行。**有序形态**（两侧排序后归并，
省内存）作为按需启用（触发：大输入 + 两侧已有索引序——与 `MergeJoin`
同一触发面）。**方向性**：`EXCEPT` 左-右不对称（左有右无）、`INTERSECT`
对称——哈希构建侧按此选小的那一侧。

## 4 关键取法与依据

### 4.1 Top-N 的边界（易说错，写死）

| 说法 | 正确口径 |
| --- | --- |
| "LIMIT 让排序提前终止" | **错**。排序必须读完输入才能知道前 n 名；`SORT ORDER BY STOPKEY`/
top-N 堆只把**排序内存**限到 n（证据 `2065263`：950K 行照扫）。 |
| "LIMIT 让扫描提前终止" | **对，但只在没有 ORDER BY 时**：`Limit` 拉到 n 行即不再调子，
上游整条流水线停摆（材料 §1.1 的"短路是免费的"）。 |
| "聚合也能短路" | 纯 `COUNT(*)`/`EXISTS` 类可短路（Oracle `COUNT STOPKEY`）；我们的
`ScalarAgg` 首版按流式全扫处理，短路作为按需项。 |

### 4.2 溢出（内存预算的执行形态）

- 预算：每执行从会话 `work_mem`（`quota_temp` 的子账）取；
  **超预算 = 溢出**（写 temp 段），**超配额 = 资源类错误**。
- 落点：`Sort` → 有序 run + k 路归并；`HashAgg` → 哈希分区重扫；
  `HashJoin` → 构建侧分批。
- **temp 段是既有的**（§4.8 `TempPool` 已实现，no-redo 写路径随本设计接入）；
  临时页**不进 redo**、不参与恢复（崩溃即丢，语义上无损失）。

### 4.3 自适应 / 增量项：一律"按需启用"

| 项 | 机制（核验过） | 我们的触发条件 |
| --- | --- | --- |
| `Memoize` | PG14+：参数化内表结果缓存；超预算 **LRU 驱逐、不落盘**；四计数 Hits/Misses/Evictions/Overflows（证据 `988815`）。材料"命中率 <5% 自动禁用"**未核验、不抄** | NL 内表重复参数值多、实测命中率高（长任务记忆检索画像很可能命中——**先测**） |
| `IncrementalSort` | PG13+：前缀有序时组内排序、对 LIMIT 有利；LIMIT 接近全量时**甚至变差**（证据 `1235140/1235143`） | `ORDER BY` 前缀由索引序提供 + 小 LIMIT 的实测热点 |
| `SkipScan` | PG18 已有（证据 `2288804`）；既有决定：V1.0 不做（SQL 子集简单） | 复合索引前导列低基数 + 非前缀谓词成为实测热点 |
| `Materialize` | 通用重扫缓冲 | 非索引内表的 NL 重扫成本成为热点（当前优化器避免该形态） |
| `MergeJoin` | 两路有序输入的流式归并（Oracle `MERGE JOIN` + `SORT JOIN`；PG 18 起可吃增量排序，材料 §5.6/§8） | 两侧输入**已按连接键有序**（都来自索引序）且大表等值连接成为热点——V1.0 先以 `HashJoin` + `NestedLoop` 覆盖（连接面无排序要求时哈希更稳），不预先付归并的"双有序输入"代价 |

### 4.4 谓词分层（Oracle 之分，采信）

- **access predicate**：能在**索引定位**里用掉的（键范围）；
- **filter predicate**：只能在行取出后判的。
- 分工：Binder 给表达式加"可下推"标记；优化器把可下推项放进
  `IndexScan.bounds` / `SeqScan.pushdown`，其余留在 `Filter`。
- **判据**：下推不改变结果（三值逻辑下 NULL 不通过）。

### 4.5 空输入与 NULL（正确性要点）

| 项 | 语义 |
| --- | --- |
| 无 GROUP BY 的空输入 | 输出一行（`COUNT(*)=0`；`SUM/AVG/MIN/MAX` = NULL） |
| 有 GROUP BY 的空输入 | 零行 |
| `LEFT JOIN` 无匹配 | 右列全 NULL（`join` 条件在三值逻辑下不通过也算无匹配） |
| 排序 NULL 位置 | 升序最后、降序最前（Oracle 默认） |
| `HAVING` | 在聚合之上过滤；`HAVING` 里的聚合与投影里的聚合共享状态 |

## 5 与存储/事务接口的映射

| 算子 | 调用的服务口（ENG REQ-ENG-003 / 002） |
| --- | --- |
| `SeqScan` / `IndexScan` 回表 | 表访问 `scan` / `fetch`（含 CR 可见性、转发指针、片段链重装） |
| `IndexScan` 定位 | 索引访问 `seek` / `range`（B+Tree；候选**先回表检查可见性**） |
| `FastFullScan` | 索引访问的 FFS（§9.1.6 已落地） |
| `Insert/Update/Delete` | 表访问 `insert`/`update`/`delete`（挂事务句柄；可见性与锁在服务层） |
| 溢出写读 | 临时空间（配额 `quota_temp`；生命周期挂执行/语句） |
| 目录/名字 | **不直连**——Binder 已完成；执行期只认 `ObjRef`（对象号+版本） |

**执行期不允许的事**（验收检查项）：算子直接读文件/页；算子自行推测可见性；
算子持锁等待（等待只发生在写路径的引擎调用内）。

## 6 参考模型：直译执行器（差分验收工具）

`spec/SQL.md` REQ-SQL-005 的验收要求"对照**参考模型**——直译执行器
（逐行按语义求值、不做优化）"。**它与算子执行器同为交付物**：

| | 直译执行器 | 算子执行器 |
| --- | --- | --- |
| 输入 | 同一份 Bound Query（绑定后的语义树） | 物理计划（优化器产物） |
| 求值 | 逐行、按语义**直译**；不建哈希表、不下推 | 算子树（本设计） |
| 路径 | **只用最朴素的访问路径**（顺序扫描 + 逐行 CR） | 可用索引/哈希/排序 |
| 用途 | **差分基准**（同一查询两路执行，结果必须逐行一致） | 生产路径 |

两者共享 Binder 与 `TYP` 求值内核（**共享语义、不共享执行**——否则
"自己对自己"的差分没有意义）。

## 8 本期暂缓（非永久不做）+ 触发条件

**口径（2026-10-06 用户明确）**：下列各项是**后续切片/版本的目标**，
本期不实现、语法上不存在入口——**不是永久排除**。简单常用构造
（`DISTINCT`、集合运算）已并入本期（§2.7；`spec/SQL.md` 已同步）。

| 暂缓项 | 为什么暂缓 | 触发条件（何时重审/启动） |
| --- | --- | --- |
| **列存所需算子**（向量化/批量 SIMD 执行） | **本系统未引入列存**——Oracle 的深度向量化绑定 In-Memory 列存（证据 `519184`），行式 + 内部批量已覆盖主要 I/O 收益 | 列存层立项（分析型扫描成为主导负载） |
| 并行执行（PX/Gather） | 单查询并行在 SQL 面之外；算子契约会因此变复杂（分发/合并、闩锁面） | 单查询吞吐成为瓶颈且多核闲置 |
| 窗口函数 | 复杂算子，留后续切片 | SQL 面按需求变更控制扩面 |
| 子查询 / CTE / 递归 | 同上（涉及重写与计划面） | 同上 |
| 自适应计划（运行时切 NL↔Hash） | 计划不可变是本库纪律（REQ-SQL-004）；先靠统计与差分把计划选对 | 统计过期导致的错计划成为实测主要问题 |
| `Materialize` / `Memoize` / `IncrementalSort` / `SkipScan` / `MergeJoin` / `MergeAppend` / 有序 `SetOp` | 按需启用的**优化**项（§4.3 已列触发条件），不是正确性缺口 | 各自触发条件成立 |
| `RETURNING` / 触发器 / `ON CONFLICT` | SQL 面清单外 | 需求变更控制 |
