# 图多索引排名融合（2026-10-09）

`bicdb.searchNodes` 新增显式 `indexes` 选项，复用原生全文过程和语句预算，把多个索引的独立排名按顺序轮转、去重后返回。沿用参考 Rust daemon 的 ordinal rank fusion 思路，不比较不同索引的 BM25 数值。本阶段未连接或修改 Neo4j。

## SQL 用法

```sql
CREATE FULLTEXT GRAPH INDEX names ON kg NODES (name)
OPTIONS '{"update":"batch","interval_ms":5000,"batch_rows":256}';
CREATE FULLTEXT GRAPH INDEX summaries ON kg NODES (summary)
OPTIONS '{"update":"batch"}';
CYPHER kg 'CALL bicdb.searchNodes("buffer pool",{
  db_type:"mariadb", indexes:["names","summaries"],
  labels:["Entity","Knowledge"], consistency:"eventual", limit:20
}) YIELD node,rank,mode
RETURN node.name,rank,mode';
```

索引字符串需按字典实际名称给出，必须属于当前图且为节点全文索引。未知名称、跨图索引、关系索引、重复或空索引列表均拒绝。列表至多 16 个不重复的非空名称，每个名称至多 128 字节。

`db_type` 显式必填；`labels` 是 OR 标签过滤，可为空表示不额外限制。领域、索引定义标签和查询标签共同决定每路的合格候选，先过滤再执行每路 limit。新标签过滤也可用于 SQL `SEARCH FULLTEXT GRAPH INDEX ... OPTIONS` 和命名节点全文过程，关系检索不接受 labels。评分统计仍取已发布的域与字段语料，不因 labels 再计算一套统计。

`limit` 默认 20，范围 1–1000，是融合后的总上限。每路保留至多同样数量的候选；由于单路 ID 不重复，其更后面的命中已经有至少 limit 个不同的前驱，不能影响最终前 limit 个结果。各路轮流取同一名次，遇到已经返回的 ID 跳过，顺序由 indexes 列表决定。返回 rank 从 1 开始，后续 YIELD WHERE 不重新编号。

`fields` 可选，为所有指定索引均具备的字段名称；若任一索引缺少该字段则报错，不能静默遗漏。省略或为空使用各索引全部字段。要按字段轮转，分别建立单字段索引；多字段索引内部仍使用其原有 BM25 排名。索引匹配采用全文分词与 terms/phrase/exact 通道，区别于旧扫描的子串匹配。

## 一致性、预算及回退

默认 consistency=strict，各路建立当前可见源视图，mode=strict_round_robin。eventual 各路使用原生倒排并复核当前源修订，mode=fulltext_round_robin；未维护的新内容可能缺失，因此这个模式不代表完整覆盖。需要覆盖水位时使用命名全文过程返回 complete、source_seq 等列。

若同一语句已写入，所有后续索引查询都使用暂存图严格视图，mode=strict_staged_round_robin。失败不提交部分源修改；正常提交沿用原有源与队列事务。全路共享现有原生读预算和表达式/扩展预算，超限报错，不截断为成功结果。

只读 v2 路径只向执行器装载合格命中节点，之后可继续 MATCH；PROFILE 分别显示实际访问的每个索引、模式、posting 和源核验。strict 构建、冷语料载入仍有有界全源或全文语料开销，不能把装载节点缓存计数解释为总磁盘读取量。

没有指定 indexes 时，原有 fields 默认值、子串匹配、字段轮转以及 mode=bounded_scan 保持兼容；该分支不接受只用于索引的 consistency/channel 选项。指定索引后发生错误不会退回扫描。随后已加入 indexes:"auto"，按字段和完整标签覆盖自动选择，见[自动选择规则](bicdb_图全文自动索引选择_20261009.md)。
