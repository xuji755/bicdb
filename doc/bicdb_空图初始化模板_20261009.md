# 空图初始化模板（2026-10-09）

本阶段扩展现有 EMPTY SCHEMA 模板，使新工作区可以初始化命名图及其索引结构。模板仍不携带业务数据，也不是 D5 中带数据的 reflink 快照。

## SQL 使用

在 PUBLIC 的本机管理连接执行。源必须无主、ACTIVE、非 PUBLIC、没有运行中的实例，所有业务表零行、所有图无顶点和边。

```sql
ALTER DATABASE ADD TEMPLATE 'graph_init' FROM graph_seed;
CREATE WORKSPACE left_graph FROM TEMPLATE 'graph_init';
CREATE WORKSPACE right_graph FROM TEMPLATE 'graph_init';
ALTER DATABASE DROP TEMPLATE 'graph_init';
```

源结构可以包括以下定义：

```sql
CREATE GRAPH kg;
CREATE UNIQUE GRAPH INDEX node_key ON kg NODES LABEL "Entity" (db_type,name);
CREATE GRAPH INDEX link_weight ON kg RELATIONSHIPS TYPE "LINK" (weight);
CREATE FULLTEXT GRAPH INDEX words ON kg NODES LABEL ("Entity","Fault")
    (name,config."Alias"[0]."Question")
    OPTIONS '{"update":"batch","interval_ms":3000,"batch_rows":7}';
ALTER FULLTEXT GRAPH INDEX words ON kg PAUSE;
```

`CREATE WORKSPACE ... FROM TEMPLATE` 创建新数据库文件，执行定义并重新生成保护访问树。每个工作区使用自己的对象身份、段、分配器、源事件队列和全文语料。不能根据不同工作区内相同的数值对象号推断共享身份。

## 保留内容与新状态

| 对象 | 保留的定义 | 不复制的状态 |
| --- | --- | --- |
| 图 | 命名图，含大小写和引号规则 | 顶点/边、历史实体 ID、分配器水位、原始物理记录 |
| 属性索引 | 节点/关系、标签/类型、标量/组合/JSON 对象路径、唯一性、无字段标签树 | 物理树、陈旧索引项、旧对象号 |
| 全文索引 | 节点/关系、OR 标签/类型、选定 JSON 键及固定数组路径、维护策略、显式间隔/批次、暂停状态 | 文档、倒排、统计页、源事件、旧覆盖水位 |

JSON 路径的 SQL 标识符遵循大小写折叠；要匹配 Alias、Question 等大小写敏感键，使用双引号。

没有显式写入策略的间隔和批次数保持“继承”，在克隆工作区中使用目标实例参数。不会把源实例的运行配置固化到模板。新全文索引为 managed、原生数据格式 v2，文档与源计数为零；旧的未托管索引定义也会按新版本创建。源删除后的陈旧派生文档与待处理删除事件不属于模板业务内容，不复制。

源导出使用完整图验证并拒绝非空图、失效属性索引及不支持的索引种类。索引描述及受保护访问树元数据必须有效。它不遍历旧全文文档正文来拷贝语料，因此模板操作不能作为全文语料完整性检查。

## 文件与加载校验

仍采用 `BICDB_SCHEMA_TEMPLATE_V1` 的 manifest 和 schema.sql，不要求现有表模板迁移。文件最多 1 MiB，结构语句 1..512 条；源检查和校验完成后，经私有暂存目录、fsync、原子改名发布。模板不可覆盖，删除不影响已经创建的工作区。

SHA-256 只验证文件一致性。加载还必须通过结构白名单：CREATE TABLE、普通表 CREATE INDEX、CREATE GRAPH、图属性/全文索引创建，以及仅针对本模板刚创建的该图全文索引的 PAUSE。目标表或图须在本模板中先定义；对象和索引名字不能冲突。Cypher、DML、DROP、通用 ALTER、SYNC、在线 OPTIONS 和外部目标均拒绝。加载检查发生在目标文件创建前。

此白名单不是完整的预绑定器。语法合法但语义无效的列类型、索引路径或选项仍可能在执行 DDL 时失败；沿用现有规则，不登记工作区并保留未登记文件供诊断，不宣称整个结构应用是单一事务。

## 实现和验证

- `Session::empty_graph_initialization_sql` 导出图定义，生成带引号的 SQL；CLI 组合普通表与图结构，并在导出和加载时调用同一白名单。
- 原生 DCL 测试覆盖两份独立克隆、节点/关系属性及全文定义、数组 JSON 路径、唯一约束、暂停/恢复/WAIT、陈旧语料不复制、非空/占用源拒绝、仅含图的模板，以及重新计算 SHA 后的非法结构在创建文件前拒绝。
- 真实服务测试使用两个新测试用户，验证目标参数继承、认证工作区隔离、全文索引功能、重启及删除模板不影响克隆。
- 同时回归原有表模板、Store 首次绑定、图 SQL/索引/全文/GRAPH_TABLE 和附件接口。证据见 [本阶段验证](evidence/bicdb-graph-template-20261009/README.md)。

既有部署的 bicbotv2_templete 不添加图、不覆盖内容；业务用户和生产数据不重建。该阶段没有连接或修改 Neo4j，测试写入仅使用隔离 bicdb 实例。

带数据图快照、W7、tpl$、reflink 与完整管理审计仍属后续 D5 工作；受管引用、专用邻接段、旧段回收和大型知识图谱性能验收等仍未完成。
