# 页工作区标识（`workspace_ref`）设计

版本：0.1　日期：2026年10月3日　状态：设计稿，待评审

配套：`doc/存储架构设计_v1.0.md` §5.2、总体方案 §3/§7、需求文档 REQ-ISO-001/006/007

---

## 1 问题

每个数据页的页头含一个字段 `workspace_ref`（总体方案 §7 称"WorkspaceId 或其受校验映射"）。它要回答一个问题：

> **这一页属于哪个工作区？**

要求：
- 不能只把工作区 ID 原样抄一遍（那样既不防伪造、又泄露 ID）
- 校验必须**极廉价**——它在每一页、每一次页访问上
- 必须**能承受备份、恢复、离线诊断**
- 必须能检出**跨工作区误读**

---

## 2 威胁模型（先划清边界，避免过度设计）

### 2.1 结构性的防线在别处

**本产品的隔离主要是靠三层非密码学手段实现的**：

| 层 | 手段 | 依据 |
| --- | --- | --- |
| 进程 | 每工作区独立 OS 身份或等效文件访问沙箱，只获得本工作区目录权限 | 总体方案 §2、§3 |
| 路径 | 受约束的目录句柄 + 服务端对象 ID；检查路径穿越、符号链接与 TOUCH 竞态 | 总体方案 §4、REQ-ISO-007 |
| 元数据 | 对象 ID 为密码学随机数，不可猜测 | CONV §1.1 |

在这个结构下，**工作区 A 的进程在正常情况下根本打不开工作区 B 的文件**——操作系统就会拒绝。

### 2.2 因此 `workspace_ref` 防的是这三类

| # | 场景 | 是否现实 |
| --- | --- | --- |
| 1 | **隔离实现的 bug**——路径检查被绕过、文件句柄绑定错误、缓存键复用错误，导致 A 的进程读到了 B 的页 | **最现实**，是主要目标 |
| 2 | **运维/工具误操作**——备份恢复错目录、文件被手工搬错、导入导出的工作区身份错配 | 现实 |
| 3 | **蓄意注入**——攻击者把 A 的页写进 B 的文件，使 B 读到 A 的数据 | 需要同时对两个工作区有文件写权限；在 OS 隔离下难以达成 |

### 2.3 明确不防的

- **进程被完全攻破**——攻击者取得工作区进程的代码执行权限后，该工作区的数据对他就是公开的。`workspace_ref` 无法改变这一点。
- **宿主机 root、备份介质持有者、控制面被攻破**——总体方案 §3 已把这列为**基础设施信任边界**，明确"不能用数据库权限宣称消除此类能力"。

> **诚实定位**：`workspace_ref` 是**纵深防御与一致性检查**，不是密码学边界。它把"静默的跨区数据串读"降级为"可检出的错误"。**不应据此宣称隔离由它保证。**

## 3 设计

### 3.1 定义

```text
workspace_ref = H(workspace_id) 截断至 8 字节
```

- `H`：密码学哈希（SHA-256 或 BLAKE3，P0 冻结具体算法）
- `workspace_id`：服务端生成的 128 位不透明随机 ID（CONV §1.2）
- 截断至 **8 字节**（64 位）

### 3.2 关键性质：哈希只在打开工作区时算一次

**校验不是每页做一次哈希，而是一次 8 字节整数比较。**

| 时机 | 动作 | 成本 |
| --- | --- | --- |
| 工作区打开 | 计算 `H(workspace_id)` 并**缓存在内存** | 一次 |
| 每页读/写 | 比较页头的 8 字节与缓存值 | **一次整数比较，可忽略** |

这是本设计最重要的工程性质：**热路径零额外开销**。

### 3.3 为什么不加密钥

一个自然的提案是改成密钥 MAC：`workspace_ref = MAC(K, workspace_id)`，以防伪造。**分析后不建议**：

| 问题 | 说明 |
| --- | --- |
| 密钥放哪 | 工作区进程需要密钥来校验。若密钥在工作区自己的文件里，能写该工作区文件的攻击者也能拿到它——**不增加任何防线** |
| 若密钥放实例级 | 需分发到每个工作区进程；一旦某进程被攻破即全实例失效；且**恢复到另一实例时密钥变化**，备份恢复会失败 |
| 与威胁模型不匹配 | §2.2 的三类场景里，只有第 3 类需要防伪造，而它已被 OS 隔离挡在门外 |

**结论**：不加密钥。用**无密钥哈希**，并与页头其他字段（`file_id`、`block_id`）配合，覆盖"误操作"与"实现 bug"这两类现实威胁。

> 若将来确有防伪造的强需求，应作为**独立的加固项**重新评估，而不是默认加进来——因为密钥管理本身会带来恢复与运维的新失败面。

### 3.4 为什么是 8 字节而不是 4

| 宽度 | 碰撞概率（N 个工作区） | 评价 |
| --- | --- | --- |
| 4 字节 | N=1 万时约 1.2%；N=100 万时必然碰撞 | **不足**——产品目标含大量工作区 |
| **8 字节** | 任何现实规模下均可忽略 | 采用 |

代价：页头从 48 增至 64 字节（见 §5），占 16KB 页的 0.39%。**可忽略。**

### 3.5 为什么不绑定 `file_id`

`file_id` 已在页头**独立存在**（§5 页头布局），打开文件时即校验。同工作区内"页被搬到另一个文件"的情形由 `file_id` 字段检出，无需 `workspace_ref` 重复承担。

**`workspace_ref` 只绑定工作区**，职责单一。

## 4 边界情形

| 情形 | 行为 |
| --- | --- |
| **备份** | 页内的 `workspace_ref` 随页一起复制，值不变 ✓ |
| **恢复到原工作区**（总体方案 §21：恢复保留相同身份） | `workspace_id` 不变 → `ref` 不变 ✓ |
| **恢复清单校验** | 除 `WorkspaceId` 与格式版本外，首屏即比对 `workspace_ref`，双重确认（REQ-ISO-009） |
| **离线诊断工具**读页 | 需由调用方提供期望的 `workspace_id` 才能校验；未提供时**只报告不判定**，且在输出中标注"未校验" |
| **页从未初始化**（`ref` 全零） | 判定为未初始化页；`flags` 位 0（初始化完成）为 0 时一律拒绝使用 |
| **`ref` 不匹配** | **按隔离事件处理**：拒绝该操作、写审计（REQ-OPS-003）、不得在错误信息中泄露对方工作区名称、内容或规模（REQ-ISO-006） |
| **临时文件（file 2）** | 同样带 `workspace_ref`——虽然是临时的，但跨区读临时文件同样是泄漏 |

## 5 对页头布局的影响

`workspace_ref` 由 4 字节增至 8 字节，页头由 48 增至 **64 字节**（同时增加 `seg_id` 并留出扩展余量）。

**新页头（64 字节）**：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 8 | `checksum` |
| 8 | 2 | `format_version` |
| 10 | 1 | `page_type` |
| 11 | 1 | `flags` |
| 12 | **8** | **`workspace_ref`** |
| 20 | 2 | `file_id` |
| 22 | 4 | `block_id` |
| 26 | 4 | `generation` |
| 30 | 8 | `page_lsn` |
| 38 | 2 | `slot_count` |
| 40 | 2 | `tuple_count` |
| 42 | 2 | `free_start` |
| 44 | 2 | `free_end` |
| 46 | 2 | `frag_used` |
| 48 | 4 | `seg_id` |
| 52 | 1 | `seg_type` |
| 53 | 3 | `reserved` |
| 56 | 8 | `reserved`（未来扩展） |

**取 64 字节的理由**：① 8 字节对齐；② 留出扩展余量，将来加字段不必升格式版本；③ 相对 16KB 页开销仅 0.39%，而格式版本变更的代价极高。

## 6 验收要点

- **构造**：将工作区 A 的某个数据页整页复制到工作区 B 文件的相同偏移。
- **预期**：B 读取该页时**检出 `workspace_ref` 不匹配并拒绝**，错误信息不泄露 A 的身份或内容。
- **构造 2**：正常读取本工作区页。
- **预期**：校验通过，且**热路径无额外哈希计算**（可用性能对比验证：开关校验的每页访问耗时无显著差异）。
- **构造 3**：备份 → 恢复到原工作区。
- **预期**：全部页校验通过。
- **构造 4**：把工作区 A 的备份恢复到工作区 B。
- **预期**：在**恢复清单校验阶段**即被拒绝（不进入逐页阶段）。
- **构造 5**：全零 `workspace_ref` 的页。
- **预期**：判定未初始化，拒绝使用。
- **审计**：每次 `workspace_ref` 不匹配都产生审计记录。

## 8 设计结论摘要

| 问题 | 结论 |
| --- | --- |
| 是什么 | 8 字节，`H(workspace_id)` 截断 |
| 防什么 | 隔离实现 bug、运维误操作（**纵深防御，非密码学边界**） |
| 不防什么 | 进程被攻破、宿主机 root、备份介质持有者 |
| 热路径成本 | **零**——哈希只在打开工作区时算一次，每页只是一次 8 字节比较 |
| 为什么不用密钥 | 密钥无处安放：放工作区文件里不增加防线，放实例级则破坏备份恢复 |
| 为什么 8 字节 | 4 字节在目标规模下会碰撞 |
