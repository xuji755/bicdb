# 图全文固定目标 WAIT（2026-10-09）

```sql
ALTER FULLTEXT GRAPH INDEX words ON kg WAIT;
ALTER FULLTEXT GRAPH INDEX words ON kg WAIT OPTIONS '{"timeout_ms":0}';
ALTER FULLTEXT GRAPH INDEX words ON kg WAIT
OPTIONS '{"target_source_seq":123,"timeout_ms":30000}';
```

WAIT 主动执行有界批量维护，等待指定索引达到一个固定图源序号。未指定 target_source_seq 时在调用开始的可见队列中确定；不会随之后新增写入扩大目标。显式目标只能是已经存在的非负整数，不等待未来序号。序号是图源变更计数，不能与提交序号混用。

timeout_ms 默认 30000，范围 0–60000；0 只检查状态，不发布维护批次。暂停索引不自动恢复。结果为一个 SQL 行集；TIMEOUT 和 PAUSED 是明确的未达标状态，不能把语句执行成功解释为目标达标。

| 列 | 含义 |
| --- | --- |
| index_name / status | 当前图索引，READY / TIMEOUT / PAUSED |
| target_source_seq | 本次固定目标 |
| covered_source_seq / source_seq | 已证明覆盖的源序号、当前可见源序号 |
| generation | 已发布文档 generation |
| target_reached | 固定目标是否已经覆盖 |
| source_complete | 是否覆盖当前全部源；达到较旧目标不代表这一列为 true |
| paused | 当前暂停状态；旧目标已达标时可以同时 READY、paused=true |
| batches / changed | 本次成功发布的批次数、相关实体应用数量（包括删除） |
| elapsed_ms | 本次耗时；包含装载和维护开销 |

## 固定集合与合并标记

队列按实体 ID 合并最新变更，不能仅凭 cursor >= target 证明旧目标覆盖。FixedTarget 在调用开始固定尚未处理的实体集合；按照稳定 ID 顺序处理当前标记的最新修订。后来新增实体不会扩大集合；已完成实体再次改写也不会被反复追赶。集合中的实体被重新改写时采用其当前标记，以免合并隐藏目标之前的未处理变化。

显式较旧目标不能从合并后的标记恢复历史快照，因此会保守处理开始时现有的未应用标记；最终只发布指定目标覆盖，较新的标记仍可由后续维护消费。它不是历史版本全文查询。

每个批次沿用原生文档、倒排和队列的原子发布。部分 WAIT 批次保留原有消费水位和队列标记；直到固定集合处理完才把覆盖推进到本次目标，之后新增标记仍保留。其他慢消费者决定共享队列清理，不能因一个 WAIT 完成而删掉其积压。

超时或后续批次失败不会撤销已经提交的批次，但也不提前宣称覆盖。重试/重启可从已发布 generation 的精确源修订及删除结果证明部分工作已应用，跳过重复分析；未处理和后来改写的修订仍需维护。不写入新的持久格式或永久 WAIT 任务；最后的目标确认与 generation 水位在同一事务中发布。

## 时间和权限边界

超时在批次边界检查，不会中断正在分析或提交的批次。重批次可能使 elapsed_ms 超过 timeout_ms；最后一批完成后返回 READY 表示目标已经达成，不因时间过去而撤销它。批次大小沿用索引 batch_rows 或实例设置。单批仍有全文语料/统计和共享队列恢复开销；这是逻辑预算，不是 RSS 限额。

当前原生服务仍为单写者，WAIT 驱动维护时占用当前连接；不是独立并发索引线程。核心状态机测试通过插入新写入和重复改写验证固定集合，不代表数据库已经支持同时运行多个写者。

活动用户事务禁止 WAIT，避免把尚未提交的源变化标成持久覆盖。具名 PUBLIC 用户保持只读，不能通过 WAIT 触发维护。旧的非 managed 全文索引没有图源计数，必须明确报错，不能把旧提交水位冒充 target_source_seq。索引仍需属于当前图。

## 验证和后续

覆盖默认/显式目标、零超时、暂停、已达到旧目标、多个批次、慢消费者保留、后续失败不假覆盖、重启和精确修订重试、源回滚、非法选项、当前图所有权、PUBLIC 只读与控制台输出；纯 Rust 状态机额外验证持续新增/合并标记、应用期间版本变化拒绝、固定旧目标和持久队列重载。
