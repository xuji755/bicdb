# 图全文共享变更队列与批量维护（2026-10-09）

> 后续进展：服务定时 batch、间隔/批次参数与在线策略调整已实现，见
> [定时维护与参数](bicdb_图全文定时批量维护与参数_20261009.md)。下文保留此阶段的历史边界。


## 当前实现

图全文已经接入原生共享变更队列。创建新版全文索引时，完整初建、索引对象、文档存储与
队列消费者在同一个 DDL 事务中提交。图源写入在原有原生事务中保存变化对象的 ID、类别、
最新修订或删除标记、序号与首次待处理时间；不在源写入路径分词，也不保存源正文到队列。
同一元素的反复变化合并成一条记录，同图多个索引共享该记录。

`SYNC` 固定开始时的 source_seq 为目标，每批最多 256 个合并事件。完整访问树的 v2 图
按元素记录读取这些对象，不扫描全部源图；旧源格式保留受预算约束的全图校验回退。
变化文档的分词、分片更新、倒排追加与队列确认通过同一 heap/undo/WAL 事务提交。
一批失败不提交该批文档或确认；此前成功批次保留，下一次 SYNC 从已持久化 cursor 继续。

关系维护/查询在同一快照中仅校验一次共享端点，避免反复读取带大型属性的同一节点。
维护仍需装载有界全文 generation，扫描/排序有界待处理队列并恢复内存全文统计；尚未做
大型图谱耗时/RSS 验收。此阶段不是定时任务：当前只接受显式 `update=manual`，自动调度、
间隔参数继承、固定目标 WAIT 和服务等帧期间的调度仍待实现。
没有连接 Neo4j，没有修改其数据、索引、配置或服务。

## SQL

```sql
CREATE FULLTEXT GRAPH INDEX answers ON kg
  NODES LABEL "Entity" (name,config.question,config.answers[0])
  OPTIONS '{"update":"manual"}';
SET LINESIZE 240
SHOW FULLTEXT GRAPH INDEXES ON kg;
ALTER FULLTEXT GRAPH INDEX answers ON kg PAUSE;
ALTER FULLTEXT GRAPH INDEX answers ON kg RESUME;
ALTER FULLTEXT GRAPH INDEX answers ON kg SYNC;
ALTER FULLTEXT GRAPH INDEX answers ON kg REBUILD;
DROP FULLTEXT GRAPH INDEX answers ON kg;
```

SET 为 bicdbcli 控制台命令；其他为 SQL。索引创建/同步/重建/暂停/恢复/删除不允许在活动
用户事务中执行。具名用户对 PUBLIC 只读，不能维护其中的全文索引。暂停状态跨重启保留，
源写入继续累计变化；暂停时 SYNC 拒绝，REBUILD 仍可完整刷新并保留暂停状态。

## 进度及一致性

SHOW 保留原有前十列，并追加以下列：

| 列 | 语义 |
| --- | --- |
| covered_source_seq | 新版索引已证明完整覆盖的图源序号 |
| source_seq | 本图共享队列当前序号，按变化对象递增，不是数据库提交序号 |
| cursor | 已应用的部分批次位置；不能冒充完整覆盖水位 |
| shared_pending | 本图共用合并事件数；不是本索引剩余事件数 |

未追平状态为 DIRTY；暂停为 PAUSED；完整覆盖且未暂停为 READY_GENERATION。
慢消费者的 covered_source_seq 决定清理边界，快消费者追平后仍可能看到 shared_pending>0。
新消费者必须跟随当前完整源初建，在当前 source_seq 注册；不能用已经清理的旧历史补建。
删除消费者与其索引一起提交，并释放不再被其他消费者需要的事件。

全文查询追加 covered_source_seq 与 source_seq。新版 eventual 的 covered_commit_seq 为
NULL，只有已发布文档水位等于当前图源水位时 complete=true；源修订复核仍逐命中执行。
部分批次可返回已更新且仍有效的命中，但 complete=false。strict 继续从完整语句可见源构造
严格视图，含用户事务未提交变化；covered_commit_seq 表示该语句快照，covered_source_seq
表示当前队列源视图。显式 LIMIT 仍可能减少结果，complete 表示源覆盖保证而非返回全部行。

旧版未登记队列的全文索引保持原有提交序号语义与扫描源的增量 SYNC，source 列为 NULL；
它们不能 PAUSE/RESUME，也不会代替新版消费者确认队列。新旧索引可在同图并存。
旧 descriptor 不被读查询暗中迁移；本阶段没有提供将旧全文索引转换成新消费者的原地命令。

## 存储与事务

- 新索引 descriptor 使用 `bicdb-graph-fulltext-managed-v1` 包装完整 Definition，区分源计数
  与旧 descriptor 的提交水位。文档 generation 仍使用现有分片格式。
- 队列为保护对象 type#258，`gftq_<graph_obj>$`，两列 ordinal NUMBER/data BYTES(4096)；
  唯一 ordinal 树为 `i_gftq_<graph_obj>$`。普通 SELECT/DML/表删除/普通索引管理均拒绝访问。
- 头记录 SHA-256 在 ordinal=0，JSON 在连续 1..16 分片；兼容旧状态机的单分片头。
  事件基键 `(3<<60)|(element_id<<10)`，保存 checksum/data 两行。未知/断裂分片、坏摘要、
  外来 ID、重复水位等会明确报错。
- 源写入及全文缓存版本检查显式走原生 ordinal 树，读取头及受影响 ID 的旧事件，不依赖优化器可能因旧行数
  估计选择的队列 heap 全扫，也不克隆/重写全部积压。没有消费者时不保存标记或增加序号。
- 队列默认逻辑字节预算 100 MiB、事件计数上限 600000，另有保守编码估算；字节预算会
  更早限流，超限使源语句失败/回滚，不丢事件。这不是 RSS 限制。
- 创建/重建/删除索引的少数 DDL 使用完整有界队列镜像，更换队列 heap/ordinal 段并保留
  对象号，与全文 DDL 一起提交。源写入和普通 SYNC 则增量修改原段。
- REBUILD 完整重分词、换全文三段、确认此消费者当前源水位，与队列更新一起提交。
  DROP GRAPH 级联删除队列及 ordinal 对象。退役物理段空间回收仍未实现。
- 倒排继续采用追加旧项与读时复核；REBUILD 清理陈旧项。维护失败不会绕过候选预算。
