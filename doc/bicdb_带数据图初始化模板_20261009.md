# 带数据图初始化模板（2026-10-09）

增加显式 `WITH GRAPH DATA`，将无主种子工作区的已提交图实体保存为不可变模板，新工作区重建自己的原生记录、访问树、属性索引和全文语料。原有空结构模式仍拒绝非空图。这是逻辑图快照，不作为通用表数据、reflink、W7 或完整 D5 的完成证据。

## SQL 与源边界

在 PUBLIC 本机管理连接中执行，源必须无主、ACTIVE、非 PUBLIC 且没有运行中的实例。导出期间持有源实例的独占锁。普通业务表仍要求零行；不能把用户所属工作区做成共享种子。

```sql
ALTER DATABASE ADD TEMPLATE 'graph_data' FROM graph_seed WITH GRAPH DATA;
CREATE WORKSPACE left_graph FROM TEMPLATE 'graph_data';
CREATE WORKSPACE right_graph FROM TEMPLATE 'graph_data';
ALTER DATABASE DROP TEMPLATE 'graph_data';
```

模板名不可覆盖。导出后修改源图或删除模板，都不影响已经保存的快照或已创建的工作区。认证用户仍受已有工作区边界约束，不能执行管理面的 ADD/DROP TEMPLATE。

## 保留和重建

| 内容 | 克隆行为 |
| --- | --- |
| 节点/关系、物理关系身份 | 保留数值 ID，多标签、平行关系、自环、正反方向、端点和 JSON 属性原样复制 |
| 精确数字、字符串、列表/对象 | 沿用 arbitrary_precision JSON 和图属性验证，不通过浮点转换，不把字符串作为 SQL/Cypher 执行 |
| 分配器 | 保留原生 seq$ 的持久化高水位，包括批量预留未用完和失败写入占用的编号范围；在目标新的原生 seq$ 中检查并预留，后续创建不会复用源已预留的 ID |
| elementId | 采用目标 workspace_ref、目标图对象号和元素类别；不同源/目标、不同克隆的 elementId 不混淆 |
| 原生存储和访问树 | 创建目标自己的堆、唯一记录键、节点/正反 B-tree；实体及访问项在同一原生事务发布 |
| 属性/唯一索引 | 根据目标实体重新构建，使用目标字典和段，继续校验唯一约束 |
| 全文 | 根据目标实体构建新的 v2 generation、文档、倒排和统计；不复制源的陈旧文档、待处理事件、覆盖水位或物理段 |
| 维护策略 | 保留 manual/batch、显式间隔/批次和暂停状态；继承项使用目标实例参数。先完整建索引，再应用 PAUSE，暂停索引也有初始完整语料 |
| 普通业务表 | 复制现有模板支持的空表结构和索引，仍拒绝非空表及不支持的特殊类型/选项 |

普通 JSON 中人为写入的源 elementId 字符串仍是字符串，不自动重写；类型化受管引用另属 GRP-012 的未完成工作。目标图的后续源变更通过自己的全文队列维护。模板中的 bot 表必须保持空白；Host 验证表/索引并用目标认证身份建立初始化记录，图知识不会带入源用户身份或会话信息。

## 文件格式与校验

旧空结构格式 `BICDB_SCHEMA_TEMPLATE_V1` 不变。新模式使用 `BICDB_GRAPH_TEMPLATE_V2`：

- `schema.sql` 仍最多 1 MiB、1..512 条结构白名单语句，拒绝 DML、Cypher、DROP 和外部索引目标。
- JSON `manifest` 最多 1 MiB，包含格式、模板名、schema 摘要和每个图的确切名称、字节数与 SHA-256。
- 数据文件使用固定 `graph-0.json` 等编号，不从不可信元数据读取任意路径。所有图文件的共享有效载荷上限为 100 MiB，单图沿用节点/关系、属性深度/节点数、属性大小和 ID 预算。
- 每个已定义图恰好有一个数据文件，包含空图。加载验证确切名字集合、唯一性、文件大小、摘要、格式、ID、分配器、端点和属性结构；即使重新计算 SHA，非法图仍拒绝。还预验证原生实体分块编码和访问项规划预算，不能用合法逻辑 JSON 绕过原生存储限制。
- 读取使用原有不跟随符号链接的文件 I/O。模板经私有暂存目录、文件及目录 fsync、原子改名发布；工作区标记采用新格式和整个 manifest 的摘要。

所有数据文件与结构校验完成后才创建目标文件。应用时依据解析器的字节位置拆分结构语句，先建表/图，再导入实体，最后建派生索引和暂停策略；不会按分号粗拆含引号标识符。受信任的 `restore_graph_snapshot` API 拒绝活动事务、非管理身份、非空/非新目标、已有用户索引或非新分配器，不向普通 SQL 开放任意内部写入。

快照恢复的原生实体/访问项发布具有语句原子性，但整个工作区的多次 DDL/导入不宣称为单一事务。语义无效的索引或后续 I/O 失败仍可能留下未登记的诊断目录；失败时也会干净关闭实例。ID 耐久预留遵循既有允许跳号规则，不因失败复用。目标只有成功应用模板和完整关闭后才登记。

100 MiB 是有效载荷和现有图操作预算，不是进程 RSS 上限。导出、验证和恢复目前有完整图装载/编码及索引构建，尚未实现流式大图快照。

## 验证

证据：[bicdb-graph-data-template-20261009](evidence/bicdb-graph-data-template-20261009/README.md)。核心装配覆盖两个克隆、含分号和中文的图名、JSON 精确数、实体和边身份、索引、暂停全文的新语料、ID 高水位、拒绝损坏/非新恢复和重新计算摘要的非法文件。真实认证服务覆盖源占用/无主边界、源修改后快照不变、双用户隔离、目标配置继承、bot 首次身份绑定、实际进程异常恢复、删模板及重启后独立存在；另有超过 8 MiB 的图快照、属性/全文重建和重启验证。

实现与测试均在 bicdb 中进行，没有连接或修改 Neo4j，也没有重建现有生产模板或业务工作区。通用 D5 的业务行快照、reflink、tpl$、W7 与管理审计，以及受管引用、专用邻接段、并发端点锁、旧段回收和大型知识图谱性能验收仍在后续范围内。
