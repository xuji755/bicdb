## 1 层次总览

```text
工作区
└── 表空间
    └── 数据文件（file 0 元数据 / 1 undo / 2 temp / 3+ 数据）
        └── 段（表、索引、Undo 各占一个段）
            └── 区（8 页 = 128KB）
                └── 页（16KB）
                    ├── 页头 48B
                    ├── 槽位目录（向高地址增长）
                    ├── 空闲区
                    └── 行数据（向低地址增长）
```

**所有层级共用同一页格式与行格式**——包括元数据页、Undo 页、索引页。差异体现在 `page_type` 与行的解释方式，而非另起一套格式。这是"一个引擎 + 表选项"在物理层的体现。

## 2 页

### 2.1 页类型（`page_type`）

| 值 | 类型 | 用途 |
| --- | --- | --- |
| 1 | 数据页 | 堆表行 |
| 2 | 索引页 | B+Tree 分支与叶 |
| 3 | 邻接页 | 按 `src` 聚簇的边（见 `存储容量与规模基线_v0.1.md` §4） |
| 4 | 元数据页 | file 0 内的段目录、对象目录等 |
| 5 | 引导页 | file 0 块 0，格式永久固定 |
| 6 | Undo 页 | file 1 |
| 7 | 临时页 | file 2，不持久化 |
| 8 | 位图页 | 区分配位图 |
| 9 | 段头页 | 段的第一个页 |
| 10 | ANN 索引页 | HNSW / IVFFlat 的页 |

> 页类型决定**如何解释页体**。加载一页后先看 `page_type`，再按对应结构解析。格式版本变更时，`format_version` 优先于 `page_type` 判定。

### 2.2 页头（48 字节，固定）

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | `checksum` | 覆盖全页（本字段置零后计算） |
| 8 | 2 | `format_version` | 从 1 起 |
| 10 | 1 | `page_type` | 见 §2.1 |
| 11 | 1 | `flags` | 位标志，见下 |
| 12 | 4 | `workspace_ref` | 工作区**受校验映射**（非原始 ID） |
| 16 | 2 | `file_id` | 有效 10 位 |
| 18 | 4 | `block_id` | 有效 28 位，与 ROWID 一致 |
| 22 | 4 | `generation` | 页代次 |
| 26 | 8 | `page_lsn` | 最近一次修改的日志位置 |
| 34 | 2 | `slot_count` | 槽位数（含已删槽） |
| 36 | 2 | `tuple_count` | 活动元组数 |
| 38 | 2 | `free_start` | 空闲区起始偏移（槽位目录末尾） |
| 40 | 2 | `free_end` | 空闲区结束偏移（行数据起始） |
| 42 | 2 | `frag_used` | 已被行片段占用的字节（跨页行，见 §3.4） |
| 44 | 1 | `seg_type` | 所属段的类型（数据/索引/undo…） |
| 45 | 3 | `reserved` | 对齐保留 |

**`flags` 位定义**：

| 位 | 含义 |
| --- | --- |
| 0 | 页已初始化完成（未完成的页不得被使用） |
| 1 | 页含跨页行片段 |
| 2 | 页有空闲槽位可复用 |
| 3 | 页已被标记待回收 |
| 4–7 | 保留 |

**设计要点**：

- `file_id` 与 `block_id` **分开存**，而不是存一个 pack 后的 ROWID——因为页头要能被独立校验，且与 ROWID 的位宽解耦（ROWID 位宽将来变化时页头不受影响）。总长 6 字节，与 ROWID 的 file+block 部分等宽。
- `workspace_ref` 是**受校验映射**而非原始工作区 ID。其构造方式须保证：伪造或跨区误读可被检出（总体方案 §7）。
- `checksum` 覆盖全页，是全页完整性的唯一保证。**`logging = none` 的表依赖它检出撕裂页**。

### 2.3 槽位目录

每个槽位 **2 字节**：

```
位 15–2 (14 位)：行数据起始偏移（0–16383，恰好覆盖 16KB 页）
位 1–0  (2 位)：槽位状态
```

| 状态值 | 含义 |
| --- | --- |
| 0 | 空闲（未使用或已回收） |
| 1 | 正常行 |
| 2 | **转发指针**（行已迁移，见 §3.3） |
| 3 | **片段头**（跨页行的首片段，见 §3.4） |

**行长不存于槽位**——存于行头（§3.1）。理由：槽位占 2 字节时，1024 槽共 2KB（页的 12.5%）；若存 `(偏移, 长度)` 需 4 字节，则 4KB（25%），代价过高。

**槽位上限 1024** —— 与 ROWID 的 `row_id` 10 位耦合，两者必须同时修改（见 `spec/README.md` D-06）。

### 2.4 空闲空间管理

- 页内只有一个连续空闲区：`[free_start, free_end)`。
- 页头记录 `free_start` / `free_end`，不回写全局结构（区别于 LMT 位图——那只管**区间分配**，不管页内空间）。
- **页内空间整理（defrag）**：当空闲空间分散、无法容纳新行时，将活动行向页尾 compaction，合并空闲区。这是 Oracle"块内重组"的对应机制。
  - 触发条件、整理阈值须定义（P0）
  - 整理**必须更新所有槽位的偏移**，且必须受 WAL 保护

### 2.5 页尾校验

页最后 1 字节为**固定哨兵值**。

作用：与 `checksum` 配合检出**部分页写入**。若只写了页的前半部分，哨兵值会是垃圾 → 立即判定页不完整，不需要计算完整校验和。

> 这是廉价的快速否定检查；完整判定仍以 `checksum` 为准。

## 3 行

### 3.1 行头

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `row_flags` | 见下 |
| 1 | 2 | `row_len` | 本行（或本片段）总长，含行头 |
| 3 | 2 | `col_count` | 列数 |
| 5 | 2 | `null_bitmap_len` | NULL 位图字节数 |
| 7 | 2 | `var_col_count` | 变长列数 |
| 9 | *n* | `null_bitmap` | 每列 1 位 |
| | *2m* | `var_offsets` | 变长列相对行首的偏移，`m = var_col_count` |
| | | 列数据 | 定长列在前、变长列在后 |

**`row_flags` 位定义**：

| 位 | 含义 |
| --- | --- |
| 0 | **已删除**（tombstone，见 §3.5） |
| 1 | 行已迁移（本槽位是转发指针） |
| 2 | 跨页行片段（本行是一个片段而非完整行） |
| 3 | 含大字段（存在外置或跨页存储的值） |
| 4–7 | 保留 |

**设计要点**：

- **删除是打标记，不立即回收** —— 与需求文档 REQ-STO-003 一致：删除在行头打删除标记，索引项随事务一并维护，提交后槽位即可复用。
- 行头**不含版本号、不含时间戳** —— 存储层不做版本化（REQ-STO-014）。这些属于数据模型层。
- 行头**不含事务 ID** —— See §3.6。

### 3.2 列存储

- **定长列**（NUMBER 的整数快路径、DATE、UUID、FLOAT32/64 等）按声明顺序紧凑存放，无偏移表。
- **变长列**（VARCHAR2、JSON、VECTOR 等）偏移存于 `var_offsets`，数据在定长列之后。
- **NULL 用位图表达**，不占列空间。注意区分**字段缺失 / JSON null / SQL NULL** 三种语义（REQ-CFG-002）——它们在存储层是不同的表示，不可压成一个位。

### 3.3 行迁移与转发指针

行更新后变长、原页放不下时触发迁移：

```text
原槽位：状态 = 2（转发指针）
        行体只放一个 6 字节的新 ROWID

新位置：完整行，槽位状态 = 1
```

**规则**（与 REQ-STO-005 一致）：

- **头片段的 ROWID 保持稳定**，作为"稳定入口"。头片段不发生二次迁移（若再次增长，转为行片段链而非再次迁移）。
- 索引**不需要更新**——索引仍指向原 ROWID，经转发指针到达新位置。
- 转发指针**受 WAL 保护**，插入与更新在事务内原子完成。

> **代价说明**：经转发指针访问需**多读一页**。因此迁移不应频繁发生。P0 须定义 `PCTFREE` 类的预留比例（页内预留空间，降低迁移概率）。

### 3.4 跨页行与行片段链

行首次插入即超过单页可用空间时（大 JSON、高维向量），拆为**行片段链**：

```text
头片段（槽位状态 = 3）：
  行头 + row_flags 位 2 置位 + 指向下一片段的 ROWID

中间片段：
  片段头（下一片段 ROWID）+ 数据

尾片段：
  片段头（下一片段 = NULL）+ 数据
```

**规则**：

- 只有**头片段**有稳定的 ROWID 并出现在索引中。
- 片段链**必须受 WAL 保护**——任一点中断后可恢复为一致状态，不得出现半截链。
- 链长度**有界**，超限返回明确错误（I/O 上界由 P0 冻结）。
- 页头 `frag_used` 记录该页被片段占用的字节，用于空间核算。

> **与 16KB 页的关系**：选 16KB 正是为了让**主流维度向量（≤3072 维，12KB）不落进这条路径**。跨页是例外路径，不是热路径。

### 3.5 删除与槽位复用

| 步骤 | 动作 |
| --- | --- |
| 1 | 置 `row_flags` 位 0（已删除），写 Undo |
| 2 | **索引项随事务一并移除**（删除即移除、回滚即恢复） |
| 3 | 提交后槽位置为**空闲**（状态 0），可被复用 |
| 4 | 空间由 **defrag** 合并，不在删除时立即回收 |

**已知行为**（REQ-STO-016）：RC 下索引扫描可能漏读语句开始后被并发删除的行。这不是缺陷，须在测试基线中断言"允许漏读"。

**`cleanup = segment_drop` 的表不适用本节**——它们整段丢弃，不逐行删。

### 3.6 行头为何不含事务 ID

本设计采用 **Undo + 一致性读**（Oracle 式），而非 PostgreSQL 式的堆内多版本（`xmin`/`xmax`）：

- 可见性由 **Undo 链 + 快照**判定，不由行内字段判定
- 行内不留事务信息 → **行更紧凑**，且避免"更新即改行头"带来的写放大
- 与 REQ-STO-004（原地更新，不采用 ASTORE 式堆内多版本）一致

> 这与 §3.1 的"行头不含版本号"是同一原则的两个侧面：**存储层不承载版本与事务语义**。

## 4 区与段

### 4.1 区

- **区 = 8 页 = 128KB**（16KB × 8），一次分配的单位。
- 区大小固定，不按对象调整——便于空间核算与配额。
- 连续区减少碎片；小对象的空间浪费由"按需申请/释放区"控制。

### 4.2 区分配位图

**每个数据文件头部各持一份**（已确认），不集中在 file 0。理由：文件因此**自描述**——单独移动、校验、恢复时能自证；区分配操作只触碰目标文件。

- 位图记录该文件内**哪些块已分配给某个段**。
- 位图本身受 **WAL 保护**（即使所属表是 `logging = none`，见 `表类型与存储选项_v0.1.md` §2.2）。
- 位图页类型 = 8。

### 4.3 段头

每个段（表、索引、Undo）的第一个页是**段头页**（`page_type = 9`），记录：

| 项 | 说明 |
| --- | --- |
| 段类型 | 数据 / 索引 / 邻接 / Undo / 临时 / ANN |
| 表选项副本 | `logging`、`update_mode`、`cleanup` 等（引擎据此分派行为） |
| 区清单 | 本段占用的区 |
| **高水位（HWM）** | 见 §4.4 |
| 空闲空间索引 | append-only 表用于定位可追加位置 |

**表选项存在段头**（而非只存目录）的理由：引擎打开段时即可分派行为，不必回查目录；且段自描述，利于单文件恢复。

### 4.4 高水位与两类表

**高水位（HWM）语义**（Oracle 式）：段内"已格式化且可能含数据"的边界。**删除不降低 HWM**，全表扫描会扫过空块。

| 表类型 | HWM 策略 |
| --- | --- |
| `update_mode = in_place` | 采用 HWM，可配合段收缩（`TRUNCATE` / 重组）回收 |
| **`update_mode = append_only`** | **不需要 HWM**——追加位置由段头显式记录，`cleanup = segment_drop` 时整段丢弃，不存在"扫过空块"的问题 |

**这是 append-only 表相对堆表的实质优势**：省掉 HWM 的空扫代价，TTL 也退化为整段操作。

## 5 表空间各文件的页使用

| 文件 | 页类型 | 说明 |
| --- | --- | --- |
| **file 0** | 5（引导）+ 4（元数据）+ 8（位图） | 块 0 为引导页，格式永久固定；bootstrap 数据在固定偏移；段目录、对象目录、文件角色表 |
| **file 1** | 6（Undo） | 只有 `logging = full` 的表产生 Undo |
| **file 2** | 7（临时） | 不持久化，不参与恢复；可零长度占位 |
| **file 3+** | 1/2/3/9/10 | 数据、索引、邻接、段头、ANN |

**引导页与 bootstrap**（file 0 的块 0）：

- **块 0 的格式永久固定**，内核硬编码知道——解决自举问题（要读目录先要知道目录结构）。
- 引导页指向 **bootstrap 数据**（紧随其后的固定块偏移），内容是"段目录/对象目录长什么样"的定义。
- 参照 Oracle `bootstrap$`：其位置（`file 1 block 377`）、对象号、初始区大小都是**硬编码**的，内核不依赖任何字典即可读取。
- bootstrap 位置约定**一旦发布不可变更**（或必须以 `format_version` 区分）。

## 6 按表类型的物理差异汇总

| 表类型 | 页类型 | 空间管理 | HWM | Undo | 特殊 |
| --- | --- | --- | --- | --- | --- |
| 普通关系表 | 1 | 空闲区 + defrag | ✅ | ✅ | 可能行迁移/跨页 |
| 配置表 | 1 | 追加为主 | 不需要 | ❌ | 版本保留内联淘汰 |
| 会话表 | 1 | **顺序追加** | 不需要 | ❌ | **按时间分段，整段丢弃** |
| 图数据 | 1 + 3 | 空闲区 + defrag | ✅ | ✅ | 出边邻接页按 `src` 聚簇 |
| 记忆表 | 1 | 追加为主 | 不需要 | ❌ | 向量列可选 |

> **注意**：`update_mode = append_only` 的表仍使用**同一套数据页格式**（类型 1），只是空间管理策略不同。**不引入第二套页格式**——这是"一个引擎"的底线。
