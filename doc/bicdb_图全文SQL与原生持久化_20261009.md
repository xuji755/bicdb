# 图全文 SQL 与原生持久化（2026-10-09）

> 后续进展：服务定时 batch、间隔/批次参数与在线策略调整已实现，见

## 当前可用接口

在已有全文 Rust 内核基础上，本阶段接入工作区内的 SQL、原生 heap/B-tree、字典及 undo/WAL。
支持节点与关系的全文索引，固定 JSON 对象路径和数组下标，显式手动创建/同步/重建/删除，
以及按 `db_type` 过滤的查询。不连接 Neo4j，不修改其数据、索引、配置或服务。

当前维护模式必须明确指定 `manual`。省略维护选项或者指定 `batch` 会报错，因为定时维护和
服务的自动调度尚未接线。新版索引已登记原生共享队列，图写事务仅保存变化 ID/修订。
`SYNC` 分批消费队列，在同一原生事务中提交变化文档、倒排追加与队列确认。v2 源按 ID 读取；
旧全文索引保持扫描源的增量同步；尚需扫描有界队列、装载全文语料并重算统计。
详见 [共享队列与批量维护](bicdb_图全文共享变更队列与批量维护_20261009.md)。
关系表/配置表字段全文与文档对象索引仍是独立待实现接口，不能用本图语法替代。

```sql
CREATE GRAPH kg;
CYPHER kg 'CREATE (:Entity {db_type:"mariadb",name:"innodb_buffer_pool_instances",config:{question:"MariaDB 缓冲池实例",answers:["10.5.1 弃用，10.6 移除"]}})';

CREATE FULLTEXT GRAPH INDEX answers ON kg
  NODES LABEL ("Entity", "Fault")
  (name, config.question, config.answers[0])
  OPTIONS '{"update":"manual"}';

SHOW FULLTEXT GRAPH INDEXES ON kg;

SEARCH FULLTEXT GRAPH INDEX answers ON kg FOR '缓冲池'
  OPTIONS '{"db_type":"mariadb","consistency":"eventual","limit":20}';

ALTER FULLTEXT GRAPH INDEX answers ON kg SYNC;
ALTER FULLTEXT GRAPH INDEX answers ON kg REBUILD;
ALTER FULLTEXT GRAPH INDEX answers ON kg PAUSE;
ALTER FULLTEXT GRAPH INDEX answers ON kg RESUME;
DROP FULLTEXT GRAPH INDEX answers ON kg;
```

关系示例：

```sql
CREATE FULLTEXT GRAPH INDEX causes ON kg
  RELATIONSHIPS TYPE ("CAUSE", "RELATED") (config.answers)
  OPTIONS '{"update":"manual"}';
```

标签/关系类型之间为 OR，可省略限制。节点使用 LABEL，关系使用 TYPE，不能互换。
字段至少一个，最多 16 个；支持 `config.answers[0]."Title"`，不支持 JSON 通配符或动态下标。
未引号 SQL 名称折叠为小写；Cypher 属性/标签区分大小写，所以 `"Entity"` 必须保留引号。
创建、同步、重建、暂停、恢复和删除禁止在活动用户事务中执行；查询允许，并遵循该会话的语句可见性。

`bicdbcli` 在服务和直连模式均转发 `SHOW FULLTEXT GRAPH INDEXES ON graph`，带/不带分号均可；
`HELP GRAPH` 提供操作示例。控制台按已有列宽显示，完整列元数据仍通过数据库结果集返回。

## 查询与一致性

OPTIONS 必须为 JSON 对象，仅接受以下键，未知键或错误类型明确拒绝：

| 键 | 值与默认行为 |
| --- | --- |
| db_type | 必填、非空字符串、最长 128 字节 |
| fields | 可选，选定字段的规范名称数组；缺省使用索引全部字段 |
| channel | terms（默认）、phrase、exact |
| consistency | strict（默认）或 eventual |
| limit | 无符号整数 0..10000，缺省 10000；在域/字段/词项/修订过滤和排序后应用 |

字段规范名称由 SHOW 返回，例如 `config.answers[0]`。通道、UTF-8 字节位置、数组边界、
按域统计的 BM25 及完整词法标识符语义沿用
[全文内核说明](bicdb_图全文内核与批量变更队列_20261009.md)，不宣称 Lucene 查询语言或分数兼容。

eventual 读取已发布 generation，原生 B-tree 范围扫描得到候选，再复核字段、通道、域和
当前源实体修订。源已删除、改名、改域、改标签或改内容时，旧文档不能作为陈旧答案返回。
尚未同步的新对象/新文本可以缺失。完整访问格式的图按记录键获取源实体；旧格式回退为
全图读取。关系候选同时校验身份范围和当前两端节点存在性。

strict 必须包含当前语句可见的源变化，含本事务未提交内容。当前通过受预算约束的全源重建
语句内视图实现，明确返回 `mode=strict_scan`，不写数据库、不覆盖已发布 generation。
没有用旧倒排候选截断严格结果。后续共享队列和尾部合并接入后再减少这项开销。

结果列为：

```text
element_id score field snippet byte_offset line_number
mode generation covered_commit_seq complete covered_source_seq source_seq
```

- `generation` 为已发布代号；严格视图沿用这个标识，不代表发生了额外持久发布。
- eventual 的 mode 为 `FULLTEXT_BTREE`；新版索引完整覆盖水位等于当前图源水位时才
  complete=true。未追平或部分批次发布为 false；旧索引因未登记队列保持 false。
- strict 的 complete=true 表示源覆盖完整；显式 limit 仍可能减少返回行数。
- 新版索引采用 `covered_source_seq`/`source_seq`，按变化对象递增。eventual 的
  `covered_commit_seq` 为 NULL；旧索引保持构建快照序号。strict 使用当前语句快照提交序号。
  **不能把图源计数当作数据库提交序号，也不能把部分 cursor 当作完整水位。**
- 索引单次结果超过 10000 会报预算错误，不先做隐式 Top-K 再声称返回完整结果。

每个数据库 Session 最多缓存一份不可变 generation，键为索引对象号及文档头的 SHA-256。
每次使用前读取原生 ordinal=0 校验记录；增量发布和完整重建都会改变头摘要，令缓存失效。
删除释放缓存。缓存不共享工作区，不省略源修订复核。
冷查询需要解码整个已发布文档语料并恢复统计；热查询复用它。这还不是只读取命中文档的
完全按需全文存储，也没有通过大型知识图谱耗时/RSS 基准验收。

## 原生对象及发布事务

- 倒排索引为 `ind$.type#=260 GRAPH_FULLTEXT`，属于指定 GRAPH，`icol$.col#=0`。
  payload 是 48 位元素 ID，不允许普通堆表 DML 把它当 ROWID 维护。
- 文档存储为受保护的 `obj$.type#=257 GRAPH_FULLTEXT_DATA`，名称 `gft_<index_obj>$`，
  两列 ordinal NUMBER、data BYTES(4096)。独立受保护的唯一 ordinal B-tree 为
  `i_gft_<index_obj>$`。普通 SELECT/DML、DROP TABLE、CREATE/DROP/REBUILD 普通 INDEX 无法绕过管理。
- Definition 版本、文档分片、源 SHA-256、位置及倒排键沿用已有全文内核原生编码。
  创建在一个 DDL 事务中写入索引、文档 heap、ordinal 树及其字典行。
- 新版 SYNC 每批消费至多 256 个合并事件，按 ID 获取源，只编码头与这些文档的差异；
  文档更新、倒排追加与队列 cursor/完整覆盖确认在同一原生事务中提交。保留物理段；
  失败批次不提交，已完成批次保留，下一次从持久 cursor 继续。旧索引保留扫描源的增量路径。
- 同图共享保护队列 type#258 与唯一 ordinal 树保存 ID/修订，不保存正文，不在写路径分词。
  前台按头和受影响 ID 原生树读取，源补丁与队列补丁同事务提交。详见共享队列文档。
- REBUILD 先完整分词并验证语料预算，再建立三个新全文物理段。所有数据准备好后，在同一
  DDL 事务中切换稳定对象的非键 seg$ 路由/统计/版本，并刷新此消费者及共享队列。保留对象号。
  失败回滚保留原路由，旧 generation 仍可读取。
- 显式 DROP FULLTEXT 和 DROP GRAPH 级联清理文档存储及内部 ordinal 索引的字典对象。
  DROP 沿用既有字典删除路径；未额外宣称任意底层 I/O 故障下物理字典键删除的恢复保证。
  新旧物理段回收仍待实现，多次全量重建会累积空间占用。
  增量 SYNC 不删除旧倒排项；查询复核当前文档词项与源修订。反复维护会累积陈旧项，
  达到候选预算时明确报错，可使用 REBUILD 清理；不能声称索引空间已自动回收。

REBUILD 独立读取并验证文档头，不需要先解码旧文档体；完整源仍是权威数据。
头摘要/定义本身损坏仍会报错，未实现任意全文元数据损坏的自动修复。

本阶段修复 `index_objects_of` 的原始 i_ind_pk 全扫：失败 DDL 后物理树可能残留已回滚
字典项，直接 fetch 会触发 RowMissing。现在枚举当前存活的 ind$ 行，不把残留项当活对象。
