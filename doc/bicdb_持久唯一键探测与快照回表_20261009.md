# 持久唯一键探测与快照回表（2026-10-09）

## 写入唯一性检查

此前净变更只生成受影响实体的索引键，但唯一约束仍编码并扫描整个最终图的未修改实体。本轮增加 PropertyIndex::changed_entries_with_probe：先检查修改实体的最终键集合，再对每个完整、可比较的唯一键请求所有持久候选。候选必须完整；Some(empty) 表示完整空结果，None 表示调用方没有证明，保留原有流式扫描。错误、预算耗尽均传播，不把截断当空结果。

SQL 对属于当前图、status=1 的唯一属性索引使用自身 B-tree 的闭区间 [key,key]。不会借用其他索引，也不会因探测失败回退为“无冲突”。每个候选按最终 Graph 的身份、标签/关系类型和规范属性键重新核验：删除、改值、退出标签的历史候选不会误报；修改身份已在最终变更集合检查，所以同语句键交换和释放后重用有效。包含 null 的键按既有规则不受唯一性限制；唯一字段仍必须是标量，JSON 路径和组合键规则保持。

每次空探测也消耗一个工作单位，返回的历史候选继续计账。多个唯一索引共用余额，初始工作计数包含查询表达式/遍历工作和已有 provider 条目读取。范围读取多取一条用作超限哨兵，超过工作预算必须拒绝；按完整键长度加 32 字节限制一次探测的行数，防止历史候选分配失控。时间在读取前后及核验后检查。写入拒绝发生在存储发布前，显式事务先前成功语句仍保留。历史候选过多可显式 REBUILD 索引恢复容量。

这仍不是一般并发唯一性算法：当前工作区单写者保证下，索引构建和净变更同事务维护提供完整候选；未来多写者需要键级同步及源版本证明。普通写入仍加载并验证完整图，没有实现部分源加载或完整执行器 RSS 预算。未来若使用部分源缓存，必须取回并验证全部探测候选的可见源值；缓存缺失不能当作候选已删除，否则会漏判唯一冲突。

## 修复快照转发读取

新增 SQL 回归在 v1 格式转换及回滚后触发旧视图漏行。根因位于通用 fetch_rows_resolved：先在当前页沿转发指针找目标，再对目标恢复快照。迁移前的快照中目标尚不存在，原行却仍在源页，因而索引回表返回空。

修复后每一轮先按请求块地址分组，恢复固定 ReadView 的 CR 页，再判断该快照中的槽是行、删除还是转发。只有快照中的转发槽才进入下一轮；输出身份也是快照解析后的实际位置。每轮按块复用 CR，一次仅保留一个块的当前页及 CR 副本，顺序与重复请求原样回填；转发上限、损坏/环与 I/O 错误继续明确返回。索引旧入口和新位置可以在当前视图解析为同一行，并由调用方据此去重。该修复同时用于普通关系索引回表。

## 验证范围

新增三个图核心测试覆盖 2000 节点下单键探测、真实候选/历史候选、null、错误/不完整探测、非法身份、标签退出、键交换和关系 JSON 组合键。新增两个 SQL 测试覆盖 v1/v2/v3、回滚及保留此前成功语句、旧视图、全文队列/SYNC、重启、真实历史成员引起的工作拒绝、重建后可写、多索引空探测共享余额。新增认证/wire 测试覆盖已释放键重用、键交换、失败语句与重启约束。

原事务迁移用例增加了真实 fetch_rows_resolved 的旧视图、目标不存在、当前视图、稳定入口/实际位置及重复请求断言，补上之前只验证单页 CR 而没有验证索引回表组合的缺口。最终测试与发布以[本轮证据](evidence/bicdb-graph-unique-probes-20261009/README.md)和[阶段交接](交接文档_bicdb图增强与bicbot协作_20261009.md)为准。所有数据均为隔离 bicdb 合成数据，没有连接或修改 Neo4j。
