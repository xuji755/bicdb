# 外部检索摘要：PG `pg_xact_status` / `txid_status` 与 CLOG（2026-10-04，2 轮 WebSearch）

## 1. `pg_xact_status`（原 `txid_status`）语义

- 函数：`pg_xact_status(xid8) → text`（PG 13+；9.6 起为 `txid_status(bigint)`）。
- 返回：`committed` / `aborted` / `in progress` / **`NULL`**（事务太旧、状态已被丢弃；或该 xid 在"未来"时另报错）。
- **官方用途**："determine whether a transaction committed or aborted when the application and
  database server become disconnected while a COMMIT is in progress"——即**连接在 COMMIT 期间断开**的消歧；
  定位为两阶段提交的轻量替代。
- 客户端须自行取号：应用要在事务里调 `txid_current()`（PG 不会自动把 xid 报给客户端）。
- 实现要点：持有 `ClogTruncationLock`（并取 `XidGenLock`）与 CLOG 截断互斥，避免"查一半被截断"的竞态；
  "oldest 可安全查阅 XID"单独跟踪（截断时序下与回绕复用值不同）；补丁链 = Craig Ringer
  "Transaction traceability – txid_status(bigint)"（reviewer: Simon Riggs）。
- 特例：prepared 事务报 `in progress`；子事务 xid 不得用于该函数；Bootstrap(1)/Frozen(2) 恒报 committed。

## 2. CLOG（pg_xact）与截断

- 存储：`pg_xact/` 目录、256 KB SLRU 文件，**每事务 2 bit**（IN_PROGRESS / COMMITTED / ABORTED / SUB_COMMITTED）；
  checkpoint / shutdown 落盘，启动装载；元组 hint bit 避免重复查；PG 17 加 `transaction_buffers` 缓存。
- 截断：`vac_truncate_clog()`；`CLOG_TRUNCATE` WAL 记录带 oldestXid（备库推进）；
  "查询与截断必须互斥"即 `ClogTruncationLock` 的由来——**这正是"太旧 → NULL"的边界来源**。

## 本轮取用的关键结论（写入 evidence.md）

1. 点查语义四值 + "太旧 → NULL"；2. 官方场景含"COMMIT 期间断连"；
3. 查询与截断互斥（`ClogTruncationLock`）；4. 客户端自行取号（对照：我们由服务端分配、回执必带）。
