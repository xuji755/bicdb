# 证据包：B+Tree 索引页体补全与并发分裂协议（B-link 形态）

模块：存储架构 §5.11（索引页页体）+ §9.1（通用索引）　对应：待冻结项 #8（索引部分）
核验日期：2026-10-04　原始输出：`raw/01–12`（同目录）

## 结论

1. **B-link（Lehman-Yao）是并发分裂的正确参考形态**——right link + high key：
   ①高键不变量：**父页 downlink 允许滞后，但"过期的页只可能偏左"，向右移动必达正确页**；
   ②分裂时**右页复制原页高键**，最右页无高键（∞）；③moveright 以最右页标志终止；
   ④下行**闩耦合逐层释放父页**，回插父页时重找（导航栈可能过期）；
   ⑤扫描以**兄弟链接快照**（`next.link_prev == cur` 校验）处理并发分裂。
   PG nbtree 与 GIN 均为该形态的实现。
2. **Oracle 的分裂行为可直接借鉴的骨架**：空间不足且不可用 PCTFREE 时触发；
   **插入最大键用 99/1、否则 50/50**；叶分裂后用 `KDICBIN` 向分支块插行、根分裂用
   `KDICRSP` 初始化新根；分裂期间**阻塞**其他操作（我们改以高键自愈做到不阻塞）。
   分支块对键做**后缀截断（suffix truncation）**；叶块键压缩（`COMPRESS`）是可选优化，不取。
3. **崩溃窗口的容错有先例、无完整机制**：哈希索引"恢复后保留分裂标志、扫描能正确处理、
   **后续操作完成未完成的分裂**"是可借鉴的容忍模式；btree 侧知识库**未见**"补插缺失下链"
   的直接描述 ⇒ **本项目以"高键自愈 + 检查器容忍态"作为该窗口的定案语义（自主决策）**。

## 本项目自主决策

1. **锚条目升级为高键条目**（槽位 1，永不回收）：Oracle 的幽灵行只保住"路由能找到这页"，
   无法纠正下链滞后时期"进了左页、找不到、误判不存在"——高键把锚升级为**上界 + 右移判据**。
2. **分支区分前缀生成规则**：取分裂点两侧相邻键（左页最大、右页最小）的
   **最长公共前缀 + 1 字节**（取自右页最小键）。两条不变量使其**永不需要维护**：
   ①前缀 ≤ 右子树一切现存键（创建时前缀是右页最小键的前缀；此后经路由进入右子树的键都 ≥ 前缀）；
   ②前缀 > 左子树一切现存键（创建时大于左页最大键；此后进入左子树的键都 < 前缀——路由判据使然）。
   重复键跨分裂时前缀**退化为完整键**。比较仍是**纯字节序**，无需新比较器。
3. **树头（根页 ROWID）落段头页类型扩展区**（与 PG metapage 存根指针同形）；空索引的
   初始根为一张空叶页（类型 2），首次分裂即走"立新根"路径。
4. **根分裂原子性**：页分裂（双页记录）+ **单条原子记录**（旧根 4→3 降级、新根建立、
   树头更新）——崩溃落在两记录之间时旧根仍为根，树自愈可用。
5. **99/1 分裂作为常态路径**：本库序列 ID（`memory_id`、`edge_id`、`event_id`…）索引
   全是单调追加，99/1 = 零搬移 + 新键独立成页，分裂频次最小。
6. **单阶段分裂**：页内（新页 + 链）在 latch 内一次完成——不取 `kdxlespl` 空洞、不做
   两阶段半分裂；父页下链滞后是**协议容忍态**而非损坏。检查器以"叶链可达 + 键序单调"
   判完整性（检查项 ⑥ 范围），下链缺失不报损坏。
7. 叶页**不做** Oracle `COMPRESS` 键压缩（保持条目自包含、二分无跨条目依赖）。
