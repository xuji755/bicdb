## 结论

1. **缓冲是循环的，空间在"写出"后即可复用**：日志缓冲区是 SGA 中的
   **循环缓冲区**（redo blocks）；LGWR 把其中的日志项写进联机日志文件后，
   **服务器进程即可写入已释放的位置——无需等待事务提交**；系统依赖 LGWR
   "快速、频繁"地刷盘来避免缓冲区写满后前台等待。（证据 1–3）
2. **生产者路径与空间等待**：前台经 `kcrfwr()`——计算大小 → 定 SCN →
   取 **redo copy latch（拷贝）与 redo allocation latch（分配）** → 把变更向量
   拷入缓冲；空间不足时取 redo write latch、检查日志文件空间、**通知 LGWR
   或请求日志切换**。缓冲满且 LGWR 未写完 ⇒ 前台等待 **`log buffer space`**
   （`kcrfws()`，超时 1 秒；切换进行中 5 秒）；监控指标
   **`redo buffer allocation retries`**。（证据 4、5、6）
3. **LGWR 的写盘触发有明确的四条**：① **事务提交时强制**（Log Force at
   Commit）；② 缓冲区**达到 1/3 满**；③ **每 3 秒超时**；④ **DBWR 写脏块前**
   （Write Ahead Logging）。LGWR **批量**写出"当前所有未落盘 redo"。
   （证据 7、8）
4. **提交耐久契约（与本项目 §11.1 规则 3 同构）**：会话提交时**通知 LGWR
   把缓冲区中"当前所有未写入磁盘的 redo"（含本次会话的）写进重做日志**；
   LGWR 完成后**通知会话**；会话等待的这段时间就是 **`log file sync`**
   ——即"通知 LGWR"到"收到完成确认"之间的间隔。**并发提交会话共享同一次
   写**（组提交的出处）。（证据 9）
5. **容量规则与代价**：`LOG_BUFFER` 默认 = **max(512KB, 128KB × CPU 数)**，
   须为物理块大小整数倍；**强制下限 = 4× 最大数据库块大小 + 2 个保护页**。
   过小 ⇒ 频繁写盘与 `redo buffer allocation retries`；**过大也有代价**——
   "缓冲区满时必须把所有数据写入重做日志文件，LGWR 要一直等到最后的 I/O
   完成"，因此刷盘等待更久。OLTP 常见建议 1–3 MB。（证据 10、11）
6. **strand（共享/私有）与切换的耦合**：多缓冲时每个称一个 strand；共享
   strand 任何前台可用，**私有 strand** 属于 IMU 模式的单事务（提交时并入
   共享 strand，或 ZC redo 直写）；私有 strand 有
   Free/Used/**Committed**/Flushed 四态；**日志切换必须等所有私有 strand
   刷完**（否则 alert 记 "Private strand flush not complete"）。
   **共享 strand 的大小取决于最大重做记录（128K）与 CPU 数**。（证据 12–14）

## 本项目自主决策

1. **单流单 latch 起步，多写者走"分配与拷贝分离"**：P3 单写者下追加由一把
   latch 串行化（既有口径）；P4 多写者时按证据 4 的形态拆分——**latch 内分配
   位置/占槽，拷贝在 latch 外**，不引入 Oracle 的多 strand/私有 strand
   （无 IMU；画像为短事务，证据 12、13 的动机在本项目不成立）。
2. **复用边界 = sync 成功**（比 Oracle 的"写出即可复用"更保守）：与
   "刷盘失败即放回"同一条纪律——页只在 sync 成功后离开未刷出集合并被
   回收；代价是少量复用余量，换来失败重试语义简单（不需要 "written but not
   synced 不可复用"的额外分支）。
3. **环形 = 固定容量页池 + 位置三量**：`appended_lsn`（追加位）、
   `synced_lsn`（耐久位 = 可复用边界）、页按"位置 mod 容量"落槽；
   空间判据 `end − synced ≤ capacity`。**已刷页不再追加**（页序列永远是
   文件前缀）——保留既有纪律，环形只复用**内存页**，不改变盘上形态。
4. **写触发照四条（证据 7）**：提交强制刷到提交记录终点；追加时缓冲占用
   ≥ 1/3 ⇒ 建议刷盘（`flush_recommended`）；~3 秒周期兜底（由写线程切片
   接入）；DBWR 写页前按 `page_lsn` 刷到规则 2。P3 单写者用"满则刷 + 重试"
   实现空间等待（多写者时改为等待 + `log buffer space` 同构诊断）。
5. **容量规则**：下限 = **最坏单条 34 页 + 余量 ⇒ 36 页**（保证缓冲空时
   任何单条必能落下）；默认 **256 页 = 128 KiB**（< 默认组 256 KiB 的 1/2；
   证据 10 的 512KB 默认值是为通用库定的，本库画像小，取更小并保留配置）；
   1/3 触发 ⇒ 单次刷盘体量 ≈ 43 KiB。
6. **提交契约**：与 §11.1 规则 3 同一句——**提交响应必须晚于提交日志的
   耐久确认**；组提交共享同一次 fsync（证据 9 的"并发提交共享同一次写"）。
