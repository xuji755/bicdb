# 证据包：行片段链的逐片事务性定案（Oracle 多片行参照）

模块：存储架构 §6.3（跨页行）/ §6.4（删除与槽位复用）　对应：**待冻结项 #62（撤销）**
核验日期：2026-10-04　原始输出：`raw/01–03`（同目录）

## 结论

1. Oracle 的多片行（chained row / migrated row）是**逐片独立**的：每片带
   **行片段标志（row piece flag）**与 **NRID**（下一片段行地址）链接；诊断事件 10227
   "verify (multi-piece) row structure"正是**逐片检查"行片段标志 + NRID 链接"**的完整性。
2. 因此"片段是裸字节、只由头片段管生死"不是成熟做法——Oracle 的 row piece
   **各自有行头/标志**，与普通行同规参与事务与回收。
3. 本项目据此把 §6.3 的片段规格升级为：**链上每一片段都是页里的一"行"**——
   各有行头（`row_flags` 位 2 + `itl_slot`）、各自 undo 与回收；**删除逐片置标志、
   删除记录逐片含整片段旧值、回收与普通行无区别**。
   **待冻结项 62 的错误前提（"删除 undo 只含头片段字节、片段空间需与最老快照特判"）不成立，予以撤销。**

## 本项目自主决策

1. **片区统一为"普通行"**：槽位状态 = 3（头/中/尾同一取值），行头齐全（`row_flags` 位 2 +
   `itl_slot`）；头/中/尾由链指针与 NULL 终止区分。
2. **删除的 undo 逐片承载该片段全部字节**——合计 ≈ 一行大小，与普通行"整行旧值"同量级；
   回收判据不特判（提交 + 置空即可复用；一致性读由整片段旧值 undo + `ITL 覆盖`兜住）。
3. **撤除"页头 `frag_used`"提法**——片段走通用槽位目录与空闲区核算（该提法是旧模型残迹，
   页头字段表中本就不存在）。
4. 依据：本证据包结论 1–2 + 用户评审意见（2026-10-04）。
