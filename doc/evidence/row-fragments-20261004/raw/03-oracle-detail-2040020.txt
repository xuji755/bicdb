  Bug 18607546 - ORA-600 [kdblkcheckerror]..[6266] corruption with self-referenced chained row.
  ORA-600 [kdsgrp1] / Wrong Results / ORA-8102 (文档 ID 18607546.8) Symptoms: Related To: Corruption
  (Logical) Internal Error May Occur (ORA-600) Wrong Results Error May Occur ORA-8102 / ORA-1499
  ORA-600 [kdsgrp1] ORA-600 [kdBlkCheckError] ORA-600 [ktbsdp1] ORA-600 [25027] Chained or Migrated
  Rows UPDATE Description ORA-600 [kdsgrp1] with a row piece of a chained row (nrid) pointing to
  itself or if db_block_checking is enabled, the corruption is caught and prevented going to disk with
  ORA-600 [kdBlkCheckError] [file#] [block#] [6266]; message "kdrchk: Row piece pointing to itself" in
  the trace file. It is most likely to happen but not limited to tables with a large number of columns
  (e.g. more than 255 columns). Subsequent SQL operations may produce wrong results or different
  errors like: ORA-8102 by UPDATE (if the table has indexes) ORA-600 [kdsgrp1] ORA-600 [25027]
  ORA-1499 by "analyze table <name> validate structure cascade" (logical corruption between index and
  table as the table is returning wrong values for the affected row) Corruption Example from a block
  dump: Row 58 in Block rdba 0x01aff394 tab 0, row 58, 0x17a tl: 19 fb: -------- lb: 0x16 cc: 10 nrid:
  0x01aff394.3a --> it points to the same row 58 Both ASSM and MSSM segments are exposed to this
  problem. Rediscovery Notes ORA-600 [kdsgrp1] with block dump confirming chained row with a row piece
  pointing to itself. If db_block_checking is enabled then a kdBlkCheckError block check error is seen
  including arguments 6266 Workaround Once the corruption is introduced: Recreate the table skipping
  the row: "Create Table As Select (CTAS) where rowid != <rowid of head piece>" or similar can be used
  eg: export with query clause (where rowid != <rowid of head piece>) then drop or truncate, import OR
  Use dbms_repair to Soft Corrupt the affected block and skip it for DML's To prevent the corruption
  going to disk set db_block_checking=medium which will cause ORA-600 [kdBlkCheckError] [file#]
  [block#] [6266] but the corruption is not propagated to disk. To permanently prevent the issue from
  happening install this fix. HOOKS OERI:kdsgrp1 OERI:kdBlkCheckError OERI:ktbsdp1 ERROR:ORA-8102

  ── 摘要 ──
  Bug 18607546 会导致链式行（chained row）的行片段（row piece）自引用（nrid 指向自身），触发逻辑损坏。启用 db_block_checking 时，会报 ORA-600 [kdBlkCheckError] [file#] [block#] [6266]，trace 中出现“kdrchk: Row piece pointing to itself”。否则可能出。
