     [KnowledgeEntry] Fast Checkpoint 触发条件与行为  (排序分: 10.0)
     └ 摘要：Fast checkpoint 是数据库在恐慌情况下的紧急机制，当日志切换阻塞前台（alert log 中出现“checkpoint not complete”）时触发。正常 checkpoint 中，DBWR 按队列顺序写入 buffer，不影响 LRU 老化；而 fast checkpoint 下，LGWR 发送特殊请求，DBWR 不再遵循队列顺序，改为扫描 LRU 和 LRUW 列表中的所有 buffer，写入那些最低 RBA 小于 checkpoint RBA 的 buffer。这可能导致 I/O 风暴并阻塞所有日志生成，本质上是一种性能降级保护。应通过调整正常 checkpoint 频率来避免其发生。边界条件是，若 checkpoint queue 中 buffer 数量异常多（如大型 DML），fast checkpoint 可能持续很长时间，导致系统几乎停顿。
     详情请见：python3 kb_graph.py oracle detail 4:8ed6c541-fe08-4ade-ae68-a79bf45316f4:154762

     [KnowledgeEntry] LRU 列表与 LRUW 列表互斥关系  (排序分: 10.0)
     └ 摘要：在Oracle数据库的缓冲池管理中，当缓冲被修改后，会从LRU列表移至LRUW列表，以便DBWR进程集中写入。当LRUW列表过长且DBWR来不及写入时，会导致前台进程在需要干净缓冲时首先遍历LRU尾部，若LRU中干净缓冲不足，便会触发'free buffer waits'等待。具体算法中，前台进程获取缓冲时，如果LRU扫描超过阈值（如_db_block_max_scan_pct），就会发出该等待信号。
