核验日期：2026-10-04　原始输出：`raw/01–04`（同目录）

## 结论

1. Oracle 的可传输表空间 = **三件套**：①复制**数据文件**（OS / RMAN）②**导出元数据**
   （Data Pump `TRANSPORT_TABLESPACES`）用于目标端**重建结构** ③**兼容与自包含检查**
   （`DBMS_TTS.TRANSPORT_SET_CHECK`、源置只读、`V$TRANSPORTABLE_PLATFORM` 查平台/字节序；
   受"同平台、同版本"约束）。
2. 我们的离线迁移**同构**并落在**工作区粒度**上：文件（表空间文件 + 外部文件）
   + **元数据恢复数据**（本工作区导入清单 + **public 侧注册数据**——对应 TTS 的"目标端重建"，
   但我们的实例级注册在 `public`，故多出这一份）+ **兼容性预检**（格式版本 / 字节序 / 页大小）。
3. 差异（自主）：**无跨平台字节序转换**——本库的字节序规则本就只声明一族
   （`REQ-PRT-003`），不支持的平台在构建期排除，因此迁移预检只做**拒绝**、不做转换。

## 本项目自主决策

1. **按工作区迁移**；包 = 目录（规范形态）：表空间文件（原样物理格式）+ 外部文件（资产目录）+
   **元数据恢复数据**（本工作区 + public 侧）+ 文本清单（哈希 + schema 版本）+ 完成标记。
2. **不带 temp / 不带 redo**：transient 与可重建件都不进包；redo 起点按 §2.7 规则
   （"源序列下一整组边界"）在导入端重建。
3. **`workspace_id` 保留**（页上 `workspace_ref` 依赖；目标冲突 ⇒ 拒绝导入）；
   `ws#` 由**目标**的 `seq$` 重新分配。
4. **相对布局 + 导入端路径重写**（控制文件写目标池的绝对路径）。
5. **校验三关**：打包哈希 → 导入比对 → 兼容预检（拒绝而非转换）。
6. **导入失败逆序清理**（注册在最后一步）；完成标记未写 ⇒ 目标拒绝视为可用。
7. **离线 = 源工作区已关闭**（静止点），不需要 §2.14 的冻结窗口。
