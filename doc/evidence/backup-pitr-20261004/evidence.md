# 证据包：在线备份与时间点恢复定案（PG / Oracle 参照）

模块：存储架构 §2.14（在线备份，新增）/ §11.10（介质恢复与 PITR，新增）
对应：**待冻结项 #15 / #16（结案）**　核验日期：2026-10-04　原始输出：`raw/01–08`（同目录）

## 结论

1. **PG 的在线文件级复制**靠"检查点 + 备份模式（`pg_backup_start`/`stop`，备份期强制全页写）"
   提供一致性——它需要 FPW 是因为**没有文件系统快照**。**我们有快照能力时，等价保障由
   "冻结窗口"提供**：暂停写一个瞬时窗口 + 时间点副本，快照即恢复写。这是"简化路线"的依据。
2. **Oracle 的 `BEGIN BACKUP`**：把数据文件头推进到备份起点 SCN、**暂停头更新**、开启块影像日志，
   产出**模糊副本**——靠"**从该检查点 SCN 起的重做日志**"做介质恢复（= "库备份 + WAL 恢复"的经典形态）。
   `RECOVER ... UNTIL` 的应用范围 = "控制文件记录的起始 SCN → 目标点"的归档日志，**隐含链连续**；
   **目标点之后尚有未归档在线日志时须先归档**，否则恢复失败。
   → 直接支撑我们的形态选择与"先强制归档再恢复"的要求。
3. **目标点的时间形式不可靠**：Oracle 明确"恢复基于 SCN，SCN 不因时间调整而倒退；
   时间戳可能前后变化——应改用 `UNTIL CHANGE`"。**我们把"提交序号为权威、墙钟时间为近似
   （采样对插值、超窗报错）"写死**；重放终止条件取"最后一条 `commit_seq ≤ S*` 的提交记录"，
   随后回滚未提交——与 PG 的"在最后有效位点优雅停止、未完成事务自动回滚"同一语义。

## 本项目自主决策

1. **备份 = 冻结窗口 + 时间点副本**（三冻结项：拒新写等在途 / 暂停该工作区全部控制文件更新 /
   无需额外刷盘）。快照顺序跨卷等价于单一瞬时；多卷无原子快照是必须冻结的理由。
2. **备份集 = 快照拷贝 + 自快照点起的 WAL 归档链**（"全备份后要备份 WAL 日志"）；
   自描述记录快照点（提交序号 + LSN）与所需最小归档序列号。
3. **PITR = 库备份 + WAL 重放**；目标点默认到归档链末端；下界 = 快照点；
   终止 = 最后一条 `commit_seq ≤ S*` 的提交记录，随后回滚未提交。
4. 无快照能力部署：**回落离线一致备份**（REQ-OPS-007）。
