# 证据包：redo 记录字节格式定案（Oracle 参照）

模块：存储架构 §11.5（redo 的文件结构与记录格式）/ §5.11（REDO 页）　对应：待冻结项 #11
核验日期：2026-10-04　原始输出：`raw/01–06`（同目录）

## 结论

1. Oracle 重做记录的形态：**从块边界开始**——块头（block header）→ **记录头**
   （含记录长度、有效标志 VLD、生成 SCN / 子 SCN）→（strand 头）→ **一组变更向量（CV）**；
   定位用 **RBA = 日志文件序列号 + 块号 + 块内偏移**。**CV = 描述"一个块"的变更**，
   头含 opcode（定义变更类型）、块类、绝对文件号 + 相对 DBA、**变更前块的 SCN 与序列号**、
   附加信息类型码（如 BWR）；CV = 头 + **长度数组**（第一项为数组总长）+ **按 4 字节对齐**的数据数组；
   **多个 CV 捆成一条记录 = 一个原子变更**；CV 跨块时**跳过中间块头**。
2. 我们的三段结构（记录头 + 块段 + 可选主段）与"CV 捆包"**同构**，差异各有理由：
   **无 per-CV opcode**（apply 路径唯一，§11.5.4）；**无 before-SCN**（页自带 `page_lsn`，
   重放幂等统一判定）；**不强制 4B 对齐**（顺序 memcpy，无字段级随机访问）；
   **页内线性打包**（非块边界起——512B 页下"每条记录补零到页边界"平均浪费半页）；
   **记录不得跨文件**（每文件可独立校验）。
3. 定量收口（配合 #46 已结的"512B 页 + 去记录 CRC"）：记录头定 **20B**；最坏单条记录 =
   **重写一整个数据页** ⇒ 内容 16,417B、跨 **34 个 redo 页 = 17 KiB**；
   **组大小下限（不跨文件）= 17 KiB**；主段与块段**不带长度字段**（由 `tot_len` 推导）。

## 本项目自主决策

1. **记录头 20B**（照 #46 去掉 4B CRC）：`tot_len 4B │ lsn 6B │ txn_id 6B │ op 1B │
   flags 1B（bit0 块段 / bit1 主段）│ 保留 2B`。
2. **块段**：`blk_cnt 1B` + 块引用[]（`flags 1B │ rdba 5B │ chg_cnt 2B`，8B 项）+
   块数据[]（按块序、每块 `chg_cnt` 项 `offset 2B │ len 2B │ after_bytes`）——**无长度字段**。
3. **主段**：`payload`——**无长度字段**（= `tot_len` − 纪录头 − 块段长度）；按 `op` 的格式：
   0x01 日志切换 = 组号 1B + 新序列号 4B；0x02 检查点 = 与控制文件"检查点进度"同构的 24B；
   0x30 提交 = `commit_seq 6B`；0x31 回滚完成 = 空；0x10 页修改 = 用块段。
4. **上限与下限**：单条记录内容 ≤ 16,417B（数据页全重写 + 块段开销），跨页后 **17 KiB** ⇒
   **组大小下限 17 KiB**（§2.4 的"组大小 ≥ 最大单条记录"由此定量；原"≈16.4KB"文字同步修正）。
5. **主数据格式**：见存储架构 §11.5.2 / §11.5.4（本次定案，含 Oracle 对照表）。
