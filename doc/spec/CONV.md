# 公共约定（CONV）

被全部域文件引用。**修改本文件须评估对所有域的影响。**

---

## 1 标识符

### 1.1 通用规则

**所有对外可见的对象 ID 由系统级序列产生**——序列的元数据存放在每工作区的 **`seq$` 字典表**里；
**`public` 有自己的 `seq$`**，承载实例级序列（`workspace_id` 等）。

| 规则 | 说明 |
| --- | --- |
| **由序列分配** | 不采用随机数、不由客户端提供、不由时间戳派生——**唯一的分配者是 `seq$` 里的序列** |
| **从 1 起** | 0 保留为"无"；**允许跳号**（缓存与崩溃只向前跳、不回收）——**ID 不要求连续** |
| **不回绕** | 到达上限**显式报错**（与对象号同一政策，存储架构 §3.1.3）——**绝不回收重用** |
| 工作区内唯一 | 除 `workspace_id` 外，各 ID 在**产生它的工作区内**唯一；跨工作区出现相同号不冲突 |
| 不作为权限凭证 | 持有 ID 不代表有权访问；每次访问仍须经工作区与所有者校验（REQ-ISO-001） |

**"猜 ID"在序列方案下为什么仍然安全** ✗✓——替代此前"不可猜测"要求的，是三条**结构性事实**：

| # | 事实 |
| --- | --- |
| 1 | **跨区无路径**——ID 只在产生它的工作区内有意义；没有跨工作区读取，**猜中一个号也没有对象可达** |
| 2 | **不构成权限凭证**——访问校验先于 ID 解析（上表第 5 行） |
| 3 | **响应不可区分**——"存在与否"由响应契约保证（REQ-ISO-006），**不依赖 ID 的随机性** |

**明确接受的代价**：ID 顺序 = **分配顺序**，故属主可推断自己对象的创建顺序与规模——
属主本就能看到自己的全部数据，**这不构成泄露**；`public` 中的顺序对读者可见（公共数据亦然）✓。

### 1.2 ID 类型与序列

| 名称 | 适用对象 | 序列（`seq$` 中各一条） | 表示 |
| --- | --- | --- | --- |
| `workspace_id` | 工作区 | **`public` 的实例级序列** | 48 位，十进制文本 |
| `user_id` | 主体（`public` 的 `user$`） | **`public` 的实例级序列** | 48 位，十进制文本 |
| `object_id`（即对象号 `obj#`） | 表、索引、图 | 每工作区；**起点 100**（1–99 留自举） | 同上 |
| `memory_id` | 记忆主体 | 每工作区 | 同上 |
| `asset_id` | 资产对象 | 每工作区 | 同上 |
| `vertex_id` | 图的顶点 | 每工作区（`GRP` 域） | 同上 |
| `edge_id` | 图的边 | 每工作区（`GRP` 域） | 同上 |
| `request_id` | 单次请求 | **不走序列**——客户端提供或服务端生成 | 仅要求长度有界且可打印 |

> **补记（2026-10-04）**：`user_id` 此前未列在本表、字典表把它写成了 `UUID`——
> 那是 D-01 之前的遗留。按 §1.1"不采用随机数、由序列分配"与"`public` 的 `seq$`
> 承载实例级 ID"，`user_id` 与 `workspace_id` 同规（本行即其归属）。

**已撤销**：`idempotency_key`（2026-10-04，随 REQ-API-006）——防重与"提交结果未知"的消歧改由**协议层对账**承担（`API` REQ-API-014）。

**宽度与编码**：**48 位无符号（6 字节）**——与提交序号、LSN、ROWID 的 48 位惯例一致 ✓；
线上按 6 字节整数，文本按十进制。**序列的持久化、缓存与跳号语义**见存储架构的 `seq$` 规定。

> **ROWID 不是 ID**。ROWID 是记录的物理定位（见 STO 域），会随行迁移变化，不得作为对外持久引用，也不得作为跨事务的业务标识。

### 1.3 排序与比较

- ID 的比较按**数值**（它们是 48 位整数），不按文本序 ✓。
- **ID 的顺序是分配顺序，不是提交顺序** ✗✓——两个事务的提交先后可与 ID 顺序相反，
  回滚还会在序列里留下空洞（不回收）：**不得把 ID 用作时序判据**；
  时序一律用显式时间字段或提交序号。

## 2 时间与时钟

| 项 | 约定 |
| --- | --- |
| 内部基准 | 全部时间戳以 **UTC** 存储，不存本地时间 |
| 原始时区 | 仅在业务需要时作为**独立字段**保存，不混入时刻值（REQ-TYP-007） |
| 精度 | 内部统一纳秒精度；`TIMESTAMP` 对外按 0–9 位小数秒，默认 6 位 |
| 无时区类型 | `DATE`、`TIMESTAMP` 按无时区语义处理，与 UTC 时刻区分（REQ-TYP-007） |
| 单调性 | **系统墙钟可能回拨，不得用于判定先后**。需要严格单调的场合使用逻辑计数（如提交序号） |
| 时间来源 | 生产环境应使用非回拨时钟源（如 `CLOCK_MONOTONIC` 做间隔，墙钟做时间戳）；P0 确认部署要求 |

**TTL 与过期判定**（REQ-MEM-012）：过期属于**可见性规则**，以查询时刻判定；后台物理清理可延迟。判定所用时钟基准须 P0 冻结。

## 3 提交序号与 LSN

两者是**不同**的单调量，**不得混用**（REQ-TXN-004）。

| 名称 | 语义 | 用途 | 性质 |
| --- | --- | --- | --- |
| **LSN**（Log Sequence Number） | 日志中的字节位置 | WAL 记录定位、恢复起点、页上 pageLSN | 物理量；由日志写入推进 |
| **提交序号**（Commit Sequence） | 逻辑提交点编号 | 快照构造、可见性判定 | 逻辑量；由提交推进，与日志大小无关 |

**规则**：

1. 快照只由提交序号构造；LSN 不得出现在可见性判定中。
2. 页上的 `pageLSN` 只用于恢复期判断"该页是否已包含某日志的效果"。
3. 两者不得互相赋值、比较或换算。
4. 实现上建议使用**不同类型**（newtype）使混用无法通过编译。

## 4 错误模型

### 4.1 错误码方案（已定 D-02）

格式：**`BIC-<五位数字>`**——照 Oracle 的 `ORA-XXXXX` 形状（固定前缀 + 五位数字）✓。
**域归属不编码进错误码** ✗✓——四类判定走 §4.3 的字段，域与语义走码清单本身；
数字段只承担"稳定标识"，不承担分类。

**常用错误与 Oracle 数字对齐**（同语义者同数字，便于按 Oracle 经验检索）：

| 码 | 语义 | 对应 |
| --- | --- | --- |
| `BIC-00001` | 唯一约束冲突 | ORA-00001 |
| `BIC-00054` | 资源忙（锁不可得 / 等待超时） | ORA-00054 |
| `BIC-00060` | 死锁检出（**语句级**回滚，见 `TXN` D-03） | ORA-00060 |
| `BIC-00904` | 无效标识符（列 / 名字不存在） | ORA-00904 |
| `BIC-00942` | 表（对象）不存在 | ORA-00942 |
| `BIC-01400` | 不得插入 NULL（NOT NULL 违例） | ORA-01400 |
| `BIC-01555` | 快照过旧 | ORA-01555 |
| `BIC-01722` | 无效数字 | ORA-01722 |
| `BIC-02292` | 存在引用，删除被拒（资产 / 顶点） | ORA-02292 |

**对齐表之外的错误从 `BIC-10000` 起顺序分配**——清单随代码维护，**P0 冻结**
（需求文档 §8 第 9 项）；**只增不改、不复用**（错误码的历史即兼容承诺）✓。

### 4.2 错误必须携带的字段

| 字段 | 用途 |
| --- | --- |
| `code` | 稳定错误码 |
| `retryable` | 布尔；是否可原样重试 |
| `retry_after_ms` | 可重试时的建议等待（可选） |
| `txn_status` | `none` / `active` / `aborted` / `unknown` |
| `message` | 人类可读，**不得包含私有数据内容**（REQ-OPS-002） |

### 4.3 四类必须可区分的错误结果

需求 REQ-API-012 要求 SDK 能区分以下四类。**每一类都必须能由错误响应的字段判定，不得靠字符串匹配**：

| 类别 | 语义 | 重试语义 |
| --- | --- | --- |
| 可重试冲突 | 死锁牺牲、CAS 失败、序列化冲突 | 可自动重试（幂等操作） |
| 资源拒绝 | 配额耗尽、并发超限 | 等待后可重试；`retry_after_ms` 有效 |
| 已中止事务 | 事务已被回滚，连接仍可用 | 必须新开事务，不得重试原事务 |
| 提交结果未知 | 提交已发出但结果未确认 | **不得盲目重试**；须用**协议对账**消歧（`sync` / `status`，REQ-API-014；REQ-TXN-011） |

## 5 编码与序列化

### 5.1 NUMBER 无损十进制（REQ-API-005）

| 项 | 约定 |
| --- | --- |
| 传输形式 | 十进制文本，保留声明精度与标度 |
| 禁止 | 不得经二进制浮点中转；不得静默截断尾随零之外的精度 |
| 特殊值 | 无 NaN/Infinity（Oracle NUMBER 语义） |
| 负零 | 归一为 0 |

### 5.2 向量二进制格式（REQ-RET-017）

| 项 | 约定 |
| --- | --- |
| 元素类型 | `FLOAT32`（IEEE 754 单精度），小端 |
| 布局 | 连续数组，**无头部、无长度前缀**（长度由维度元数据给出） |
| 维度来源 | 由集合元数据 `dimension` 决定，不在数据中重复 |
| 对齐 | 不要求对齐；接收方自行处理 |
| 校验 | 字节长度必须等于 `dimension × 4`，否则拒绝 |

> 大端平台必须显式转换；不得依赖平台字节序（REQ-PRT-003）。

### 5.3 JSON

见 CFG 域。公共约定仅规定：**JSON 数值不得经二进制浮点中转**（REQ-CFG-003）。

### 5.4 文本与字符集

| 项 | 约定 |
| --- | --- |
| 标识符与 SQL 文本 | UTF-8 |
| 长度语义 | 区分字节长度与字符长度；`CHAR`/`VARCHAR2` 声明按字节上限（REQ-TYP-001） |
| 比较与排序 | 按 Unicode 码点，不按本地化排序规则 |

## 6 状态机通用约定

多域涉及状态流转（记忆状态、资产状态、配置 active、索引 generation）。

| 规则 | 说明 |
| --- | --- |
| 显式状态集 | 状态取值必须穷举且有限，不得使用自由文本 |
| 转换留痕 | 每次转换记录**操作者**与**原因**（REQ-MEM-005） |
| 不可跳变 | 非法转换必须拒绝，不得静默忽略 |
| 终态 | 终态不可逆；需要逆转时通过新建对象表达 |
| 并发 | 状态变更必须受事务保护；不得出现两个转换同时"成功" |

## 7 版本、revision 与 generation

三个词在本项目含义不同，**不得混用**：

| 术语 | 含义 | 层次 |
| --- | --- | --- |
| **业务 revision** | 记忆/配置等业务对象的版本号 | 数据模型层（普通列，见 REQ-STO-014） |
| **Undo 快照** | 事务可见性用的历史版本 | 存储层，事务结束即可回收 |
| **generation** | 派生索引（ANN、倒排）的构建批次标识 | 索引层；切换后旧 generation 待读者退出再删 |

**铁律**：业务 revision **不等于** Undo 快照（需求文档 REQ-MEM-006）；二者生命周期、存储位置、回收策略均不同。存储层不得为业务 revision 保留任何数据结构（REQ-STO-014）。

## 8 资源额度命名

各域引用资源额度时使用统一名称，实际数值 P0 冻结（REQ-PERF-001、REQ-RES-001）：

`max_buffers`、`max_query_memory`、`max_connections`、`max_task_queue`、`cpu_budget`、`io_bandwidth`、`max_files`、`max_asset_bytes`、`max_vectors`、`max_graph_expansion`、`max_temp_bytes`、**`work_memory_target`**（实例侧工作内存目标——2026-10-06 追加冻结，P0 冻结决议的评审记录）

**分层**：每个额度同时存在**工作区上限**与**实例总上限**。任一超限均返回**资源拒绝类**错误（码自 `BIC-10000` 起，见 §4.1、§4.3）。

## 9 术语速查

| 术语 | 含义 |
| --- | --- |
| 工作区 | 用户私有数据边界；另有保留工作区 `public` |
| public | 保留工作区及数据所有者，非 SQL 的 PUBLIC 角色 |
| 水位（watermark） | 派生索引相对源数据的同步进度标记 |
| 严格新鲜度 | 查询声明需看到已提交的最新数据，必要时补查未入索引部分 |
| 最终一致 | 查询返回索引水位；**不得**称为"实时一致"（REQ-RET-016） |
| 代次（generation） | 既用于页槽位复用（STO），也用于索引批次（RET）；按上下文区分 |
