## 0 存储模型总述

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 页大小 | **16KB**，实例内固定不可变 | 总体方案 §2、§7 |
| 组织 | 表空间 → 段 → 区 → 块（页） | REQ-STO-001 |

### REQ-STO-001　存储分层：表空间、段、区、页

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 语义

工作区内的空间按四级组织，便于分配与回收。

#### 规格

| 层级 | 说明 | 规模建议 |
| --- | --- | --- |
| 表空间 | 工作区内逻辑容器，对应一组文件 | 每工作区至少 1 个 |
| 段 | 表、索引等对象占用的空间集合 | 每对象 1 个 |
| 区 | 连续页的分配单位，减少碎片 | 建议 8 页/区（**128KB**） |
| 页 | **16KB**，I/O 与缓存的最小单位 | 固定 |

- 页大小在实例生命周期内固定，**不可按对象或表空间调整**。
- 区大小可在 P0 调整；调整须评估对小表的空间浪费。

#### 验收要点

- **构造**：创建多个对象，反复分配/释放。
- **预期**：区分配与回收正确，无重叠、无泄漏（`db_check` 校验）。

### REQ-STO-002　数据页必备字段

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 语义

每页必须能自证身份、可校验、可判断是否已包含某日志的效果。

#### 规格（推荐布局，待确认 D-06）

页头固定区，位于页起始：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | `checksum` | 覆盖整页（自身字段置零后计算） |
| 8 | 2 | `format_version` | 从 1 起 |
| 10 | 1 | `page_type` | 数据页/索引页/元数据页等 |
| 11 | 1 | `flags` | 位标志 |
| 12 | 4 | `workspace_ref` | 工作区**受校验映射**（非原始 ID，防伪造） |
| 16 | 4 | `file_id` | 文件标识 |
| 20 | 8 | `page_id` | 页在文件内的编号 |
| 28 | 4 | `generation` | **页代次**，页复用时递增。**用途已收窄**：仅用于识别**文件重建后的陈旧页引用**，**不参与行寻址**（ROWID 不含代次，见 REQ-STO-003） |
| 32 | 8 | `page_lsn` | 最近一次修改的日志位置 |
| 40 | 2 | `slot_count` | 槽位数（含已删槽） |
| 42 | 2 | `tuple_count` | 活动元组数 |
| 44 | 2 | `free_space_ptr` | 空闲区起始偏移 |
| 46 | 2 | `reserved` | 对齐保留 |

页体：槽位目录自偏移 48 向高地址增长；元组自页尾向低地址增长；中间为连续空闲区。

- 页尾最后一个字节为特殊字节，用于**检测部分页写入**（配合 REQ-TXN-014）。
- `workspace_ref` 必须是受校验的映射值，**不是**原始 `workspace_id`，防止跨区页被误读。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 校验和不匹配 | 判定损坏，上报（不静默返回数据） |
| `format_version` 高于本实例支持 | 拒绝打开该文件，**不得**尝试兼容读取 |
| `workspace_ref` 与当前工作区不符 | 拒绝，按隔离事件处理（REQ-ISO-001） |

#### 验收要点

- **构造**：`page_dump` 读出全部字段并核对。
- **注入**：翻转任意字节，`db_check` 必须检出校验和失败。

### REQ-STO-003　ROWID 结构与槽位复用

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 语义

ROWID 是记录的**物理定位**，在同一逻辑行生命周期内稳定。

**不使用代次**：陈旧引用由"**索引项不晚于其所指的行消失**"这一机制排除，而非用代次检测。

#### 规格

**ROWID = 48 位 = 6 字节**：`file_id(10) + block_id(28) + row_id(10)`

| 字段 | 位宽 | 容量 |
| --- | --- | --- |
| `file_id` | 10 | 1024 文件（**表空间内相对编号**） |
| `block_id` | 28 | 268,435,456 块 × 16KB = **4 TiB/文件** |
| `row_id` | 10 | 1024 槽（**与 D-06 页内槽位上限耦合，两者须同时修改**） |

- **ROWID 不含代次**。理由：删除在行头打删除标记，**索引项随事务一并维护**（删除即移除、回滚即恢复），提交后槽位即可复用。因此不存在"索引项比其所指的行活得更久"的窗口。
- **槽位复用**：删除提交后即可复用，无需等待、无需代次校验。
- **行迁移**（REQ-STO-005）：**头片段** ROWID 保持稳定（稳定入口）；后续片段通过链访问，其 ROWID 可变化。
- **ROWID 是表空间内相对地址**：不同工作区会出现相同 ROWID。所有共享结构（缓冲池键、日志、诊断、审计）必须**另带工作区标识**；页头的受校验工作区映射作为兜底。
- **ROWID 不是对象 ID**：不得作为对外持久引用，不得作为业务标识（CONV §1.2）。
- ROWID **不得**用于行锁定位（REQ-TXN-002 要求逻辑行标识）。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 删除提交后槽位复用 | **不应存在**指向旧行的存活索引项。若观察到，属索引维护缺陷，**不是**可接受的边界行为 |
| ROWID 指向已迁移行的头片段 | 经稳定入口与链定位到当前片段 |
| ROWID 跨工作区使用 | 由工作区标识与页头受校验映射检出并拒绝 |
| `row_id` 超出 1024 | 不可能：D-06 限定页内槽位上限为 1024，写入路径必须强制该上限 |

#### 已知行为（非缺陷）

| 情形 | 行为 |
| --- | --- |
| RC 下索引扫描 | 语句开始后、索引读取前被并发删除的行，索引项已移除，**可能漏读**。此为 Oracle 同类模型的既有取舍，见 REQ-STO-016 |

> 页头仍保留 `generation` 字段，但**用途已收窄**：仅用于识别**文件重建后的陈旧页引用**，不参与行寻址。

#### 验收要点

- **构造**：删除一行并**提交** → 插入新行使槽位复用 → 检查是否存在指向旧行的存活索引项。
- **预期**：**不存在**此类索引项（不是"存在但被代次检出"）。
- **回滚**：删除后回滚 → 索引项与行一并恢复，行可经原 ROWID 访问。
- **迁移**：行迁移后经稳定入口定位到当前片段，内容与参考模型逐字段一致。
- **跨区**：用 A 工作区的 ROWID 在 B 工作区解析，必须被拒绝。
- **边界**：构造页内槽位数达 1024 的情形，确认无 `row_id` 溢出。

### REQ-STO-004　原地更新，不做存储层版本化

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7、需求文档 §2.1

#### 语义

常规更新**修改当前行**，历史信息进 Undo；主堆中**不保留**完整旧版本。

#### 规格

- 更新路径：定位行 → 加锁 → 写 Undo → 写日志 → **原地修改**该行。
- **禁止**：堆内版本链、ASTORE 式版本组织、LSM 式 MemTable/SSTable/Compaction 主路径。
- Undo 中的旧版本仅用于**回滚**与**一致性读**，事务结束且无快照引用后即可回收。
- 业务级多版本（记忆 revision 等）由**数据模型层**用额外的行/节点表达（REQ-STO-014）。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 更新后行变长，原块放不下 | 触发行迁移（REQ-STO-005），**不**保留旧版本 |
| 需要保留历史 | 由业务层插入新版本行，存储层不知情 |

#### 验收要点

- **结构检查**：堆表页中不存在指向其他版本的指针或版本号字段。
- **接口检查**：存储接口无任何版本参数。
- **代码审查**：无版本链遍历代码。

### REQ-STO-005　跨页行、行片段与行迁移

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 语义

单行可超过一页（大 JSON、高维向量），或更新后增长到原页放不下。两种情况都必须支持。

#### 规格

区分两种形态：

| 形态 | 触发 | 结构 |
| --- | --- | --- |
| **行链接（chaining）** | 插入时行就超过单页可用空间 | 行被拆为多个**片段**，分布在多页 |
| **行迁移（migration）** | 更新后行变长，原页放不下 | 整行移到新页，**原槽位保留转发指针** |

**统一协议**：

- **稳定入口**：行的 ROWID 始终指向**头片段**所在槽位；头片段不发生二次迁移。
- **可恢复链接**：片段链的建立与更新必须**受 WAL 保护**，任一点中断后可恢复为一致状态（不得出现半截链）。
- 片段顺序由链序确定，不依赖物理位置。
- 链的最大长度必须有界（P0 冻结），超限返回明确错误。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 链在建立中断 | 恢复后可判定地完成或回退 |
| 链过长超限 | 拒绝写入，返回资源/大小类错误 |
| 行既迁移又需链接 | 先迁移至可用页，仍不足再链接 |

#### 验收要点

- **构造**：超页 JSON 与高维向量的写入、读取、更新、删除。
- **注入**：在链建立/迁移各步骤注入崩溃，验证恢复一致。
- **对照**：链式读取结果与参考模型逐字节一致。

### REQ-STO-006　BufferPool 与 PageGuard

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 规格

BufferPool 提供：

| 能力 | 说明 |
| --- | --- |
| `pin` | 固定页，防止被替换；引用计数 |
| `latch` | 保护**内存结构**（非事务冲突） |
| 脏页管理 | 标记、刷盘、与 `page_lsn` 配合 |
| `page_lsn` 管理 | 与 WAL 联动（REQ-TXN-008） |

**PageGuard**：

- 以 RAII 控制页引用生命期，离开作用域自动 unpin。
- **不得向 SQL 层返回裸页面指针**——这是硬约束，验收方式为接口层无裸指针暴露。
- 早期可使用简单替换策略与粗粒度结构锁；优化须有证据，不得凭直觉调整。

#### 验收要点

- **接口检查**：对外接口无裸指针类型。
- **注入**：页面操作中途出错/取消，验证 pin 计数归零（无泄漏）。
- **SRS-007 联动**：持 latch 期间不做 I/O、不等事务（见下条）。

### REQ-STO-007　latch 使用约束

**优先级**：必须　**阶段**：P2–P4　**追溯**：总体方案 §7、§15

#### 语义

latch 只用于保护**内存结构**的短临界区。违反会导致长时间阻塞与死锁。

#### 规格

持 latch 期间**禁止**：

1. 等待事务锁；
2. 执行文件 I/O；
3. 阻塞网络；
4. 获取另一 latch 而不遵守**全局锁序**。

- 锁序必须在代码中显式定义并有文档，不得隐式依赖调用顺序。
- 条件变量等待、队列等待一律不得在持 latch 时进行。

#### 验收要点

- **代码检查**：I/O 与锁管理器调用点不在 latch 临界区内（可用静态检查或封装强制）。
- **运行时断言**：调试构建下断言 latch 深度与禁止操作。
- **并发检查**：TSan 无未解释竞态；线程池满时回滚与超时仍可进展。

### REQ-STO-008　B+Tree 索引

**优先级**：必须　**阶段**：P4　**追溯**：总体方案 §7、§18

#### 规格

- 支持**唯一键**、**复合键**、**范围访问**。
- 键比较使用统一类型内核（REQ-SQL-010），保证与 `WHERE` 判定一致。
- 叶项保存指向堆表的定位（ROWID 或逻辑行标识，P0 定）。
- 至少支持 **100 万键**规模（总体方案 §18）。
- 并发分裂协议须**先产出证据包**再实现（总体方案 §22）——涉及 Lehman-Yao 类协议与 right-link，不得凭印象编写。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 唯一约束冲突 | 拒绝并在错误中给出冲突值（不泄露他人数据） |
| 键更新导致移动 | 保留旧快照所需入口，延迟回收 |
| 分裂中断 | 按系统操作协议恢复（REQ-STO-010） |

#### 验收要点

- **规模**：100 万键的建、查、删、分裂、键更新。
- **对照**：崩溃后索引与可见堆表对照一致。
- **并发**：并发插入/删除/扫描下的正确性。

### REQ-STO-009　索引候选回表检查可见性

**优先级**：必须　**阶段**：P4　**追溯**：总体方案 §7

#### 语义

索引不存储可见性信息；索引项命中**不等于**该行对当前快照可见。

#### 规格

- 索引扫描得到候选后，**必须回表**检查事务可见性（REQ-TXN-001）。
- 删除与键更新时**保留**旧快照所需的入口，延迟回收至无快照引用。
- **不得**用索引项直接回答查询（除非有独立可见性映射，首版不做）。

#### 验收要点

- **构造**：事务 A 删除行但未提交，事务 B 用索引扫描该键。
- **预期**：B 仍能看到该行（按 RC 语义）；A 回滚后行为正确。
- **构造 2**：长快照 + 索引键更新，验证旧入口未被提前回收。

### REQ-STO-010　页分裂使用单独的系统操作协议

**优先级**：必须　**阶段**：P2–P4　**追溯**：总体方案 §7

#### 语义

结构变更（分裂、分配、合并）比普通行修改复杂，必须使用单独审查的协议与恢复规则。

#### 规格

- 分裂视为**系统操作**，不参与业务事务的语义失败判定——即"分裂失败"不得被简单当作业务事务失败忽略。
- 分裂过程必须**受 WAL 保护**，任一点中断可恢复。
- 恢复时能判定分裂已完成还是未完成，且**不得**出现两个页都认为自己拥有某键区间。
- 分裂的并发控制与锁（latch）协议须有文档与证据包。

#### 验收要点

- **注入**：在分裂各步骤（分配新页、搬移元组、更新父页、更新兄弟链）注入崩溃。
- **预期**：恢复后树结构一致，`db_check` 通过，无区间重叠。

---

### REQ-STO-011　空间分配元数据受 WAL 保护

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7

#### 规格

以下结构的所有变更必须记日志：

- 空闲页分配与回收
- 页初始化
- 区/段位图
- 控制元数据（文件头、段头）

#### 验收要点

- **注入**：在分配与位图更新之间注入崩溃。
- **预期**：恢复后无"页已分配但位图未记录"或反向的不一致。

### REQ-STO-012　页编码、检查器与损坏处理先于 SQL 执行器

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7、§17

#### 规格

- P2 必须交付：页编解码、`page_dump`、`db_check`、损坏识别与处理路径。
- 在此之前**不得**开始完整 SQL 执行器（P5）的实现。
- 损坏处理必须给出**明确判定**（可用 / 可修复 / 不可恢复），不得静默返回数据。

#### 验收要点

- **构造**：至少 100 万次带种子的页操作与参考模型比较，覆盖页满、复用、压缩、迁移、损坏与超限。
- **持久性**：关闭重开后结果一致。
- **工具**：`page_dump`/`db_check` 在 P2 可用。

### REQ-STO-013　资产不混入堆表页链

**优先级**：必须　**阶段**：P6　**追溯**：总体方案 §7、§9

#### 规格

- 资产内容保存在独立文件中，**不进入**堆表页链。
- 堆表中只保存资产**元数据**与引用（ASSET_REF）。
- 资产与页存储的路径、配额、回收策略相互独立（REQ-AST-012）。

#### 验收要点

- **结构检查**：堆表页中无资产内容。
- **配额**：资产字节与页空间分别计量。

---

### REQ-STO-014　存储层不得实现版本化存储

**优先级**：必须　**阶段**：P2　**追溯**：总体方案 §7、§10；需求文档 §2.1

#### 语义

**多版本是数据模型层的事，不是存储层的特性。** 存储层对"版本节点"的处理就是普通的插入与原地更新。

#### 规格

- 存储接口**不得**接受版本参数，不得提供"追加新版本"语义。
- 堆表中**不得**存在版本链、版本号列、或指向历史版本的指针。
- 业务多版本的实现方式（示例，由业务层决定）：
  - 图的**主节点 + 版本节点**；
  - `memory` + `memory_version` 两张表。
  - 对存储引擎而言，以上都是**普通的行**。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 提案要求存储层保留旧版本 | 拒绝；须走 ADR（REQ-STO-015） |
| 业务需要历史版本 | 由业务层插入新行，存储层不感知 |

#### 验收要点

- **结构检查**：页格式中无版本相关字段。
- **接口检查**：存储层接口无版本参数。
- **代码审查**：无版本链遍历逻辑。

### REQ-STO-015　存储层保留旧版本的提案须经 ADR

**优先级**：必须　**阶段**：贯穿　**追溯**：需求文档 §2.1、REQ-MNT-004

#### 语义

这条不是"不得做"，而是"不得**想当然**地做"。该推导极易被误认为自然（"记忆是版本化的 → 底层要版本化"），必须强制论证。

#### 规格

任何"因业务需要多版本，故存储层应保留旧版本"的提案，必须：

1. 先提交 **ADR**，说明为何数据模型层方案不可行；
2. 评估对堆膨胀、Undo/回收语义、恢复协议的影响；
3. 评估对 REQ-TXN-012/013 恢复协议与 REQ-STO-010 分裂协议的冲击；
4. 经评审后方可实施。

#### 验收要点

- **流程检查**：无 ADR 的此类变更不予合入。
