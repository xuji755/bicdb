需求文档 §4.2。公共约定见 [`CONV.md`](CONV.md)。

## 0 类型系统总述

**参考环境**：Oracle 19c、`AL32UTF8`、`MAX_STRING_SIZE = STANDARD`、固定 NLS。

**内部实现照 Oracle 的设计**——它被证明高效且适用面广。
**合规边界与红线见** [`../类型实现与Oracle的合规边界_v0.1.md`](../类型实现与Oracle的合规边界_v0.1.md)：
**只承诺行为、不承诺字节**（REQ-TYP-004），以及"不接触源码、不照抄文档文字"两条纪律。

### 0.1 类型清单

| 类别 | 类型 | 物理编码（在哪） | 声明宽度 |
| --- | --- | --- | --- |
| **标量** | `NUMBER` / `INTEGER` | 变长基 100（§6.5） | 变长 |
| | `DATE` | 固定 **7B**（§6.5） | 7B |
| | `TIMESTAMP(p)` | **7B**（p=0）或 **11B**（p≥1）（§6.5） | 由 p 定 |
| | `CHAR(n)` | 固定 n 字节，空格填充（§6.5） | n |
| | `VARCHAR2(n)` | 变长，**无长度前缀**（§6.5） | 变长 |
| **扩展** | `BOOLEAN` | 1B（§6.6） | 1B |
| | `UUID` | 16B 大端（§6.6） | 16B |
| | `FLOAT32` / `FLOAT64` | **同 `NUMBER`**（§6.6） | 变长 |
| | `TIMESTAMP_TZ` | 11B + 时区偏移（§6.6） | — |
| | `JSON` | 二进制 JSON（§6.6） | 变长 |
| | `VECTOR(n)` | 连续 IEEE 754 FLOAT32，小端（§6.6） | n × 4B |
| | `ASSET_REF` | 6B（§6.6） | 6B |

### 0.2 三条统摄全局的选择

| 选择 | 理由 |
| --- | --- |
| **`INTEGER`、`FLOAT32`、`FLOAT64` 都是 `NUMBER` 的子类型**，共用一套编码 | "**保序**"这个性质**一次实现、三处受益**——字典表索引、整数列范围扫描、浮点列范围扫描都因此成立（§6.5） |
| **长度一律按字节声明**（`CHAR` / `VARCHAR2`） | 与参考环境一致（`CONV §5.4`）。**字符长度是派生的**，由字符集决定 |
| **没有 LOB 类型** | 大对象走 `ASSET_REF` 的受管外部文件，**不进库、不进 redo**（§6.6）。所以"长文本"只是普通变长字符值 |

### REQ-TYP-001　六类标量

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

提供 `CHAR`、`VARCHAR2`、`NUMBER`、`INTEGER`、`DATE`、`TIMESTAMP` 六类标量，
**行为与参考环境兼容**。

#### 规格

**① 声明与取值域**

| 类型 | 声明 | 取值域 |
| --- | --- | --- |
| `NUMBER` | 裸，或 `NUMBER(p,s)`；`p` 1–38、`s` −84–127 | 绝对值 **1.0×10⁻¹³⁰ 到 9.99…9×10¹²⁵**，**38 位有效数字**；另有**零** |
| `INTEGER` | 无参数 | 语义为 `NUMBER(38,0)`——见 REQ-TYP-003 |
| `DATE` | 无参数 | 公元前 4712-01-01 到公元 9999-12-31，**含时分秒**（无小数秒、无时区） |
| `TIMESTAMP(p)` | `p` 0–9，默认 6 | 同 `DATE` 的日期范围；小数秒按 `p` |
| `CHAR(n)` | `n` 1–2000（`STANDARD`） | **固定 n 字节**，不足部分**空格填充** |
| `VARCHAR2(n)` | `n` 1–4000（`STANDARD`） | **变长**，只存实际字节 |

> **上表是"以参考环境实测为准"的声明**——它是我们据以实现的规格，
> **不是权威来源**。任何一格与实测不符，**以实测为准**并回改本文档。

**② `CHAR` 与 `VARCHAR2` 的比较语义不同，而这直接来自编码差异**

| | `CHAR` | `VARCHAR2` |
| --- | --- | --- |
| 存储 | **固定 n 字节**，空格填充 | 变长，无填充 |
| 比较 | **空格填充语义**——`'a'` 与 `'a  '` 相等 | **非填充语义**——尾随空格**参与比较** |

**这不是"额外加的规则"，是编码的直接结果**：`CHAR` 在盘上就是 n 个字节，
空格是**实际存储的内容**；`VARCHAR2` 只存实际字节，尾随空格是**用户写的**。

**③ 数值运算的精度**

- `NUMBER` 的运算**按十进制进行**，不经二进制浮点（见 REQ-TYP-002）；
- `NUMBER(p,s)` 的**结果标度**按参考环境的规则（加/减取最大标度、乘取标度和……）；
- **`ROUND` / `TRUNC` 的边界**（`.5` 的方向、负数）**必须逐值差分验证**。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 超出行长 | 拒绝，报**明确的类型错误**，不静默截断 |
| `NUMBER` 超出 38 位有效数字 | 按参考环境的舍入规则处理，不静默截断 |
| `p` / `s` 越界 | 拒绝 |

#### 验收要点

- **构造**：每类标量至少 100 条确定用例。
- **预期**：与参考环境**差分一致**——比较、哈希、索引键、常量折叠、客户端往返五条路径**分别验证**（REQ-TYP-004）。

### REQ-TYP-002　`NUMBER` 不得以 double 承载

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

`NUMBER` 不得以 double 承载；**裸 `NUMBER` 不得归一为 `NUMBER(38,0)`**。

#### 规格

**① 承载方式**

`NUMBER` 的**磁盘编码与计算路径都是十进制的**——变长基 100（§6.5）。
**不存在"存成 double"这条路径**：

| | 十进制（采用） | 双精度 |
| --- | --- | --- |
| `0.1` | **精确** | 二进制循环小数，不精确 |
| 38 位整数 | **精确** | 超出 53 位有效位后失真 |
| 累加误差 | **无** | 逐次累积 |

**② 整数快路径的边界**

允许存在整数快路径，但**它只能存在于计算路径，不得改变磁盘编码**（§6.5）。

> **为什么这条必须写死**：若 `INTEGER` 用小端 64 位整数存储，
> 其字节序与 `NUMBER` 编码**不同序**，同一列内索引比较会错。
> **"快路径"是一个优化，不是一个类型**——它不能渗进格式。

**③ 裸 `NUMBER` 与 `NUMBER(38,0)` 不是同一个类型**

| | 裸 `NUMBER` | `NUMBER(38,0)` |
| --- | --- | --- |
| 标度 | **任意** | **固定为 0**——只能存整数 |
| 精度 | 38 | 38 |

**"归一"会把一个能存小数的列变成只能存整数的列**——那是一次静默的类型收窄。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 任何把 `NUMBER` 落到浮点的转换 | **禁止**——转换要么精确，要么报错 |
| 裸 `NUMBER` 上做 DDL 时被隐含为 `(38,0)` | **禁止** |

#### 验收要点

- **构造**：超出双精度精度的十进制值逐值比对。
- **注入**：在裸 `NUMBER` 列插入小数。
- **预期**：往返后**逐位一致**；小数**不被截断**。

### REQ-TYP-003　`INTEGER` 语义为 `NUMBER(38,0)`

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

`INTEGER` **语义为 `NUMBER(38,0)`**，不得退化为 32/64 位机器整数。

#### 规格

- **磁盘编码与 `NUMBER` 完全相同**（§6.5）——所以它**不引入新的编码路径**；
- 语义是 `NUMBER(38,0)`：**标度 0**、精度 38；
- **`38 位边界值读写往返必须一致`**（REQ 的验收）——这是对"不得退化为机器整数"的直接检验：
  64 位整数上限约 1.8×10¹⁹（19 位），**存不下 38 位**。

**本库对象号、序号、计数一律用 `INTEGER`**（§3.1.3）——因为**数目不会超过 38 位**，
而"用 `INTEGER` 而不是 `NUMBER(38)`"让意图清楚。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 超出 38 位 | 报类型错误，**不回绕、不截断** |
| 非整数赋给 `INTEGER` | 按参考环境的规则（四舍五入）或拒绝——**以实测为准** |

#### 验收要点

- **构造**：`10³⁸ − 1` 与 `−10³⁸ + 1`。
- **预期**：**读写往返逐位一致**。

### REQ-TYP-004　兼容是行为契约

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

类型兼容是声明、取值、赋值、转换、比较与客户端往返的**行为契约**，
**不要求内部字节编码相同**。

#### 规格

**这是本域最重要的一条，因为它划定了"什么是契约、什么不是"。**

| 是契约（对外承诺） | **不是契约**（实现自由） |
| --- | --- |
| 声明与取值域 | **内部字节编码** |
| 比较与哈希**的结果** | 编码中的字段顺序、位宽 |
| 索引键的**字节序**（因为它决定扫描结果） | 编码用了几个字节 |
| 客户端往返**的值** | 页内布局 |
| 常量折叠与转换的**结果** | 计算路径是否走了快路径 |

**五条必须分别验证**（REQ 的验收原文）：**比较、哈希、索引键、常量折叠、客户端往返**。

> **这一条同时是最佳工程判断与最佳法律位置。**
>
> | 角度 | 含义 |
> | --- | --- |
> | **工程** | 内部编码是实现细节，**改了不该影响任何调用方** |
> | **法律** | 我们承诺**行为**不承诺**字节**——**撞上专利时改编码即可**，对外契约不受影响 |

> **"完全参考 Oracle 的实现"与这一条不冲突**：前者是**当前的选择**（因为它被证明高效、
> 适用面广），后者是**保留的自由**。**选择可以变，自由不能丢。**

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 调用方依赖内部编码 | **不受支持**——不是契约的一部分 |
| 内部编码变更导致对外行为变化 | **视为缺陷**，不是"编码自由" |

#### 验收要点

- **构造**：五条路径各一组用例。
- **预期**：**五条全部一致**；且**内部编码变更后仍全部一致**（这一条要专门测）。

### REQ-TYP-005　空字符串：SQL 与 JSON 分别处理

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5、§6

#### 语义

**SQL 空字符串按参考环境的字符规则处理；JSON 空字符串保持其文档语义。**
**两者分别验证，互不串用。**

#### 规格

**这是本域最容易做错的一条，因为它要求"同一个字面量在两条路径上含义不同"。**

| | SQL 路径 | JSON 路径 |
| --- | --- | --- |
| `''` 的含义 | **等同于 NULL** | **一个长度为 0 的合法字符串** |
| `'' IS NULL` | **真** | 不适用 |
| `LENGTH('')` | **NULL**（不是 0） | **0** |
| `'' = ''` | **NULL**（未知），不是真 | 不适用 |
| 能否存进 `VARCHAR2` 列 | **存不进去**——它变成 NULL | 能，`""` 是一个值 |

**实现要点**：

1. **归一发生在 SQL 类型层**——空字符串**在进入存储之前**就被归一为 NULL。
   于是**存储层永远不会看到"空串"与"NULL"两种东西** ✗✓ ——这是**简化**，不是复杂化。
2. **JSON 不走那条路**——`JSON` 有自己的二进制表示（§6.6），
   `""` 在其中是一个**合法值**，与 `null` **不同** ✗
3. **禁止任何一处"统一处理"**——两者混用会在 JSON 上引入 SQL 的怪癖，
   或在 SQL 上破坏参考环境兼容 ✗

> **第三点是这条需求真正的分量**：它们的**默认答案相反**，
> 而"统一一下"是任何重构里最自然的动作。**所以它必须写成一条禁令。**

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| `INSERT INTO t VALUES ('')` | 存入 **NULL**——与参考环境一致 |
| JSON 文档里的 `""` | **保持为字符串**，不得转为 null |
| 从 JSON 取 `""` 再当 SQL 字符串用 | **在该转换点上按 SQL 规则**——转换点是唯一的归一位置 |

#### 验收要点

- **构造**：`''` 在 SQL 各处的行为（`IS NULL`、`LENGTH`、`=`、`INSERT`、`CONCAT`）。
- **构造**：JSON 文档含 `""` 与 `null` 两个字段。
- **预期**：**两者都正确，且不互相影响**——`""` **不**被转成 null。

### REQ-TYP-006　扩展类型

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

提供扩展类型 `BOOLEAN`、`UUID`、`FLOAT32`、`FLOAT64`、`TIMESTAMP_TZ`、`JSON`、`VECTOR`、`ASSET_REF`。

**各自独立规范与参考模型；不宣称全量 Oracle 兼容。**

#### 规格

**这一条的关键在最后半句**：扩展类型**没有"Oracle 参考环境"可对** ✗——
所以它们的正确性**由我们自己的规范定义**，不由差分测试定义 ✓。

| 类型 | 规范在哪 | 与参考环境的关系 |
| --- | --- | --- |
| `BOOLEAN` | §6.6 | Oracle SQL 层历史上**没有** `BOOLEAN`（PL/SQL 有）✗——我们**不宣称兼容** |
| `UUID` | §6.6 | 参考环境无此类型 |
| `FLOAT32` / `FLOAT64` | §6.6 + §6.5 | **是 `NUMBER` 的子类型**——与 Oracle 的 `FLOAT` 同路，**与 `BINARY_FLOAT` 不同路** |
| `TIMESTAMP_TZ` | §6.6 + `CONV §2` | 时刻存 **UTC**，**原始时区另存** |
| `JSON` | **`CFG.md`**（内部表示参照 PG 的 `jsonb`）+ §6.6 | 数值**不得经二进制浮点中转**——内部就是 `NUMBER` |
| `VECTOR(n)` | §6.6 + `CONV §5.2` | **pgvector 式**：维度写在类型里 |
| `ASSET_REF` | §6.6 | 6 字节资产 ID（48 位序列值，`CONV` §1.2），**内容不进库** |

**`FLOAT32` / `FLOAT64` 的一处边界要重申**（§6.6）：
它们是 `NUMBER` 的子类型，**失去 IEEE 754 的全值域**——
`NUMBER` 上限约 40 位十进制，**装不下 `FLOAT64` 的 ~1e308**。
**换来的是天然保序**，因而**可以直接建范围索引**。

> **`VECTOR` 的元素 `FLOAT32` 与标量列 `FLOAT32` 不是同一个东西**：
> 前者是 **IEEE 754、定长 4 字节**，后者是 **`NUMBER` 编码、变长**。
> **必须如此**——ANN 的定长槽依赖定长（§5.11）。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 把扩展类型当作"Oracle 有的类型"来用 | **不受支持**——它们没有参考环境 |
| `VECTOR` 元素数与声明维度不符 | **拒绝**（`CONV §5.2`：字节长度必须等于 `dimension × 4`） |

#### 验收要点

- **构造**：每个扩展类型**独立**的规范与参考模型（REQ 原文要求）。
- **预期**：**由我们自己的规范判定正确性**——不声称与任何产品差分一致。

### REQ-TYP-007　时间的 UTC 与原始时区

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5

#### 语义

**时间事件统一保存 UTC 时刻**，需要时保留原始时区；
**`DATE` / `TIMESTAMP` 仍按无时区处理**。

#### 规格

**约定见 `CONV §2`**——本文档只补**类型层面**的两条：

| 类型 | 时区语义 |
| --- | --- |
| `DATE`、`TIMESTAMP` | **无时区**——存的是一个"墙上时间"，**不是一个时刻** ✗ |
| `TIMESTAMP_TZ` | **有时刻语义**——存 UTC + 原始时区偏移 |

**这个区分不能含糊**：

> `DATE` / `TIMESTAMP` 存的是**墙上时间**，它**不指向一个唯一时刻**——
> 同一串字节在不同时区是不同时刻。**所以它们不能用于跨时区的排序或比较** ✗
>
> 需要"何时发生"的地方（`ctime`、审计、TTL 判定）**必须用 `TIMESTAMP_TZ` 或提交序号**。

**"原始时区另存"的含义**：它是**独立字段**，**不混入时刻值**（`CONV §2`）——
所以 `TIMESTAMP_TZ` 的时区偏移是**"它原来是从哪个时区录入的"这个事实**，
**不是时刻的一部分** ✓。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 用 `TIMESTAMP` 做跨时区排序 | **语义错误，不是缺陷**——文档必须写清 |
| 需要严格先后 | 用**提交序号**，不用墙钟（`CONV §2`：系统墙钟可能回拨） |

#### 验收要点

- **构造**：跨时区往返、夏令时、回拨。
- **预期**：UTC 时刻往返一致；原始时区**作为独立字段**保留；无时区类型的墙上时间语义**不因会话时区改变**。

### REQ-TYP-008　用例集：它同时是证据

**优先级**：应当　**阶段**：P2　**追溯**：总体方案 §5

#### 语义

合计不少于 **1 万条生成用例**，记录**版本、NLS、SQL、绑定与结果**。

#### 规格

**功能上它是一套测试；性质上它是 conformance suite。**

在 clean-room 的实务里，"**追求行为兼容而非文本复制**"的最强实际证据
就是一套**固定、可复现、带版本与结果记录**的用例集
（见 [`../类型实现与Oracle的合规边界_v0.1.md`](../类型实现与Oracle的合规边界_v0.1.md) §4.3）。

**所以那五个字段不是"顺带记的"**：

| 字段 | 为什么它是证据的一部分 |
| --- | --- |
| **版本** | 证明**当时**的参考环境是什么——没有它，结果不可复现 |
| **NLS** | 排序与转换依赖 NLS；不记则结果无意义 |
| **SQL** | 用例的**输入本身** |
| **绑定** | 绑定变量与字面量在参考环境里**行为可能不同** ✗——不记就漏了一类 |
| **结果** | 差分比对的基准 |

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 用例通过但**未记录 NLS/版本** | **视为不完整**——不可复现的结果不能作为证据 |
| 既有用例被静默修改 | **必须留痕**——证据链断了就失效了 |

#### 验收要点

- **预期**：**1 万条以上**，**逐条可复现**；用例集本身纳入版本控制。

---

### REQ-TYP-009　范围边界

**优先级**：必须　**阶段**：P1　**追溯**：总体方案 §5、§6

#### 语义

**完整 PL/SQL、DDL 隐式提交不由类型兼容要求推导**——不在 V1.0 范围内。

#### 规格

**这一条防的是"从类型兼容推出更多兼容"这个滑坡**：

| 不做 | 为什么不能从类型兼容推出来 |
| --- | --- |
| 完整 PL/SQL | 类型系统是**数据**层面的；PL/SQL 是**过程**层面的，两者没有推导关系 |
| DDL 隐式提交 | 那是**事务语义**，不是类型语义。**本库的 DDL 与 DML 共用同一套事务**（§3.1.2）——**这是刻意的差异** ✗ |
| 其他 Oracle 特性（`%TYPE`、`ROWTYPE`、`PACKAGE`…） | 同上 |

> **DDL 隐式提交那条尤其要写明**：参考环境里 DDL 会隐式提交当前事务 ✗，
> 而本库**不这么做**——DDL 是一个可回滚的普通事务（§3.1.2）。
> **这与"类型兼容"无冲突**，但**从外部看是一个明显的差异**，必须写在明处。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 要求 PL/SQL 支持 | **拒绝**——不在 V1.0 范围 |
| 期待 DDL 隐式提交 | **不会发生**——DDL 可回滚 |

#### 验收要点

- **构造**：类型兼容的全部用例。
- **预期**：**没有一条**推导出对 PL/SQL 或隐式提交的要求。

## 待确认汇总（TYP 域）

### 已随本域定案

| 项 | 结论 |
| --- | --- |
| 内部实现 | **照 Oracle 的设计**；合规边界见专门备忘 |
| 契约边界 | **行为是契约，字节不是**（REQ-TYP-004）——同时是工程与法律上的正确位置 |
| 数值承载 | 十进制，**不经二进制浮点**；整数快路径**只在计算路径** |
| `INTEGER` | `NUMBER(38,0)`，**共用 `NUMBER` 的编码** |
| 空字符串 | **SQL 路径归一为 NULL；JSON 路径保持为值**——两条路**不得统一处理** |
| `FLOAT32`/`FLOAT64` | `NUMBER` 的子类型，**天然保序、可建范围索引** |
| `VECTOR` 元素 | **IEEE 754 定长 4 字节**，与标量列 `FLOAT32` 不是一回事 |
| 时间 | `DATE`/`TIMESTAMP` **无时区**（墙上时间）；时刻用 `TIMESTAMP_TZ` 或提交序号 |
| 用例集 | **同时是 conformance suite**，五个字段都要记 |
