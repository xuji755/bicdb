## 0 模型总述

### 0.1 一条流水线，五个阶段

```text
SQL 文本 ──▶ ① Raw AST ──▶ ② Bound Query ──▶ ③ 逻辑表示 ──▶ ④ 物理计划 ──▶ ⑤ 执行
              （解析）      （绑定）           （变换）        （选择）       （逐次）
              不碰 Catalog  碰 Catalog        保持语义       不可变、可缓存   单次状态
```

**①②③④ 是"编译"，⑤ 是"执行"** ✗✓——这条分界是整个域的总纲：

| 阶段 | 产物 | 可变性 | 依赖 |
| --- | --- | --- | --- |
| ① 解析 | Raw AST（语法 + 源码位置） | — | **零依赖**（REQ-SQL-002） |
| ② 绑定 | Bound Query（带类型） | — | Catalog **只读**（REQ-SQL-003） |
| ③ 逻辑 | 逻辑表示（关系代数型） | 变换须保语义（REQ-SQL-007） | — |
| ④ 物理 | **物理计划（不可变）** | **编译一次、执行多次**（REQ-SQL-004） | 值不进计划 |
| ⑤ 执行 | 单次执行状态 | **每次执行新造** | 事务 / 快照 / 模块接口 |

### 0.2 扩展面不是旁路——这是本域最重要的形状

图查询、ANN 检索、JSON 路径、向量距离——**它们都汇入这条同一条管线** ✗✓：

| 入口 | 解析 | 之后 |
| --- | --- | --- |
| SQL | 本域的解析器 | 同一条 ②③④⑤ |
| **图语言**（独立入口，`GRP` 域） | 图语言子集的解析器 | **转换为受控计划节点**，走同一条 ②③④⑤ |
| JSON 路径 / 向量距离 | **不是入口**——是 SQL 表达式里的函数与操作符 | 同一张表达式树 |

**"不得绕过工作区与事务检查"（REQ-SQL-008）不是靠检查实现的，是靠"没有第二条路"** ✓✓——
图扩展节点带 `workspace_id` 与事务上下文，ANN 节点带索引 generation 与水位校验，
**它们不给执行器留任何"我自己去读文件"的可能**（执行器不直接改页，见 §0.3）。

### 0.3 阶段间的模块调用（方案 §14 的落地）

| 谁 | 调什么 | 约束 |
| --- | --- | --- |
| ② 绑定 | `Catalog.resolve / type_descriptor / object_version` | **只解析本人对象与显式 public 只读入口** |
| ② 绑定 | `TYP` 内核（类型规则，REQ-SQL-010） | 无旁路 |
| ⑤ 执行 | `TableAccess` | **负责可见性；执行器不直接修改页** |
| ⑤ 执行 | `GraphAccess`（create / match / expand / delete） | 同事务、有界遍历 |
| ⑤ 执行 | `Retrieval`（text / vector / hybrid / index_watermark） | 结果回查有效 revision |
| ⑤ 执行 | `AssetStore` | 不接受任意本地路径 |
| 全程 | `Transaction`（begin / snapshot / commit / abort） | **不跨工作区** |
| 全程 | `WorkspaceContext`（identity / quota / root_handle） | **业务不可修改** |

### 0.4 名字解析：三个命名空间 + 一份保留清单

会话解析一个名字时，按**固定顺序**查三处（REQ-SQL-003 的第一步）：

| 顺序 | 命名空间 | 内容 | 可写 |
| --- | --- | --- | --- |
| 1 | **对象命名空间**（`obj$`，name + namespace 1=表 / 2=索引） | 用户对象（`obj# ≥ 100`）**与预置对象**（见下） | 属主可写 |
| 2 | **固定表命名空间**（保留名清单，不在 `obj$`） | `file$`、**`session$` / `lock$`**（会话内省，`API` REQ-API-018）及将来（§3.1.4） | **不可写** |
| 3 | 自举对象（`obj# ≤ 99`：`obj$`、`tab$`…） | **不在会话解析范围内** ✗——引擎内部用 | — |

**三条规则从这里直接得到**：

- **找不到 = "不存在"**（不区分"别人的""已删除的""从不存在的"）——REQ-ISO-006 的不可区分，与 §13.5 的表级过滤同一语义；
- **固定表的"只读"不是检查，是"没有入口"** ✗✓——`INSERT/UPDATE/DELETE` 的**目标解析**里根本没有固定表这一格；`SELECT` 的表源才认它们；
- **保留清单**：**以 `$` 结尾的名字、以及预置对象的名字**，`CREATE TABLE / GRAPH / INDEX` 一律拒绝 ✗✓（未来的固定表与系统表不会再撞名）。

**预置对象**（工作区创建时建立，属主可读写、**不可删**，名字保留）：

| 名字 | 是什么 |
| --- | --- |
| `memory` / `memory_version` / `task_checkpoint` / `source_record` / `derived_link` | `MEM` 域的五个业务对象 |
| `session` | 会话表（对话记录；`§8.2` #3：`append_only` + `logging = none` + TTL + `segment_drop`）——**与固定表 `session$`（协议会话内省）不同**（`API` REQ-API-018） |
| `asset$` | 资产元数据（**只读**——写入只经资产接口，`AST` 域） |
| `ref$` | 引用登记（**不进名字解析**——系统簿记，无直接查询路径） |
| `audit` | 审计（**属主只读**——写入只经引擎的审计路径，`OPS` REQ-OPS-003；无 DML / DDL 入口） |

**标识符规则**（本域定；比较照 `CONV` §1.3 的字节序）：

| | |
| --- | --- |
| 不加引号 | **大小写不敏感**——折叠为小写后比较与存储 |
| 双引号 | 大小写敏感，原样 |
| 分隔与注释 | 语句以 `;` 分隔；`--` 行注释、`/* */` 块注释 |
| 参数 | **`:name`**（命名）——类型在绑定期推导，推导不出则拒绝 |

### 0.5 两条清单（"不提供"的落点）

本域把 SQL 面固定为**两条正面清单**——**语句清单**（REQ-SQL-005）与**表达式构件清单**
（同一处给出）——并在 REQ-SQL-006 给出**反面清单**。
**依据"不提供实现禁止"**（存储架构 §13.7）：**没有入口，就没有漏判** ✓。

### REQ-SQL-001　阶段分离

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

采用 Raw AST → Binder → 逻辑表示 → 物理计划 → 执行的**阶段分离**。

#### 规格

**四个编译阶段各有自己的对象类型，接口只有一条单向流**（§0.1 的表）：

| 阶段 | 输入 → 输出 | 明确不做 |
| --- | --- | --- |
| ① 解析 | 文本 → Raw AST | 不解析名字、不定类型、**不碰 Catalog** |
| ② 绑定 | Raw AST + 会话上下文 → Bound Query | 不做变换、不选访问路径 |
| ③ 逻辑 | Bound Query → 逻辑表示 | **只做保语义变换**；不选物理路径 |
| ④ 物理 | 逻辑表示 → 物理计划 | **不读运行期值**；产物不可变 |
| ⑤ 执行 | 物理计划 + 参数 → 结果 | **不改变计划**；状态全在单次执行对象里 |

**阶段分离的判据是"对象里装了什么"**（验收"阶段对象分离"）：

- Raw AST 里**只有**语法结构与位置（REQ-SQL-002）；
- Bound Query 里**有**对象引用（obj# + 版本）、类型、参数清单；
- 物理计划里**只有**编译期决策（访问路径、连接算法、算子树），**没有值**。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 语法错误 | **① 阶段报错**（带源码位置） |
| 名字 / 类型 / 权限错误 | **② 阶段报错**——绝不拖到执行期 |
| 执行期错误（约束、等待超时、资源） | ⑤ 阶段报错，按 `CONV` §4 分类 |

#### 验收要点

- **构造**：分别制造四类错误（语法 / 名字 / 类型 / 运行），检查报错阶段归属。
- **预期**：**错误在最早能发现的阶段报出**；各阶段对象可独立构造与单测。

### REQ-SQL-002　Raw AST 不查 Catalog

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

Raw AST 只记录**语法与源码位置**，**不得查询 Catalog**。

#### 规格

**Raw AST 里有什么**（正面清单，代码审查据此）：

| 有 | 没有 |
| --- | --- |
| 语法节点（语句 / 子句 / 表达式） | **任何对象号 / 对象版本** |
| 标识符的**文本**与大小写 | 任何解析结果（表不存在？列是否存在？） |
| 字面量的原文本与位置 | 任何类型判定 |
| 源码位置（字节偏移区间） | 任何权限判定 |

**这条纪律买到三样东西** ✗✓：

| 收益 | 说明 |
| --- | --- |
| **可单测** | 解析器零依赖——给定文本、给定 AST，不需任何目录状态 |
| **可跨工作区复用** | 原始 AST 与工作区无关 ⇒ **文本 → AST 的缓存可以做在实例级** ✓（安全：它不含任何对象引用，不泄露任何名字空间 ✓✓） |
| **名字探测不可能发生在解析期** | 探测类信息（存在与否）**只在 ② 阶段、且只在会话自己的工作区里**产生（REQ-SQL-003） |

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 引用了不存在的表 | **解析期不报错**——② 才报"不存在" |
| 名字大小写 | ① 阶段只记录文本；折叠规则在 ② 应用 |

#### 验收要点

- **代码审查**：`AST` 模块不 import 任何 Catalog 接口（REQ 的验收原文）。
- **构造**：对空工作区发引用任意名字的合法语句。
- **预期**：错误一律来自 ②，且**不泄露**该名字在任何地方的存在性。

### REQ-SQL-003　Binder

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

Binder 解析**对象与参数**，形成**带类型的 Bound Query**。

#### 规格

**绑定的六个动作，按序**：

| # | 动作 | 失败即报错 |
| --- | --- | --- |
| 1 | **名字解析**（§0.4 的顺序） | "不存在"（不可区分） |
| 2 | **对象版本捕获**：每个解析到的对象记 `(obj#, 版本)` | —（供计划缓存，REQ-SQL-009） |
| 3 | **类型推导与检查**：走 `TYP` 内核（REQ-SQL-010） | **类型错误在绑定期**（REQ 验收原文） |
| 4 | **参数定型**：`:name` 的类型由用法推导 | 推导不出 ⇒ 拒绝 |
| 5 | **写目标检查**：不得是固定表 / `asset$` / `ref$` / 自举对象；不得是 `public`（写侧只有标准接口） | 拒绝 |
| 6 | **登记点标记**：写含**受管引用值**的列时，标出同一事务内维护 `ref$` 的位置（`AST` / `GRP` 的规则） | — |

**Bound Query 里装什么**：类型化表达式树、对象引用集合（含版本）、参数清单（名 + 类型）、
图 / 索引引用、登记点。**这些正是计划缓存键的成分**（REQ-SQL-009）✓。

**图名解析走同一格**（第 1 步）——**图名 = 工作区内的对象名**（`GRP` REQ-GRP-013）：
**不是切换工作区的入口**，没有 `workspace.graph` 这类语法 ✗。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 类型不匹配（如向量与标量比大小） | **绑定期**错误 |
| 参数无类型上下文 | 拒绝 |
| 名字解析到固定表却出现在写目标位置 | 拒绝（"不是检查，是没入口"的落地） |

#### 验收要点

- **构造**：类型错误、缺名字、写固定表、写 public、图名跨区尝试。
- **预期**：**全部在绑定期失败**；`obj#` 与版本被记入 Bound Query（可断点查验）。

### REQ-SQL-004　共享计划不可变

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

共享计划**不可变**；参数、游标、哈希表与取消状态**属于单次执行**。

#### 规格

| 属于计划（共享、只读） | 属于单次执行（每次新造） |
| --- | --- |
| 算子树与算子参数（编译期决策） | **参数值** |
| 访问路径与连接算法 | **游标 / 流式位置** |
| 对象版本集合（作废判据） | 哈希表、排序缓冲、临时空间 |
| 预算上限（编译期可定部分） | **取消标志**与时限 |

**两条硬纪律**（验收"并发执行互不干扰"的判据）：

1. **计划里不得有可变字段** ✗✓——"下一个在哪"这类位置只能活在执行对象里；
2. **执行对象之间不共享可变结构**——同一计划被 N 个会话并发执行，
   N 个执行对象之间**无共享可写内存** ✓（TSan 验证，与 `TXN` 的并发验收同规）。

**游标是执行态**：结果**流式返回**；**不提供 `DECLARE CURSOR` / `FETCH` 语法** ✗——
客户端协议层的游标归 `API` 域，SQL 层没有第二条命名的结果路径 ✓。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 同计划并发执行 | 各自独立，结果与串行一致 |
| 执行中对象被 DDL 改变 | 计划的版本集合失配（REQ-SQL-009）——按该条的失效路径处理 |

#### 验收要点

- **构造**：同一参数化计划 × N 并发执行；TSan 构建跑并发用例。
- **预期**：无未解释竞态；结果与串行逐行一致。

**图全文增补（2026-10-09，已实施）**：独立的 `CREATE/SHOW/SEARCH/ALTER/DROP FULLTEXT GRAPH INDEX`
管理节点/关系、固定 JSON 对象/数组路径、原生文档与倒排，支持显式 `update=manual|batch`。
新版 SYNC 从同图原生共享队列分批消费 ID/修订，变化文档、倒排与确认同事务提交；
旧索引保留扫描源的增量同步。REBUILD 完整重新分词并换段；PAUSE/RESUME 跨重启持久。
新版覆盖使用源计数，与旧版提交序号区分；部分 cursor 不冒充完整水位。
eventual 复核源修订，默认 strict_scan 包含当前语句可见变化。
图源事务与共享队列、服务定时调度及间隔/批次参数已接入；支持 `ALTER FULLTEXT GRAPH INDEX ... OPTIONS` 在线修改策略，不换段。上段普通表/配置/文档源接口及固定目标 WAIT 仍待实现，见[定时维护](../bicdb_图全文定时批量维护与参数_20261009.md)。
详见 [图全文 SQL 与原生持久化](../bicdb_图全文SQL与原生持久化_20261009.md)。

#### 语义

首版 SQL 包含**建删表索引、CRUD、事务控制、表达式、参数绑定、INNER 与 LEFT JOIN、
聚合（含 `DISTINCT` 变体）、排序、LIMIT、**`SELECT DISTINCT` 与集合运算
（`UNION [ALL]` / `INTERSECT [ALL]` / `EXCEPT [ALL]`）**及 JSON 路径与向量距离接口**。

#### 规格

**语句清单**（正面清单，闭集）：

```text
── DDL：属主对自己工作区 ──────────────────────────────────────
CREATE TABLE <名> (<列定义>, …) [WITH (table_type = …, …)]
DROP TABLE <名>
CREATE [UNIQUE] INDEX <名> ON <表名> (<表达式>, …)
DROP INDEX <名>
CREATE INDEX <名> ON <图名> VERTEX (<表达式>)      ┐ GRP 的"选定属性索引"；
CREATE INDEX <名> ON <图名> EDGE   (<表达式>)      ┘ 图不存在时拒绝
CREATE GRAPH <名>          ┐ 建 / 删一组对象（GRP §0.2）
DROP GRAPH <名>            ┘ —— 伴随对象不单独删（无入口）
── DCL：仅 admin，在 public 上执行（**依赖顺序 FS → WORKSPACE → USER**）────
CREATE FILESYSTEM <名> USING '<路径>'          -- 池成员（路径可以是挂载点，也可以只是目录）
ALTER FILESYSTEM <名> SET ALLOCATE = ON | OFF  -- 退役排水阀
DROP FILESYSTEM <名>                           -- 硬前置：该路径下无任何数据文件
CREATE WORKSPACE <名> [DEFAULT FILESYSTEM <fs>] [FROM TEMPLATE '<模板>']
                      [QUOTA <量>|UNLIMITED ON FILESYSTEM <fs>]…
ALTER WORKSPACE <work_ref> ADD FILESYSTEM <fs> [QUOTA …]
ALTER WORKSPACE <work_ref> SET DEFAULT FILESYSTEM <fs> | NAME = '<新名>'
                         | QUOTA (data=…, undo=…, temp=…, asset=…)
ALTER WORKSPACE <work_ref> TO TEMPLATE '<模板>'
DROP WORKSPACE <work_ref>
CREATE USER <主体名> IDENTIFIED BY '<口令>' USING WORKSPACE <work_ref>
ALTER USER <主体名> IDENTIFIED BY '<新>' [EXPIRE] | IDENTIFIED BY '<新>' REPLACE '<旧>'
                    | PAUSE | RESUME | USING WORKSPACE <work_ref>
                    | DROP WORKSPACE <work_ref>
DROP USER <主体名> [CASCADE]
ALTER DATABASE ADD TEMPLATE '<模板>' FROM <work_ref> | DROP TEMPLATE '<模板>'

```

**逐类的最小语义**（细则如下，超出即拒绝）：

| 类 | 规定 |
| --- | --- |
| **列定义** | 列名 + `TYP` 类型 + **可选 `NOT NULL`**。**没有** DEFAULT / PRIMARY KEY / FOREIGN KEY / CHECK（REQ-SQL-006）——主键效果由"`NOT NULL` + 唯一索引"达成 ✓ |
| **表选项** | `WITH (table_type = normal │ config │ session │ memory)`——**类型决定 §8.1 选项全组**（§8.2 的五种）；另可附 `retention = <时长>`、`version_keep = <个数>` 两个有合法默认的覆盖项。**非法组合不可能出现**（类型之外没有自由组合）✓。图数据表**只经 `CREATE GRAPH`** |
| **事务控制** | **默认自动提交**——每条语句自成事务；`BEGIN` 进入多语句事务，`COMMIT`/`ROLLBACK` 结束。**DDL 在活动事务中拒绝**（TXN REQ-TXN-016）。隔离级别固定 RC，**无 `SET TRANSACTION`** |
| **JOIN** | `INNER JOIN`、`LEFT [OUTER] JOIN`（`ON` 条件）；逗号 = 普通连接 ✓。**无 RIGHT / FULL / NATURAL / USING** |
| **聚合** | `COUNT(*)` / `COUNT(x)` / `SUM` / `AVG` / `MIN` / `MAX` + `GROUP BY` + `HAVING`；**`DISTINCT` 变体**（`COUNT(DISTINCT x)` 等——去重键 = 该聚合的参数表达式） |
| **去重与集合运算** | `SELECT DISTINCT`；`UNION [ALL]` / `INTERSECT [ALL]` / `EXCEPT [ALL]`——两侧列数一致、逐列类型可隐式统一（`TYP` 内核判定）；结果列名取第一个 `SELECT`；**未写 `ALL` = 去重**（SQL 标准默认）；链式出现（`A UNION B UNION C`）自左向右 |
| **排序 / 限行** | `ORDER BY <表达式> [ASC│DESC] [, …]`——**NULL 位置**：升序在最后、降序在最前（Oracle 默认）✓；`LIMIT n [OFFSET m]` |
| **表达式构件** | 字面量、列引用、算术（`+ - * /`）、比较（`= <> < <= > >=`）、`IS [NOT] NULL`、`AND / OR / NOT`、`IN (<字面量列表>)`、`BETWEEN`、`COALESCE` / `NULLIF`、`CASE WHEN … THEN … ELSE … END`、`CAST(e AS 类型)`——求值语义全部由 `TYP` 内核定义（REQ-SQL-010） |
| **参数绑定** | `:name`；**类型绑定期推导**；**不做字符串插值**——参数只经参数通道 ✓ |
| **JSON 路径接口** | **函数式**：`json_get(doc, '路径')`、`json_exists(doc, '路径')`、`json_set(doc, '路径', v)`。路径语法**受限且可判定**：`键` / `.键` / `[整数]`，键为标识符或引号字符串——**无通配、无切片、无表达式**（`CFG` REQ-CFG-005）。三层 NULL 语义（缺失 / JSON null / SQL NULL）照 `CFG`。`json_set` 在存储上是**整值重编码写回**（`CFG` REQ-CFG-006——页格式不开例外）✓ |
| **向量距离接口** | 操作符：**`<->`（L2）、`<=>`（余弦）、`<#>`（负内积）**——与 pgvector 同形（`RET` §0.3 的既取形状）。**ANN 加速条件**：`ORDER BY 向量 <操作符> :参数 LIMIT k` 且列上存在**距离度量匹配**的 ANN 索引（`RET` REQ-RET-021）——度量不匹配则不走索引 ✓ |
| **表达式索引** | `CREATE INDEX` 的键可以是列，也可以是 **JSON 路径表达式**（`json_get(col, 'a.b')`）——`CFG` 的"表达式 B+Tree"由此落地 ✓ |

**工作区 DDL 的三条语义**（待冻结项 48 的落地）：

| 规则 | |
| --- | --- |
| **仅 admin** | 四个语句要求会话主体是 admin——**资格检查先于对象查找** ✗✓：普通主体发出时**在解析对象之前就拒绝**（否则"这个 id 不存在"与"它不是你的"之间的差别是一次探测） |
| **执行位置** | 在 `public` 上执行——管理元数据（`ws$`）就在那里；**不跨工作区**（全程一个事务，`REQ-ISO-005`） |
| **语义** | 三步顺序与各动作的完整性归存储架构 §2.12；**依赖顺序 `FS → WORKSPACE → USER`**（建区时**无主**，属主只在 `CREATE USER … USING WORKSPACE` 一处定——`DCL语句设计` v0.2 §0.5）；`DROP USER` 有区且无 `CASCADE` ⇒ 拒绝；`DROP FILESYSTEM` 硬前置 = 该路径下无任何数据文件 |
| **引用位** | `名 := 标识符 | Str`（两者等价）；`WorkRef := 整数 | 名`（**名字实例内唯一**——没有 `FOR USER` 限定）；`FsRef := 整数（池槽位） | 名（文件系统名）`——**路径不是引用位**（`CREATE FILESYSTEM … USING '<路径>'` 只是创建参数） |

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 清单外的构造 | **解析期拒绝**（指向 REQ-SQL-006） |
| 写 `public` / 固定表 / `asset$` | **绑定期拒绝**（REQ-SQL-003 第 5 步） |
| 普通主体执行工作区 DDL | **资格拒绝**——不查找任何对象 |
| 图名不存在 / 属性索引的图不存在 | "不存在"（REQ-GRP-013） |

#### 验收要点

- **构造**：**至少 1000 条手写确定性 SQL + 1 万条生成查询**（REQ 验收原文），
  对照**参考模型**——参考模型 = 引擎内建的**直译执行器**（逐行按语义求值、不做优化）✓。
- **预期**：结果集**逐行一致**；清单外的构造**零执行**。
- **工作区 DDL**：普通主体尝试四个语句 → 在**任何对象信息产生之前**被拒；
  名字碰撞只在同属主内（建两个同名于不同属主 → 都成功）。

### REQ-SQL-006　不提供（范围控制）

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

**复杂重写、窗口函数、子查询/CTE/递归、JIT、单查询并行与列存所需算子延后**——**延后 ≠ 永久不做**：这些是后续切片/版本的目标，本期不实现、语法上不存在入口；简单常用构造（`DISTINCT`、集合运算等）在 `REQ-SQL-005` 的正面清单内。

#### 规格

**延后与不提供的完整清单**（逐项语法上不存在 ✗✓）：

| 类别 | 不提供 |
| --- | --- |
| 查询构造 | 子查询（标量 / `IN` / `EXISTS`）、`WITH` / CTE / 递归、`RIGHT / FULL / NATURAL / USING` 连接、`INSERT…SELECT`、`UPDATE…FROM`、`RETURNING`、窗口函数 |
| DDL 面 | 视图与物化视图（待冻结项 25）、`ALTER TABLE`（含加列 / 改名）、列默认值与约束（PK / FK / CHECK）、`TRUNCATE`、序列 / 自增、`MERGE` / UPSERT、触发器 / 存储过程（V1.0 无 PL/SQL） |
| 执行与优化 | **JIT**、**单查询并行**（一条语句内的并行算子）、**列存所需算子**（向量化/批量 SIMD 执行——本系统未引入列存）、复杂重写（子查询解嵌套 / 外连接消除等——本就没有子查询）、跨语句的计划共享以外的自适应计划 |
| 会话与诊断 | `SAVEPOINT`、`SET TRANSACTION`（隔离级别固定）、`LOCK TABLE`、会话变量（`SET` / `SHOW`）、`EXPLAIN`、显式游标语句 |
| 其他 | 跨工作区的一切（含 `public` 写）、`SELECT` 的 `FOR UPDATE`（锁的获取是写路径的事） |

**每一项都不是"被检查拒绝"，而是语法上不存在** ✓——与 `GRP` REQ-GRP-006 同一纪律。

**为什么连 `ALTER TABLE` 都不给**：加列会改变行格式的**声明宽度**与既有行的读取路径，
是行格式演进问题（需要版本化行格式），**不是一条 DDL 语法** ✗——
把它当成语法来加，等于把一个存储问题藏进 SQL 层 ✓。删表重建是 V1.0 的替代路径。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 用到清单内构造 | **解析期错误**："不支持该构造"+ 指向本条 |
| 试图绕过（如自连接模拟窗口函数） | 允许 ✓——那是查询写法，不是新入口 |

#### 验收要点

- **构造**：穷举上表清单，逐条发语句。
- **预期**：**零执行**——全部解析期拒绝。

### REQ-SQL-007　优化变换保持语义

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §18

#### 语义

优化变换必须保持 **NULL、异常、外连接与类型**语义。

#### 规格

**V1.0 的变换白名单**（闭集——白名单之外的变换不做，哪怕它"显然正确" ✗✓）：

| 变换 | 约束 |
| --- | --- |
| 谓词下推 | **不得越过外连接**；不得下推到可能产生 NULL 的行集一侧（除谓词本身可证明不受 NULL 影响） |
| 常量折叠 | 折叠失败（如除以零）⇒ **绑定期错误**——把运行期异常转成早期错误是**保语义**的（同一语句无论如何都报错）✓ |
| 等值传递（连接谓词间） | 仅限 `=` 且两侧类型相同（`TYP` 内核判定） |
| 投影裁剪 | 不得裁掉可能报错、或带受管引用登记点的表达式 |
| 连接顺序 | 只在**内连接**之间重排（外连接位置固定 ✗） |
| 访问路径选择 | 全扫 / B+Tree / 表达式索引 / 图扩展 / ANN——**只影响代价，不影响结果** ✓ |

**四条不变量**（验收"开 / 关优化结果语义一致"的判据）：

| # | 不变量 |
| --- | --- |
| 1 | **NULL 三值逻辑**逐点保持 |
| 2 | **外连接不退化**——V1.0 不做外连接消除（即使谓词可证明也不做 ✗，白名单之外） |
| 3 | **类型转换点不移动**——变换不得跨越 `CAST` / 隐式转换点（REQ-SQL-010 的同一内核判它们） |
| 4 | **错误行为不变**——优化不得删除或移动"可能报错的求值"；判据：**允许出错变早，不允许出错变没、变晚** ✗✓ |

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 变换后结果不同 | **验收失败**——差分测试判据（下） |
| 变换后错误类别不同 | 同上（除"更早"这一方向） |

#### 验收要点

- **构造**：**参考直译执行器**（无优化）+ 优化引擎，同一查询各跑一遍；
  随机数据 × 生成查询（REQ-SQL-005 的 1 万条语料）。
- **预期**：结果集逐行一致；错误类别一致（允许阶段提前）。

### REQ-SQL-008　扩展路径不绕过检查

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

**图与 ANN 路径不得绕过工作区与事务检查**。

#### 规格

**"不绕过"的实现方式在 §0.2 已经给了：扩展面没有第二条执行路径** ✓✓。
本条的规格是**把检查逐一列出来，并指出它由哪一层承担**：

| 检查 | 由谁承担 | 图 / ANN 路径上怎么发生 |
| --- | --- | --- |
| **工作区** | 物理计划的**每个节点**携带 `workspace_id`；执行器断言与 `WorkspaceContext` 一致 | 图扩展节点读的是**本工作区图的段**；ANN 节点只认本工作区的索引 × generation |
| **事务与可见性** | `TableAccess`（执行器不直接改页） | 边条目 / 顶点行的可见性走 §12 的三步判定——**与普通行同一套** |
| **名字解析** | ②（REQ-SQL-003） | **图名不是工作区入口**（`GRP` REQ-GRP-013）；`GRAPH_TABLE` 的图名在会话工作区内解析 |
| **public 只读** | ② 的写目标检查 | 图语言写语句对 `public` 图同样拒绝（`GRP` REQ-GRP-011） |
| **索引有效性** | ④ 选择 + ⑤ 复核 | ANN 激活条件（generation + 水位 + 完整性清单，`RET` REQ-RET-022）**在执行前复核一次**——编译到执行之间失效则回退全扫 ✓ |

**最后一行是"两处检查"的唯一允许的重复**：不是因为不信任编译期，而是因为
**编译与执行之间隔着时间**——索引是派生物，**可以由后台重建**（`RET`）✗✓。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| `GRAPH_TABLE` 的图名指向别的区 | "不存在"（解析在会话工作区内） |
| 对 `public` 图发写语句 | 绑定期拒绝 |
| ANN 索引在执行前失效 | **回退全扫**（结果正确），不报错 ✓ |

#### 验收要点

- **构造**：跨区图名、public 写、ANN 执行前重建、边条目并发的可见性用例。
- **预期**：安全检查覆盖全部路径；**没有一条路径产出越权或陈旧数据**。

### REQ-SQL-009　计划缓存键

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

计划缓存**包含工作区、对象版本、类型版本、索引 generation 及相关配置版本**；
**版本变化后计划失效**。

#### 规格

**缓存键 = 下列各项的元组**（任何一项不匹配即未命中）：

| 成分 | 来源 |
| --- | --- |
| **工作区 ID** | `WorkspaceContext`——**首项就是隔离** ✗✓：缓存是实例级的，**命中不得跨工作区** |
| 规范化语句文本 | ① 的产物（字面量归一化后的文本） |
| **参数类型签名** | ② 推导的参数类型列表 |
| **对象版本集合** | ② 捕获的每个 `(obj#, mtime)`——`mtime` 是最后修改的提交序号（§3.1.3） |
| **类型版本** | `TYP` 内核版本标识 |
| **索引 generation / 状态** | 每个被引用索引：B+Tree 用 `(obj#, mtime, status)`；ANN 另加 **generation**（`RET` REQ-RET-022） |
| **相关配置版本** | 参与编译决策的配置项的版本号（`CFG` 的 revision 机制） |

**失效方式是"比对失败"而不是"通知"** ✗✓：
不做主动失效广播、不做依赖反转——**建索引、删索引、`Move` 致索引失效（§4.7）、
表选项修改**都落在 `mtime / status / generation` 上，**自然失配** ✓。
代价是失效的**颗粒归键**（同一对象变了，依赖它的计划一起重编译）——V1.0 的规模下正确性优先 ✓。

**与 §0.4 的呼应**：Raw AST（文本 → 语法树）**与工作区无关**，可以实例级共享；
**从 Bound Query 起的一切都进工作区键** ✓✓——两层缓存的边界与 REQ-SQL-002 的纪律是同一条线。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 缓存中的计划引用的索引已删 | 键失配 → 重编译 ✓（**不得**用陈旧计划执行） |
| 两个工作区同文本同参数 | **不共享** Bound 及之后的一切 ✓ |

#### 验收要点

- **构造**：编译并缓存 → `DROP INDEX` / 改表选项 / `Move` → 重发同一语句。
- **预期**：**计划失效并重编译**；执行不出现"引用已失效索引"类错误。

### REQ-SQL-010　类型内核统一

**优先级**：必须　**阶段**：P5　**追溯**：总体方案 §14

#### 语义

类型规则**调用统一 Oracle 兼容内核与扩展类型规范**。

#### 规格

**"统一"的判据是"同一件事只有一个实现"** ✗✓：

| 类型规则 | 唯一实现 | 由谁共用 |
| --- | --- | --- |
| 比较与排序 | `TYP` 内核比较器 | SQL 表达式、**索引键**、`ORDER BY`、JSON 取出的标量、**图属性过滤** |
| 转换（CAST / 隐式） | `TYP` 内核转换表 | 绑定期推导、表达式求值、字面量解析 |
| NULL 传播 | 内核的三值逻辑 | 全部算子 |
| NUMBER / 字符 / 时间编码 | `TYP` 的物理编码 | 页格式、索引键、聚合 |

**三条"不得"**（验收"无旁路类型处理"）：

1. 图语言的 `WHERE` 属性比较**不得**自带比较器——走内核（属性是 JSON 标量，取出来即内核类型）✓；
2. JSON 路径取出的标量比较**不得**用 JSON 文档的排序（`CFG` §0.1 已禁文档排序）✓；
3. 索引键比较**与列比较必须同一个比较器**——否则"索引查得到、扫描查不到"✓。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 内核拒绝的转换 | 绑定期拒绝（不静默有损——`TYP` 的既定点） |

#### 验收要点

- **构造**：同一值的比较在**四条路径**（SQL 列 / JSON 路径 / 图属性 / 索引键）
  上各查一次。
- **预期**：**逐点一致**；代码审查确认各路径无独立类型逻辑。

### REQ-SQL-011　外部数据访问（表值函数）

**优先级**：必须　**阶段**：P5 起　**追溯**：用户决策（2026-10-04，待冻结项 #64）；`RET` REQ-RET-028

**接口增补（2026-10-08，设计）**：新统一查询入口 `fulltext_search(索引名,查询[,选项文本])` 按索引来源区分表/JSON/配置/附件/资产包；管理走 SQL DDL。下面的跨边界无事务契约**仅针对库外资产**，不适用于库内附件和表字段。原 `file_search` 若保留只作显式索引兼容入口。现已实现的是库内附件 `attachment_grep` 字面扫描，全文仍待开发。详见[SQL 设计](../bicdb_全文与文档索引SQL设计_v0.1.md)。

SQL 面提供**访问外部数据（资产文件）的只读接口**——**表值函数**，可进 `SELECT` 参与过滤 / `JOIN` / 聚合（与"图查询作表值接口"同一手法）：

- `asset_grep(包, 模式 [, 选项])`——文件内容查找（**扫描式**）；
- `file_search(包, 查询 [, 选项])`——全文检索（**使用库外索引**）。

#### 规格

- **完整性**：用索引时守"**超集 + 回读验证 + 尾扫**"——结果精确（REQ-RET-028）；
- **跨边界只读**：读库外数据**不经事务 / 存储服务**——**不在语句的事务原子承诺内**（接口上必须可区分，`TXN` REQ-TXN-018 精神：不得让调用方误以为与页数据同一事务）；
- **权限**：与资产访问同口径（会话身份、工作区、包、过期硬拒绝）；
- **无索引**：`file_search` 返回明确错误；
- **扩展面无旁路**：函数执行经同一编译-执行管线（REQ-SQL-008）——仅"读库外"这一步跨边界；
- 具体列名 / 选项 / 上限随 REQ-RET-028 与 P0 数值。

#### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 事务中调用 | 允许——**但不承诺原子**（文档明示"跨边界只读"） |
| 访问他人 / 跨区包 | 报"不存在"（不可区分） |

#### 验收要点

- **构造**：`SELECT … FROM file_search(…) WHERE …` 与元数据 `JOIN` 各一轮；事务内调用。
- **预期**：结果精确；跨边界语义被**文档与接口同时标明**。
