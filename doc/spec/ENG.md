# 引擎模块接口（ENG）

承接总体方案 §14（SQL 引擎与模块接口）与 §15（多线程与访问协议）。**本域只定义"模块之间的接口面"**——
行为语义在各自域（`TXN` / `STO` / `SQL` / `RET` / `GRP` / `AST` / `API`），
本域定义**谁调谁、传什么、越不过什么**，并把各域既有的接口约束收拢成一份**可审查的不变量清单**。

**状态**：🚧 **进行中**（v0.4：v0.3 全部 + **资产检索与索引服务接口**〔#64，REQ-ENG-010〕；CLI·MCP 名册已成稿〔`API` REQ-API-016 / 017〕；登记收尾随后）。

## 0 模型总述

### 0.1 分层与调用图

```text
对外（协议面——语义在 API 域）
  会话（接入层认证的结果在此构成"上下文"）
    ├─ execute（SQL 与图语言——引擎内解析分派）──→ SQL 引擎
    ├─ search ────────────────────────────────→ 检索引擎（RET）
    ├─ 资产流（asset_begin / …）──────────────→ 资产引擎（AST，登记式）
    └─ sync / status / cancel（对账与取消）────→ 事务引擎（查询终态）

引擎内（本域）
  SQL 引擎（Raw AST → Binder → 逻辑 → 物理 → 执行）
    ├─→ 目录与字典（Catalog）
    ├─→ 事务引擎（begin / 快照 / 提交 / 回滚 / 锁 / 终态查询）
    ├─→ 存储服务（表访问、索引访问——含 ANN，细则在 RET）
    └─→ 图访问（GraphAccess）

共享服务（被多个引擎调用，仍属本域接口面）
  检索引擎 ──→ 存储服务（每个候选回查，REQ-RET-023）
  资产引擎 ──→ 存储服务（登记行的读写；文件本体不经此）
```

**调用只向下、同层不直调、存储不认识 SQL。**
存储服务只认行、ROWID 与索引键——不认识"SQL"这个概念；检索要读行，经存储服务，不自己去页。

**存储服务分两扇门**（REQ-ENG-003 / 004）：**库内数据（redo 承载）**——对引擎外只经统一编译-执行管线（SQL 引擎）；**外部文件（无 redo）**——可由携带**合法会话身份**的通道（CLI / MCP / 资产流）直连。

### 0.2 接口条目的共同形态

每个接口条目（REQ）给四样：

1. **操作集**：操作名 + 输入 + 输出（语义级，不含语言/类型细节——签名留实现期）；
2. **调用方**：白名单式——不在白名单的调用者为实现缺陷；
3. **契约**：可见性 / 事务归属 / 并发与锁 / 错误映射（`CONV` §4）；
4. **边界检查**（验收方式）：接口面上**不出现什么**——如"无裸页指针""无版本参数""无隔离级别参数""无身份参数"。
   边界检查以**接口面审查 + 依赖方向检查**执行，与 `STO` 域既有检查同款。

### 0.3 与各域的关系（不重复原则）

- 行为与语义在各自域（如 RC 语义在 `TXN`、页与行格式在 `STO`）；
- 本域只写**接口面**（操作 / 契约 / 纪律），引用各域条目，不复制其内容；
- 发现与需求文档 / 总体方案的不一致或缺口 → 走需求回流（`spec/README` §1）。

## REQ-ENG-001　模块分层与调用纪律

**优先级**：必须　**阶段**：P2 起（持续适用）　**追溯**：总体方案 §14、§15

### 语义

引擎内模块之间的调用**单向、分层、经公开接口**；一组横切不变量对**所有接口**成立，且**可被审查**（接口面检查 + 依赖检查）。

### 规格

**不变量清单**（收拢自各域，本域声明为"全接口成立"）：

| # | 不变量 | 出处 |
| --- | --- | --- |
| 1 | **执行器不碰页**——一切行访问经存储服务；可见性由存储服务负责 | 方案 §14（TableAccess 行） |
| 2 | **存储接口无"页"概念**——不返回裸页面指针、无版本参数、无"追加版本"语义 | `STO` REQ-STO-014 及接口检查条目 |
| 3 | **读路径不含锁**——读路径不调用锁管理器（依赖里不出现锁模块） | `TXN` REQ-TXN-005 |
| 4 | **latch 与 lock 分工**——latch 仅保护内存结构、短暂持有；持 latch 不等待事务、不做文件 I/O、不阻塞网络 | `STO` REQ-STO-007、方案 §15 |
| 5 | **解析不查目录**——Raw AST 只记语法；对象与参数解析在 Binder | `SQL` REQ-SQL-002 |
| 6 | **扩展面无旁路**——图 / ANN / JSON / 向量全汇入同一编译-执行管线，不绕过工作区与事务检查 | `SQL` REQ-SQL-008 |
| 7 | **上下文不可伪造**——WorkspaceContext（主体 / 工作区 / 配额 / 根句柄）由认证与监督器生成、业务不可修改；任何接口**不带身份 / 工作区覆盖参数** | `API` §0.2、`ISO` REQ-ISO-002 |
| 8 | **不跨工作区**——事务、锁、快照不跨工作区；`public` 只读经专门路径 | `TXN` REQ-TXN-019 |
| 9 | **错误模型统一**——所有接口的错误走 `CONV` §4（稳定错误码 + 四类判定字段）；模块不自造错误分类 | `CONV` §4 |
| 10 | **预算随请求**——deadline、取消检查、内存预算贯穿所有接口；取消后释放锁、页引用、文件与队列状态 | 方案 §15 |
| 11 | **三类存储可区分**——页数据 / 资产文件 / 派生索引在接口上必须可区分，不得让调用方误以为同一事务原子 | `TXN` REQ-TXN-018 |
| 12 | **句柄不透明**——跨接口传递的是句柄与不可变对象（事务句柄、快照句柄、计划对象）；不传递可变内部结构 | `SQL` REQ-SQL-004 |
| 13 | **接口不藏线程**——模块接口在调用方线程内完成；异步只存在于显式后台任务（写者 / 提取 / 索引构建） | 本域定（方案 §15 的细化） |
| 14 | **两扇门**——库内数据（redo 承载）对引擎外只经 SQL 引擎的统一编译-执行管线；外部文件（无 redo）可由**携带合法会话身份**的通道（CLI / MCP 等）直连；两扇门在接口上分开 | 本域定（2026-10-04 用户口径）；细则 REQ-ENG-003 / 004 |

**边界检查**（验收机制，ENG 通用）：

- **接口面检查**：第 2 / 7 条等以"接口面上不出现该物"验收；
- **依赖检查**：第 3 / 5 条以依赖方向验收（读路径依赖不含锁模块；AST 模块不 import Catalog）；
- 新增接口须声明**调用方白名单**。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 上层绕过服务层直达存储内部 | **实现缺陷**（验收判据） |
| 接口出现身份 / 工作区覆盖参数 | **实现缺陷**（同上） |
| 模块自造错误分类 | 实现缺陷；错误一律映射到 `CONV` §4 |

### 验收要点

- **构造**：审查接口清单与依赖图；对每个新接口跑白名单与边界检查。
- **预期**：不变量清单**逐条成立、零违例**。

## REQ-ENG-002　事务引擎接口

**优先级**：必须　**阶段**：P3 起　**追溯**：总体方案 §8、§14

### 语义

事务引擎向执行器（SQL / 图 / 检索 / 资产登记）提供**事务、快照、锁、提交与终态查询**的接口；
**不向调用方暴露 undo、事务表、ITL 等存储内部构造**（句柄不透明——不变量 12）。

### 规格

**操作集**：

| 操作 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `begin` | 工作区上下文 | 事务句柄 | 不跨工作区（REQ-TXN-019） |
| `snapshot` | 事务句柄 | 快照句柄 | **语句级 RC**（REQ-TXN-001）：语句开始取、语句结束释放；读路径的唯一共享点（快照注册表） |
| `commit` | 事务句柄、可选**请求标签** | 提交序号 | 次序：提交记录先入日志流 → 标记可见 → 唤醒等待者（§11.1.1 次序表）；响应晚于耐久确认（REQ-TXN-010、REQ-TXN-007/008） |
| `rollback` | 事务句柄 | — | 反向应用 undo、释放锁与快照；**断连中止 = 会话层对在途事务调用本操作**（REQ-API-014） |
| `语句回滚点` | 事务句柄 | 回滚点句柄 | 死锁牺牲者 = **语句级回滚**（REQ-TXN-003、D-03）；事务其余部分保留 |
| `lock` | 事务句柄、行标识（ROWID）或对象 | 获得 / 等待 / 牺牲 | 同一行并发写由行级排他锁串行化（REQ-TXN-002）；等待超时默认 `-1`（死等，D-04）；死锁检测阈值默认 **3 秒**（D-03）；DDL 用对象锁（REQ-TXN-016） |
| `查询终态` | **请求标签**（会话层请求序号） | 已提交（含提交序号）/ 已中止 / 未找到 | **REQ-API-014 对账的落点**：终态随提交路径持久化、按判定窗口裁剪（细则归 #63） |

**契约**：

- **可见性判定不外包**：`snapshot` 与存储服务共同决定可见行；执行器不得自行推测可见性。
- **提交与请求标签**：会话层把请求标签交给 `commit`（写事务）——"每个请求有确定终态"（REQ-API-014）在引擎内的实现方式（= PgQ"工作与确认同事务"的对应物）。
- **长快照**：快照句柄的持有封顶 undo 保留（**最老快照**规则，D-05）；undo 耗尽 → 快照过旧由存储层报出、经本接口上抛。
- **资源类边界**：事务表槽位耗尽、锁等待超时、undo 配额 → 资源类错误（`CONV` §4.3）。

**边界检查**：

- 接口**无隔离级别参数**——隔离级别固定 RC（REQ-TXN-001；`SQL` 侧"无 `SET TRANSACTION`"）；
- 接口**不出现** `undo_ptr` / 事务表槽号 / ITL 槽等内部构造；
- **读操作不带锁参数**。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 跨工作区事务 | 拒绝（REQ-TXN-019） |
| 快照过旧 | `BIC-01555`——调用方按四类判定处理 |
| 死锁牺牲 | `BIC-00060`，**语句级回滚**，事务其余部分保留 |

### 验收要点

- **构造**：并发跑"两写者同键""死锁环""长快照 + undo 耗尽"三类用例，观测接口行为与错误分类。
- **预期**：四类判定字段可区分；语句级回滚后事务仍可用；取消 / 断连路径不泄漏句柄与锁。

## REQ-ENG-003　存储服务·库内数据（redo 承载）

**优先级**：必须　**阶段**：P3 起　**追溯**：总体方案 §14（TableAccess）；用户口径（2026-10-04）：**凡写 redo 的数据访问必须经过 SQL 引擎**

### 语义

表行、索引、字典、大段值与临时空间的读写服务。**对引擎外，唯一入口是 SQL 引擎通道**（`execute`——SQL 与图语言同一通道；检索经同一管线的受控计划节点汇入）；引擎内的其他调用方（执行器、目录、事务引擎、检索回查、受控维护任务）经**同一套可见性与写入纪律**访问本服务。

**这与 REQ-SQL-008"扩展面无旁路"是同一件事的两面**——口径从查询侧推广到**数据访问侧**：不存在绕过统一编译-执行管线进入库内数据的通道。

### 规格

**操作集**：

| 操作 | 说明 |
| --- | --- |
| 表访问 `scan` / `fetch` / `insert` / `update` / `delete` | **可见性由本服务负责**（执行器不得自行推测）；`fetch` 经转发指针取行（含片段链重装） |
| 索引访问 `seek` / `range` / `insert` / `delete` | B+Tree（`STO` REQ-STO-008 / 010）；候选先回表检查可见性（REQ-STO-009） |
| ANN 查询 | 细则在 `RET`（REQ-RET-021 等）；**经同一执行管线**，不设第二通道 |
| 字典访问 | 供目录（Catalog）与名字解析——解析器自身不得绕过目录直读字典（REQ-SQL-002） |
| 大段值 | 行片段链的读写（`STO` REQ-STO-005）；对调用方表现为"大值"而非"片段" |
| 临时空间 | 排序 / 哈希 / 中间结果（配额 `quota_temp`）；生命周期挂在事务 / 会话 |

**调用方白名单**：

- **引擎外**：**仅**统一编译-执行管线（`execute`）——CLI / MCP / 适配层**不提供**任何直连库内数据的工具或命令；
- **引擎内**：执行器、目录、事务引擎、检索回查、受控维护任务（索引构建、回收、提取）。
- **协议级服务的定位**：资产登记等协议服务是**引擎内调用方**——外部只能发它的命令（`asset_begin` / `asset_end`…），**不能触达本服务**；其库内写（如 `asset$` 行，有 redo）由引擎施行、经本服务的同一纪律——与"引擎外唯一入口"不冲突。

**契约**：

- **无"页"概念**（不变量 2）：接口不出现页号、裸指针或版本参数；
- **写入次序**照 `TXN` REQ-TXN-007 / 008（先日志后数据；页持久化前 WAL 已持久化）；
- **事务归属**：一切读写挂事务句柄与快照句柄（REQ-ENG-002）——**不提供"无事务写入"**；
- **三类存储可区分**（不变量 11）：本服务承载**页数据与派生索引**；资产文件本体**不在**本服务（见 REQ-ENG-004）。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 引擎外通道直连本服务（任何形式） | **实现缺陷**——不存在该路径；验收 = CLI / MCP 工具清单审查 + 依赖检查 |
| 调用方自行推测可见性 / 触碰页 | 实现缺陷（不变量 1 / 2） |
| 临时空间超配额 | 资源类错误（`CONV` §4.3） |

### 验收要点

- **构造**：审查 CLI / MCP 工具清单与 crate 依赖图；跑"不存在的直连"负用例。
- **预期**：库内数据的通路**有且只有**统一编译-执行管线一条。

## REQ-ENG-004　存储服务·外部文件（不写 redo）

**优先级**：必须　**阶段**：P5 起　**追溯**：总体方案 §14（AssetStore）；用户口径（2026-10-04）：**外部文件访问不经 SQL 引擎，但必须携带合法会话身份**

### 语义

资产**文件本体**（字节）的存取服务。**不经过 SQL 引擎与编译-执行管线**——可由 **CLI / MCP / 资产流 / SDK 等任何通道**直接驱动；**但调用必须携带合法会话身份**（认证结果 + 工作区绑定），并**照常**受权限校验、资源配额、取消与审计约束。内容**不写 redo、不进缓冲池、不参与事务**。

### 规格

**操作集**（= 方案 §14 的 AssetStore 行 + `AST` 七步协议）：

| 操作 | 说明 |
| --- | --- |
| `upload` | **登记式**：内容先写暂存（调用方直写 / 数据帧流），校验后发布；**路径由服务端按 `asset_id` 推导**（§2.9 分层） |
| `read_range` | 按 `asset_id` + 偏移 / 长度读；只读 |
| `delete` | 文件本体删除（与 `asset$` 状态机、回收三条件联动） |
| `status` | 存在性 / 大小 / 校验和 / 介质状态（卷可用性） |

**调用方**：**任何携带合法会话身份的通道**——CLI、MCP、资产流（`API` REQ-API-003）、SDK。**没有会话身份 = 拒绝**（含 CLI 本地与 MCP 路径——MCP 身份来自启动配置绑定，REQ-API-013；会话引用纪律见 REQ-API-015）。

**契约**：

- **元数据 vs 文件本体的分界**：`asset$` 等元数据行是**库内数据**（redo、事务——走 REQ-ENG-003）；**文件字节只在本服务**——两者用登记协议衔接（内容先于名字、名字先于元数据）；
- **路径安全**：不接受任意本地路径或网络地址；根目录不经用户输入（`ISO` REQ-ISO-008）；
- **身份不豁免**：跨主体访问 → 拒绝且不可区分（`ISO` REQ-ISO-006、REQ-API-015）；到期资产 → **访问硬拒绝**（#59）；
- **预算随请求**（不变量 10）：大文件传输受 deadline / 取消 / 配额（`max_asset_bytes` 资源族）约束；取消后释放句柄与暂存残留。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 无会话身份访问（任何通道） | **拒绝**（稳定错误；不进入任何文件操作） |
| 调用方传任意路径 / URL | 拒绝（参数不存在该形态） |
| 登记前读文件内容 | 不存在该状态（内容先于元数据） |
| 文件本体被误当作事务对象 | 实现缺陷（不变量 11：三类存储可区分） |

### 验收要点

- **构造**：CLI / MCP 两条通道各跑一次上传 → 读 → 删；无身份用例；跨主体用例。
- **预期**：**不经 SQL 引擎**可完成；**无身份一律拒绝**；全程零 redo、零缓冲池进入。

## REQ-ENG-005　SQL 引擎接口

**优先级**：必须　**阶段**：P4 起（会话接入于 P5）　**追溯**：总体方案 §14、§15

### 语义

会话层经本接口驱动语句执行：**编译与执行分离**——共享计划不可变、执行状态单次新造（REQ-SQL-004）；图语言经**同一入口分派**（引擎内解析分派，不是线上第二通道）。

### 规格

**操作集**：

| 操作 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `compile`（准备） | 上下文、语句文本 | **不可变计划对象** + 结果形状（列元数据） | 五阶段前四阶（REQ-SQL-001）；图语言在此分派为受控计划节点；**参数类型在绑定期推导**（REQ-SQL-003） |
| `execute` | 计划对象、类型化参数值、**请求标签**、deadline / 取消句柄 | 行批次流 + 结束状态 | **执行状态单次新造**（REQ-SQL-004）；自动提交语义照 `SQL`（默认每条语句自成事务；`BEGIN` 起显式事务）；**请求标签透传至 `commit`**（REQ-ENG-002） |
| `cancel` | 执行句柄 | — | 释放锁、页引用、临时空间与队列状态（方案 §15） |

**契约**：

- **协议层的一次 `execute` 命令 = 计划定位（缓存，REQ-SQL-009：键含工作区、对象 / 类型版本、索引 generation、配置版本）/ 构建 + 执行**——缓存是实现细节；接口语义上"同一计划可并发执行、各自状态"；**跨工作区不共享计划**；
- **编译对象单向流动**（REQ-SQL-001 / 002）：Raw AST 只记语法（不查目录）；Binder 查目录与参数；
- **扩展面无旁路**（REQ-SQL-008）：图 / ANN / JSON / 向量全部经本接口的同一管线；
- **参数值走类型化参数通道**（REQ-API-003 的引擎内面）——引擎侧不做文本拼接；
- **预算与上限**：批量事务上限（行数 / 字节 / 时长，REQ-API-008）在本接口执行侧强制；deadline 到点走 `cancel` 路径；
- **错误**：编译错误 = 稳定错误码、不可重试；执行期错误照 `CONV` §4 四类。

**边界检查**：

- 接口**无身份 / 工作区参数**（上下文带入——不变量 7）；
- 接口**无隔离级别参数**（固定 RC）；
- **Raw AST 模块不 import 目录接口**（依赖检查）。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 执行状态跨执行复用 | 实现缺陷（REQ-SQL-004） |
| 执行中取消 | 资源释放后返回取消状态（`txn_status` 可判定） |
| 参数与绑定类型不符 | 执行前拒绝（绑定期已定类型） |

### 验收要点

- **构造**：同一计划对象并发两次执行（参数不同）；跨工作区同名表缓存用例；取消长查询。
- **预期**：执行互不污染；缓存**不串区**；取消后零残留（锁 / 页引用 / 临时空间）。

## REQ-ENG-006　目录服务接口（Catalog）

**优先级**：必须　**阶段**：P3 起　**追溯**：总体方案 §14

### 语义

对象解析与类型信息的**唯一来源**（Binder 与名字解析）；解析**只覆盖本人对象与显式 `public` 只读入口**。

### 规格

**操作集**：

| 操作 | 说明 |
| --- | --- |
| `resolve` | 名字 → 对象（表 / 列 / 索引 / 图 / 例程）；保留名与 `$` 结尾名走固定表命名空间（`SQL` 相关约束） |
| `type_descriptor` | 列与参数的类型描述子（类型内核统一，REQ-SQL-010） |
| `object_version` | 对象版本——**计划缓存键的组成部分**（REQ-SQL-009） |

**调用方**：Binder、图名字解析、DDL、管理面。

**契约**：

- **解析不得成为工作区入口**（REQ-SQL-003 / `GRP` REQ-GRP-013）——名字里的库 / 图名不是切工作区的按钮；
- **只读**：目录接口**无写操作**——对象创建 / 修改走 DDL 路径（`TXN` REQ-TXN-016：独立事务与对象锁）；
- 解析结果携带 `object_version`，供计划缓存失效判定。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 名字指向他人工作区 | 报"不存在"（`ISO` REQ-ISO-006 不可区分） |
| 解析器绕过本接口直读字典 | 实现缺陷（依赖检查——REQ-SQL-002 同款手法） |

### 验收要点

- **构造**：跨区名字、保留名、版本变更后缓存失效。
- **预期**：不可区分；`object_version` 贯穿缓存判定。

## REQ-ENG-007　检索引擎接口（Retrieval）

**优先级**：必须　**阶段**：P4 起　**追溯**：总体方案 §14

### 语义

`search` 命令与（经 SQL 管线的）ANN 查询的服务面——**不绕过工作区与事务检查**。

### 规格

**操作集**（对应 `RET` REQ-RET-006 的六项输入）：

| 操作 | 说明 |
| --- | --- |
| `text` / `vector` / `hybrid` | 三条检索路线（REQ-RET-021）；融合 = 秩融合，不合并分数（REQ-RET-007 / 008） |
| `index_watermark` | 水位（REQ-RET-015 / 016）——"到哪个提交序号已进索引" |
| ANN 查询（供 SQL 管线） | 受控计划节点；加速条件 = 距离度量匹配的 ANN 索引（`SQL` 向量接口） |

**契约**：

- **每个候选回查**（REQ-RET-023）：结果经存储服务按当前快照回查——**不可见的候选不得返回**（校验先于返回，REQ-RET-012）；
- **`public` 与私有分开执行、显式融合**（REQ-RET-011）——不存在全用户索引；
- **截断状态显式**（`GRP` REQ-GRP-009 同款纪律）：近似 / 预算导致的截断不得伪装成完整结果；
- 派生索引与源数据的一致性由（generation、水位、清单）表达（REQ-RET-022）——**不在本接口的原子承诺内**（不变量 11）。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 检索绕过回查直接返回索引内容 | 实现缺陷（REQ-RET-023 验收） |
| 跨模型混搜 | 拒绝（REQ-RET-018） |
| 近似召回越权 | 不允许——越权一律不可区分拒绝（REQ-RET-024） |

### 验收要点

- **构造**：索引落后于源数据时的检索；撤销 / 过期命中；截断场景。
- **预期**：回查把关；水位与截断显式；零越权。

## REQ-ENG-008　图访问接口（GraphAccess）

**优先级**：必须　**阶段**：P4 起　**追溯**：总体方案 §14

### 语义

图元素增删查与遍历的服务面；被 SQL 引擎（图语言计划节点）调用，与本人关系数据**同事务**。

### 规格

**操作集**：

| 操作 | 说明 |
| --- | --- |
| `create` | 顶点 / 边；**同事务校验端点存在**（`GRP` REQ-GRP-002） |
| `match` / `expand` | 受控计划节点：一跳与有限跳遍历（REQ-GRP-004 / 005）；**带上限**（REQ-GRP-008：扩展边数预算为主约束） |
| `delete` | 默认拒绝有边顶点；`detach` 显式（REQ-GRP-003） |

**契约**：

- **随附对象同事务维护**：`ref$` 登记随元素同事务（REQ-GRP-012）；**无悬空边**（REQ-GRP-002）；
- **边界显式**：预算触底返回明确截断 / 资源错误（REQ-GRP-008 / 009）；
- **隔离**：禁止跨私有工作区边；`public` 图只读（REQ-GRP-011）。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 插入边而端点不存在 | 拒绝（同事务） |
| 越预算 | 截断状态或资源错误——**不得静默** |
| 跨区图访问 | 报"不存在"（REQ-GRP-013 / `ISO` REQ-ISO-006） |

### 验收要点

- **构造**：参考邻接模型对照（匹配 / 方向 / 多边 / 端删 / 属性过滤 / 分页）；预算用例。
- **预期**：与 `GRP` 域验收一致；截断显式。

## REQ-ENG-009　资产登记服务（协议级）

**优先级**：必须　**阶段**：P5 起　**追溯**：总体方案 §14；`AST` 七步协议

### 语义

资产登记（元数据与发布）的协议级服务：外部经 **`asset_begin` / 数据帧 / `asset_end` / `asset_abort`** 驱动；文件字节走 REQ-ENG-004，元数据（`asset$` 行）走 REQ-ENG-003 纪律——**本服务是两者的衔接者**。

### 规格

- **七步协议**（`AST` REQ-AST-007）：**内容先于名字、名字先于元数据**；暂存（staging）是已提交的行；发布 = 校验 + 元数据事务；
- **幂等**：同 `idempotency_key` + 异声明 → 拒绝（REQ-AST-005）；
- **身份不豁免**：任何通道（CLI / MCP / 资产流）调用本服务都必须携带**合法会话身份**（同 REQ-ENG-004）；
- **恢复入口**：同 `(idempotency_key)` 找回 `staging` 行（REQ-AST-007 的续传）。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| `asset_end` 校验失败 | 拒绝；暂存可续传（七步可恢复） |
| 无会话身份 | 拒绝 |
| 直接 SQL 写 `asset$` | 拒绝（`SQL` 写目标检查） |

### 验收要点

- **构造**：中断续传（`asset_abort` 后重来）；同键异声明；跨通道（CLI、MCP）。
- **预期**：七步可恢复；**元数据与字节两侧的分界成立**。

## REQ-ENG-010　资产检索与索引服务接口（库外派生）

**优先级**：必须　**阶段**：P5 起　**追溯**：`RET` REQ-RET-028、`AST` REQ-AST-013

### 语义

库外侧的资产检索与索引服务接口：源文件访问适配器**不含数据库事务、不经库内存储服务**。SQL 引擎调用检索适配器；后台维护管线调用内部构建/删除操作。

**设计变更（2026-10-08，未实现）**：全文/文档索引管理统一 SQL，CLI / MCP 的相关操作包装相同 SQL，不另设命令旁路。SQL 层持久化定义、`ft_delta$` 来源变更、批量任务和发布水位；派生文件服务仍不接收库内事务句柄。字段/JSON/配置来源与库内附件通过各自原生来源适配器提供数据，不能误用本节库外资产的无事务契约。详见[SQL 设计](../bicdb_全文与文档索引SQL设计_v0.1.md)及[批量维护研究](../bicdb_JSON配置表全文索引与延迟维护研究_20261008.md)。

### 规格

**操作集**：

| 操作 | 调用方 | 说明 |
| --- | --- | --- |
| `grep`（扫描） | SQL 引擎（客户端/工具包装 SQL） | 精确且新鲜；护栏（长度 / 超时 / 结果上限） |
| `search`（按包索引） | SQL 引擎（客户端/工具包装 SQL） | 水位显式；strict 超集 + 验证 + 尾扫，显式 eventual 报告滞后 |
| `index_build` / `index_drop` / `index_status` | **SQL 管理层 / 后台维护管线** | 内部操作由 SQL 生命周期驱动；构建/合并在后台 |

**契约**：

- **跨边界只读**：接口**不接受事务 / 快照句柄**（边界检查：参数表里没有事务构造）；结果**不在事务原子承诺内**；
- **身份不豁免**：调用必须携带合法会话身份与工作区（同 REQ-ENG-004 的纪律）；
- **回查**：结果返回前校验资产现存 / 未过期 / 属主（REQ-RET-028）；
- 索引体的读写在派生服务内完成——**无 redo、不进缓冲池**（不变量 2 / 11 的精神）；SQL 层的定义/任务/指针为原生持久元数据，不受此豁免。

### 边界与错误

| 情形 | 行为 |
| --- | --- |
| 调用侧传事务句柄 / 快照 | **不存在该参数**（边界检查） |
| 构建中查询 | 水位显式（覆盖内走索引 + 尾扫） |

### 验收要点

- **构造**：三路调用各跑一轮；向接口注入事务语义的试探用例。
- **预期**：接口面**无事务构造**；结果与 REQ-RET-028 的完整性纪律一致。
