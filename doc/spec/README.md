## 1 本目录的作用

需求文档回答"必须做到什么"，本目录回答"**精确到什么程度才不会设计歧义**"。

每条 REQ 在本目录展开为：精确语义 → 规格细节 → 边界与错误 → 验收要点。

**约束**：本目录不得引入需求文档中不存在的新需求。若细化时发现需求缺失或矛盾，回流到需求文档并走变更控制（需求文档 §9）。

## 3 规格条目格式

每个域文件按如下模板展开。**不要求每条都填满所有小节**——无内容的节应省略，而非写"无"。

```markdown
### REQ-XXX-000　标题

**优先级**：必须　**阶段**：P<N>　**追溯**：总体方案 §N

#### 语义
精确、可判定的行为描述。避免"合理""适当"这类不可判定表述。

#### 规格
- 具体字段、类型、取值范围、默认值
- 处理顺序（有顺序要求时逐步列出）
- 与其他 REQ 的依赖与交互

#### 边界与错误
| 情形 | 行为 | 错误码 |
| --- | --- | --- |

#### 验收要点
- **构造**：前置状态与输入
- **注入**：如何触发（正常路径 / 故障注入）
- **预期**：可判定结果
```

## 5 未决数值的统一处理

需求文档 §8 列出 10 项 P0 冻结项。本目录的处理方式：

- **能技术推导的**（如错误码方案、游标有效期、批量上限）：正文给出**推荐值**，并在待确认表登记备选。可直接按推荐值设计，确认后视为冻结。
- **必须由业务决定的**（如 Recall@10 目标、性能基准机规格、资源默认额度）：正文**标为「P0 待冻结」**，不填数值，设计中不得依赖具体数字。
