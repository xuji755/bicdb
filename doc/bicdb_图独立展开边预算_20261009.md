# 图独立展开边预算（2026-10-09）

已有 `max_expansions` 同时计表达式、展开和部分 provider 工作，不能单独控制遍历边数。本阶段新增独立 `max_edge_expansions`，保留原工作预算，并使同一 SQL 的多个 GRAPH_TABLE 来源共用工作区边预算。超限是资源错误，整条语句不返回部分结果。

## 配置与 SQL

```ini
[graph]
max_edge_expansions=100000
```

范围 `0..100000`，默认 `100000`，重启生效。配置文件、`-c graph.max_edge_expansions=...`、受信任 Session 政策使用同一范围；STATUS 显示 `graph_max_edge_expansions`。0 允许节点点查、纯表达式和无边的查询，拒绝需要检查非空邻接候选的操作。

```sql
PROFILE CYPHER kg 'MATCH (a:Hub)-[:LINK]->(b) RETURN b.name'
  BUDGETS '{"max_edge_expansions":1000}';

SELECT g.name FROM GRAPH_TABLE(kg, :query BUDGETS :budgets
  COLUMNS (name VARCHAR2(128))) g;
```

请求只可降低工作区值。未知键、非整数、负数、超过工作区上限的值明确拒绝。该参数不影响节点或边语料总数；`max_edges` 仍约束持久化图的规模。

## 计数单位

- 遍历从一个端点获取方向和关系类型限定的邻接候选，每个不同候选边 ID 扣一。类型条件可由原生访问路径提前限定，不要求为使用类型索引的查询读取整个端点的所有类型。
- 原生候选先按 ID 去重、计数，再读取边记录和复核方向、类型、端点。陈旧候选/不存在的 ID 也计入；超宽候选集在实体读取前失败。
- 内存遍历计所选择类型和方向的邻接候选。属性过滤、终点标签过滤、路径中已经使用的边等后续残余检查不会免除计数。未使用索引与含陈旧键的原生访问可能得到不同的实际计数，这是访问路径工作量差异。
- 同一候选在另一条路径、另一输入行或另一子查询中再次被访问，再次扣一；实体缓存不免除访问费用。自环在一次无向邻接获取中按一个 ID 计，平行边保留各自身份。
- CALL、EXISTS、UNION 分支以及 shortestPath 的有界候选遍历共用同一 Runner 计数，不可重置。独立 `Graph::shortest_path` BFS API 也检查此上限，在 visited 过滤前扣除所检查的候选。
- DETACH 按实际端点 incidence 扫描计数，与去重后的 `detach_edge_limit` 分开。自环的入、出两条 incidence 各计一次，共享端点也会重复计扫到的边；不同删除子句累计使用同一预算。
- 属性索引读取、全文候选/源校验、实体点取和表达式计算仍有原工作/字节预算；本参数不替代这些预算，也不是所有物理 B-tree 条目读取总计数。

## GRAPH_TABLE 与诊断

一条 SQL 计划中的图来源，包括联接和 set-operation 分支，依次从共享工作区边余额扣除成功来源的实际计数。每个来源的执行上限是其请求上限与剩余余额中的较小值。请求的合法性仍对照工作区政策，先验证再收紧；不能通过增加来源或重新指定 BUDGETS 放大总预算。

所有来源只允许只读 Cypher。若后续来源超限，整个 SQL 拒绝结果；INSERT SELECT 在写入前进行图来源物化，失败不会写入部分行。共享余额只在该次物化中存在，下一条 SQL 获得完整预算。

PROFILE 追加 `edge_expansions` 与 `work_units`，旧字段顺序保留。两列均为整条 Cypher 计数，在每个访问路径行重复展示，不能把不同 PROFILE 行相加作为查询总量。`work_units` 展示 Runner 的原混合工作计数，原生 reader 的物理读取仍由既有路径指标显示。

失败的图写语句不发布其暂存图、属性索引或全文 journal 变更，外层显式事务此前成功的 SQL 保持。ID 预留仍允许留下耐久跳号；已有旧格式索引准备不作为业务内容提交。本阶段不更改持久化图格式、全文格式或后台维护节奏。
