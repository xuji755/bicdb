# 图全局统计与快照版本（2026-10-09）

本阶段为后续按需写入补齐可信全图预算和快照身份。当前 SQL 写入仍完整加载、验证源图；不能据此宣称已经实现局部加载写入或并发 MERGE 锁。

## 持久格式

保留 `BICGRV3\0` 标识和原有路由、ID 水位及节点/边计数。读取端同时接受原 124 字节头与扩展的 148 字节头，其他长度拒绝。扩展头在原计数之后保存三个大端 u64：

| 偏移 | 字段 | 含义 |
| --- | --- | --- |
| 92 | logical_bytes | 使用存储头的 ID 水位、规范 JSON 序列化的完整图长度 |
| 100 | record_bytes | 完整原生规划语料：逻辑 v2 manifest、节点记录/校验和、规范边记录逻辑大小/校验和；不包含全文或辅助索引行 |
| 108 | generation | 大于零的已发布原生权威版本 |
| 116 | SHA-256 | 校验前 116 字节，包括统计与版本 |

旧头的 SHA-256 仍从偏移 92 开始。读旧格式不改写；新图、显式迁移和重建生成扩展头。旧原生图首次实际写入初始化版本 1。已测量头实际内容或存储水位变化递增版本；边属性更新即便计数和 ID 水位不变，也必须递增。净空操作没有版本增量。物理路由重建递增版本，即使逻辑图内容不变。版本耗尽原子拒绝，不回绕。

新程序兼容读取旧头。仅认识 124 字节头的旧程序不能读取新头；不要把运行程序回退到旧版。物理邻接布局及 SQL 查询列没有变化。

## 验证和预算

完整加载时用已验证实体重测规范 JSON 字节数，与头的 logical_bytes 核对；record_bytes 与规划 image 的完整标量字节数核对。两者不一致拒绝源写入，且不修改任何行。头的校验和不替代源内容验证，也不提供恶意外部修改的真实性保证。

原生记录 patch 在预检时使用经过检查的加减法计算完整最终 record_bytes，防止下溢/溢出，并继续执行全图预算。边只保留独立拓扑计划及标量大小；不能以空 heap patch 判断整条语句没有边更新。原生边仍不产生第二套旧 kind-2 记录。

全图统计不会直接占用小预算点读请求的字节余额；完整加载和写入仍按其请求预算验证实际数据。节点历史记录无需被重编码成规范格式才能读取；原生语料字节与规范逻辑 JSON 字节分别计算。

模板逻辑导出会对齐单独保留的数据库序列水位，因此其 JSON 长度可能与头的 logical_bytes 相差 ID 位数。统计描述的是存储快照，不替换序列分配器，也不与全文 source_seq 混为一谈。
