# 服务与客户端（`bicdb start|stop` + `bicdbcli`）v0.1

- **日期**：2026-10-06
- **范围**：实例独占锁、后台服务的生命周期命令、过渡控制协议、SQL\*Plus 形态客户端。
- **取法**：生命周期照 **PG `pg_ctl`**（`start/stop/status/restart`、`-D` 数据目录、
  `-l` 日志、`-w` 等就绪、`-m fast|immediate`）；会话形态照 **Oracle SQL\*Plus**
  （缓冲 + 行号续行 + `/` 重跑 + 斜杠命令 + `SPOOL` + `@脚本` + `DESCRIBE` 版面）。
- **零 unsafe**：不用 `fork(2)`/`setsid(2)`/`kill(2)`——分离用
  `Command::process_group(0)`（新进程组，终端关闭不带走服务），停止走
  **控制套接字**而不是信号（服务自己收尾）。

## 0.5 文件面（按 `docs/storage/02-工作区存储布局.md` §2.1 的布局）

```text
<db_root>/                      根区目录（参数文件注册它）
├── bicdb.ini                   实例参数文件（实例的入口）
├── bicdb.pid / bicdb.sock      实例锁 / 控制套接字（运行期，随服务退出清理）
├── bicdb.log                   服务日志
├── control/control01.ctl       控制文件双副本（恢复锚点）
│         control02.ctl
├── wal/redo_g<组>_m<成员>       日志组 × 成员（组数/成员数由 [init] 定）
└── data/<ws>_meta              file 0（数据字典）   <ws> = 工作区标识（V1.0 = bicdb001）
       <ws>_undo              file 1（撤销）
       （后续数据文件 <ws>_data_NN）
```

**2026-10-06 对齐**：CLI 原先是平铺（`file0.dat`/`undo.dat`/`cf_a`/`cf_b` 直接躺在根区），
与冻结设计的 `<工作区根>/{control,wal,data}` 布局不符——本次按设计改成
`control/control01.ctl`、`data/<ws>_meta`、`data/<ws>_undo`（WAL 目录本就同规）。
**单工作区 CLI 不引入**设计里的文件系统池（§2.8）与多数据文件分布：`db_root` 是一个本地目录，
数据文件命名规则与设计一致，扩展时不需要改名字。

**面向使用者的完整说明见 [`docs/使用手册.md`](../docs/使用手册.md)**（本详设只讲实现与取舍）。

## 1 单写者纪律：实例锁（`crates/cli/src/lock.rs`）

```text
<dir>/bicdb.pid   pid │ 进程启动时刻 │ 模式(direct|service) │ 套接字路径 │ 版本
```

**为什么必须有**：V1.0 每工作区的写者是**一个**（缓冲池、undo、日志全是单写者
语义）。服务在后台跑着的时候另一个进程再把同一实例开起来——两个写者各写各的
池与日志，不是并发，是**互相破坏**。

**判活（照 PG 的三件套简化版）**：pid 存在 ∧ `/proc/<pid>/stat` 的 `starttime`
与记录一致 ⇒ 活；否则**陈旧锁**，打开路径自动清理接管（`kill -9` 之后能起来，
不需要人工删文件）。

**取锁点**：`create_instance` / `open_instance` 都取 `Direct`；守护进程取
`Service`（先取锁再打开实例——反过来会有一段"打开了但没上锁"的窗口）。

## 1.5 参数文件与实例寻址（`<db_root>/bicdb.ini`）

**口径（照 Oracle，不照"启动指向某个目录"）**：

```text
根区目录（db_root）   ← 实例的全部文件都在它下面；由参数文件**注册**（权威）
<db_root>/bicdb.ini   ← 参数文件；`bicdb init` 生成（含全部默认值）
```

| 命令 | 接受什么 | 说明 |
| --- | --- | --- |
| `bicdb init <根区目录>` | **唯一**接受目录的命令 | "指向文件系统"那一步：建库 + **生成默认参数文件** |
| `start`/`stop`/`status`/`restart`/`params`/`sql`/`shell` | `-p <参数文件\|根区目录>` | **不指向目录**——实例在哪儿由参数文件说 |
| `bicdbcli` | `-p <参数文件\|根区目录>` | 同上 |

**寻址顺序**：`-p <路径>` > 环境变量 `BICDB_INI` > 当前目录的 `./bicdb.ini`；
都没有 ⇒ 报错并把试过的位置列出来（对比：Oracle 靠 `ORACLE_SID`、PG 靠 `PGDATA`）。

**参数文件形态**（INI；`#`/`;` 注释；未知节/未知键**具名拒绝**）：

```ini
[instance]
db_root = /data/bicdb        # 根区目录（本文件即 <db_root>/bicdb.ini）

[init]                       # 建区期参数：`init` 读它造库；**建区后不可改**
file0_initial_blocks = 4096
undo_initial_blocks  = 512
wal_groups           = 2     # 日志组数（2–8）
wal_members          = 1     # 每组成员数（1–8）
wal_group_pages      = 8192  # 每组成员页数（512 B/页）

[buffer]   pool_frames = 256                # 缓冲池帧数（16 KiB/帧）
[storage]  file_extend_blocks = 512         # 段增长撞文件尾时的固定增量（块）
[service]  socket = bicdb.sock   log = bicdb.log
[lock]     park_ms = 50          deadlock_threshold_ms = 1000
```

**四条纪律**：

1. **关键参数不硬编码**：建区期与运行期都由文件给；`bicdb init -c init.wal_groups=4
   -c init.wal_members=2` 直接按参数造库（程序里只留"没有文件时"的默认值）；
2. **建区期参数建区后不可改**：控制文件是权威，`bicdb start` **逐项核对**
   （组数/成员数），不符即拒绝并说明"改需重建"——实测把 `wal_groups` 从 4 改成 2
   之后启动报 `wal_groups：参数文件 2，控制文件 4`；
3. **优先级**：命令行 `-c 节.键=值`（也接受唯一键名）> 参数文件 > 内置默认；
   `bicdb params` 打印**全部可调项**（取值 + 来源 + 建区期/运行期类别）；
4. **每项都有落点**（收下不生效就是空壳）：`pool_frames`→缓冲池；
   `file_extend_blocks`→`storage::segment`；`socket`/`log`→服务；
   `park_ms`/`deadlock_threshold_ms`→`WaitPolicy`；`[init]` 五项→建区。

**不核对的项（记档）**：`wal_group_pages` 只作建区输入——日志成员文件是**懒增长**的
（用到哪写到哪），文件长度不是组容量（实测新库 g1 只写了 31 页、g2 还是建时满长），
拿它推断会误报；`*_initial_blocks` 同理（建区后由自动扩展接管）。

**启动失败的诊断**：守护进程的 stderr 落日志；`bicdb start` 发现子进程早夭时
**把日志尾三行带进错误**（不必让用户自己去翻文件）。

## 2 服务生命周期（`crates/cli/src/service.rs`）

```bash
bicdb start   <dir> [-s 套接字] [-l 日志] [-w 秒]     # 分离进程 + 等就绪
bicdb stop    <dir> [-m fast|immediate]
bicdb status  <dir>
bicdb restart <dir>
```

| 事 | 落法 |
| --- | --- |
| 分离 | `start` 用 `std::env::current_exe()` 起 `__daemon` 子进程：`process_group(0)`（新进程组）+ stdin 空 + stdout/stderr 落日志 |
| 与父进程的关系 | `start` **等就绪**（轮询套接字的 `STATUS`，`-w` 默认 30 s；子进程早夭立即报错），就绪后才返回 |
| 日志 | 默认 `<dir>/bicdb.log`（PG `-l` / Oracle alert log 的简化）；启动/恢复/收尾各记一条 |
| 打开 | 就是 `open_instance` 的那条链：**三阶段恢复** → 建池 → 接客 |
| 停止 | 经套接字发 `SHUTDOWN fast|immediate`：`fast` 先做**完全检查点**再退；`immediate` 直接退（**下次打开走崩溃恢复**——提交记录在日志里，不丢） |
| 收尾 | 删套接字、删 pid 文件、日志记"服务已退出" |
| 崩溃 | 被 `kill -9` ⇒ pid 文件变陈旧；下次 `start`/直连自动接管（有 e2e 用例） |

**不做**（记档）：不做守护进程的双 fork、不做多实例注册表、不做 `pg_ctl reload`
（配置重载——bicdb 还没有可重载的配置面）。

## 3 控制协议（`crates/cli/src/wire.rs`，**过渡形态**）

```text
请求： VERB \n <载荷字节数> \n <载荷>
应答： OK|ERR \n <载荷字节数> \n <载荷>
动词： HELLO | STATUS | SQL | DESCRIBE | SHUTDOWN <fast|immediate>
```

**记档（重要）**：设计里的对外协议是 `bicdb-net` 的**版本化请求协议**
（封套/终态/ACK 对账，REQ-API-*），那是独立切片。本协议只是**本机服务模式**
的过渡形态：长度前缀 + 文本载荷，够 `bicdbcli`、`bicdb start|stop|status` 用，
**不声称与设计协议同形**；`bicdb-net` 落地即替换（届时本协议只剩"控制面"）。

**连接 = 会话**：服务端**一个连接一个 `Session`**——`BEGIN … COMMIT` 跨该连接的
多条语句成立（SQL\*Plus 一句一发，事务语义必须绑连接而不是绑单条语句）。

## 4 客户端 `bicdbcli`（`crates/sqlplus/`）

```bash
bicdbcli [选项] <实例目录> [@脚本]
  -S            静默（不出横幅与提示符——SQL*Plus 同一开关的语义）
  --direct      强制直连
```

**连接选路**：服务在跑 ⇒ 经套接字；没人占 ⇒ 直连；**别人直连着 ⇒ 拒绝**。

**SQL\*Plus 的招牌行为（已实现）**：

| 行为 | 落法 |
| --- | --- |
| 多行输入 + 行号续行 | 续行提示符 = 缓冲行号（`  2  `、`  3  `） |
| `;` 执行、**空行结束输入不执行** | 缓冲状态机（`filling`） |
| **`/` 重跑当前缓冲** | 执行后缓冲**保留**；`RUN` 先列后跑 |
| 缓冲编辑 | `LIST(L)` / `DEL` / `APPEND(A)` / `INPUT(I)` / `CHANGE(C)` / `CLEAR BUFFER`（全按**行号**） |
| 会话参数 | `SET` / `SHOW`：`ECHO` `FEEDBACK` `TIMING` `PAGESIZE` `LINESIZE` `NULL` `TERMOUT` `SQLPROMPT` `VERIFY` `CONCAT` `WHENEVER SQLERROR` |
| 假脱机 | `SPOOL <文件|OFF|OUT>`；`SET TERMOUT OFF` 时屏幕安静、**文件照收** |
| 脚本 | `START <文件>` / `@<文件>` / `@@<文件>`（相对当前脚本目录）；`WHENEVER SQLERROR EXIT` 生效时脚本中断 ⇒ 退出码 1 |
| 替换变量 | `DEFINE 名=值` / `UNDEFINE` / `&名`（`&&名` 记住） |
| 版面 | 表头 + 虚线、**数值列右对齐**、`PAGESIZE` 翻页重打表头、`N rows selected.`、`Elapsed: 00:00:00.01` |
| 对象 | `DESCRIBE(DESC) <对象>`：`Name / Null? / Type` 版面（直连与经服务同版面） |
| 其它 | `PROMPT` / `REM` / `HOST`(`!`) / `TIMING` / `HELP [主题]` / `EXIT|QUIT [码]` |

**明确不做的**（都记档）：`CONNECT`（连接由启动参数决定）、`ACCEPT`、`COLUMN`
格式化、`BREAK`/`COMPUTE`、`COPY`、`SET ARRAYSIZE`（我们没有批量游标面）、
`EDIT`（需要外部编辑器与临时文件协议）。

| 用例 | 钉什么 |
| --- | --- |
| `crates/cli/tests/service.rs`（4 例） | start/status/stop/restart 全链；第二个 start 被拒；`immediate` 停后重开**恢复 20 行**；陈旧锁被接管；服务在跑时直连被拒 |

| `crates/sqlplus/src/*`（10 单测） | 分号判定（含行尾注释）、`CHANGE` 分隔符、`LIST` 范围、行编辑、`SET`/`SHOW`、数值右对齐、`PAGESIZE` 收窄、`Elapsed` 格式 |

**顺带修掉**：词法器原先只认 ASCII 标识符 ⇒ `CREATE TABLE t (名称 VARCHAR2(8))`
报"无法识别的字符"。照 PG（`scanner.l` 把 ≥ 0x80 的字节当字母）改为接受非 ASCII
标识符，未引号名仍只做 ASCII 折叠。
