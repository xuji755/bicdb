# 图全文自动索引选择（2026-10-09）

`bicdb.searchNodes` 支持 `indexes:"auto"`：从当前图的可见原生全文索引定义中，为每个请求字段选择具备完整覆盖的节点索引，逐字段查询并按字段顺序轮转去重。既有显式索引列表和无索引子串扫描保持兼容。本阶段没有连接或修改 Neo4j。

```sql
CYPHER kg 'CALL bicdb.searchNodes("buffer pool",{
  db_type:"mariadb", indexes:"auto", fields:["name","summary"],
  labels:["Entity","Knowledge"], consistency:"eventual", limit:20
}) YIELD node,rank,mode RETURN node.name,rank,mode';
```

## 覆盖规则

1. 只选择当前图拥有、在语句快照可见的节点全文索引；关系索引以及其他图、其他工作区的索引不能补足覆盖。
2. 索引必须包含当前字段的完整规范路径名称，例如 name、config.question、config.answers[0]。路径名称沿用已有全文 Definition 编码，不能把带点的单个键混同于嵌套路径。
3. 无 labels 或空 labels 时，必须使用不限制标签的索引；不能因当前数据碰巧都带某个标签就推断未来覆盖。
4. labels 是 OR 范围。有标签限制的索引也采用 OR，因此其标签集合必须包含所有请求标签；只覆盖其中一个标签的索引不够。无限制标签的索引始终可覆盖。
5. 多个安全候选优先字段数量少的索引，其次按字节序选择名称，使结果不依赖目录枚举顺序。该规则不是基于统计估算的成本优化，也不按发布时间挑选最新索引。
6. 先解析全部字段的计划，再运行任一全文查询。只要一个字段没有完整覆盖就明确报错；不会静默省掉字段、返回部分结果或改用不同匹配语义的扫描。

fields 应为 1–16 个不重复非空字段名。省略时采用 name、title、summary、search_text 四个默认字段，仍需全部有覆盖；显式空列表拒绝。只希望检索 name/summary 时应明确给出这两个字段。其余 domain、labels、channel、consistency、limit 验证及预算沿用[多索引融合](bicdb_图多索引排名融合_20261009.md)。

自动选择按字段产生查询，每一路只请求该字段。即使多个字段使用同一个多字段索引，也保留独立排名和字段顺序；因此不同于将所有字段交给单个索引生成综合分数。字段顺序改变会改变轮转顺序，交叉命中只返回一次。每路过滤域/标签和源修订后才截取 limit。

## 一致性和诊断

默认 strict 使用当前源建立完整视图，eventual 使用选中索引的已发布倒排并过滤陈旧源。自动选用暂停或未维护的索引不会改变其 eventual 语义，新内容可能缺失。要求当前完整结果时使用 strict；需要水位/complete 时使用命名全文过程。

同一语句已经写入时使用暂存图严格视图；计划失败和后续执行失败都不能提交部分源变化。每次重新从当前语句可见定义规划，DROP 后会选择其他具备覆盖的索引，不缓存过期的名称。PUBLIC 具名用户可只读检索，写入仍受原权限约束。

元数据枚举和全部全文调用共享原生语句工作预算；枚举计费为一次调用加返回定义数量。PROFILE 新增 FULLTEXT_PLAN / <auto> 记录，其 entries_read 为本次可见全文定义数，不能解释成 posting 读取；后续每个真正选中索引的 FULLTEXT_BTREE / strict_scan 记录显示实际访问。缓存节点数仍不是全源/冷语料总读取成本。

## 验证和边界

验证字段顺序和逆序、少字段优先与名称稳定选择、JSON 路径、OR 标签全部覆盖、无标签全域、跨图拒绝、缺少字段先于任何检索失败、失败源回滚、暂存写入、DROP 重规划、重启、PUBLIC 只读，以及 PROFILE 的计划和选择结果。

这是原生索引路由，不是 Neo4j 兼容承诺。大规模成本规划、仅命中文档读取、固定目标 WAIT、GRAPH_TABLE、模板、受管引用和回收仍待后续完成。证据见[自动索引选择验证](evidence/bicdb-graph-auto-fulltext-20261009/README.md)。
