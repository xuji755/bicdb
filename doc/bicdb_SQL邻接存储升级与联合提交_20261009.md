## SQL 与兼容行为

```sql
ALTER GRAPH kg UPGRADE STORAGE;

CYPHER kg 'MATCH (a)-[r]->(b) RETURN id(r),a.name,b.name';
PROFILE CYPHER kg 'MATCH (a)-[r]->(b) RETURN r.name';

ALTER GRAPH kg REBUILD ACCESS;
```

升级是写操作，必须在用户事务之外执行。PUBLIC 的普通主体不能升级共享图；私有区主体沿用原有结构写权限。只读查询不会迁移，也不会创建物理路由。再次升级已经是 v3 的有效图返回其当前版本，不重复填充。

升级前完整核验原图，必要时补齐旧 ordinal/访问索引。旧版缺少的这些派生索引可在预备 DDL 中建立；不能据此宣称所有预备元数据都由最终迁移事务撤销。四个物理伴随对象、节点记录转换、边填充、旧拓扑删除及 v3 标记在最终同一个 DDL 事务中发布或撤销。失败保留原图数据与原版本，未发布的四个物理路由撤销。

已有空的非活动物理路由集合目前不自动接管，升级报错；须后续实现受验证的接管/重建协议。不要手动写入受保护图表或通过删索引强行修复。源图格式损坏、端点缺失、重复身份、预算/时间超限也会拒绝升级。

v3 不在 heap 中保留 kind-2 边拓扑。节点仍为 kind-1 校验记录；kind-3 为边的页外属性，kind-4 为源入口元数据。完整加载拒绝 v3 heap 中混入 kind-2 或未知种类。物理边保存实际端点 ROWID，定位/入边候选最终回查同快照的端点、逻辑身份及完整关系类型。

## 版本标记与读取

`crates/sql/src/graph_manifest.rs` 定义固定 124 字节的 `BICGRV3\0` manifest：工作区、文件号、记录堆/ordinal 树与四个物理路由的对象号和段地址、分配器水位、节点/边数量，以及 SHA-256。

固定长度避免计数增长引发根行转发。由旧标记增长到新标记时，普通原生记录写入保留旧入口、删除旧行并追加新行；候选索引项保留，旧快照仍能读取旧标记。读取校验标记长度/校验和、身份/数量限制、路由无别名及目录归属；有效载荷哈希并不能证明路由属于本图。

读取使用标记中冻结的地址；不因后续目录段地址变化自动跟随新的路由。实际物理段也核验类型、对象、dataobj、工作区和 ROWID 范围。目录校验核对相应快照的对象与索引种类/描述，不用另一图中同数字 ID 的实体代替端点。

按需图读取不再查询旧 OUT/IN 逻辑 ID 树，而通过原生邻接出边、反向树入边和稳定定位树加载边。同一请求缓存已经解码的边，避免在发现邻接候选后重复读取其页外属性。PROFILE 使用 `ADJACENCY_NATIVE` 标识该路径。

完整写入/严格全文等需要完整图验证的入口，读取节点记录和各源的真实邻接，再构建仅供现有逻辑变更规划使用的 v2 形式投影。投影中的 kind-2 数据不能写回 v3；不能把它当作第二份拓扑权威。

## 联合提交与长事务

已有 SQL 提交路径统一编排节点行、原生边增删改、版本标记、节点目录/属性索引和全文源事件。自动提交失败回滚整个事务；显式事务失败撤销本语句，保留此前成功语句。原生数据口自己不提交，不调用嵌套 SQL 或嵌套 engine。

删除先撤销相关边，再删除节点锚点；新节点先写入，再插入新边。边属性更新保留逻辑 ID、类型、端点和稳定目录 ROWID，内联增长放不下时采用页外描述符。节点锚点为固定大小校验行，属性块增长不移动锚点。节点 Move 的一般协议仍未完成。

普通 v3 CYPHER 写入复用已验证的 before/after 图规划物理边操作，不为了本阶段接线额外完整加载并重编码一次图。现有执行器仍有整图验证/暂存，不宣称已完成局部增量写入规划。

长原生记录写入在 heap put/remove 和边增删改处使用现有 `checkpoint_safe_point`，支持活动事务日志组切换，不放宽 WAL/undo 耐久纪律。大于 8 MiB 的模板恢复回归曾检出缺失此检查点，修复及最终重跑日志保留在本阶段证据中；失败日志不计为通过。

同一大模板回归随后检出另一个内核问题：数据页写入能自动扩展文件，创建新段的 DDL 规划却不能。在 `Segment::plan_create` 和段增长入口共用扩展规划后，新段遵守 autoextend 设置，并继续使用当前事务的位图镜像，不能复用尚未落盘但已经占用的区。新增内核用例覆盖连续待提交分配跨文件尾的情况；大模板原有大小和断言保持不变。

原生数据口在一次事务上下文中复用 `TableAccess`，保留 heap 插入位置提示，避免每条节点/大属性记录从段头重新寻找空闲页。该优化减少重复扫描，不改变记录归属、回滚和旧快照规则；本阶段没有统一大型知识库性能结论。

图/正文工作、候选、目录和载荷预算及协作式时钟沿用工作区上限。当前载荷计账仍不等同于实际 RSS 或完整执行器内存计账；单次 I/O 与 COMMIT 不可抢占。旧行/候选项继续保留供 CR，尚未提供回收。
