# SQL 邻接事务适配（2026-10-09）

本阶段实现 `sql::graph_adjacency::NativeAdjacency` 原生数据口：在已经建立的图所属邻接段和三棵物理树中读写真实边，并在原图受保护堆中维护入口元数据和页外属性。它使用普通 engine、heap、undo、WAL 和目录路由；不启动独立事务，不访问外部数据库。

**普通 CYPHER 当前仍使用 v2。** 这是 SQL 执行器后续接入的数据口，尚未发布 v3 manifest，未迁移用户图。完整目标继续按[验收清单](bicdb_图增强验收清单_20261009.md)追踪，不能把以下原生数据口测试说成 SQL 存储切换已经完成。

隔离数据口用例直接操作原始事务并单独验证物理数据，未将这些测试夹具声明为可供普通 SQL 使用的已迁移图。生产接入时，不能在仍为 v2 的标记下提交 kind-3/4 行；填充数据与 v3 标记必须一起提交或撤销。普通 v2 图的兼容性另由完整 SQL/原生服务回归验证。

## 记录与图归属

`GraphRecords::resolve` 按图身份解析原图的受保护堆及唯一 ordinal B-tree；普通 ordinal 索引列号为 1，与物理伴随树的内部列描述不同。数据口绑定固定对象号和段地址，验证堆/树/邻接段的类型、对象、dataobj、工作区和 ROWID 所属范围，拒绝重叠路由。

顶点锚点是本图 kind-1 校验和行：核对 ordinal、32 字节载荷和稳定入口。逻辑节点属性的完整校验仍属于图执行器的节点加载/完整写入验证。转发后的锚点当前明确报错，节点 Move 协议尚未完成。不能用另一个图中相同的数字 ID 直接提供物理端点。

源树指向本图普通 heap 中的固定 32 字节 `SourceEntry`，记录头/尾页和历史最大边 ID。入口、边页和页外数据使用同一个 `ReadView`。出边校验链尾和 ID 水位；入边通过覆盖键回表核对完整类型和两端；定位树指向实际稳定边 ROWID。长类型哈希仅是候选。测试另外构造一个 codec/hash 完全有效、物理目标却属于其他图的边，原生读取必须拒绝它。

## 写入及撤销

调用方提供最新 engine 序号和自身事务视图，必须持有图写串行化直至发布。插入先解析端点、取得有序行锁，再读取源入口；在同一原始事务中写邻接边、页外块、入口、ordinal 索引、源树、定位树和反向树。逻辑 ID 必须先通过已有图序列预留，不复用失败或删除的身份。

属性更新保持边 ID、类型、端点和目录 ROWID。内联增长在既有页放不下时，改用外部描述符；测试先填满真实页，证明小于 4096 字节的文档也会外部化，同时保持定位。页外行增长采用删除旧行、追加新行及候选索引项，避免通过当前转发地址丢失旧快照入口。等长/收缩可就地 undo 更新。

删除撤销记录和页外行；索引候选和目录序号保留，旧快照仍可取旧值，当前读取不暴露删除的数据。这不是旧段或陈旧键回收的实现。源最大身份不因正常删除减小。

本口不提交。外层须用普通语句标记处理失败，使节点变化、manifest、属性索引、全文源事件与上述数据共同发布。测试在已有成功写入后制造预算失败，先证明物理边和部分 heap 块确实已写入，再撤销该语句，检查包括未进入索引的 heap 行也已撤销，先前成功写入及后续独立写入均保留。

## 预算、恢复及剩余接线

数据口计账候选项、堆读写、索引维护、邻接页、含墓碑的目录项、独立节点/边及载荷字节。`append_with`/`read_with` 每页提供取消和工作检查；`fetch` 按单个稳定目录 ROWID 做 CR，不能调用普通 heap 解码器。协作式时钟不能中断单次 I/O；载荷计账不宣称是 RSS 或完整内存预算。

真实磁盘/子进程测试先更新已有边并插入大属性边，flush WAL、flush buffer 后直接退出 99，不走事务清理。父进程重开实例，由真实 redo/undo 恢复旧边、入口和属性，清除未提交新增数据；随后还可插入更大的新 ID。忽略的崩溃辅助函数由父用例实际运行，不重复计算为通过。

下一步为：v3 manifest 保存完整路由（包括记录堆/ordinal 树），执行器各只读、写入、严格全文和模板入口选择同一版本；同一事务内编排本口、节点与现有索引/全文事件；v1/v2 迁移和版本回滚；REBUILD 时同步更新活动 manifest 的路由并保留旧视图；实际 SQL 并发交错、节点 Move、回收和大图性能。原生端点锁交错测试不等同于这些 SQL 层余项完成。
