# 图全文冷批次维护（2026-10-09）

此前 v3 已支持查询词统计桶按需读取，但后台维护仍加载所有已发布文档并从全部 token 重算统计。本轮增加 v4：受管索引的 SYNC、WAIT、定时 batch 在冷启动后也只读取批次涉及的旧文档正文，用旧文档减去、新文档加入的方式更新域内 BM25 统计。

## 格式和预算

- 沿用受保护的全文 heap、ordinal B-tree、倒排树及 v3 统计桶/Merkle 校验页，不依赖外部索引服务。
- 新头格式为 `bicdb-graph-fulltext-v4`。保留 v3 的七个字段，新增 `corpus_budget`，包含全语料的 `tokens`、`document_bytes`、`native_bytes`。
- `tokens` 是各域/字段/通道的 token 总数；`document_bytes` 沿用 DocumentBudget 的逻辑费用，包含文本、段、token 等开销；`native_bytes` 是当前有效原生记录的序列化 payload 总字节数。后者固定编码为 20 位十进制字符串，使头部长度不随计数值变化。
- 每次维护通过减去旧文档费用、加入新文档费用更新全局预算，不以“本批很小”绕过语料上限。完整解码会核对全部正文、统计和全局计数。默认 100 MiB 仍是逻辑/payload 预算，不是进程 RSS 或包含旧段、陈旧键的物理磁盘上限。

## 批次路径

1. 检查索引定义、generation、covered_seq 与共享 journal 的消费者水位。
2. 通过 ordinal 树读取头、完整统计/校验元数据及本批 ID 对应的旧文档记录；未变更的正文保持关闭。
3. 校验旧统计根、选中文档校验和及 ID；检查批次 ID 唯一性、源修订、新文档与预算。
4. 按域/字段/通道减少旧文档的 N、总长度和每文档去重 df，再加入新文档贡献；支持换域、移除索引标签、删除、插入及无 token 文档。
5. 编码新统计根、受影响的文档/倒排和头，通过差异 patch 与 journal 确认在同一原生事务内发布。验证失败不提交该批，也不确认其事件；此前成功提交的批次保持有效。

`NativeBatch` 返回经过校验的 before/after 记录、倒排增量和元数据，不返回可以误当作完整语料发布的局部 Generation。完整 `Generation.apply_batch` 保留为旧格式升级及内存参考路径。

聚合统计范围可包含多份记录，使用独立的 100000 条范围读取上限，并继续受共享记录工作预算和字节预算限制；单个实体/文档仍保留 1024 分块上限。超过范围预算明确报错，不回退扫描、不静默截断。

## WAIT 和兼容性

- WAIT 使用被事件涉及的旧文档修订证明判断是否已应用，不加载无关正文。证明读取失败会中止规划，不会当作“已应用”跳过事件。
- SYNC 回执增加 `DOCUMENTS_LOADED`；WAIT 在原有列后追加 `documents_loaded`；定时维护日志增加同名计数。它统计本次命令的旧正文解码访问次数，同一文档被 WAIT 证明和批次处理分别读取时计两次，不等于物理磁盘 I/O 次数，也不包括新源实体读取。
- v1/v2/v3 只读继续使用原格式，不因打开或查询自动迁移。首次实际维护仍完整读取旧格式并原子发布 v4，之后使用冷批次路径；REBUILD 仍完整从源重建。索引对象号、源 journal 身份和维护策略保持。
- 新建索引及新发布的完整 generation 使用 v4。查询仍按查询词选择统计桶，BM25 仍使用完整语料统计；PROFILE 的既有列保持。

## 验证

测试只使用隔离的合成 bicdb 工作区，没有连接或修改 Neo4j。

- 核心 oracle 对插入、修改、移除标签、换域、删除和无 token 文档逐步比较整份原生记录及倒排输出，要求与独立完整重建相同，并冷解码核对 BM25。
- 覆盖全局文档/token/字节超限、重复及非法 ID、非请求正文、选中文档/统计/证明损坏、无变化批次和 WAIT 证明错误。失败保持输入与 journal 不变。
- 原生服务测试创建 501 份正文，重启后修改一份：SYNC 的旧正文访问为 1；WAIT 的修订证明加维护访问为 2。之后换域、删除、再重启和空批次查询与 strict 完整重建结果核对。
- 保存的 v3 服务创建旧索引，新版只读仍显示 v3；首次维护升级到 v4，随后重启的单文档维护仅读取一份旧正文。与已有 v1/v2、旧图恢复、事务、定时、模板和 SQL 联查测试一起回归。

完整日志、固定测试程序 SHA-256、部署校验及计数见 [证据](evidence/bicdb-fulltext-cold-batch-20261009/README.md)。

## 边界和后续

本轮避免未变更正文装载和全 token 重算；维护仍完整读取、解码和重新编码词汇统计/证明元数据，不能宣称成本仅与本批词项数有关。部分统计桶可能因同组 N/长度变化而重写。

稀疏维护只验证选中正文及完整统计根，不审计未触及正文的损坏；全量解码和 REBUILD 的检查范围更大。源写入仍有整图暂存，strict 查询仍从源完整重建。旧段/陈旧键回收、专用邻接段、并发端点锁、图元素句柄、受管引用、完整预算/部分结果协议和大型知识库性能验收仍需继续，整体图增强目标保持进行中。
