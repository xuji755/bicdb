# 邻接页与事务访问内核（2026-10-09）

本阶段实现 GRP-002 所需的物理邻接存储基础：type-3 段、type-5 页、稳定边目录、事务写入和一致性读。全部写入、撤销和恢复测试使用独立的合成 bicdb 实例；未连接 Neo4j。

**当前 SQL 图仍使用 v2 heap 实体记录。** 本阶段没有自动迁移用户图，也未把正反 B-tree 宣称为权威邻接存储。物理内核可供后续 SQL 图适配器调用，GRP-002/010 的整体验收仍待完成。

## 物理布局

沿用 `doc/arch/05-页.md` 的邻接页布局。公共页头与 ITL 之后是 16 字节页体头：源顶点 ROWID、活边数、保留标志、下一页地址和保留字节。下一页使用行号为 0 的页地址 ROWID。边目录每项 2 字节，顺序对应严格递增的 48 位边 ID；边体从页尾向前增长。

边固定头 17 字节，包含边 ID、目标顶点 ROWID、删除标志、ITL 槽、标签字节数和属性载荷字节数。标签为 UTF-8，长度不超过 255 字节。载荷由调用方编码，本层不把任意字节宣称为已验证的 JSON。

同页仅存一个源顶点的边。目录序号构成稳定的边 ROWID，删除和插入撤销都保留目录槽和已使用 ID；不复用槽位、不拆页。页满时追加新页，通过事务性下一页指针连接。

`Page::slot_directory_start/free_start` 识别邻接页的 16 字节前缀。ITL 扩展同时移动前缀和目录，不能沿用只移动 heap 目录的处理。普通 heap 写入口及行读取明确拒绝邻接页，避免误解边头。

## 事务和撤销

`storage::adjacency` 实现格式验证与页内操作；`txn::write::adjacency` 复用既有 buffer pool、ITL、undo、redo 和事务表。插入、更新、删除、尾链连接不自行提交。

- 插入撤销按稳定目录序号标记删除。
- 删除保存完整旧边；恢复时核对边 ID、目标 ROWID、标志和 ITL 范围，不能把另一个端点的边写回旧位置。
- 更新保存完整旧边，使用目录序号定位，补丁相对于当前边体；不能修改 ID/目标 ROWID。写入前检查旧值和新值均能容纳完整撤销记录。
- 链连接使用既有 Update 撤销格式，目标为行号 0 的页地址，仅允许页体相对偏移 9、长度 6 的下一页指针补丁。不能覆盖任意公共头字段。
- 邻接页补偿先在副本应用，完整成功后才替换原页。越界、多补丁中途失败、伪造身份或端点的撤销不损坏原页。

`cr::reconstruct` 接入 type-5 页，沿同一个 ReadView 撤销不可见事务。遍历跟随重建后的下一页指针，因此其他事务不可见的新尾页不会被读到。普通语句回滚、整事务回滚、WAL 恢复调用同一补偿实现。

页整理保留完整的已分配区间，包括删除边和更新前尾部字节，并改写目录中的物理偏移。撤销仍通过稳定目录定位。这是保守整理，可能不释放空间；不是已实现的快照水位垃圾回收。

## 段访问和端点锁

`access::adjacency::AdjacencyAccess` 使用普通 `create_segment`、追加位置、区增长、页格式化和 WAL 接口。新页先物理格式化及 fsync，再完整 redo，随后进入共享 buffer pool。既有段头、位图和追加位置走原有 redo。回滚可留下无引用的已分配页，与普通 heap 的分配规则一致；本阶段不实现这些孤页的回收。

读取检查段类型、工作区、段范围/HWM、页地址、源 ROWID、目录和链顺序，并检测环。页面数量、返回活边数量和完整边记录字节分别有显式限额；超限报错，不静默返回前半链。记录字节计数不等于进程 RSS，不替代执行器实际内存计账。

当前追加遍历完整源链定位尾页并检查 ID 顺序，尚未使用受管尾页目录快速定位；单页严格验证逐项检查记录区间。源顶点度数很大时这些检查仍有成本，本阶段没有大型知识库吞吐或延迟结论。

追加、更新、删除按物理 ROWID 升序锁住两个真实 heap 顶点；自环只锁一次。使用既有行锁和事务撤销，不建立第二套锁算法。缺失/已删除端点不能写边；被活动事务锁住的活端点返回 RowLocked。未提交删除使当前 heap 行不可读时也明确失败，不以旧快照绕过删除创建悬空边。

**调用方必须在端点锁获得后读取源链入口索引。** `lock_endpoints` 提供这一步；追加中再次锁端点为重入。锁前取得的入口可能过期，本层不能从外传的头地址判断该情况。发生冲突，调用方先回滚本语句已取得的部分锁，再走既有等待/重试机制。多次操作并不承诺全局无死锁。

本层验证邻接页属于指定源和段；两个顶点 ROWID 必须由图适配器在该图的节点段内解析并验证。单凭一个可读 heap ROWID 不能推断它属于哪个逻辑图。

## 下一阶段接入条件

SQL 图适配器必须在同一事务中维护源入口树、边 ID→稳定边 ROWID 定位树、反向树和属性/全文变更事件；任何失败回滚全部变更，入口及链记录采用同一快照。当前低层访问接口不会自行维护这些图索引。

v2 实体记录可以保存超过单页的属性。新邻接边目前只支持页内载荷，SQL 切换之前必须实现并校验页外大属性路由，保留既有大属性、校验和、预算和历史快照能力。还需完成节点稳定 ROWID/Move 路由、旧图原子迁移、真实 SQL 并发交错验证、增量写规划和旧段回收。不得仅因为 type-3/type-5 测试成功便宣称 SQL 已使用权威邻接页。

## 验证

专项测试覆盖页布局、UTF-8 标签、最大 48 位 ID、稳定目录/墓碑、多次 ITL 扩展、真实物理整理后的撤销、180 步变长更新/删除/整理与参考模型比对、畸形数据及伪造撤销不污染页；事务层覆盖读己所写、其他快照、活动边锁、语句回滚、链连接回滚及实际 WAL 恢复。

真实段测试使用普通建段/顶点 heap 插入，覆盖跨页扩展、段类型/页类型、未提交尾页可见性、端点锁与删除、跨源/跨段/跨工作区拒绝、页数/边数/字节上限、环、更新/删除定位及重启恢复。最终回归、构建发布校验见[证据目录](evidence/bicdb-graph-adjacency-pages-20261009/README.md)，整体进度以[验收清单](bicdb_图增强验收清单_20261009.md)为准。
