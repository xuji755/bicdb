# 图语句变更集与局部写入规划（2026-10-09）

## 目标与接线

原执行器为写入复制一份完整图，SQL 再复制一份用于比较；提交前对全部节点和边做差异扫描，并为全部索引准备旧/新键。现在执行器原地执行写语句，以首次修改前的实体作为语句 journal；成功时归并为净变更集，失败时恢复实体、分配器和受影响目录成员。SQL 的正常 v2/v3 写入使用同一变更集准备实体记录、原生边操作、属性/目录键和全文源事件。

这是局部写入规划的基础和实际 SQL 接线。**当前仍完整加载并校验源图**，v3 `StorageImage::from_adjacency` 还会构造逻辑记录投影；唯一键冲突仍对最终图中的未修改实体做流式核验。没有宣称写入已支持部分图缓存、持久索引唯一性证明或 O(修改量) 的全部执行成本。

## 语句 journal

`GraphChanges` 只记录被修改的节点/边及其首次修改前的可选值；新增实体的原值为 None。多次修改同一个实体不复制多份原文；CALL/UNION 共用外层 Runner 和 journal。查询读取、暂时修改后恢复原值、创建后在同语句删除的实体都不进入成功后的净变更集。分配器仍保留成功语句的 ID 高水位，防止临时创建的 ID 被再次使用。

所有 CREATE/MERGE、SET/REMOVE、标签修改、DELETE/DETACH 都通过有 journal 的模型入口。标签修改只更新该节点的相关标签目录，不重建全图标签。回滚只恢复受影响的节点/边及标签/出入目录成员，并记录目录桶首次修改前是否存在，保留既有空桶的结构；不会通过复制邻接集或重建所有目录来恢复。失败语句不返回可发布的变更集。

读查询仍沿用原先的缓存隔离方式；只读按需存储端口禁止写部分图。v1 向 v2 的完整格式转换仍保存一份源逻辑图用于兼容迁移，不能只根据变化实体丢弃未修改源记录。

## 记录、索引与队列

`StorageImage::patch_changes` 根据净变更 ID 范围生成/比较实体 checksum/chunks；删除和缩小记录会撤回旧尾块。已校验映像缓存原记录字节总量，用增删替换的载荷差量维持完整结果预算。原有全图 `patch` API 保留给导入、格式转换等操作；两个算法的最终行补丁使用同一底层实现。

正常 SQL 的原生边规划直接读取变更集：插入、更新、删除互斥；manifest 高水位和节点/边计数来自最终图。v3 仍不持久化第二份 kind-2 heap 拓扑。节点、边、索引键、全文事件与 manifest 保持原有同事务及 statement mark 回滚机制。

属性与目录键规划只枚举净变更实体，添加尚未存在于原值的新键。原生 B-tree 的旧候选继续按实体可见性/实际键复核；这里没有进行旧候选物理删除或 GC。唯一约束同时核验变更实体之间的重复和变更值对未修改实体的冲突；支持最终状态合法的键交换、标签退出释放旧键、null/missing 和组合 JSON 路径。该核验仍扫描完整最终图，但不为未修改实体构造旧/新键集合。正常写入只在目录树确实缺失时准备全图派生树；已有完整目录仍检查元数据有效性。

全文 journal 改为根据净逻辑变更及规范实体 revision 生成事件。修复了 v1 仅转换存储格式也把全部未修改实体送进全文队列的问题；改后恢复原值、仅创建再删除、格式重新编码不造成内容脏事件。源校验 revision 与既有规范编码一致，实际删除仍发布 tombstone，后续 SYNC 继续批量原子维护。

## 字节校验和边界

执行器不再为了字节预算构造完整 JSON 图，改为累加空图 header、数组分隔符及逐实体的规范 JSON 字节数；最多编码当前一个实体，按实体检查继承时钟。该数值与 `Graph::to_bytes` 的完整紧凑 JSON 长度一致，保留精确边界拒绝和失败回滚。它仍遍历完整最终图，也不等于真实堆内存/RSS、临时索引键及序列化缓冲的统一计账。

journal 保留受修改实体的原始载荷，受既有完整图/语句预算约束；没有独立承诺跨组件总 RSS 上限。只读缓存复制、源图验证、v3 逻辑投影、唯一性流式扫描、一般节点 Move 和旧段 GC 是后续工作。

## 验证

新增模型/存储用例覆盖首次原值、嵌套调用、多次变更及净空变更，失败恢复标签/拓扑/空桶/ID，增长/缩小/DETACH 与完整差异算法逐行等价，2000 节点下小预算的局部键规划，组合 JSON 与关系索引、唯一键交换/冲突/标签退出，以及精确 JSON 长度预算。

SQL 集成覆盖 v1/v2/v3、净空变更不污染全文状态、唯一冲突保留此前事务写入、完整 ROLLBACK、后续 SYNC 与重启。新增 Store 用例通过实际认证服务验证相同边界。已有迁移、物理重建、真实刷盘崩溃和旧程序兼容回归继续执行。最终命令、计数、输入哈希、部署与实例核验见[本阶段证据](evidence/bicdb-graph-write-delta-20261009/README.md)。Neo4j 没有连接或修改，测试均为隔离 bicdb 合成实例。
