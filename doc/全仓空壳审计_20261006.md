# 全仓「空壳」审计（2026-10-06）

- **触发**：发布 v0.1.0 之后的复查请求——"再看一遍所有代码，有没有只是空壳、并没真正实现的部分"。
- **范围**：`crates/` 全部 19 个 crate（约 6 万行）。
- **方法**：五个分组并行审读（storage / wal+txn / exec+sql / catalog+access+cli / index+common+types+workspace+tools+daemon+骨架），
  判据 = **文档或签名承诺 > 实际行为**（恒返回、空 `Ok(())`、参数被忽略、错误被吞、写而不读、分支不可达）；
  随后由主线**逐条复验**并修掉可当场修的。
- **不列入**：明确的具名拒绝（`Err(Unsupported/…)`）、测试夹具、已记档且写明触发条件的后续切片
  （这些单列在 §4，便于对照）。

**一句话结论**：各层**算法本体都是真实现**（页/段/缓冲区、WAL 三阶段恢复、undo/ITL/CR/回滚、
B+Tree 分裂与批量灌树、19 个执行算子、SQL 四阶段），不存在"返回常量的假算子"；
**空壳集中在"接线"**——实现好了但没被生产路径调用的东西，以及"选项/检查写进了字典或段头却没人读"。
本次共修 **16 项**（含 3 项会直接卡住用户：写 ~180 条即失败的墙 ×2、带参 INSERT 打唯一索引必失败）。

## 3 复验过的"不是空壳"（防止误读）

- **19 个执行算子**：全部有真实算法与测试（含 Sort 外排、HashAgg/HashJoin 分区与二次重分区、NestedLoop 参数化重扫）；
  差异只在"生产可达性"（G3）。
- **多成员 WAL 镜像**：TeeSink 扇出、按成员标 `STALE`、跳过坏成员、`rebuild_member` 复制前缀并清位、控制文件往返，全为真实现（本次只补了后台发布口 F5）。
- **死锁/等待算法本体**：真实现（见 G1 的接线缺口）。
- **存储层**：页/段/文件/控制文件/缓冲池（O2–O4）、undo–ITL–CR–回滚恢复、扫描区读，均有真实实现与消费方。
- **daemon**：两层资源拒绝、有界队列满即拒绝、维护线程、NUMA 绑定（真调用 `bind_current_thread`）均为真。
- **五个骨架 crate**（`asset`/`graph`/`memory`/`net`/`retrieval`）：各 10 行纯文档，**明确写着"未实现（骨架占位，无可调用 API）"**，
  且**没有任何 crate 依赖或 import 它们**——不是伪装，是阶段未到（P5–P10）。
- **工具**：`page_dump`、`db_check` 的页级检查（两层完整性、槽位目录、空闲区、按状态解析记录、片段位自洽）为真实现（堆级见 G6）。
