# 图全文候选文档按需读取（2026-10-09）

## 问题与本阶段结果

此前 eventual 查询先从倒排 B-tree 得到候选 ID，但加载完整文档语料以重算 BM25 统计。冷查询即使命中一个文档，也读取所有文档、位置和文本；strict 查询与 SHOW 同样先装载旧语料。本阶段把已发布语料统计与文档内容分开，保持既有分词、得分、域/字段过滤、源修订复核和 SQL/Cypher 返回语义。

- v2 eventual：读头、倒排候选（字段间并集、查询词间交集）、持久统计页，再按候选 ID 经受保护的 ordinal B-tree 读取文档分片。不存在的候选记录按陈旧倒排项处理；存在但损坏的候选记录报错。
- 无候选：只校验头及查询参数，不装载统计页或文档。
- strict / staged：读头，然后直接按当前源视图重新构建；不预读旧文档语料。
- SHOW：仅读独立校验头，返回声明的文档数、代数及覆盖水位，不逐一验证文档正文。
- v1：只读兼容，命中查询保留完整加载和原有评分。读、SHOW、在线 OPTIONS 不迁移格式；SYNC/WAIT 发布新代或 REBUILD 时，在原有事务中迁移到 v2，不改变逻辑索引身份及共享队列身份。

## 持久格式与原子维护

头格式 `bicdb-graph-fulltext-v2`，在原来的五个字段外增加 `statistics_pages` 和 `statistics_sha256`。仍使用原生 gft heap 与唯一 ordinal B-tree，没有新远程服务或第二份源文档。

- 文档种类 1 的 ID 编码、分片和 SHA-256 校验不变。
- 统计种类 2 的记录按页序排列，每页独立校验，逻辑条目为 `(domain, field, channel, N, length, term, df)`。全体统计页再由头内的 SHA-256 绑定，防止跨代拼接。
- 域、字段、通道与词序确定；读取检查重复/顺序、域与词长度、N/df/总 token 数、计数溢出、页面完整性及全体摘要。每组 N 不得超过头声明文档数。
- 完整语料加载还把持久统计与文档重算统计逐项比对。查询的部分图像检查候选 token 对应的统计存在，局部 N/length/df 不得大于全局值。
- 只保留候选文档的内存图像标记为 search-only，拒绝维护、导出原生行或发布倒排，避免被误当成完整代而丢失其他文档。

维护仍加载完整已发布代、重算统计；增量 native_rows_for 除变化文档外包含统计页。前后记录 diff 保留未变化页，只把变化/增加/删除的统计页与文档、倒排和 journal 确认在同一事务发布。v1 载入的代保留其原格式编码，保证 v1→v2 diff 与真实旧记录一致。

源图写入仍只登记 ID/修订标记，不分词、不同步维护全文统计。

## 可观测性与资源边界

`PROFILE CYPHER` 保留原九列，末尾增加 `fulltext_documents_loaded`，记录原生全文实际解码的文档数；多次/多字段调用按逻辑访问累计，不等于进程缓存数量。v1 命中查询会报告完整语料数，v2 报告候选中实际存在的文档数。strict 报告当前源构建出的索引文档数。

`SHOW FULLTEXT GRAPH INDEXES` 保留原十八列，追加 `storage_format`（v1/v2）与 `statistics_pages`（v1 为 NULL）。水位、READY/DIRTY 和暂停状态含义不变。

候选记录字节、token 数仍受现有 100 MiB / 1,000,000 token 预算约束；相关调用把统计/文档原生记录数纳入既有共享工作预算，并叠加倒排、源修订和端点检查。无命中调用仍有最小元数据成本，不能借空结果绕开表达式预算。

本阶段**仍读取全部统计元数据**，尚未按查询域/词定点读取统计；陈旧倒排键仍通过文档与源复核，REBUILD 用于压实。维护仍需要完整已发布语料；统计页编码增加持久空间并共享记录字节预算。100 MiB 是逻辑预算，不是进程 RSS 上限。本阶段不能证明大型 Neo4j 知识库的性能等价。

## 验证与部署

`crates/graph/tests/fulltext.rs` 验证候选图像与完整代在 terms/phrase/exact 上的 ID、评分、摘要、偏移一致；未选中正文损坏不影响候选读取，选中/统计损坏或缺失被拒绝，部分图像不能发布。

`graph_fulltext_sparse` 原生测试构造 102 个文档与较大的无关正文，重启服务后单命中仅加载 1 个文档，无命中与查询词候选不相交时加载 0 个；eventual 与 strict 的全局 BM25 得分逐值一致。另验证陈旧修订、WAIT 更新及本人事务删除/回滚。旧 managed-v1 原生测试验证只读保持 v1、SYNC 同一索引迁到 v2、评分一致及重启后单候选读取。

证据目录：`doc/evidence/bicdb-fulltext-sparse-20261009/`。最终经 `python3 scripts/build_bicbot_v2.py` 发布，并比对安装、构建、回执及实际测试程序 SHA-256；仅更新空闲服务，保留用户会话。

所有测试写入仅在隔离 bicdb 实例内；本阶段没有连接或修改 Neo4j，没有修改 source 原始方案，没有 Git 提交或推送。

> 2026-10-09 后续实施：全文 v3 按域、字段、channel、query 词选择统计桶及 Merkle 校验页，前台不再读取全词汇统计。v1/v2 保留只读兼容，维护时原子升级；维护仍加载完整语料。PROFILE 追加实际统计行读取计数。见[规则](bicdb_全文统计按查询词读取_20261009.md)。
