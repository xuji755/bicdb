# 工具功能描述清单

更新时间：2026-10-01。适用项目：`bic-scriptnew`。

本清单依据当前仓库的客户端入口、Python/Rust 服务端实现、命令帮助及部署文档整理，覆盖公开检索工具、管理工具、构建部署工具、知识维护脚本和测试辅助工具。功能是否返回数据取决于所连接图谱实际收录的内容；注册了数据库类型，不代表该类型已经具备全部知识、系统对象或 SQL。

## 1. 项目定位与目录

项目为数据库及相关技术知识提供命令行检索、图谱关系分析、SQL 知识查询和配套运维能力。常规检索由 Python 命令行客户端发起，经常驻 daemon 访问 Neo4j；可按客户端配置选择 Rust 或 Python 后台。

| 目录 | 职责与使用方式 |
| --- | --- |
| `client/` | 正式客户端与管理入口源码。检索入口通常只负责请求封装和结果输出。 |
| `rust-daemon/` | Rust 常驻检索服务源码，原生实现公开检索接口。 |
| `python_backend/` | Python 对照检索服务及其业务实现，可供兼容验证和按项目选用。 |
| `deploy/client/` | 已装配的完整客户端交付目录，包含导入实现、共享库、环境准备工具及离线依赖；现场应复制整个目录。 |
| `deploy/` | 发布包生成、安装、环境检查、配置模板和冻结的上游导入实现。 |
| `build/` | 双架构编译入口，以及实体词典、OpSQL 发布、支持范围审核和专项修复工具。 |
| `tests/` | 客户端、协议、双后台差分、性能、安全及发布隔离验证。 |
| `python-runtime/` | 保留的完整 Python 研发资产和历史工具；不整体作为正式消费客户端发布。 |
| `config/` | 数据库类型、日志模式、查询改写及运行配置模板。 |
| `doc/`、`docs/` | 中文使用说明、设计说明、审计和验证记录。 |

清单以独立命令及具有明确用途的维护工具为单位。同一入口的发布副本不重复计数；普通内部函数、共享模块和数据文件不单独当作用户工具。

### PL/SQL标准检索工具

`plsql_kg.py <db> search|detail|context|entity`复用kb_graph的位置数据库参数、--version及--scope语义；--program-context仅block/procedure/package。Python入口只发送请求、显示JSON及传递退出码，契约校验、图谱访问、有效定义/稀疏补丁解析、规则关系、示例和知识补查均在Rust daemon。Skill不分发工具，也无客户端直连/本地检索回退；需要支持plsql_kg action的新版Rust daemon。

search支持句中API标识符召回与有界候选，detail读取稳定身份或目录全名，context组装定义、规则、依赖、示例、反例和未解决项，并可--view精确补查；entity view/table/function直接复用产品对象检索。文本候选保持version_scope_validated=false；命令完成不证明对象存在/目标版本支持/实际权限可用。结构读取与补查分别有时间预算，多次Query API读取不承诺同一快照。图谱审核状态不作门禁，适用性冲突、不支持、缺环境和完整性问题保留。

```bash
python3 client/plsql_kg.py oracle detail --catalog-name DBMS_SQL.IS_OPEN --catalog-kind function --version 11gR2
python3 client/plsql_kg.py oracle context --version 11gR2 --program-context procedure --catalog function:DBMS_SQL.IS_OPEN --query 'AUTHID DEFINER 权限' --view DBA_TEMP_FREE_SPACE
```

历史表空间用例保留在tests/plsql_examples，冻结Python解析器仅供tests/plsql_reference对照，不属于客户端/服务依赖。collect_tablespace_fs.py是独立的数据库主机OS采集工具，不是远程检索服务；复用既有OS认证，默认输出调用文本，Skill禁止写文件的任务不使用其可选文件输出参数，也不重定向落盘。

## 3. 公共使用约定

### 3.1 运行前提

以下消费命令示例均从仓库根目录执行，使用 `python3 client/<工具>.py`。现场部署时，将 `client/` 替换为完整客户端安装目录，并使用已准备的 Python 环境。完整交付客户端要求 Python 3.12 及以上。

```bash
export KG_RETRIEVAL_RUNTIME_CONFIG=/etc/kg-retrieval/client.json
python3 client/health_check.py --daemon
python3 client/kb_graph.py --help
```

| 配置项 | 用途 |
| --- | --- |
| `KG_RETRIEVAL_RUNTIME_CONFIG` | 选择检索客户端或服务端的运行配置；两端使用各自配置文件。 |
| `KG_RETRIEVAL_ENDPOINT` | 在支持该覆盖方式的客户端路径中选择具体 daemon 端点。 |
| `KG_NEO4J_CONFIG` | daemon、健康检查、索引管理及导入工具使用的 Neo4j 连接配置。 |
| `KGTOOLS_CREDENTIAL_KEY` | 解密连接配置中 `enc:` 凭据所需的密钥。 |
| `KG_NODE_KEY_PARTS_FILE` | 服务端加载受保护图谱字段的节点密钥片段；不属于普通检索客户端配置。 |
| `KGTOOLS_LLM_CONFIG` | LLM 检查及相关辅助能力的配置。 |
| `BIC_CONFIG` / `MCP_CONFIG_PATH` | `bic_manual_sql.py` 使用的已有 MCP 配置文件。 |
| `BIC_QA_PYTHON` / `BIC_QA_LICENSE_CLIENT` | 集成 BIC-QA 授权检查的 Rust 服务调用离线许可证验证入口所用的 Python 和脚本路径。 |

公开检索 CLI 的帮助也由 daemon 提供，因此仅安装脚本不等于已具备离线检索能力。查询结果支持的格式按各工具说明选择，不能假定所有工具都有 `--json`。

### 3.2 数据库、版本和范围

`<db>` 通常接受规范名称、别名或四位 `db_type`。完整注册表见第 10 节。带 `$` 的对象名称应使用单引号，例如 `'GV$OB_MEMORY'`，避免 shell 展开。

视图、系统表、函数、参数和 OpSQL 的版本/范围参数只在各自支持的命令中使用。系统对象根据节点和字段的 `versions` 以及直接范围属性筛选；不存在的版本不应被自动替换为其他版本。Oracle 容器、OceanBase 租户、GaussDB 架构等范围含义不同；MySQL 系统对象查询虽然兼容解析 `--scope`，但不据此筛选。

独立的版本集合和范围集合不自动证明每个版本与范围组合都已验证。OpSQL 的支持范围与实际执行回执也应分别理解。详见 [系统对象检索口径](系统对象版本与范围检索口径-20260927.md)。

## 4. 公开检索工具（16 个 action）

本节 16 个工具均通过 daemon 检索。它们读取知识及参考内容；图谱写入、现场 SQL 执行和服务管理另见后续章节。

### 4.1 `kb_graph.py`：统一知识图谱入口

**入口：** `client/kb_graph.py`；action：`kb_graph`。

**功能：** 在指定数据库/知识域内检索知识条目、故障模型、案例、系统对象及关系；支持综合分析、分层诊断、批量查询、详情展开和跨库等价关系查询。输出以可读文本、实体清单和 Markdown 表格为主。

| 子命令 | 输入 | 功能与结果 |
| --- | --- | --- |
| `stats` | 数据库 | 查看该知识域图谱统计；仅传数据库是兼容简写。 |
| `problem` | 问题、日志、错误码或多个独立关键词 | 检索相关知识和实体；多个参数分别查询后合并。 |
| `analyze` | 自然语言描述 | 综合展示实体、诊断链、影响及相关关系。 |
| `diagnose` | 问题描述 | 按 problem → fault → entity → 知识条目 → 文档的多层策略诊断。 |
| `batch` | 多个查询字符串 | 批量检索、合并去重和排序；Rust 可按配置并发处理，并按输入顺序合并。 |
| `entity` | 类型、名称/ID/用途及可选条件 | 按类型查询，具体见下一表。 |
| `detail` / `ke_detail` | Neo4j `elementId` | 查看实体完整内容；后者为兼容别名，OpSQL 详情可展开完整 SQL。 |
| `csdetail` | 案例 `elementId` | 查看案例详情。 |
| `diagnostic` | 一个或多个故障别名 | 展开故障模型的诊断传导链。 |
| `fault` | 故障关键词 | 搜索故障模型，支持多词分隔。 |
| `impact` | 实体类型和 ID/名称 | 查看实体关联影响的知识和故障。 |
| `discover` | 可选最小共现次数，默认 3 | 发现尚未建边的高频共现实体；输出候选关系。 |
| `equivalent` | 目标数据库、视图名、可选来源数据库 | 查询跨库等价视图；省略来源时默认 Oracle。 |

**`entity` 类型完整清单：**

| 类型/别名 | 功能与主要条件 |
| --- | --- |
| `metric` | 指标 ID 精确优先，再按名称或内容召回。 |
| `param` / `parameter` | 查参数名称或用途；支持 `--version`、`--scope`，返回匹配的参数定义信息。 |
| `wait` / `wait_event` | 查等待事件，支持中英文名称模糊召回。 |
| `view` / `system_view` | 查系统视图、适用版本、范围和字段；支持 `--version`、`--scope`、`--nocolumn`。 |
| `table` | 查系统表和字段；支持上述视图筛选参数。 |
| `column` | 按字段名称或关键词检索系统表/视图字段。 |
| `function` | 按名称或用途查函数及关联参数；支持 `--version`、`--scope`。 |
| `funcion` | 兼容拼写；先查函数，未命中同名函数时回退通用实体检索。 |
| `opsql` | 按需求、系统对象或关联知识查已发布运维 SQL；支持 `--version`、`--scope`。 |
| `opsqllist` | 列出已发布运维 SQL 的 Markdown 目录，可按版本和范围过滤。 |
| `knowledge` / `ke` / `knowledge_entry` | 查询知识条目。 |
| `fault` / `fault_model` | 查询故障模型。 |
| `casestudy` / `case_study` | 查询案例。 |
| `module` | 查询诊断模块。 |
| `operator` | 查询执行计划算子及关联规则、案例。 |
| `bug` | 查询 Bug 节点。 |
| `error` / `errorcode` / `error_code` / `sqlstate` | 查询错误码或 SQLSTATE。 |
| `all` | 不限实体类型的通用召回；通用检索请显式使用 all，未知类型名会报错。 |

不知道对象名称时，可在函数、参数、视图和表查询中传入完整用途描述。候选结果需再用精确名称查看定义；用途检索依赖关键词、图谱词典和查询改写，不是通用向量语义检索。

OpSQL 强匹配可以直接展示 SQL；较弱匹配只列候选与 `detail` 命令。SQL 是图谱中已发布的参考内容，工具不会因此在目标业务数据库执行查询。支持数组表示声明的适用范围，不能用实际验证版本替代支持清单。

```bash
python3 client/kb_graph.py oracle problem 'ORA-00600'
python3 client/kb_graph.py ob batch '合并阻塞' '内存不足'
python3 client/kb_graph.py ob entity view 'GV$OB_MEMORY' --version 4.2.1 --scope SYS
python3 client/kb_graph.py ob entity function '计算数值的绝对值' --version 4.2.1 --scope MYSQL
python3 client/kb_graph.py ob entity opsql '合并阻塞' --version 4.2.1 --scope SYS
python3 client/kb_graph.py ob entity opsqllist --version 4.2.1
python3 client/kb_graph.py ob detail '<检索结果中的elementId>'
```

### 4.2 `kg_deep_diagnose.py`：深度关系诊断

**入口/action：** `client/kg_deep_diagnose.py` / `kg_deep_diagnose`。

从关键词出发，沿知识图谱关系查找关联知识、故障、实体及诊断信息，适合需要解释关联证据的分析。输入为数据库和一个或多个关键词；`--limit/-l` 控制结果上限，`--format/-f text|json` 选择输出格式。结果是知识依据，不代表已经对现场实例完成根因验证。

```bash
python3 client/kg_deep_diagnose.py oracle '日志切换缓慢' --limit 10 --format json
```

### 4.3 `kg_log_search.py`：日志特征分析与检索

**入口/action：** `client/kg_log_search.py` / `kg_log_search`。

解析用户提供的日志文本，识别数据库线索、错误码和日志特征，规范化后检索相关知识。支持位置参数或 `--stdin`；`--db` 指定数据库，默认自动识别；`--no-search` 仅解析；`--format text|json` 和 `--limit` 控制输出。工具不主动采集本地文件、远端服务器或数据库日志。

```bash
python3 client/kg_log_search.py --db oracle 'ORA-04031: unable to allocate memory' --format json
python3 client/kg_log_search.py --db mysql --stdin < /path/to/provided.log
```

### 4.4 `doc_retrieve.py`：文档原文检索

**入口/action：** `client/doc_retrieve.py` / `doc_retrieve`。

通过 Neo4j `DocText` 和全文索引查找已入库的官方文档、MOS Note 等内容，返回命中文档及相关原文。`--db` 指定文档数据库目录，`--list` 只列清单；`--dbs` 列出可搜索目录，配合 `--detail` 显示统计。`--list --db <目录>` 可在不提供关键词时列文档。它检索图谱中的文档，不实时下载官网材料。

```bash
python3 client/doc_retrieve.py 'shared_pool' --db oracle
python3 client/doc_retrieve.py --dbs --detail
```

### 4.5 `search_kg.py`：SQL 优化方案检索

**入口/action：** `client/search_kg.py` / `search_kg`。

检索 `bic_agent_SQLOptimization` 中的优化方案。输入一个或多个关键词；`--db` 筛选指定数据库专用方案及通用方案，不指定时跨库检索；`--limit` 默认 10；`--json` 输出结构化结果。名称中的“KG”不表示它承担所有类型的图谱搜索，系统对象请使用 `kb_graph entity`。

```bash
python3 client/search_kg.py --db oracle '执行计划' --limit 10 --json
```

### 4.6 `search_sqlgen.py`：SQL 优化改写规则检索

**入口/action：** `client/search_sqlgen.py` / `search_sqlgen`。

查询 `bic_agent_SQLOptimizationRule`，兼容旧标签 `bic_agent_SqlOptimizationRule`，提供 SQL 编写、改写及禁止项等规则依据。`--db`、`--category`、`--version`、`--keyword/-k` 手动筛选；`--auto` 从需求检测数据库和类别；`--detect-only` 只检测；`--no-common` 排除通用规则；`--limit` 默认 30；支持 `--json`。本工具提供规则检索，不承诺自动生成完整 SQL。

```bash
python3 client/search_sqlgen.py --db oracle --category 'SQL改写' --keyword '谓词推入'
python3 client/search_sqlgen.py --auto 'Oracle 执行计划突然变差怎么处理' --detect-only
```

### 4.7 `metric_lookup.py`：指标定义与关系查询

**入口/action：** `client/metric_lookup.py` / `metric_lookup`。

语法为 `<db> <action> [value]`，支持 `--limit`（默认 20）和 `--json`。查询的是图谱中的指标定义与关系，不采集实时监控值。

| 操作 | 功能 |
| --- | --- |
| `lookup` | 按指标 ID/名称查询单个指标。 |
| `batch` | 查询逗号分隔的多个指标 ID。 |
| `search` | 根据关键词查指标。 |
| `edges` | 查看一个或多个指标的关系边。 |
| `related` | 查同指标域内的相关指标。 |
| `cross` | 查引用该指标的知识条目和故障模型。 |
| `top` | 按图谱引用数量查看高频指标。 |
| `fault` | 参数解析保留的选项；当前 Python 和 Rust 实现均没有实际查询输出，不应当作已实现的故障查询能力。 |

```bash
python3 client/metric_lookup.py oracle search '逻辑读' --json
```

### 4.8 `wait_event_info.py`：等待事件专用查询

**入口/action：** `client/wait_event_info.py` / `wait_event_info`。

按数据库和等待事件名称查询定义及关联信息。支持一个名称、逗号分隔多个名称或多个位置参数。输出格式以最后一个位置参数 `text` 或 `json` 指定，默认文本。

```bash
python3 client/wait_event_info.py oracle 'log file sync' json
```

### 4.9 `view_join_search.py`：系统对象 JOIN 关系查询

**入口/action：** `client/view_join_search.py` / `view_join_search`。

根据视图/系统表名称和可选 `--db` 查找已建模 JOIN 关系。`--direction both|outgoing|incoming` 指定方向；`--trusted-only` 仅保留带来源、置信度元数据的关系；`--min-confidence` 设置阈值；`--include-review` 包含默认隐藏的待复核关系，`--exclude-needs-review` 排除需要复核的旧关系；支持 `--json`。已建边和有置信度不等于 JOIN 在任意版本都正确。

```bash
python3 client/view_join_search.py 'GV$OB_MEMORY' --db ob --trusted-only --json
```

### 4.10 `parameter_info.py`：参数精确查询

**入口/action：** `client/parameter_info.py` / `parameter_info`。

**入口/action：** `client/sql_full_check.py` / `sql_full_check`。

### 5.4 图谱导入工具

完整实现随 `deploy/client/kgtool_import/` 发布，上游算法由独立 `kgtool` 项目维护。仓库 `client/` 下的三个脚本是启动适配器，直接运行时仍需完整装配目录；适配器验证发布文件哈希后，在隔离 Python 子进程中启动导入。

| 入口 | 包类型 | 功能与默认行为 |
| --- | --- | --- |
| `kg_full_import.py` | KGV2 `bic-kg-ledger`，`package_kind=full` | 导入全量基线；默认预检，`--write` 才实际写入。 |
| `kg_incremental_import.py` | KGV2 `bic-kg-ledger`，`package_kind=incremental` | 按包链导入增量；默认预检，`--write` 才实际写入。 |
| `kg_incremental_import.py` | 无 `protocol` 的旧包 | 兼容旧格式，默认写入；预检使用 `--dry-run`，禁止套用 KGV2 的 `--write` 用法。 |

### 5.5 `bic_manual_sql.py`：BIC SQL 执行适配器

**入口：** `client/bic_manual_sql.py`。这是独立 MCP 适配器，不属于 16 个检索 action。

读取已有 BIC MCP 配置，定位 `bic_manual` 分组的 `sql_executor`，向指定 BIC 对象提交 SQL。单条模式使用 `--object-name` 和 `--sql-b64`；批量模式使用 `--request-b64`，内容为包含 `object_name` 和 `queries` 的 UTF-8 JSON 的 Base64。支持 `--pretty`，`--timeout` 为 1–120 秒。每批最多 20 条，单 SQL 文本最多 256 KiB。

输出包含总体状态、每条查询 ID、成功/空结果或失败状态。适配器会真实调用外部执行服务；本地只做输入格式和大小等检查，不应把它视为独立、完整的 SQL 只读安全校验器。适用语句和执行权限由实际执行服务及目标账号约束。
