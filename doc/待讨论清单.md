## 一、明天的讨论顺序（建议）

### 1. D-06　页内槽位数上限与格式版本起点　★ 最优先

**推荐值**：每页最多 **1024 槽**；格式版本从 **1** 起。

**为什么排第一**：它是**页头布局**（REQ-STO-002）与 **ROWID 的 `row_id` 位宽**的
**共同上游**——1024 这个数正是 `row_id 10 位`的依据，两者必须同时改。
它卡着下面所有页格式，不定它就没法往下写。

### 2. 页体格式细则（待冻结项 8 + 9）—— 下一个设计块

| 项 | 内容 |
| --- | --- |
| **8** | 索引页、邻接页、ANN 页、Undo 页的**页体格式细则** |
| **9** | **字典表各表的列定义**（表清单与分层已定，见 §3.1） |

**为什么是它**：结构性设计已完成（§9.1.3 已与 Oracle `kdxco` 逐字段对照过，
省掉了其中大半），剩下的是把"每页字节长什么样"写死。
**这是存储设计最后一块结构性工作。**

**被推翻或修正的决定**（明天别按旧版讨论）

| 原设计 | 现设计 | 原因 |
| --- | --- | --- |
| file 0 是"固定格式的目录" | file 0 = **数据字典**（普通表结构） | 一套代码 |
| 做 TOAST 存长文本 | **不做**——内联行片段链 + redo 按页拆分 | 推导链第一环不成立 |
| 做 FPW / 双写区防 torn page | **都不做**——交给文件系统 | 轻量优先；前提是提供原子页写的文件系统 |
| 控制文件**不存路径** | **存完整路径** | 恢复锚点必须自包含；池引入了任意位置 |
| "逻辑行标识"，行锁不得用 ROWID | **已证伪删除**——行锁与索引叶项都用 ROWID | 前提"行迁移会改 ROWID"不成立（转发指针） |
| 缓冲池/DBWR 未定层次 | **实例级共享**，分区为工作集，`N=1` 合法 | 大小工作区共用一套 |
| redo 组大小"没依据" | 边界已推导（下限=检查点周期，上限=恢复重放≤2 组） | 只差具体数值 |
