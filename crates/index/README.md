# bicdb-index

B+Tree：唯一键、复合键、范围访问、并发分裂

| 项 | 值 |
| --- | --- |
| 设计依据 | §7 索引的物理组织（§9.1 页体/分裂协议、§5.11 页类型 2/3/4、§9.1.6 扫描族） |
| 对应阶段 | P4（已启动） |
| 当前状态 | **v0.3**——页体读写 + 树算法（点查 / 插入（99-1、50/50）/ 删除 / 范围扫描 / IFS 全扫描 / **FFS 快速全扫描** / 结构自检）+ **索引统计**（entries / leaf_blocks / blevel / **聚簇因子**）+ **接入存储**（`PoolStore` 池存取口 + `IndexIo` 写口 + 树头落段头页扩展区、`Tree::open` 按页类型推高度）；并发右移（闩耦合）随会话/执行器切片 |

## 状态说明

- **页体**（`page`，§5.11 类型 2/3/4）：正文头（`entry_count 2B │
  left_child 6B`）在 68B 页头之后，有序条目目录紧随（**项 1 恒为高键**——
  锚 / 上界 / 右移判据三合一），条目区自页尾向上；**叶页页尾 12B 双链**
  （`link_prev`/`link_next` 各 6B；页尾区 16B = 12B 链 + 4B 页尾副本），枝/根页无链。
  键即字节序：叶页按**复合键 `(key, ROWID)`**、枝页按**区分前缀**比较——
  不解码、无类型比较器。高键 `key_len = 0xFFFF` = ∞（最右页），
  **只在建页与分裂时写**；条目 < 高键（∞ 除外）。
- **分裂**（`tree::split_leaf`/`split_branch`，§9.1.5）：**单阶段**——
  99/1（新条目最大；**单调追加是常态路径**，零搬移）或 50/50；
  三页协议：P′ 复制原高键、P 改存新上界（右半最小条目）、**P′ 继承 P 的
  后继且 Q 的 `link_prev` 改指 P′**；父层滞后是容忍态（高键 + 右链兜底），
  根分裂 = 旧根降级（分支）+ 新根（类型 4）+ 高度 +1。
  `adjust_split` 校正分裂点：左半 + 新高键 + 目录必须放得进原页。
- **树算法**（`tree::Tree`）：点查（下行走高键 + 右移自愈）、插入、
  删除（**空页留树中**——高键是锚，§9.1.2；页回收 V1.0 不做）、
  **范围扫描**（闭区间，沿叶链）、**IFS 全扫描**（= 无谓词范围扫描）。
- **FFS 快速全扫描**（`Tree::fast_full_scan`，§9.1.6）：按**物理块序**枚举全段
  索引页（`PageStore::blocks`），**连续块成组区读**（`read_run`，≤ 8 页/次），
  逐页**页头自证**（自述块号/文件与请求一致）后只取叶页条目——**不沿叶链、
  不保序、不承诺快照一致性**；产出只喂不接受顺序的消费方（统计/无条件聚合）。
- **索引统计**（`Tree::statistics` → `IndexStats`）：沿叶链一趟、**零回表
  I/O**（只比较条目自带的 ROWID 字节）；**聚簇因子**照 Oracle `CLUFAC` 口径
  （Note:39836.1，证据包 `index-stats-20261006`）——按索引序扫叶，相邻条目的
  `(file_id, block_id)` 变化则 +1（首条计 1），值域 [表块数, 行数]；另有
  `entries`/`leaf_blocks`（`LEAFCNT`）/`blevel`（树高 − 1）。持久化随目录域
  `stat$`（本 crate 只计算）。
- **结构自检**（`Tree::validate`）：链走到底（最左叶 `link_prev` 必须为空、
  **链的尽头必须是 ∞ 页**）∧ 页内键序单调 ∧ 条目 < 高键 ∧
  双向链一致 ∧ **与根下行清点相等**（链断/叶子失联在这条上现形）。
- **页存取缝**（`store::PageStore`）：执行器以段 + 缓冲池实现；测试用内存仓
  `MemStore`。树头（根页 ROWID + 高度）由 `Tree` 显式携带，接入时落段头页
  的 B+Tree 扩展区；**闩锁由接入方提供**——单线程实现以"一次一个页"的纪律
  串行化（§9.1.5），并发右移协议随执行器接入。
- 两处实测坑（已修，回归钉住）：
  · **P′ 必须继承 P 的后继**——漏掉时 P′ 恒以 no_link 收尾、叶链提前终止，
    **单调追加看不见**（P 恒最右），乱序插入才暴露；
  · **`set_high_key` 之后必须 `compact`**——新高键追加在条目区顶部、旧高键
    字节留作死空间；不回收则左半预算比 `adjust_split` 估算少一份高键
    （实测：607B 键、25 条左半恰好差 615B ⇒ NoSpace）。
- **接入存储**（`store::{IndexIo, PoolStore}` + 段头树头）：`read` 经缓冲池、
  `write`/`allocate` 交给执行器的 `IndexIo`（**写必须带 redo**——索引项不做
  独立撤销（§9.1.2），但索引页受 WAL 保护；分裂记录的正文随记录 ⇒ 新页可重放
  重建）；`Tree::open(store, file_id, root)` 从树头打开、**高度由页类型下行推出**
  （树头只存 6B 根页 ROWID）；根页 ROWID 随根分裂变化 ⇒ 执行器在
  `InsertOutcome.grew` 时重写树头。
- 用例：单页往返（插/查/扫/删）、多层分裂全可查、99/1 常态路径占比、
  乱序插入 50/50 与可达性、非最右叶分裂的叶链回归、重复键按 ROWID 排序、
  空页留树、超长键拒绝、长公共前缀的区分前缀截断；**FFS 区读形态**
  （计数包装：零逐页读、≤ 8 页成组、与 IFS 同集合）与 `limit`；
  **聚簇因子**两种构造（完美聚簇 = 块区间数 / 交替块 = 行数）与值域不变量、
  空树全零；**接入端到端**（真段 + 真缓冲池：插入 → 树头写回段头页 →
  关池重开 → 按树头打开、全键可查、IFS 保序、FFS/统计与 IFS 对账；
  redo 镜像形态断言）。
