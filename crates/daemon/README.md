## 状态说明

实现进度请以仓库根 `README.md` 的阶段表为准。

设计依据（P1 切片）：

- **启动自检**（§17 的"启动恢复"）：逐工作区校验根与布局、以**句柄**确认可打开
  （`ISO` REQ-ISO-008）；任一失败 **fail closed**——整体不启动，不做半开
  （按工作区隔离降级归 `NFR` REL-005，P11 落实）；
- **`WorkspaceContext` 由监督器生成**（§14 明文），身份来自
  `AuthenticatedSubject`——路由是身份的函数（`ISO` REQ-ISO-002）；
- **两层资源拒绝**（`NFR` REQ-RES-001/004）：活跃工作区数（默认 8 / 上限 32）+
  每工作区任务额度（`max_task_queue`）+ 实例池队列，各自有界、满即拒绝，
  拒绝里带"哪个额度、当前值、上限"（`CONV` §4.3 资源类错误的字段形态）；
- **专用维护线程**（REQ-RES-003）：维护任务不经执行池——池打满时维护照常完成
  （用例直接验证这条）；
- 执行池**在途任务不被中断**：优雅关闭等在途任务跑完（刻意语义，强制终止归管理面）。
