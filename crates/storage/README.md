## 状态说明

设计依据（P2 切片）：

- **页格式**：页头 68B（描述区/事务区/空间区）、页尾副本（检断裂块）+
  CRC32C（检数据损坏）；槽位目录 2B/槽，上限 1023（与 `row_id` 10 位耦合）；
- **`ROWID`**：`file_id` 10 │ `block_id` 28 │ `row_id` 10，6 字节小端，不含代次；
- **行格式**：行头 10B + NULL 位图 + 变长列偏移数组；不设每列长度前缀；
  片段链（头片段 `row_len` = 整行长度）与转发指针（6 字节）；
- **堆表**（§5.7/§5.9/§8.4）：行自页底向上生长、`free_start` 可推导；
  插入复用最低空闲槽（`in_place`）或只追加（`append_only`）；
  **PCTFREE 是插入下限**（含新增槽位目录 2 字节的记账）；
  删除只置槽位空闲（空间留给 `defrag`）；
- **跨页行片段链**（§6.3）：插入时 **> 单页可用空间即自动成链**（否则普通插入）；
  头片段 = 完整行头 + 6B 下一片段 + 数据段（`row_len` = **片段自身长度**，
  与普通行同规；整行长度不存、由链求和推导）；**除末片外满装**；
  读取沿链收集并**回填整行长度、清除 `FRAGMENT` 位**（重组结果 = 原始行字节流）；
  三道防线：环检测 / 总长有界 / 片段自洽。
- **页文件**（`pagefile`）：块 = 页（16 KiB）定长；**写 = `seal` → 定址写 →
  调用方决定何时 `sync_data`**（不隐式 fsync）；**读 = 定址读 → 两层完整性
  校验**，损坏即返回 `Damaged`（**不静默返回数据**——REQ-STO-012）。
  经 P1 的 `FileIo` 替换接口，**故障注入（撕裂写）与页校验和在测试里闭环**，
  "关闭重开后结果一致"（关闭 → 丢 io 实例 → 重开 → 逐字节一致）有用例。
- **位图页与区分配图（LMT）**（`bitmap`，§3.2/§5.11）：页体头 8B
  （`kind` / `flags` / **`own_index`** / 保留）+ 位数组（**用尽页体**：
  16304 B = 130432 位）；**区 = 8 页 = 128 KB**、位图区 = 8 页位图
  （管 1043456 个区 ≈ 127 GB）、4 TiB 需 33 个位图区（上限 40）——
  三个数字是**算出来的**（扣页头 68 + 页尾 4 + 页体头 8），测试钉住；
  `own_index` 读盘自校验防"位图静默管错对象"；两种位图共用页体
  （kind 0 = 区分配图 1 位/区；kind 1 = 段内空闲级别 2 位/页）；
  分配**低位优先**、`ExtentMap` 管一个位图区、区号 → 数据区块号 = 1 + 区号×8；
  **不逐次 seal**——写回时由 `pagefile` 统一 seal。
- 内存 `Heap` 用顺序页号（`file_id = 1`、`block_id = 1+i`）——段管理
  （段头页、区清单、HWM）与 BufferPool 在后续切片接入。

P3 切片：

- **工作区控制文件**（`controlfile`，存储架构 §2.6 / §5.11，**恢复锚点**）：
  20 页 × 16 KiB = 320 KiB；页 0 文件头（段偏移表 8 项 + 固定偏移 132 的
  单条 undo 记录 522 B）、页 1 固定段（工作区条目 64 B │ 检查点进度 48 B │
  Redo 条目 128 B │ 归档记录 320 B）、页 2–19 数据文件记录数组
  （1024 × 280 B，**按页对齐**每页 58 条、不跨页）；
- **双副本**（`control01.ctl` / `control02.ctl`）：**先写 A 成功后写 B**，
  打开取"有效且 `seq` 较大"者；另一副本损坏/落后 ⇒ **由有效副本整份重建**；
  两份都不可用 ⇒ 该工作区无法启动（设计上接受的取舍）；
- **单区间更新协议**（≤ 512 B、不跨页、等长原地覆盖）：
  ① 写 undo（旧值）→ ② 写目标字节 → ③ 页 0 `seq` +1（发布）→ ④ 清 undo；
  崩溃后只看 undo 空不空：非空 ⇒ 用旧值回滚（幂等，"多退一次"可容忍）——
  **控制文件本身不产生 redo**（§5.11）；
- **联合发布** `write_checkpoint_and_groups`：检查点进度 + Redo 条目
  （相邻 176 B）**同一次更新**——§11.9 的发布纪律（降级不得先于低水位落盘）；
- **段头页与区映射**（`segment`，§4.2/§5.11）：段头公共部分 60B 固定偏移
  （页体头 8 / 段标识 16 / 空间状态 24 / 区映射头 12）；类型扩展区按
  `seg_type`（Undo = 事务表 6144B、B+Tree = 树头 6B、ANN 待 P8 明确拒绝）；
  区间项 = **起始 RDBA 5B │ 区数 2B**（7B/项，容量 2321——**修正**：
  设计文档原写 4B，是 Oracle 的 22 位块号宽度，装不下我们的 28 位块号）；
  **相邻者合并**（含桥接）、区数 2B 溢出不合并（保持正确性）；
  逻辑页号 → 物理块 = 经区映射（HWM/追加位置/位图页/HINT 全用逻辑页号）；
  段内位图页覆盖 [i×65216, (i+1)×65216)；`Rdba` 移入 `rowid`（redo 与
  区映射共用同一编码）。
- **数据文件与段的空间操作**（`datafile` + `segment` 的 `Segment`）：
  文件头页（偏移 68..88 字段 + **位图空间头** 88 起）与**尾部增长的
  LMT 位图区**（数据区自块 1 上行、位图区自尾部下行，相遇即 `FileFull`）；
  `allocate_extent` 候选越出数据区上限即回收位并报满（**位不泄漏**）；
  **段创建** = 首区 + 段头页（HWM/追加位置从 2 起、首区位图页 = 逻辑页 1）
  + 空闲级别位图（元数据 `FULL`、数据页 `High`）；**段扩展** = 新区就近
  合并 + 新页标 `High`；逻辑页号 → 物理块全程经区映射。
  **文件增长协议**（把位图区搬到新尾部再追加数据块）与多页位图随后。
- **Undo 段与事务表**（`undo`，§4.6.2/§4.6.3）：`txn_id` 三段式
  （`usn 8 │ slot 8 │ wrap 32`，6B）——**定位**量，`wrap` 让槽被复用后
  陈旧引用被判定为"不是自己"；事务表 256 槽 × 24B 在 undo 段头页扩展区
  （槽 0 起、`0xFFFF` 链尾），**段控制** 24B 紧随（`reclaim_seq`/提交链表/
  `slot_count`/`free_head`）；分配/释放（**释放时 `wrap + 1`**）/按
  `txn_id` 直接定位；**撤销记录**（`prev_undo 6B │ op 1B │ flags 1B │
  rowid 6B │ 载荷按 op`：插入空 / 删除整行 / 更新列前像 / 转发指针 /
  ITL 覆盖），多片标志沿用 Oracle8+ 的 0x01/0x02；`create_undo_segment`
  在 file 1 上建 `seg_type = Undo` 的段并初始化扩展区。
  **Undo 页写入与链的建立/回滚随后。**
- **ITL（事务槽）**（`itl`，§5.4）：条目 24B——`txn_id 6B │ undo_ptr 6B │
  commit_seq 6B │ lock_cnt 2B │ flags 1B │ 保留 3B`；**行锁即槽占用**、
  读路径只读条目判可见性；复用判据 `flags != Active ∧ lock_cnt = 0`；
  `grow` 动态扩展（受 `itl_max` 与页内空闲区约束）、`acquire`（复用优先、
  否则扩展、达上限明确报"应等待"）、`mark_committed`/`mark_rolled_back`、
  锁计数、**24B 原始快照/恢复**（`ITL 覆盖` undo 的旧值）。
  **布局要点**：ITL[0] 在 40；扩展槽在固定头之后（68 + (i−1)×24），
  空间区不被覆盖；"空"由 `flags` 表达（`txn_id = 0` 是合法身份）。
- **Undo 页写入与链**（`undo` 的 `put_record`/`get_record`/`UndoChain`）：
  撤销记录**只追加不复用槽**（记录向下生长）——**长度不存**：第 k 条 =
  上一条偏移 − 本条偏移，第 1 条上界 = 页初始 `free_end`（有测试钉住）；
  `UndoChain::append` 链头取自事务表槽 `undo_current`、**一个 undo 页
  同一时刻只服务一个事务**（换事务/放不下 ⇒ 新开页，必要时自动扩展段）、
  落盘次序 = **先数据页后段头页**（避免链头悬空）、页 ITL[0] 记占用事务、
  段内位图同步标级；`read` 经区映射反查（`logical_of_block`）按物理
  ROWID 回读；80 条 × 400B 跨三页的链走查有用例。
- **回滚链回放**（`undo` 的 `rollback_record`/`rollback_chain`/
  `rollback_transaction`）：五类补偿动作——插入→删行、删除→**原位**整行写回
  （槽须仍空闲、区域未被 defrag 占用；`SlotReused`/`RegionOccupied` 明确拒绝）、
  转发指针→回 `Forwarding`、ITL 覆盖→还原 24B（或恢复空闲，**载荷带 ITL 槽号**）、
  更新→**明确暂缓**（需要行布局，行/更新切片接入）；`rollback_transaction`
  取事务表槽链头 → 沿链回放 → 槽置空闲（`wrap + 1`）；
  `heap::delete_row` 改为**保留偏移**（回滚原位恢复的前提，§4.6.2 注④）。
  **幂等**：插入补偿遇"槽已空闲"= 空操作；删除补偿遇"槽里字节与旧值逐字节
  相同"= 空操作、不同才是"槽已复用"（拒绝）——恢复的撤销阶段"重走整链"、
  §4.6.6 ③ 的两条结论都落在这一对判据上。
- **一致性读回放**（`cr` 的 `reconstruct`，设计 §12.2/§12.3.1）：
  **在内存副本上**逐段回溯，源页一字节不动。判定：`Free`/`RolledBack` 直接可见；
  已清除的 `Committed` 用**页内 `commit_seq`** 快筛（不碰事务表）；其余由
  `txn_id` **直接定位**事务表槽——槽 `Committed` 比序号、`Active`/`PendingRollback`
  需撤销、**槽查不到（wrap 不符 = 已复用）即可见**。撤销：起点取**槽的
  `undo_current`**（ITL 的 `undo_ptr` 只作提示），沿链跳过别的块的记录、
  **撤销到本块的 `ITL 覆盖`记录即止**（还原前像 → 交外层重评估，前像仍不可见
  则继续下一轮）。三道防线各报具名错误：终止符缺失（`NoItlUndo`）、`prev` 环
  （步数 > `rec_count`，`ChainCycle`）、轮数上限（`TooManyRounds`）；8 条用例
  （未提交插入 / 提交晚于快照 / ITL 覆盖暴露旧事务 / 槽复用 / 三类防线 / 非数据页）。
- 六类注入覆盖（①–④ 各写点失败 + ②③④ 撕裂写）全部回退到旧值、重开后
  仍可继续发布有用例；`RedoEntries::validate` 拒绝不自洽发布
  （组数/成员数、至多一个 CURRENT 且与 `current_group` 互指、UNUSED 序列号为 0）。
