| 项 | 值 |
| --- | --- |
| 设计依据 | §8 崩溃恢复契约（存储架构 §11.1–§11.5，均已定案） |
| 对应阶段 | P3（已启动） |
| 当前状态 | **v0.3**——重做记录/redo 页字节格式 + 日志缓冲 + 日志文件落盘与扫描；日志组/切换、检查点、恢复（分析/重做/撤销）随后 |

## 状态说明

设计依据（P3 切片）：

- **记录（20B 头 + 块段 + 主段）**：`tot_len 4B │ lsn 6B │ txn_id 6B │
  op 1B │ flags 1B │ reserved 2B`；块段 = `blk_cnt` + 块引用（`flags 1B │
  rdba 5B │ chg_cnt 2B`）+ 块数据（`offset 2B │ len 2B │ after`）；
  主段**无长度字段**（由 `tot_len` 推导）；**只存 after-image**；
  **不带 CRC**（页尾校验覆盖每页）；
- **`rdba` 5B** = `file_id` 10 位 + `block_id` 28 位（比 PG 的 16B 省 11B）；
- **`op` 只是标签**（0x01 日志切换 / 0x02 检查点 / 0x10 页修改 / 0x30 提交 /
  0x31 回滚完成）——apply 路径唯一，幂等性由 `page_lsn` 判定；
  **空载荷记录（flags = 0）合法**（如回滚完成，信息全在头部）；
- **redo 页 512 B**（对齐文件系统原子写单位；页头 16B + 记录流），
  **分片头 12B**（`rec_id 6B │ frag_no 2B │ frag_cnt 2B │ frag_len 2B`）——
  分片解决的是**原子性**（系统操作的大记录跨页、单条仍原子），不是性能；
- **LSN = 日志流字节位置（分片头也算数）**；首片位置 = `rec_id` =
  记录头 `lsn` 字段（互为校验）；其余分片位置可推导、**不存**；
  新页起始 LSN = 上一页 + 512；
- **截断则整条丢弃**：分片序列不完整（末尾被截断）→ 该记录废弃，
  终止状态 `Truncated`（与"日志末尾不完整就停"同理）；
- **最坏单条 = 16417 B → 34 页 = 17 KiB**（测试钉住——组大小下限的来源）；
  "记录不得跨文件"在日志文件层接入时落实。
- **日志缓冲**（`buffer`）：追加经 **latch 串行化**（跨页无额外代价）；
  **持 latch 不执行文件 I/O**（摘页在 latch 内、写与 sync 在 latch 外）；
  **组提交**：`synced_lsn ≥ 目标` 的等待者直接返回（共享同一次 fsync）；
  **刷盘失败即放回**（页只有在 sync 成功后才离开"未刷出"集合——
  否则失败一次就丢页）；被刷出的页不再接受追加（页序列永远是文件前缀）。
- **日志文件**（`file`）：LSN = 物理字节位置（`偏移 = start_lsn − file_start`
  **互为校验**）；`FileLogSink` 顺序追加 + `sync_data`；**记录不得跨文件**
  （越界页直接拒绝：文件尾不足由上层切换逻辑处理）；`scan_log` 按**实际
  文件长度**扫描（崩溃后文件可短于声明容量）、空页即止、坏页即止，
  末尾残缺 → `Truncated`。
