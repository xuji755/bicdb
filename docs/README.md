## 几个容易误读的点

读之前先说明四处，它们在本项目里是刻意设计的，不是疏漏：

**① 存储层不做版本化**
记忆 revision、配置 revision 等"多版本"由**数据模型层**表达为额外的行/节点。存储层只做原地更新 + Undo。认为"记忆是版本化的，所以底层要版本化存储"是错误推导。

**② 行锁不由全局锁表承载**
行锁信息在**数据页的事务区（ITL）**里。这使可见性判定在块内自包含，不需要全局事务状态表。

**③ 索引扫描可能漏读，且这是已知行为**
RC 下语句开始后被并发删除的行，索引扫描可能读不到。这是同类模型的既有取舍，测试基线断言的是"**允许漏读**"，不是"必须可见"。

**④ public 只读不能只靠文件只读性**
成熟产品的只读表空间**不阻止仅改数据字典的 DDL**。public 的只读必须在**引擎层**拒绝，配合授权层双重保证。

**⑤ 文件系统的两项能力要分开看**
本库**不做整页写（FPW），也不做双写区**——torn page（部分写）防护交给文件系统。
但 **`reflink`（工作区克隆所依赖的）不等于"原子页写"**：XFS 的 reflink 只让**共享 extent** 在被写时走 COW，
一旦某段变成私有，后续写就是原地写。于是有个反直觉的组合——**XFS 支持 reflink 克隆，但不提供原子页写**。
**推荐首选 btrfs（两项都满足），次选 XFS。** 原子页写缺失是**显式接受的取舍**：
撕裂页由页校验和检出，按损坏处理（报错、从备份恢复），不会静默返回错误数据。
详见 [platform-support.md](platform-support.md) 与 [storage.md](storage.md) §11.6。
