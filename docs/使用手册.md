# bicdb 使用手册

适用版本：**v0.2.0**（V1.0 单工作区）。本手册面向**使用者**（建库、起停、写 SQL、排错）；
内部设计见 [design.md](design.md) 与 `doc/` 下的详设（本手册只讲"怎么用"）。

---

## 1 五分钟上手

```bash
cargo build --release            # 产物：target/release/{bicdb, bicdbcli}

# ① 建区：**唯一**接受目录的命令——"指向文件系统"那一步
./target/release/bicdb init /data/bicdb
#    已建区：/data/bicdb
#      参数文件  /data/bicdb/bicdb.ini      ← 实例参数文件（init 生成）
#      工作区    bicdb001
#      日志组    2 组 × 1 成员 × 8192 页

# ② 起服务（后台；之后一切按**参数文件**寻址，不再指向目录）
./target/release/bicdb start -p /data/bicdb

# ③ 用 SQL*Plus 形态的客户端连上去
./target/release/bicdbcli -p /data/bicdb
SQL> CREATE TABLE t (id NUMBER NOT NULL, name VARCHAR2(32));
SQL> INSERT INTO t VALUES (1, 'alpha');
SQL> SELECT id, name FROM t;
        ID NAME
---------- ----------
         1 alpha

1 row selected.
SQL> EXIT

# ④ 停服务（做完完全检查点再退）
./target/release/bicdb stop -p /data/bicdb
```

`bicdb sql` 适合**一条命令跑一次**（脚本、CI），`bicdbcli` 适合**交互**（缓冲、斜杠命令、
`SPOOL`、`@脚本`）。两者的 SQL 面完全一致。

## 2 实例寻址（记住一条就够）

**实例由参数文件寻址，不由目录寻址**（照 Oracle 的口径：`ORACLE_SID` 找到
`spfile<SID>.ora`；PG 用 `PGDATA`；我们用参数文件本身）。

- 参数文件叫 `bicdb.ini`，坐落于**根区目录**：`<db_root>/bicdb.ini`；
- **根区目录注册在参数文件里**（`[instance] db_root`），它是权威——参数文件放哪儿都行，
  实例在哪儿由文件内容说了算；
- 除 `init` 外，**所有命令都用 `-p` 指定参数文件**（给目录也行，等价于该目录下的
  `bicdb.ini`）。

**找不到参数文件时的顺序**：

| 顺序 | 位置 |
| --- | --- |
| 1 | `-p <参数文件\|根区目录>` |
| 2 | 环境变量 `BICDB_INI` |
| 3 | 当前目录的 `./bicdb.ini`（`cd` 进根区目录就免 `-p`） |

三者都没有 ⇒ 报错并列出试过的位置。

## 3 参数文件手册（`bicdb.ini`）

`bicdb init` 会**生成**它，含全部默认值（下面就是生成的内容）。改完**重启**生效；
`bicdb params` 随时看有效值与来源。

```ini
[instance]
db_root = /data/bicdb        # 根区目录（权威）

[init]                       # 建区期：init 读它造库；**建区后不可改**
file0_initial_blocks = 4096  # file 0（字典/数据）初始块数（16 KiB/块）
undo_initial_blocks  = 512   # 撤销文件初始块数
wal_groups           = 2     # 日志组数（2–8）
wal_members          = 1     # 每组成员数（1–8）
wal_group_pages      = 8192  # 每组成员页数（512 B/页）

[buffer]   pool_frames          = 256   # 缓冲池帧数（16 KiB/帧）
[storage]  file_extend_blocks   = 512   # 段增长撞文件尾时的固定增量（块；512 = 8 MiB）
[service]  socket               = bicdb.sock   # 控制套接字（相对根区目录）
           log                  = bicdb.log    # 服务日志
[lock]     park_ms              = 50    # 等锁单次挂起时长（毫秒）
           deadlock_threshold_ms = 1000 # 死锁检测阈值（毫秒）
```

**纪律**：

| 事 | 说明 |
| --- | --- |
| 闭集 | 未知节在 `[nope]` 那一行、未知键指到行号，**具名拒绝**（收下不生效比报错更糟） |
| 优先级 | 命令行 `-c 键=值`（可写全名 `buffer.pool_frames`，也可写唯一键名 `pool_frames`）> 参数文件 > 内置默认 |
| 建区期 | 建区后**不可改**：控制文件是权威，`bicdb start` 逐项核对，不符即拒绝启动（改需重建实例） |
| 建区期可定制 | `bicdb init /data/bicdb -c init.wal_groups=4 -c init.wal_members=2`（也可 `-p <种子.ini>` 复制参数） |
| 不核对的项 | `wal_group_pages`、`*_initial_blocks` 只作建区输入（日志文件是懒增长的，长度不是组容量；初始块数建区后由自动扩展接管） |

看有效值：

```bash
$ bicdb params -p /data/bicdb
节.键                              取值        来源   类别
instance.db_root                 /data/bicdb  文件   运行期
init.wal_groups                  2            文件   建区期
buffer.pool_frames               512          文件   运行期
...
```

## 4 命令参考

### 4.1 `bicdb`（管理命令）

| 命令 | 说明 |
| --- | --- |
| `bicdb init <根区目录> [-p 种子.ini] [-c 键=值]` | 建区 + 生成参数文件（**唯一**接受目录的命令） |
| `bicdb start [-p 参数文件] [-s 套接字] [-l 日志] [-w 秒] [-c 键=值]` | 后台起服务；**等就绪**才返回（`-w` 默认 30 秒） |
| `bicdb stop [-p 参数文件] [-m fast\|immediate]` | 停服务：`fast`（默认）= 完全检查点后退出；`immediate` = 直接退出，下次打开走崩溃恢复 |
| `bicdb status [-p 参数文件]` | 服务/实例状态（pid、套接字、运行秒数、已服务请求数、提交序号） |
| `bicdb restart [-p 参数文件]` | = stop(fast) + start |
| `bicdb params [-p 参数文件] [-c 键=值]` | 全部可调项 + 取值 + 来源 + 类别 |
| `bicdb sql [-p 参数文件] "<SQL>"… [--param 名=值 …]` | 执行 SQL（多条用 `;` 分隔；`-` = 读 stdin）；**服务在跑时自动经套接字** |
| `bicdb shell [-p 参数文件]` | 简易交互式 shell（要 SQL*Plus 形态请用 `bicdbcli`） |
| `bicdb version` / `bicdb help` | 版本 / 帮助 |

**参数化查询**：语句里写 `:名`，命令行给值：

```bash
bicdb sql -p /data/bicdb --param id=7 "SELECT name FROM t WHERE id = :id"
bicdb sql -p /data/bicdb --param "s='abc'" "INSERT INTO t VALUES (1, :s)"   # 字符串加单引号
```

值文本的形态：`NULL` / `TRUE` / `FALSE` / `'文本'` / 其余按数值。缺失、多给、形态不符
都是**具名错误**。

### 4.2 `bicdbcli`（SQL\*Plus 形态客户端）

```bash
bicdbcli [-p 参数文件] [-S] [--direct] [@脚本]
  -S        静默：不出横幅与提示符（结果照打）
  --direct  强制直连（服务在跑时会被实例锁挡住——单写者纪律）
```

**连接选路**：服务在跑 ⇒ 经控制套接字（一个连接 = 一个会话，`BEGIN … COMMIT` 跨语句成立）；
没人占 ⇒ 本进程直连；别的进程直连着 ⇒ 拒绝。

**SQL 输入**：

```text
SQL> SELECT id, name
  2    FROM t
  3   WHERE id > 0
  4   ORDER BY id;
        ID NAME
---------- ----------
         1 alpha

1 row selected.
SQL> /            ← 单独一行 `/` = **重跑当前缓冲**（不回显）
SQL> RUN          ← 列出缓冲再跑
```

- `;` 结尾执行；**空行**结束输入但**不执行**（缓冲保留）；`--` 行注释不挡分号；
- 续行提示符是**行号**（`  2  `、`  3  `）。

**缓冲编辑**（都按行号，`LIST` 的 `*` 是当前行）：

| 命令 | 作用 |
| --- | --- |
| `LIST`(`L`) [`n`\|`n m`\|`*`\|`LAST`] | 列出缓冲 |
| `DEL`(`DELETE`) [范围] | 删行 |
| `APPEND`(`A`) 文本 | 追加到**当前行**末尾 |
| `INPUT`(`I`) 文本 | 在**当前行之后**插一行 |
| `CHANGE`(`C`) `/旧/新/` | 替换当前行里的第一处 |
| `CLEAR BUFFER`(`CL BUFF`) | 清空缓冲 |

**会话参数**（只列有落点的）：`SET ECHO ON|OFF`（执行前回显）、`SET FEEDBACK`（`N rows selected.`）、
`SET TIMING`（`Elapsed: …`）、`SET PAGESIZE n`（分页并重打表头；0 = 不分页）、
`SET LINESIZE n`、`SET NULL <文本>`（NULL 的显示形态）、`SET TERMOUT ON|OFF`（脚本执行时是否上屏幕，
**SPOOL 照收**）、`SET SQLPROMPT <文本>`、`SET VERIFY`、`SET CONCAT <字符>`；`SHOW [参数]` 看当前值。

**其它命令**：

| 命令 | 作用 |
| --- | --- |
| `SPOOL <文件>` / `SPOOL OFF` / `SPOOL OUT` | 把输出同时写进文件 / 关 / 关并报文件名 |
| `START <文件>` / `@<文件>` / `@@<文件>` | 跑脚本（`@@` 相对当前脚本目录）；脚本里命令与 SQL 都能写 |
| `WHENEVER SQLERROR EXIT\|CONTINUE` | 脚本遇错：中断（退出码 1）或继续 |
| `DEFINE 名=值` / `UNDEFINE 名` / `&名` / `&&名` | 替换变量（`&&` 记住值） |
| `DESCRIBE`(`DESC`) <对象> | 列名/可空/类型（`Name / Null? / Type` 版面） |
| `HOST 命令` / `!命令` | 跑宿主命令 |
| `PROMPT 文本` / `REM 注释` | 输出一行 / 注释 |
| `TIMING [ON\|OFF]` · `EXIT`(`QUIT`) [码] · `HELP [主题]` | 计时 / 退出 / 帮助 |

**脚本示例**（`load.sql`）：

```sql
SET ECHO OFF
SET FEEDBACK ON
WHENEVER SQLERROR EXIT
CREATE TABLE emp (empno NUMBER NOT NULL, ename VARCHAR2(20), sal NUMBER);
INSERT INTO emp VALUES (1001, 'SMITH', 800);
INSERT INTO emp VALUES (1002, 'ALLEN', 1600);
DEFINE min_sal = 1000
SELECT empno, ename, sal FROM emp WHERE sal >= &min_sal ORDER BY empno;
```

```bash
bicdbcli -S -p /data/bicdb @load.sql        # -S + 脚本 = 批处理；退出码 0/1
```

## 5 SQL 面（v0.2.0）

**支持**：

| 类 | 语法 |
| --- | --- |
| 查询 | `SELECT 列[, …] FROM 表 [WHERE 条件] [ORDER BY 输出列名/序号 [ASC\|DESC]] [LIMIT n] [OFFSET n]`（单表、无聚合；**排序键必须在 SELECT 的输出列里**——想按不投影的列排序，就把它加进 SELECT） |
| 写入 | `INSERT INTO 表 [(列, …)] VALUES (值, …)[, (…)]`（值 = 字面量或 `:参数`） |
| DDL | `CREATE TABLE t (列 类型 [NOT NULL], …) [WITH (pctfree = n, itl_max = n, …)]`、`CREATE [UNIQUE] INDEX i ON t (列[, …])`、`DROP TABLE t`、`DROP INDEX i` |
| 事务 | `BEGIN` / `COMMIT` / `ROLLBACK`（一组语句一个会话；DDL 不能在显式事务里） |
| 表达式 | 算术 `+ - * /`、比较 `= <> < <= > >=`、`AND`/`OR`/`NOT`、`IS [NOT] NULL`、`IN (…)`、`BETWEEN … AND …`、`CAST(x AS 类型)`、`CASE WHEN …`、一元 `+`/`-`、`:参数` |
| 类型 | `NUMBER` `CHAR(n)` `VARCHAR2(n)` `DATE` `TIMESTAMP` `BOOLEAN` `UUID` `RAW(n)`（列类型码与 `DESCRIBE` 同源） |
| 名字 | 未引号名照 PG **折叠小写**；`"引号名"` 原样；**非 ASCII 可用**（`名称`，照 PG 的扫描器） |

**明确不支持**（都会在**绑定期具名拒绝**，绝不静默）：

`UPDATE` / `DELETE`；多表 `FROM` / `JOIN` / 表别名；子查询 / CTE / 窗口函数；
聚合（`COUNT`/`SUM`/`GROUP BY`/`HAVING`）、`DISTINCT`、集合运算（`UNION`…）、`LIKE`、
`NULLIF`、`COALESCE`、函数调用；`INSERT … SELECT`；`DROP … IF EXISTS`；
`ALTER TABLE` / 视图 / 约束；`CREATE WORKSPACE` 等管理语句（走 DCL 切片）。

**自增号**：`CREATE TABLE` 不带自增列；主键/唯一由 `CREATE UNIQUE INDEX` 提供。

**唯一索引语义**（MySQL/PG 同款）：**键含 NULL 的行不参与唯一性**（多个 NULL 合法）；
冲突在**写前**判定——取同键候选行、按**行字节重算键**逐字节比，命中即报
`唯一约束冲突`，语句整体不写。

## 6 运维

### 6.1 文件面（根区目录里有什么）

```text
<db_root>/
├── bicdb.ini                   实例参数文件（实例的入口）
├── bicdb.pid                   实例锁（pid + 进程启动时刻 + 模式；陈旧自动接管）
├── bicdb.sock                  控制套接字（服务模式；随服务退出清理）
├── bicdb.log                   服务日志（启动/恢复/收尾/in:语句失败 各记一条）
├── control/control01.ctl       控制文件双副本（恢复锚点）
│         control02.ctl
├── wal/redo_g1_m1             日志组 × 成员（组数/成员数由 [init] 定）
│      redo_g2_m1
└── data/bicdb001_meta          file 0：数据字典（+ 引导页）
       bicdb001_undo            file 1：撤销
       （后续数据文件为 bicdb001_data_NN）
```

### 6.2 单写者纪律（实例锁）

同一实例**同一时刻只允许一个写者**：服务在跑时直连被拒（反之亦然）。
判活 = pid 存在 **且** 进程启动时刻与记录一致（防 pid 复用）；进程没了（含 `kill -9`）
就是**陈旧锁**，下一个打开者自动接管——不需要手工删文件。

```bash
bicdb start -p /data/bicdb     # 服务在跑时再来一次：
# bicdb：实例已被 pid 1234（服务模式）占用
```

### 6.3 崩溃与恢复

| 情形 | 结果 |
| --- | --- |
| `bicdb stop`（fast） | 完全检查点后退出：下次打开**无需重放** |
| `bicdb stop -m immediate` | 不做检查点直接退出：下次打开**走三阶段恢复**（提交记录在日志里，**已提交的数据不丢**） |
| 进程被 `kill -9` / 掉电 | 同上；陈旧锁自动接管，`bicdb status` 会报"未运行（陈旧锁）" |
| 换错控制文件 | **拒绝打开**：`拒绝打开：文件超前于控制文件（FILE_SCN_AHEAD …）` |

### 6.4 排错

| 现象 | 处置 |
| --- | --- |
| `找不到参数文件 bicdb.ini——试过：…` | 用 `-p <参数文件\|根区目录>`，或 `cd` 进根区，或设 `BICDB_INI` |
| `未知节 [x]` / `第 N 行：… 里没有参数 y` | 参数文件写错了（闭集）；`bicdb params` 看全部可调项 |
| `建区期参数与既有的库不符（改需重建）` | 该参数（日志组数/成员数）建区后不可改；改回原值，或重建实例 |
| `实例被 pid N 占用（服务模式/直连模式）` | 用 `bicdb stop` 停服务，或等直连进程退出；`bicdb status` 看详情 |
| `服务进程 N 已退出（exit status: 1）——日志 …：` | 错误里已带日志尾行（参数错、控制文件不符等按提示处置） |
| `等待就绪超时` | 看 `bicdb.log`；大库恢复慢时加大 `-w` |
| `唯一约束冲突（重复键 …）` | 撞唯一索引；改键值或去掉索引 |
| `绑定期不支持：…` | 该语法本版不支持（见 §5 清单）；报错文本会说明 |

### 6.5 备份（V1.0 的现状）

崩溃恢复≠备份。当前可用做法：**停服务后整目录复制**：

```bash
bicdb stop -p /data/bicdb
cp -a /data/bicdb /backup/bicdb-$(date +%F)
bicdb start -p /data/bicdb
```

⚠️ **副本换位置后要改参数文件里的 `db_root`**（它注册的是**绝对路径**，与 Oracle 的
pfile 记绝对路径同理）：

```bash
# 从 /data/bicdb 拷到 /backup/bicdb-2026-10-06 之后：
sed -i 's|^db_root = .*|db_root = /backup/bicdb-2026-10-06|' /backup/bicdb-*/bicdb.ini
bicdb sql -p /backup/bicdb-2026-10-06 "SELECT …"
```

热备、时间点恢复（PITR）与归档属后续切片（设计见 `docs/design.md` 与 `doc/` 详设）。
