# bicdb 使用手册

适用版本：**v0.2.0 当前开发版**（单机、多工作区、本机协议）。面向**使用者**：装、建库、连、建表、写 SQL、运维、驱动。
详细设计和已公开的功能边界见 `doc/bicdb_*.md`；本手册只讲"怎么用"，并且**只承诺已经能跑的东西**——
设计好但未实现的，一律标"未实现 + 归属切片"，绝不写成"可以这样用"。

## 1 五分钟上手

```bash
# ① 安装（挑一个可写、可见的根并打印是哪个；也可 --home 指定）
scripts/install.sh
export BICDB_HOME=$HOME/bicdb-home          # 安装脚本会打印实际路径
export PATH="$BICDB_HOME/app/bin:$PATH"

# ② 建库（不给参数 = 初始化部署的 PUBLIC 工作区）
bicdb init

# ③ 起服务（后台；之后一切按**工作区名或参数文件**寻址）
bicdb start -p public

# ④ 用 SQL*Plus 形态的客户端连上去
bicdbcli -p public
SQL> CREATE TABLE t (id NUMBER NOT NULL, name VARCHAR2(32));
SQL> INSERT INTO t VALUES (1, 'alpha');
SQL> SELECT id, name FROM t;
        ID NAME
---------- ----------
         1 alpha

1 row selected.
SQL> EXIT

# ⑤ 停服务（fast = 做完完全检查点再退）
bicdb stop -p public
```

`bicdb home` 一条命令告诉你**程序/数据/日志/备份**四条路径——不用到处找。
`bicdb sql` 适合"一条命令跑一次"（脚本、CI）；`bicdbcli` 适合交互（缓冲、斜杠命令、`SPOOL`、`@脚本`）。
两者 SQL 面完全一致。**源码树里开发**不用装：`cargo build --release` 之后照 §3.3 用路径式建库。

## 2 安装

### 2.1 一根五目录（四件事 + 一个注册表）

```bash
scripts/install.sh [--home <目录>] [--no-build] [--force]
scripts/uninstall.sh [--home <目录>] [--purge] [--yes]
```

```text
<BICDB_HOME>/
├── app/           程序（bin + share + VERSION；**只读**，升级 = 换这一目录）
├── control/       **全局控制文件双副本**（实例注册表：有哪些工作区、各自在哪；
│                  文件系统池）——`bicdb init` 首次建立
├── public/        **PUBLIC 工作区**（数据库；结构见 §3.4）
├── log/           数据库日志（按工作区命名：public.log）——**排障第一站**
└── backup/        默认的备份包落地处
```

默认根（挑第一个**可写**的）：`/u01/app/bicdb` → `/opt/bicdb` → `$HOME/bicdb-home`，**装完会打印是哪个**。

| 想知道 | 去哪看 |
| --- | --- |
| 程序在哪、什么版本 | `app/`（`bicdb home` 一行打印） |
| 数据在哪 | `public/`（工作区自包含，`cp -a` 可搬走） |
| 日志在哪 | `log/public.log`（**所有日志在一个目录**，不跟工作区分撒） |
| 备份放哪 | `backup/`（⚠️ 同一块盘上的"备份"不算备份，生产要指到另一块盘） |
| 有哪些工作区 | `bicdb list`（**以 `control/` 里的注册表为准**）；`control/` 永不手改 |

### 2.2 `BICDB_HOME` 怎么定

| 顺序 | 来源 |
| --- | --- |
| 1 | 环境变量 `BICDB_HOME` |
| 2 | **二进制位置推断**：`<home>/app/bin/bicdb`（路径形状自证；开发树 `target/release/` 不满足） |
| 3 | 未安装（报错并指路，**不猜**） |

### 2.3 卸载

默认**只删 `app/`**（程序），数据/日志/备份保留；`--purge` 才连数据一起删（要打 `yes` 二次确认）；
**有工作区在跑时拒绝卸载**（先 `bicdb stop`，或 `--force`）。

## 3 建库（创建数据库）

### 3.1 部署形态

```bash
bicdb init                 # 建 <BICDB_HOME>/public —— 初始化这次部署
```

### 3.2 额外工作区（测试/演练）

```bash
bicdb init shop            # 建 <BICDB_HOME>/shop（名字式；不含 `/`）
bicdb list                 # 列 <BICDB_HOME> 下的工作区与状态
bicdb start -p shop        # 名字式寻址
```

> 名字式是"额外根目录"的便利，**不是**多工作区功能（§5.3）——多工作区要有属主、配额、
> 字典登记（`public.ws$`），那是 D2 切片。

### 3.3 路径式（不受安装形态约束）

```bash
bicdb init /srv/bicdb/dev      # 含 `/` 的路径原样使用（源码树里开发就这么用）
bicdb start -p /srv/bicdb/dev
```

### 3.4 建出来的东西（工作区目录结构）

```text
<工作区根>/                        # public 或你给的路径
├── bicdb.ini      实例参数文件（**入口**：db_root 注册在它里面，权威）
├── bicdb.pid      实例锁（单写者；陈旧锁自动接管）    bicdb.sock  控制套接字
├── control/       control01.ctl · control02.ctl     ← 控制文件双副本（恢复锚点）
├── wal/           redo_g1_m1 · redo_g2_m1 …         ← redo（组 × 成员）
└── data/                                            ← 表空间文件，**角色写在文件名里**
    ├── 7c9fa136d4413fa6_meta     file 0：数据字典 + 引导页
    ├── 7c9fa136d4413fa6_undo     file 1：撤销
    ├── 7c9fa136d4413fa6_temp     file 2：临时（溢出；不备份）—— 随溢出切片建
    └── 7c9fa136d4413fa6_data_NN  file 3..：**用户数据**

（前缀 = `workspace_ref` 的十六进制 = `SHA-256(工作区号)` 前 8 字节——
**文件名与文件头里的标识同源**，看一眼名字就知道文件属于哪个工作区。）
```

只有三个子目录，因为只有三样东西的生命周期不同：`control/`（建区与日志切换时写）、
`wal/`（**循环复用**）、`data/`（只增长）。`catalog`/`undo`/`temp` 不是目录——它们是
file 0/1/2 的**角色**；`index` 是数据文件里的段；文件名后缀一眼可辨。

**建区时可定**（建后不可改，控制文件是权威）：`bicdb init -c init.wal_groups=4 -c init.wal_members=2` ——见 §9。

## 4 存储位置与"登记文件系统"

### 4.1 现在怎么定位置（已实现）

**位置由参数文件注册**：`bicdb init <路径>` 决定工作区根落在哪个文件系统上，
`<工作区根>/bicdb.ini` 里的 `db_root` 是权威（把整个目录拷到别处，改这一行即可）。

也就是说：**今天"登记文件系统"= 把工作区建在那个盘上**（`bicdb init /data2/bicdb/public`），
数据文件（`data/<标识>_*`）就落在那里。

### 4.2 文件系统池（**F 组已实现**）

设计（`docs/storage/02-工作区存储布局.md` §2.8–§2.10、`DCL语句设计` v0.2 §1.2）：

```sql
CREATE FILESYSTEM data2 USING '/data2'                 -- 登记（校验存在、可写、是目录、非符号链接）
ALTER FILESYSTEM data2 SET ALLOCATE = OFF              -- 排水阀：不再分配新文件
DROP FILESYSTEM data2                                  -- 移出（硬前置：该盘上没有任何数据文件）
```

**名字是标识，路径只是创建参数**：`CREATE FILESYSTEM data2 USING '<路径>'` 给的是**名字** `data2`，
之后引用它用 `data2`（或池槽位号），**不再写路径**。**"文件系统"可以是一个独立挂载的文件系统，
也可以只是一个目录**——校验只要求"存在、可写、是目录、非符号链接"（**不要求是挂载点**）。
这也意味着池成员**不保证物理隔离**：同一块盘上可以登记多个目录，隔离只按**路径与配额**算。

- 池是**实例级**的：工作区不是一个物理目录，而是**跨文件系统的命名空间**——容量上限是整池；
- 登记信息存**全局控制文件**（权威、可重建），`public.fs$` 供查询；
- 数据文件的完整路径记在**工作区控制文件**里（工作区自包含到能独立定位自己的全部文件）；
- 新数据文件按池策略选盘；资产（`assets/`）按**卷**分布。

**现状（2026-10-07）**：**F 组已能真跑**（`CREATE/ALTER/DROP FILESYSTEM`）——两处都写：
**实例注册表**（`<BICDB_HOME>/control/` 的全局控制文件，双副本）与 `public.fs$` 行；
**写序固定：属性先、注册表最后**。管理面语句**只在 `public` 上执行**（别的区连上去发
会得到具名拒绝）。路径校验 = 存在、可写（**探针文件实测**）、是目录、**非符号链接**；
`DROP FILESYSTEM` 的硬前置 = 该路径下没有在册工作区。
```bash
bicdb sql -p public "CREATE FILESYSTEM d1 USING '/srv/data1'"
bicdb sql -p public "ALTER FILESYSTEM d1 SET ALLOCATE = OFF"   # 排水阀
bicdb sql -p public "DROP FILESYSTEM d1"                       # 硬前置：该盘上没有工作区
```
**未做**：新数据文件的落盘选盘（分配器读池）随 D2 的工作区切片；`Move` 随 C5。
**v0.2 变更**：旧的 `ALTER SYSTEM ADD|ALTER|DROP FILESYSTEM …` 已删除（与 `CREATE/ALTER/DROP
WORKSPACE`、`CREATE/ALTER/DROP USER` 同构化为三件套）；发旧语句会得到**指路文案**。

### 4.3 `file$`：本工作区的文件清单（**固定表**，只读）

```sql
SELECT * FROM file$;                             -- 本工作区登记在册的数据文件
SELECT "file#", role, path FROM file$ WHERE role = 0;
SELECT COUNT(*), SUM(creation_blocks) FROM file$; -- 它就是个普通行源
```

```text
file# | role | status | flags | creation_blocks | created_at    | path
------+------+--------+-------+-----------------+---------------+---------------------------
    0 |    0 |      1 |     0 |            4936 | 1791349549135 | /data/bicdb/data/…_meta
    1 |    1 |      1 |     0 |             512 | 1791349549135 | /data/bicdb/data/…_undo
```

- **行来自控制文件**（**权威**，不是扫 `data/` 目录）：控制文件里登记了什么，`file$` 就有什么；
  `creation_blocks` 是**创建时**大小——"现在多大"以文件头自述为准（`db_check`/`page_dump` 看它）；
- **它是固定表**：不落盘、不在 `obj$`（字典）里、**没有写入口**——
  `INSERT/UPDATE/DELETE/DROP` 对它的答案与"这张表不存在"一模一样（不是"拒绝"，是**没有这条路**）；
- 用法与普通表**完全一样**：`WHERE` / `ORDER BY` / 聚合 / 别名 / **连接**都行；
- **`public` 的 `file$` 只给管理面身份**（本机/OS 连接）：它属于**管理元数据**，
  以主体身份（`-U`）连上去看它是"表不存在"（不泄露"有这张表但你没权限"）；
  普通工作区的 `file$` 对其属主可见；
- **登记**：控制文件的数据文件记录在**建区**时写入（file 0/1），**打开**时幂等补登记
  （本切片之前建的实例，打开一次后 `file$` 就有行）。

**还没做的解释面**：`session$` / `lock$`（会话/锁内省）是同一个固定表机制的下一批
（`API` REQ-API-018）；缓冲区与工作集、检查点进度、redo 组状态也可以照此开。

## 5 用户与工作区

### 5.1 用户（主体）：**已落地**（U1–U7；口令读不回）

主体两类（`doc/spec/ISO.md`、`doc/用户与配额管理设计_v0.1.md`）：

| 主体 | 说明 |
| --- | --- |
| **admin** | 实例级管理主体。**管实例**：建/删/暂停/恢复用户、分配 FS 与配额、重置口令、建/删工作区、增删文件系统、读写 `public`。**不看用户数据**（见 §5.2） |
| **普通主体** | 身份来自**认证结果**（REQ-ISO-002），名下**可以有多个工作区** |

**设计（2026-10-07 补齐，`doc/用户与配额管理设计_v0.1.md`）**：

**依赖顺序是硬纪律：先有 FS，再有工作区，才能建用户**（`FS → WORKSPACE → USER`）：

```sql
CREATE USER alice IDENTIFIED BY '初始口令' USING WORKSPACE 'alice_ws';  -- 建主体 + 绑定工作区
ALTER USER alice PAUSE;                  -- 暂停：拒绝新会话（≈ Oracle ACCOUNT LOCK）；已开会话不掐断
ALTER USER alice RESUME;                 -- 恢复
ALTER USER alice USING WORKSPACE 'alice_ws2';   -- 加绑（1 用户 : N 工作区；目标须无主或已属本人）
ALTER USER alice DROP WORKSPACE 'alice_ws2';    -- 解绑（区变无主；不允许解绑最后一个）
ALTER USER alice IDENTIFIED BY '新口令';   -- **admin 重置口令**（遗忘找回：是重置，不是取回原文）
ALTER USER alice IDENTIFIED BY '新口令' EXPIRE;  -- 置"下次登录必须改密"
DROP USER alice [CASCADE];               -- 有工作区且无 CASCADE ⇒ 拒绝并列出
```

**`USING WORKSPACE` 是必选**——工作区是数据的去处，"建一个没有区的用户"没有意义；
**`CREATE WORKSPACE FOR USER` 不存在**（v0.2 删除）：属主只在 `CREATE USER … USING WORKSPACE` 一处定，
"一条语句只做一件事"。**配额与默认盘都归工作区**（`ALTER WORKSPACE … SET DEFAULT FILESYSTEM` /
`… ADD FILESYSTEM … QUOTA …`），用户经绑定获得——**"给用户分配 FS 与配额"就是"给他的工作区分配"**。

**现在就能跑**（2026-10-07）：上面这一组语句（U1–U7）已在 `public` 上实现——
前提是依赖顺序 `FS → WORKSPACE → USER` 都满足（先 `CREATE FILESYSTEM`，再 `CREATE WORKSPACE`，
最后 `CREATE USER … USING WORKSPACE`）。口令存的是 **PBKDF2-SHA512 散列 + 盐**（自描述形态
`pbkdf2-sha512$<迭代数>$<盐>$<摘要>`）：**任何人（含 admin）都读不回原文**，
"遗忘找回"= `ALTER USER … IDENTIFIED BY '<新口令>'` **重置**为新口令。登录见 §6.4。
**归属**：D2.5（用户面）✅、D3（文件系统池）✅、D6（认证）✅ 本机部分。

### 5.2 admin 管用户，但**不看用户数据**；授权矩阵**本产品不做**

**两件事别混读**：**管理用户**（建/删/暂停/恢复、配额、重置口令）= admin 的运维职责，**做**；
**授权**（`GRANT SELECT ON t TO r` 那类对象级矩阵）= **不做**（REQ-ISO-003 明文禁止）。

| 访问对象 | 谁 | 规则 |
| --- | --- | --- |
| **自己的工作区** | 属主 | **全部权限**——这里没有"授权"这回事，因为**没有第二个主体能进来** |
| **`public`** | 任何普通主体 | **只读** + 经标准接口发布 |
| **别人的工作区** | 任何人，**含 admin** | **没有入口**（不是"拒绝"，是没有这条路径） |

**admin 能 / 不能**（`doc/用户与配额管理设计_v0.1.md` §1、§6）：

| 能 | 不能 |
| --- | --- |
| 建/删/暂停/恢复用户、分配 FS 与配额、**初始化与重置口令**（写新散列，留痕） | 任何工作区的**行数据**（没有入口） |
| 元数据与清单（`user$`/`ws$`/`fs$`/`uq$` 的名字、状态、配额、用量） | **读回口令**（PBKDF2-SHA512 散列不可逆——"找回"= 重置为新口令） |
| 脱敏内省（`session$`/`lock$`：指纹代正文）、备份（整包搬） | 以"管理身份"获得数据访问（跨 owner 克隆也被 REQ-ISO-012 禁止） |

### 5.3 工作区：`CREATE WORKSPACE` **已能用**（管理面）

**附件 SQL**：在具名认证的私有工作区，可执行 `SELECT * FROM attachment$` 查看当前主体、当前工作区的附件元数据，也可用 `attachment_grep('IO')` 检索支持的 UTF-8 文本附件。`SHOW TABLES` 将其列为 `VIRTUAL`；目录只读，客户端 `HELP ATTACHMENTS` 给出过滤参数、完整性验证及类型限制。

**字典只读查询（2026-10-08）**：管理连接可执行 `SELECT * FROM tab$`、`SELECT * FROM fs$`、`SELECT * FROM ws$`、`SELECT * FROM user$`，并支持过滤、排序、聚合及关联。user$ 不暴露 passwd 列或口令散列；字典不能通过 DML/DDL 修改，相关变更仍使用专门管理命令。普通用户可读当前工作区的结构字典，PUBLIC 管理清单仅管理身份可见。

语法（`DCL语句设计` §1.2、§1.5）——**W1–W6/W8 已落地**；标 `（未实现）` 的随 **D5**：

```sql
CREATE WORKSPACE alice_ws                            -- 建**无主**容器（三步：建文件+引导页 → 建字典 → 登记 public.ws$）
CREATE WORKSPACE alice_ws DEFAULT FILESYSTEM data1   -- 新数据文件默认落哪块盘（缺省 = 实例默认盘）
CREATE WORKSPACE mem FROM TEMPLATE 'base'            -- 当前支持空结构初始化模板（W2），不复制业务行
CREATE WORKSPACE alice_ws QUOTA 1073741824 ON FILESYSTEM data1   -- 盘级配额（量 = 字节数或 UNLIMITED）
ALTER WORKSPACE alice_ws ADD FILESYSTEM data2 QUOTA UNLIMITED ON FILESYSTEM data2  -- 扩盘
ALTER WORKSPACE alice_ws SET DEFAULT FILESYSTEM data2   -- 之后的新文件改落 data2
ALTER WORKSPACE alice_ws SET NAME = 'alice2'            -- 改名（实例内唯一）
ALTER WORKSPACE alice_ws SET QUOTA (data = 1073741824, undo = 268435456, temp = 536870912, asset = 0)
ALTER WORKSPACE alice_ws TO TEMPLATE 'base'             -- 未实现：原地转模板（W7/D5）
DROP WORKSPACE alice_ws
ALTER DATABASE ADD TEMPLATE 'mem' FROM 3                -- 当前支持无主、空闲、零业务行源区的结构模板
ALTER DATABASE DROP TEMPLATE 'mem'
```

**引用位两种写法**：整数（`workspace_id`）或名字（字符串）——**名字实例内唯一**，
所以旧的 `FOR USER` 限定名整套作废（建区那一刻还没有属主，没法用属主限定）；
**模板的取用只有一条路**（`CREATE WORKSPACE … FROM TEMPLATE`，W2），原地固化是 W7——
一件事不设两个入口。

- **隔离单元是工作区，不是表**：一个主体一个（或多个）工作区；私有表/图/向量/资产天然属于所在工作区；
- **模板当前实现**复制空业务结构与索引定义，不复制业务数据；适合为新主体初始化同构工作区。通用带数据快照/reflink 尚未实现；
- 管理动作**都是 admin**；"普通主体自助建区"记暂缓（需求未含）。

**现状（2026-10-07）**：**F 组与 W1–W6/W8 已能真跑**——`CREATE WORKSPACE` 会建出
**一整套独立的工作区文件面**（`<BICDB_HOME>/<名>/`：参数文件 + `control/` + `wal/` +
`data/`），登记进 `public.ws$`（**属主为空**）与实例注册表；之后
`bicdb start -p <名>` 就能把它当**自己的库**用（各自的字典、日志、控制文件——
故障域也在它自己身上）。

```bash
bicdb sql -p public "CREATE WORKSPACE alice_ws DEFAULT FILESYSTEM d1"   # 无主容器
bicdb start -p alice_ws && bicdb sql -p alice_ws "CREATE TABLE t (id NUMBER NOT NULL)"
bicdb sql -p public "ALTER WORKSPACE alice_ws SET DEFAULT FILESYSTEM d2"
bicdb sql -p public "ALTER WORKSPACE alice_ws SET NAME = 'alice2'"      # 改名（目录名不动）
bicdb sql -p public "DROP WORKSPACE alice2"                            # 先 stop 那个区，否则拒绝
```

**依赖顺序是硬纪律**：池为空时 `CREATE WORKSPACE` **拒绝**（先 `CREATE FILESYSTEM`）。
**三步的可见性开关是注册表**：契约是"①文件 ②`ws$` ③注册表"——崩在中间只留孤儿文件，
不会出现"看不见却以为自己存在"的半死工作区；`DROP` 走**反向**三步（可见性**先断**、
再 `ws$` 墓碑、最后清目录），且**删之前先预检**（目录被活实例占着 ⇒ 拒绝且**不动任何状态**）。
**`public` 是保留工作区**：不能 `DROP WORKSPACE`。

**仍未完成**：带业务数据的快照模板、reflink 克隆和 W7 原地转模板。U 组用户管理、
T1/T2 模板管理与 W2 从空结构模板创建工作区已经可用。`DEFAULT FILESYSTEM` 已记录进
`ws$`；后续数据文件扩展仍需继续完善跨文件系统放置策略。

### 5.4 记档

- **配额是两级的**（都挂**工作区**）：角色级（`ws$` 四列 data/undo/temp/asset，**已有模型**）
  ＋ 盘级（新增 `wq$`：某个区**在某块盘**上的上限，Oracle `QUOTA … ON <表空间>` 的同位物）；
  用户经"绑定工作区"获得这两级限额——**用户自己不带配额列**（一个概念只留一处）。执行点在段分配/扩展处。
- **口令策略**（有效期、失败锁定、历史）、**PROFILE 式资源限制**（Oracle 的 `CPU_PER_SESSION` 等）、
  **每主体并发会话上限**（PG 的 `rolconnlimit`）：记档，触发条件 = 对外多用户成为真实场景。
- 当前隔离依赖认证身份与工作区 owner 绑定；网络传输与更细的口令策略仍属后续工作。

## 6 连接数据库

### 6.1 两条路

| 入口 | 用途 |
| --- | --- |
| `bicdb sql -p <工作区> "<SQL>"` | 一条命令跑一次（脚本/CI）；`-` = 读 stdin；多条语句用 `;` 分隔 |
| `bicdbcli -p <工作区>` | 交互式（SQL*Plus 形态：缓冲、斜杠命令、`SPOOL`、`@脚本`、`DESCRIBE`） |
| 驱动（Rust/Python） | 程序里连（§12）；协议 `docs/客户端协议_v0.1.md` |

**连接选路**：服务在跑 ⇒ 经控制套接字；没人占 ⇒ 本进程直连；别的进程直连着 ⇒ 拒绝（单写者纪律）。
`bicdbcli --direct` 强制直连；`bicdbcli -s <套接字>` 指定套接字（给了它就不必再给 `-p`）。

### 6.2 一条连接 = 一个会话

事务（`BEGIN … COMMIT`）**跨该连接的语句**成立；连接断开，未提交的显式事务由服务端回滚。
`bicdb sql "…"` **一次调用 = 一条连接**——所以事务要在**同一次调用**里做完：

```bash
bicdb sql -p public "BEGIN; INSERT INTO t VALUES (2,'beta'); SELECT id FROM t; COMMIT"
```

### 6.3 多连接与执行调度

- 同一服务可以同时保持多条独立连接；每条连接保存自己的认证身份、快照和显式事务；
- 请求由实例执行器串行调度，连接并存不表示图语句或写语句已经并行执行；
- 断开连接会回滚该连接未提交的事务；另一连接提交后，旧图快照继续写入会被提交栅栏拒绝；
- 服务运行时直连仍被实例锁拒绝；陈旧锁可以安全接管。

### 6.4 认证和私有工作区绑定

**身份有两条路**（服务端定，客户端选）：

| 连接方式 | 身份 | 依据 |
| --- | --- | --- |
| **不认证** | **管理面身份**（本机/OS） | 控制套接字的**文件权限**——谁能连上谁就是它。管理命令（DCL）要它 |
| `-U <主体>`（或驱动的 `connect_as`） | **具名主体** | 与 `public.user$` 的 PBKDF2-SHA512 散列比对 |

```bash
# 以 alice 认证跑一条 SELECT（口令从 $BICDB_PASSWORD 或终端提示；**不给命令行参数**）
BICDB_PASSWORD='她的口令' bicdb sql -U alice -p public "SELECT 2 + 3 * 4"

# 交互式
BICDB_PASSWORD='她的口令' bicdbcli -U alice -p public
```

- PUBLIC 保存用户目录和口令散列；私有工作区服务通过同一 home 的 PUBLIC 验证主体，并核对该工作区的 owner 后安装真实会话身份；
- 客户端不能通过请求中的 user/workspace 字段改变已认证身份；认证失败后连接不能退回管理身份；
- 给了 `-U` 而服务没在跑（直连形态）会具名拒绝，不会忽略认证参数；
- **具名主体在 `public` 上是只读的**（`public` 是共享内容，`doc/spec/ISO.md`）；
  `INSERT`/`UPDATE`/`DELETE`/DDL 一律具名拒绝；
- **本人改密**（唯一允许主体执行的 DCL）：`ALTER USER alice IDENTIFIED BY '<新口令>' REPLACE '<旧口令>'`；
- **`PAUSE`** ⇒ **拒绝新会话**（已开的会话不掐断）；**`EXPIRE`** ⇒ **受限会话**：
  连得上，但除本人改密之外一律拒绝；**改完即放行**（不用重连）；
- **"主体名或口令不对"是一条文案**：不区分"不存在"与"口令错"，且两种情况下服务端**代价相同**
  （防止用户名枚举）；
- **口令不进日志**：服务日志只记"谁在什么时候认证成功/失败"。

**没做**：网络承载（TCP）及通道绑定、授权矩阵（**本产品不做**，REQ-ISO-003）、
口令策略（有效期/失败锁定/历史）、管理员主体在 `user$` 里的落点。

## 7 表

### 7.1 普通关系表（**本版唯一实现的表型**）

```sql
CREATE TABLE emp (
    empno  NUMBER       NOT NULL,      -- 数值
    ename  VARCHAR2(20),               -- 变长文本（默认 255）
    tag    CHAR(4),                    -- 定长（默认 1）
    sal    NUMBER,
    active BOOLEAN,                    -- 本库扩展
    blob   BYTES(64)                   -- 字节串（默认 64；文本/二进制同形）
) WITH (pctfree = 10, itl_max = 8);    -- 表选项（见下）

CREATE UNIQUE INDEX emp_pk ON emp (empno);   -- 唯一性靠唯一索引提供
```

**表选项**（`WITH (…)`，键闭集）：

| 选项 | 取值 | 作用 |
| --- | --- | --- |
| `pctfree` | 0–99（默认 0） | 页内预留百分比（更新留白；实测 `pctfree=50` 的 800 行用 7 页 vs `=0` 用 4 页） |
| `itl_max` | 1–32（默认 8） | 页内事务槽上限 |
| `table_type` | `transactional` \| `heap` | 显式写本版唯一的表形态（写默认值，收下） |

越界与清单外的键**具名拒绝**（`pctfree = 300` 会说"越界（0–99）"，不会静默截断成 44）。

### 7.2 其余四种表型：**未实现**（`WITH (table_type=…)` 具名拒绝）

设计（`doc/表类型与存储选项_v0.1.md` §3）用**七个开关**组合出五种表：

| # | 表类型 | transactional | logging | update_mode | retention | version_keep | cleanup | embed |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | **普通关系表** | ✅ | full | in_place | — | — | — | — |
| 2 | 配置表 | ❌ | redo_only | append_only | — | ✅ | row_delete | — |
| 3 | 会话表 | ❌ | **none** | append_only | ✅ | — | **segment_drop** | ✅ async |
| 4 | 图数据 | ✅ | full | in_place | — | — | — | — |
| 5 | 记忆表 | ❌ | redo_only | append_only | 见 §4.5 | ✅ | row_delete | ✅ async |

**本版只有第 1 种**：`WITH (table_type = append_only)`、`logging = redo_only|none`、`retention = n`
一律**绑定期具名拒绝**（此前被收下、落进 `tab$`、没人读——用户以为建了追加型表，实际得到普通表）。
**归属**：表型切片（三者的写路径语义 + 段丢弃清理）。

### 7.3 列类型（**本版实际可用**）

| 写法 | 类型码 | 默认长度 | 值形态 |
| --- | --- | --- | --- |
| `NUMBER` / `INTEGER` / `INT` | 1 | — | 数值（任意精度，**不丢精度**） |
| `VARCHAR2(n)` / `VARCHAR(n)` / `TEXT` | 3 | 255 | 字节串（文本/二进制同形） |
| `CHAR(n)` | 2 | 1 | 定长字节串 |
| `BYTES(n)` | 12 | 64 | 字节串 |
| `BOOLEAN` / `BOOL` | 6 | — | 布尔 |

`NOT NULL` 在 INSERT（含 SELECT 来源）和 UPDATE 写入时校验；省略必填列同样失败。
`CHAR(n)`、`VARCHAR2(n)`、`BYTES(n)` 的 `n` 是**字节上限**，超限具名拒绝，不截断。
例如 `VARCHAR2(3)` 可存 UTF-8 的一个“汉”字，不能存“汉字”。约束失败回滚整条语句；
显式事务中此前成功的语句保留。现有数据不会自动清理；该修复约束后续写入。

**清单外一律具名拒绝**：`DATE`、`TIMESTAMP`、`UUID`、`RAW(n)`、`JSON`、`VECTOR(n)`、`ASSET_REF`。
其中日期时间的**编码已经写好**（`crates/types/src/datetime.rs`：7 字节 DATE / 11 字节 TIMESTAMP），
但**没有接线**——此前 `TIMESTAMP` 被 DDL 收下、按普通数值存（插 `'2026-01-02 03:04:05'` 报"类型不匹配"，
插 `20260102` 却成功），故本版改为**拒绝**。归属：**TYP 切片**。

### 7.4 索引

```sql
CREATE INDEX        idx_name ON t (name);              -- 普通索引（可多列）
CREATE UNIQUE INDEX t_pk     ON t (id);                -- 唯一索引（唯一性由它提供）
DROP INDEX t_pk;
DROP TABLE t;
```

- 索引键走**索引比较即字节比较**（与写路径同一份键编码）；
- **等值查询会走索引**（规则式选路，见 §8.1）：`WHERE id = 5` / `WHERE id = :id`
  命中单列索引 ⇒ 索引点查（唯一索引优先，照 Oracle RBO 的访问路径排名）；
  普通索引的同键多行也走它（返回全部同键行）；
- **唯一性语义照 MySQL/PG**：键含 `NULL` 的行不参与唯一性（多个 NULL 合法）；
  冲突在**写前**判定——取同键候选行、按行字节重算键逐字节比，命中即报"唯一约束冲突"，语句整体不写；
- 边界：`CREATE INDEX` 全表扫描建索引（批量灌树），大表耗时随行数线性增长。

### 7.5 名字规则

未引号的标识符照 PG **折叠小写**（`CREATE TABLE T` 与 `SELECT * FROM t` 是同一张表）；
`"引号名"` 原样保留大小写；**非 ASCII 可用**（`CREATE TABLE 名称表 (名称 VARCHAR2(8))`）。

## 8 SQL 语法参考（**本版实际支持**）

### 8.1 查询

```sql
SELECT * | 表达式 [AS 别名] [, …]
  FROM 表
 [WHERE 条件]
 [ORDER BY 输出列名 | 别名 | 序号 [ASC|DESC]]
 [LIMIT n [OFFSET m]]
```

- **单表**；`ORDER BY <表达式>`——**输出列**（名字/别名/序号）最省事，**不投影的列、纯表达式、
  另一张表的列**也可以（`SELECT name FROM emp ORDER BY sal DESC`）；
  `DISTINCT` 与表达式键不能并存（排序键要出现在输出列里）；聚合查询里只能排**分组列或聚合项**；
- `LIMIT` 不带 `ORDER BY` 时返回的行序不保证；
- **访问路径（规则式选路）**：`WHERE` 里有一条 `列 IN (值表)`（逐点一次点查），
  或一条 `列 = 常量/:参数`，或**两端都有界的范围**
  （`BETWEEN a AND b`、`>= a AND <= b`、`> a AND < b`……开闭照实），且该列是某个
  **单列索引**的键列 ⇒ 走 `IndexScan`（**唯一索引优先**）；**只给一侧的界**（`k > 5`）
  与其余情况（`OR` 析取、`NOT IN`、`IS NULL`、`<>`、多列键、列对列比较）一律**全表扫描**
  （无界范围会把整棵索引收进内存——随"流式游标"切片再开）。
  **结果与走不走索引无关**：索引只缩小候选，谓词仍逐行复核——索引项是"只插不删"的
  （改键只追加新项），陈旧项由**行**否掉；同一条行被两条项带出时按**物理行**去重。
- **两表连接的内表探测**：`ON`（或内连接的 `WHERE`）里有 `内表列 = 外表列` 且该内表列
  是某**单列索引**的键列 ⇒ 内表按外层行的值**索引探测**（IndexNL；Oracle 的
  `TABLE ACCESS BY INDEX ROWID` + 嵌套循环，MySQL 的 ref/eq_ref）；否则内表**顺序重扫**
  （每外层行一遍全表——不建索引时大表连接会很慢）。左外连接只在 `ON` 里认这条
  （`WHERE` 里认它要额外论证"补 NULL 行必被否掉"，第一版不摊——记档）。
  **现状**：单表**等值 + `IN (值表)` + 有界范围**、两表连接的内表探测；`UPDATE`/`DELETE`
  的 `WHERE`、**无界范围**（`k > 5`）、`OR` 的多区间、多列键仍未接（记档）。

### 8.2 写入

```sql
INSERT INTO 表 [(列, …)] VALUES (值, …) [, (值, …)]      -- 多行一条语句
INSERT INTO 表 [(列, …)] SELECT …                       -- 含集合运算来源
```

SELECT 来源按目标列清单映射，省略列填 NULL；列清单不得重复。
例如表为 `(id, v, note)` 时，`INSERT INTO t (v,id) SELECT 20,1` 写入 `(1,20,NULL)`。
UPDATE/DELETE、INSERT…SELECT 和集合运算均支持具名参数；连接内表索引探测不覆盖语句参数。
同一语句的集合分支共享参数名称和类型，外层 ORDER BY/LIMIT/OFFSET 作用于完整合并结果。
多给或重复命名参数在批次执行前拒绝，不会先提交数据再返回参数错误。

- 值可以是**字面量**或**具名参数** `:名字`；
- 参数从命令行给：`bicdb sql -p public --param id=7 --param "s='abc'" "INSERT INTO t VALUES (:id, :s)"`
  （值文本 `NULL` / `TRUE` / `FALSE` / `'文本'` / 其余按数值；缺失、多给、形态不符都是具名错误）；
- 驱动里给参数见 §12。

### 8.3 表达式

| 类 | 支持 |
| --- | --- |
| 算术 | `+` `-` `*` `/`，一元 `+`/`-` |
| 比较 | `=` `<>` `<` `<=` `>` `>=` |
| 逻辑 | `AND` `OR` `NOT` |
| 空值 | `IS NULL` / `IS NOT NULL` |
| 集合 | `IN (…)`、`BETWEEN … AND …`（脱糖为 `>= AND <=`） |
| 转换 | `CAST(x AS 类型)` |
| 参数 | `:名字` |

**NULL 是三值逻辑**：`WHERE id = NULL` 永远不选中任何行（要用 `IS NULL`）。

### 8.4 事务

```sql
BEGIN;  … ;  COMMIT;      -- 或 ROLLBACK;
```

- **一条连接 = 一个会话**；DDL 出现在显式事务里 ⇒ **具名拒绝**（REQ-TXN-016）；
- **读己所写**：事务里看得见自己未提交的行；别人看不见；
- **语句级回滚**：显式事务里一条语句失败**只回滚它自己**——此前已成功的语句照旧、事务与锁照旧、
  `COMMIT` 照旧可用。

### 8.5 其它

多条语句可用 `;` 一次发（一次往返）；行注释 `--`；`bicdbcli` 里 `;` 结尾执行、`/` 重跑缓冲（§10.2）。

### 8.6 明确不支持（**全部具名拒绝**，绝不静默）

运行参数目前不能动态重载；数据缓存大小修改需重启实例，周期性后台 DBWR/LGWR/CKPT 尚未接线（§11.2.1）。


| 类别 | 具体 |
| --- | --- |
| 写入 | `UPDATE` 改**唯一索引的键列**（写前预检只覆盖 INSERT——请 `DELETE` + `INSERT`） |
| 查询 | **三表以上 / 嵌套连接**、子查询/CTE、`ORDER BY` 里的**聚合函数**、`NULLS FIRST/LAST` 关键字 |
| 聚合与函数 | 闭集外**没有函数目录**（`UPPER`/`LENGTH`/`json_get`… 都没有）；聚合只有 `COUNT(*)`/`COUNT`/`SUM`/`AVG`/`MIN`/`MAX`（`COUNT(DISTINCT x)` 可以）；`SUM`/`AVG` 只收 NUMBER |
| DDL | `ALTER TABLE`、视图、约束（`PRIMARY KEY`/`FOREIGN KEY`/`CHECK`）、`DROP … IF EXISTS` |
| DCL | **F/W/U 三组已落地**（文件系统池 / 工作区 / 用户——见 §4.2、§5）；T1/T2/W2 已支持空结构初始化模板；**带数据快照/reflink 与 `TO TEMPLATE`（W7）** 尚未实现。旧的 `ALTER SYSTEM … FILESYSTEM` 与 `CREATE WORKSPACE FOR USER` 是**语法错误 + 指路文案** |

报错形如 `绑定期不支持：<原因>`——**在解析/绑定期就说**，不会执行到一半才失败。

## 9 参数文件（`bicdb.ini`）

`bicdb init` **生成**它（含全部默认与逐项说明）；`bicdb params -p public` 看有效值、来源、类别、说明。

```ini
[instance]
db_root               = /home/you/bicdb-home/public   # 根区目录（权威）
[init]                                     # 建区期：init 读它；**建区后不可改**
file0_initial_blocks  = 4096               # file 0 初始块数（16 KiB/块）
undo_initial_blocks   = 512                # 撤销文件初始块数
wal_groups            = 2                  # 日志组数（2–8）
wal_members           = 1                  # 每组成员数（1–8）
wal_group_pages       = 8192               # 每组成员页数（512 B/页）
[buffer]                                   # 缓冲池与替换链
pool_frames           = 8192               # 帧数（16 KiB/帧，默认 128 MiB）
hash_buckets          = 0                  # 0 = 自动（≈ 容量/4 取质数）
bucket_latches        = 0                  # 0 = 自动（须为 2 的幂，≤64）
hot_fraction          = 4                  # 热段上限 = 容量/该值
touch_interval_ms     = 3000               # 触摸计数递增间隔（三秒规则）
cool_count            = 0                  # 冷却值
stay_count            = 2                  # 驻留值
hot_criteria          = 2                  # 热判据
max_scan_fraction     = 4                  # 找空帧的扫描上限 = 容量/该值
make_free_batch_divisor = 64               # 每轮写回批大小 = 帧数/该值
[storage]
file_extend_blocks    = 512                # 段增长撞文件尾的固定增量（块；512 = 8 MiB）
multiblock_read_pages = 8                  # 一次区读的连续页数（8 页 = 128 KiB）
cr_max_rounds         = 64                 # 一致性读回溯轮数上限
[wal]
log_buffer_pages      = 256                # 日志缓冲区页数（512 B/页）
flush_trigger_permille = 333               # 未刷出占比达此千分数即建议刷盘
[catalog]
row_cache_rows        = 4096               # 字典行缓存：每型行数上限
row_cache_bytes       = 4194304            # 字典行缓存：估算字节上限（4 MiB）
rid_forward_max_hops  = 16                 # 行迁移转发链最大跳数
[index]
bulk_fill_percent     = 90                 # 建索引叶页填充率（%）
[service]
socket                = bicdb.sock         # 控制套接字（相对根区目录）
log                   = …/log/public.log   # 服务日志（**统一在 <home>/log/**）
start_wait_s          = 30                 # start 等就绪上限（-w 覆盖）
stop_wait_s           = 300                # stop 等退出上限
ready_poll_ms         = 100                # 等就绪轮询间隔
stop_poll_ms          = 50                 # 等退出轮询间隔
probe_timeout_ms      = 500                # 每轮就绪探测超时
status_timeout_ms     = 5000               # status 问服务自述的超时
log_tail_lines        = 3                  # 启动失败回显日志尾行数
[client]
handshake_timeout_ms  = 5000               # 握手超时（实例忙时据此报错，不挂住）
request_timeout_ms    = 0                  # 请求超时（0 = 不限）
[lock]
park_ms               = 50                 # 等锁单次挂起时长
deadlock_threshold_ms = 3000               # 死锁检测阈值
wait_max_rounds       = 0                  # 等锁重试上限（0 = 不限）
```

**纪律**：

| 事 | 说明 |
| --- | --- |
| 闭集 | 未知节在 `[nope]` 那一行、未知键指到行号，**具名拒绝**（收下不生效比报错更糟） |
| 优先级 | 命令行 `-c 键=值`（可写全名 `buffer.pool_frames`，也可写唯一键名）> 参数文件 > 内置默认 |
| 建区期 | 建区后不可改：控制文件权威，`bicdb start` 逐项核对，不符即拒绝启动（改需重建） |
| 生效时机 | `[init]` = 建区期；其余 = **重启**生效（`bicdb restart`）——`bicdb params` 的「类别」列 |
| 范围校验 | 解析时校验，越界具名拒绝（不"收下改成别的值"） |
| 0 的含义 | `hash_buckets`/`bucket_latches`/`wait_max_rounds`/`request_timeout_ms` 的 0 分别是"自动/自动/不限/不限" |
| 未接线的项 | `park_ms`/`deadlock_threshold_ms`/`wait_max_rounds` 三个锁参数在**单写者形态下空转**（等锁驱动随多会话切片接线）——`bicdb params` 照实显示，但今天不会有等待发生 |

## 10 命令参考

### 10.1 `bicdb`（管理命令）

| 命令 | 说明 |
| --- | --- |
| `bicdb init [<工作区名\|路径>] [-p 种子.ini] [-c 键=值]` | 建库（**唯一**接受目录的命令）；不给参数 ⇒ `<BICDB_HOME>/public` |
| `bicdb start [-p 工作区] [-s 套接字] [-l 日志] [-w 秒] [-c 键=值]` | 后台起服务；等就绪才返回 |
| `bicdb stop [-p 工作区] [-m fast\|immediate] [-w 秒]` | 停服务（`fast` = 完全检查点；`immediate` = 下次打开走崩溃恢复） |
| `bicdb status [-p 工作区]` | 服务/实例状态（pid、套接字、运行秒数、已服务请求数、提交序号） |
| `bicdb restart [-p 工作区]` | = stop(fast) + start |
| `bicdb home` | `BICDB_HOME` 在哪：程序/数据/日志/备份四条路径 + 版本 |
| `bicdb list` | `<BICDB_HOME>` 下的工作区与状态 |
| `bicdb params [-p 工作区] [-c 键=值]` | 全部可调项 + 取值 + 来源 + 类别 + 说明 |
| `bicdb sql [-p 工作区] [-U 主体] "<SQL>"… [--param 名=值 …]` | 执行 SQL（多条用 `;`；`-` = 读 stdin）；`-U` 以主体认证（口令取 `$BICDB_PASSWORD` 或终端提示） |
| `bicdb shell [-p 工作区]` | 简易交互式 shell |
| `bicdb version` / `bicdb help` | 版本 / 帮助 |

**寻址**：`-p <参数文件|工作区目录|工作区名>` > 环境变量 `BICDB_INI` > 当前目录的 `./bicdb.ini`；
名字式只在"既不是文件也不是目录"时兜底（当前目录真有同名目录时按目录走）。

### 10.2 `bicdbcli`（SQL\*Plus 形态客户端）

```bash
bicdbcli [-p 工作区] [-S] [-s 套接字] [-U 主体] [--direct] [@脚本]
  -S          静默（不出横幅与提示符，结果照打）
  -s <套接字>  连指定的控制套接字（给了它就不必再给 -p）
  -U <主体>    以某个主体认证（口令取 $BICDB_PASSWORD 或终端提示；只对经服务有效）
  --direct    强制直连（服务在跑时会被实例锁挡住）
```

- `;` 结尾执行；**空行**结束输入但**不执行**（缓冲保留）；单独一行 `/` 重跑缓冲；
  续行提示符是**行号**；
- 缓冲编辑：`LIST`(`L`) / `DEL` / `APPEND`(`A`) / `INPUT`(`I`) / `CHANGE`(`C`) / `CLEAR BUFFER`（全按行号）；
- 会话参数：`SET ECHO|FEEDBACK|TIMING|PAGESIZE|LINESIZE|NULL|TERMOUT|SQLPROMPT|VERIFY|CONCAT`、`SHOW [参数]`；
- 脚本与输出：`SPOOL <文件|OFF|OUT>`、`START`/`@文件`/`@@文件`（嵌套上限 32 层，自引用报错）、
  `WHENEVER SQLERROR EXIT|CONTINUE`、`DEFINE`/`&名` 替换变量；
- `DESCRIBE`(`DESC`) 对象（`Name / Null? / Type` 版面）、`HOST`/`PROMPT`/`REM`/`TIMING`/`HELP`/`EXIT [码]`。

**脚本示例**（`load.sql`）：

```sql
SET ECHO OFF
WHENEVER SQLERROR EXIT
CREATE TABLE emp (empno NUMBER NOT NULL, ename VARCHAR2(20), sal NUMBER);
CREATE UNIQUE INDEX emp_pk ON emp (empno);
INSERT INTO emp VALUES (1001, 'SMITH', 800);
INSERT INTO emp VALUES (1002, 'ALLEN', 1600);
SELECT empno, ename, sal FROM emp ORDER BY empno;
```

```bash
bicdbcli -S -p public @load.sql        # -S + 脚本 = 批处理；退出码 0/1
```

## 11 运维

### 11.1 日志、状态、排错

| 想看 | 去哪 |
| --- | --- |
| 服务日志 | `<BICDB_HOME>/log/<工作区>.log`（启动/恢复/收尾/语句失败各一条） |
| 状态 | `bicdb status -p public`（pid、套接字、运行时长、已服务请求数、提交序号） |
| 工作区一览 | `bicdb list` |
| 启动失败原因 | 错误里自带**日志尾行**（`-l` 可换日志文件） |

| 现象 | 处置 |
| --- | --- |
| `找不到参数文件 bicdb.ini——试过：…` | 用 `-p <工作区>`，或 `cd` 进工作区，或设 `BICDB_INI` |
| `未知节 [x]` / `第 N 行：… 里没有参数 y` | 参数文件写错（闭集）；`bicdb params` 看全部可调项 |
| `建区期参数与既有的库不符（改需重建）` | 建区期参数改不了；改回原值或重建 |
| `实例已被 pid N 占用（服务模式/直连模式）` | `bicdb stop`，或等直连进程退出 |
| `实例正忙：服务一次只服务一条连接` | 等前一条连接收尾（客户端握手超时默认 5 秒） |
| `服务进程 N 已退出（exit status: 1）——日志 …：` | 按日志尾行处置 |
| `唯一约束冲突（重复键 …）` | 撞唯一索引；改键值或去掉索引 |
| `绑定期不支持：…` | 该语法本版不支持（§8.6）；报错文本会说明 |

### 11.2 崩溃与恢复

| 情形 | 结果 |
| --- | --- |
| `bicdb stop`（fast） | 完全检查点后退出：下次打开**无需重放** |
| `bicdb stop -m immediate` | 不做检查点退出：下次打开走**三阶段恢复**（提交记录在日志里，**已提交的数据不丢**） |
| 进程被 `kill -9` / 掉电 | 同上；陈旧锁自动接管，`bicdb status` 报"未运行（陈旧锁）" |
| 换错控制文件 | **拒绝打开**（`拒绝打开：文件超前于控制文件（FILE_SCN_AHEAD …）`） |

### 11.2.1 日志与检查点：写满了会**自己推检查点**

重做日志是两个组**轮转复用**的（`[init] wal_groups` / `wal_group_pages`）。一组写满要切到
下一组时，**上一组必须先降级**（`ACTIVE → INACTIVE`），而**降级挂在检查点上**——检查点没推进，
写者就会停在"日志切换等待检查点（无可复用组：检查点未越过）"。

本版**没有后台检查点进程**（`crates/daemon` 尚未接电：设计 §11.7 的 CKPT 触发 ①"周期发布"），
所以采用了设计里的触发 ②"**组满被迫**"：**每条语句执行前**，会话只读探测一次"下一次切换
会不会被挡"，要被挡就**就地推一次完全检查点**（组随之降级），写者继续。于是：

- **连续大批量写入不会被日志挡住**（实测：`wal_groups=2` + `wal_group_pages=64`（32 KiB/组）
  的小实例上连续插入 300 行正常完成——修之前第 40 行就断）；
- **显式事务里日志写满仍会报那条例名错误**（检查点只在语句边界、且没有活动事务时推）——
  `COMMIT` 之后的下一条语句会把检查点补上；
- **量小不用管**：小批量写入根本走不到"下一组不可复用"，一次检查点都不会推。

**代价**：完全检查点会把该工作区的脏页全部写回（池小时很快；实测 32 KiB/组 vs 4 MiB/组
两种配置的灌入速率一样，差异在进程启动噪声内）。**周期增量发布**（更平滑的形态）随后台角色切片。

### 11.3 单写者纪律

同一实例同一时刻只允许一个写者（服务在跑时直连被拒，反之亦然）。判活 = pid **且**进程启动时刻
匹配（防 pid 复用）；进程没了（含 `kill -9`）就是**陈旧锁**，下一个打开者自动接管，不需手工删文件。

### 11.4 日志轮转：**未实现**

服务日志只追加、每行 flush、无大小上限（`[service] log_*` 系列随长跑切片）。

### 11.5 备份与恢复：**现状是"停服务 + 整目录复制"**

```bash
bicdb stop -p public
cp -a <BICDB_HOME>/public <BICDB_HOME>/backup/public-$(date +%F)
bicdb start -p public
```

⚠️ **同一块盘上的"备份"不算备份**——生产必须把备份落到另一块盘/另一台机器
（`<BICDB_HOME>/backup/` 只是**默认落地处**，不是安全边界）。

副本换位置后要改参数文件里的 `db_root`（注册的是**绝对路径**）：

```bash
sed -i 's|^db_root = .*|db_root = /backup/public-2026-10-07|' /backup/public-2026-10-07/bicdb.ini
```

`bicdb backup` 命令、保留策略、热备、PITR、归档、备库：**未实现**（随 OPS 与归档切片）。
恢复的**已实现**部分：崩溃恢复（§11.2）。

## 12 驱动（在自己的程序里连）

协议规格：`docs/客户端协议_v0.1.md`（Rust 与 Python 实现同一份规格）。

```rust
// Cargo.toml: bicdb-client = { path = "../bicdb/crates/client" }
use bicdb_client::{Connection, Value};
let mut conn = Connection::connect("/path/to/public")?;    // 参数文件或工作区目录
let rs = conn.query("SELECT id, name FROM t WHERE id = :id", &[("id", 1_i64.into())])?;
for row in rs.iter() { println!("{} {}", row.i64(0)?, row.str(1)?); }

// **以某个主体连**（可选；只在 PUBLIC 上；连上即认证）
let mut conn = Connection::connect_as("/path/to/public", "alice", "她的口令")?;
assert_eq!(conn.user(), Some("alice"));
```

```python
# pip install -e drivers/python   （或把 drivers/python 加进 PYTHONPATH）
import bicdb
conn = bicdb.connect("/path/to/public")
# 以某个主体连（可选；只在 PUBLIC 上）：bicdb.connect(target, user="alice", password="…")
cur = conn.cursor()
cur.execute("INSERT INTO t VALUES (:id, :name)", {"id": 1, "name": "alpha"})
conn.commit()                                    # 写入前驱动自动 BEGIN（DB-API 语义）
cur.execute("SELECT id, name FROM t WHERE id = :id", {"id": 1})
print(cur.fetchall())                            # [(Decimal('1'), 'alpha')]
```

**两侧一致的口径**：寻址与命令行同源；连接 = 会话（`BEGIN … COMMIT` 跨语句，断开即回滚）；
参数按名摆位（缺失/多给/形态不符都具名报错）；值无损（数值保精度、字节串原字节，非 UTF-8 不替换成 `�`）；
服务的错误文本**原样透出**；服务可保持多条连接，但请求在单实例执行器上串行调度。
**认证**：`Connection::connect_as(target, user, password)`（Rust）/ `bicdb.connect(target, user=…, password=…)`（Python）；
`Connection::connect_env` 认 `BICDB_USER`/`BICDB_PASSWORD`（照 libpq 的 `PGUSER`/`PGPASSWORD`）。
**没有的**：TCP/多机、网络认证（通道绑定）、连接池、服务端游标分页、异步。

### 14.1 建图和 Cypher

```sql
CREATE GRAPH kg;
CYPHER kg 'CREATE (a:Entity {db_type:"mariadb",name:"IO高"}),
                  (b:Solution {db_type:"mariadb",name:"检查慢SQL"}),
                  (a)-[:HAS_SOLUTION]->(b)';

SHOW GRAPHS;
```

已支持多标签、平行边、自环、方向、固定/有界变长路径、`shortestPath`、`OPTIONAL MATCH`、聚合、列表表达式、`EXISTS`、显式作用域 `CALL`、`UNION`、`CREATE/MERGE/SET/REMOVE/DELETE`。

### 14.2 属性索引

```sql
CREATE GRAPH INDEX domain_name ON kg NODES LABEL "Entity" (db_type,name);
CREATE UNIQUE GRAPH INDEX solution_name ON kg NODES LABEL "Solution" (name);
SHOW GRAPH INDEXES ON kg;
PROFILE CYPHER kg 'MATCH (n:Entity) WHERE n.db_type="mariadb" RETURN n.name';
```

属性索引支持标量、组合字段、JSON 对象路径、范围和唯一性。`PROFILE CYPHER` 会报告实际访问路径、物理项读取数和实体装载数。

### 14.3 `GRAPH_TABLE` 与 SQL

```sql
SELECT g.name,o.owner
FROM GRAPH_TABLE(
  kg,'MATCH (n:Entity) RETURN n.name'
  COLUMNS (name VARCHAR2(128))) g
LEFT JOIN owners o ON g.name=o.entity_name
ORDER BY g.name;
```

图结果可进入现有 SQL 过滤、联接、聚合、集合运算和 `INSERT SELECT`。`GRAPH_ELEMENT` 只是当前语句的类型化元素身份，不能作为普通列持久化。

### 14.4 一致性、预算和运维

图实体、邻接、属性索引和全文变更在同一原生事务中提交。工作区可配置节点、边、返回行、深度、遍历、文本字节和语句时间上限；`CYPHER`/`GRAPH_TABLE` 的 `BUDGETS` 只能降低请求上限。新图默认使用原生 v3 邻接；旧图可显式 `ALTER GRAPH ... UPGRADE STORAGE`。

在拥有的私有工作区内，使用图 SQL 管理节点、关系及属性全文索引。下面的索引仅提取 Entity 节点的 name 和指定 JSON 字符串路径；检索必须指定 db_type。

```sql
CREATE FULLTEXT GRAPH INDEX answers ON kg
  NODES LABEL "Entity" (name,config.question)
  OPTIONS '{"update":"batch","interval_ms":5000,"batch_rows":256}';
SEARCH FULLTEXT GRAPH INDEX answers ON kg FOR 'buffer pool'
  OPTIONS '{"db_type":"mariadb","consistency":"eventual"}';
SHOW FULLTEXT GRAPH INDEXES ON kg;
ALTER FULLTEXT GRAPH INDEX answers ON kg OPTIONS
  '{"update":"batch","interval_ms":30000,"batch_rows":512}';
ALTER FULLTEXT GRAPH INDEX answers ON kg PAUSE;
ALTER FULLTEXT GRAPH INDEX answers ON kg RESUME;
ALTER FULLTEXT GRAPH INDEX answers ON kg SYNC;
```

源写入只记录变更，分词与倒排维护在服务语句之间、空闲和客户端等输入时按批执行。用户显式事务内跳过后台维护；暂停状态跨重启保留。eventual 不返回源已变化的旧命中，但可能遗漏尚未维护的新内容；complete 与 covered_source_seq 表示已发布索引的完整覆盖水位。需要本语句完整源视图时使用 strict，它仍执行有界全源构建。

省略数值覆盖时，索引继承 bicdb.ini 的 `[fulltext] fulltext_interval_ms=5000` 与 `fulltext_batch_rows=256`。实例参数重启生效；ALTER OPTIONS 在线替换完整策略，不重建存储段。维护模式需显式选择 manual 或 batch；manual 通过 SYNC 手动消费。具名用户不能修改 PUBLIC 中的图索引。范围、失败重试、旧版兼容和当前边界见[定时维护说明](../doc/bicdb_图全文定时批量维护与参数_20261009.md)。


### 14.5 在 Cypher 中使用全文结果

```sql
CYPHER kg 'CALL db.index.fulltext.queryNodes("answers","buffer",{db_type:"mariadb",consistency:"eventual"})
YIELD node AS n,score,complete WHERE score>0
MATCH (n)-[:CAUSE]->(m) RETURN n.name,m.name,score,complete';
```

关系索引使用 queryRelationships，并 YIELD relationship。两个过程必须给出索引名、查询和选项三个参数；选项中的 db_type 必填。后续可以继续匹配、排序、限制和调用相关子查询。语句内先修改源、再检索时标记 strict_staged_scan，使用暂存源，持久水位为 NULL。参数、片段、水位、PROFILE 与当前边界见[Cypher 全文过程](../doc/bicdb_Cypher全文过程与索引访问_20261009.md)。

### 14.6 图全文多索引融合

`CALL bicdb.searchNodes(query,{db_type:domain,indexes:[index1,index2],labels:[label],consistency:"eventual",limit:20}) YIELD node,rank,mode` 使用原生全文索引并轮转去重。标签过滤先于每路 limit；省略 indexes 仍为旧扫描。详见[接口说明](../doc/bicdb_图多索引排名融合_20261009.md)。

图全文支持 `indexes:"auto"` 和显式 fields，按字段与完整标签范围选择原生索引；缺少覆盖报错。见[自动索引选择](../doc/bicdb_图全文自动索引选择_20261009.md)。

图全文支持固定目标 `WAIT [OPTIONS JSON]`，明确返回 READY/TIMEOUT/PAUSED 与目标覆盖状态；见[接口规则](../doc/bicdb_图全文固定目标WAIT_20261009.md)。
