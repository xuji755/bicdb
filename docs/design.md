# bicdb 总体设计

版本 1.0　状态：设计基线，P0 冻结前可能调整

> 本文是 bicdb 的总体设计说明。需求见 [requirements.md](requirements.md)，存储层的阶段设计见 [storage.md](storage.md)。

---

## 1 研发目标与版本范围

目标是建设**单机、按工作区隔离、多线程执行**的事务型数据库，统一保存关系数据、JSON、记忆、属性图与向量，并以受管理的外部文件保存不可变大对象。

首个受控试用版本 V1.0 应完成全部核心能力的**可靠性闭环**，而不是仅提供多个独立存储接口。

| 能力 | V1.0 必须完成 | 后续扩展 |
| --- | --- | --- |
| 隔离 | 用户独立工作区、禁止跨用户授权、public 只读 | 更强部署隔离与密钥托管 |
| 存储事务 | 堆表、跨页行、B+Tree、RC、Undo、WAL、恢复 | 备库部署（高可用） |
| 数据类型 | 六类标量、JSON、布尔、UUID、浮点、向量、资产引用 | 更多兼容类型、压缩向量 |
| Agent 数据 | 记忆版本、来源、状态、TTL、任务检查点、JSON 配置版本 | 高级生命周期与策略插件 |
| 检索 | 全文、精确向量、HNSW、IVFFlat、过滤与融合 | 量化、磁盘型 ANN、稀疏向量 |
| 图 | 属性图、有限 Cypher 子集、有界遍历、关系查询关联 | 完整图语言、大型图算法 |
| 资产 | 流式写读、范围读取、删除、清单备份 | 外部对象存储适配 |

研发优先级：**隔离与恢复 → JSON 与资产 → 可用记忆检索 → ANN 加速 → 有限图 → 综合发布**。

以下**不纳入 V1.0**：完整 Oracle SQL 兼容、PL/SQL、RAC、分布式事务、库内模型执行、复杂 LSM 及库内 LOB。

## 2 技术基线与架构选择

建议使用 C++20、CMake、Linux x86_64、本地 SSD 及 **16KB 数据页**。内核使用明确所有权、RAII 与统一错误码。磁盘格式自主设计，**不追求 Oracle 文件或网络协议兼容**。第三方库可用于网络、密码、编码、解析、分词与 ANN 算法组件，**不能引入现成数据库引擎代替存储研发目标**。

> 页大小取 16KB 而非 8KB 的依据：本产品以检索而非典型 OLTP 为核心负载。主流 embedding 维度（1536/3072，FLOAT32 下占 6KB/12KB）在 8KB 页下必然跨页，16KB 可使其落在单页内，把跨页协议从热路径降为例外。页大小在实例生命周期内固定。

建议正式部署采用统一接入与控制层、每私有工作区独立的多线程工作进程，以及独立 public 读取服务。工作进程由按需启停的监督器管理；活跃工作区数量受预算限制，空闲进程可退出。

| 边界 | 主要职责 | 可接触内容 |
| --- | --- | --- |
| 接入层 | 认证、请求限额、绑定用户与路由 | 当前请求及必要认证信息 |
| 控制层 | 工作区注册、启停、额度、版本状态 | 元数据，不提供私有内容查询 |
| 私有工作进程 | SQL、事务、私有检索、资产 | 仅本工作区文件与状态 |
| public 服务 | 公共只读查询与资产读取 | public 工作区 |
| public 发布身份 | 公共内容发布与维护 | public 工作区，无私有读取权 |

工作进程结合不同 OS 身份或等效文件访问沙箱，**只获得本工作区目录权限**，不继承其他工作区文件句柄。宿主机 root、备份介质持有者及控制面被攻破的风险另列基础设施信任边界，**不能用数据库权限宣称消除此类能力**。

## 3 用户与工作区隔离契约

用户标识由认证结果产生；Agent 使用该用户持有的凭证，**不能把请求体中的 `user_id` 当作可信身份**。凭证可限制本人工作区中的操作与资源，但不允许用户将数据权限授予其他用户。

| 主体 | 本人私有区 | 他人私有区 | public 区 |
| --- | --- | --- | --- |
| 用户及其 Agent 凭证 | 按凭证范围读写 | **所有访问禁止** | 只读 |
| public 发布身份 | 无用户私有读取能力 | 禁止 | 发布、删除、版本管理 |
| 运维管理员 | 管理健康、容量与启停 | **不提供业务内容接口** | 管理运行状态 |

私有表、图、向量集合与资产天然属于所在工作区；owner 不可变，**不提供 GRANT 给其他用户、共享链接、跨工作区外键或转移所有权**。`public` 是保留工作区及数据所有者，**不是所有用户组成的 PUBLIC 角色**。普通用户不得向 public 写入；私有数据不会自动复制、提升或发布到 public。

联合检索分别调用本人私有区与 public，融合时保留来源、版本与分数。两个工作区**没有共同提交时钟**，首版不承诺跨区原子事务或全局快照。

验收必须覆盖伪造身份、会话复用、对象 ID 猜测、同名表与缓存冲突、恶意路径、符号链接、后台任务串区、非法恢复与诊断越界。**隔离失败属于发布阻断项，不能以概率或平均成功率验收。**

## 4 工作区目录与资源管理

每个工作区根目录使用**服务端生成的不透明 ID**，由注册表映射身份，不能直接拼接用户输入。根目录下分别设置 catalog、data、index、wal、undo、assets、staging、tmp、backup 与 audit 子目录。`public` 拥有独立根目录。平台控制目录仅保存注册信息、进程状态与额度，**不保存私有正文、向量或文件内容**。

文件操作采用受约束的目录句柄与服务端对象 ID，检查路径穿越、符号链接及检查使用间竞态。私有工作区之间不使用硬链接、不共用资产目录、不做跨用户内容去重。备份恢复不得将用户 A 的备份导入用户 B 的工作区。

资源管理既设置工作区上限，也设置实例总上限，包括缓冲池、查询内存、连接、任务队列、CPU 预算、I/O 带宽、文件数、资产字节、向量数、图遍历与临时空间。达到额度时返回**稳定的资源限制错误**并注明可重试条件。日志刷盘、回滚、死锁检测、资产清理与关键恢复任务**保留专用资源**，不得被普通请求耗尽。公平调度以防止单个 Agent 循环查询拖垮其他用户为验收重点。

## 5 类型与兼容范围

保留六类标量的语义兼容约束（CHAR、VARCHAR2、NUMBER、INTEGER、DATE、TIMESTAMP）。类型兼容是**声明、取值、赋值、转换、比较与客户端往返的行为契约**，不要求内部字节编码相同。

要点：

- **NUMBER 不使用 double 承载**；裸 NUMBER 不归一为 NUMBER(38,0)；内部整数快路径只是优化。
- INTEGER 语义为 NUMBER(38,0)，不得退化为 32/64 位机器整数。
- SQL 空字符串按 Oracle 字符规则处理，但 **JSON 空字符串保持其文档语义**。
- 比较、哈希、索引键、常量折叠与客户端编码**必须一致**，不能只在输入阶段做兼容。

扩展类型新增 BOOLEAN、UUID、FLOAT32、FLOAT64、TIMESTAMP_TZ、JSON、VECTOR 与 ASSET_REF，单独定义范围与转换，**不宣称全量兼容**。时间事件统一保存 UTC 时刻，并在需要时保留原始时区。

## 6 JSON 与配置版本管理

JSON 采用可校验的内部文档表示，支持对象、数组、字符串、精确数值、布尔与 null，**明确区分字段缺失、JSON null 与 SQL NULL**。数字**不得在 SDK 往返时静默转为有损浮点数**。

配置记录包含 `config_id`、`revision`、`schema_id`、`payload`、`content_hash`、`created_at` 及 active 状态。**配置修订不可变**，以预期 revision 执行条件切换；旧版本保留，回滚只切换活动引用。

配置中的密钥**使用密钥引用**，不保存到普通 JSON 正文与日志。工作流、工具参数、提示模板与模型配置**仅作为数据保存**，数据库不据此自动加载代码或执行指令。

---

## 7 存储与跨页记录

存储以工作区内**表空间、段、区、16KB 块与槽位堆表**组织。数据页包含格式版本、页类型、工作区受校验标识、文件号、块号、日志位置、校验和、空闲区及槽位目录。

**ROWID 为 6 字节**：`file_id 10 + block_id 28 + row_id 10`（单文件上限 4TiB，每表空间 1024 文件；页内槽位上限 1024，与 `row_id` 位宽耦合）。**ROWID 不含代次**——删除在行头打删除标记，**索引项随删除/键更新事务一并维护**（删除即移除、回滚即恢复），提交后槽位即可复用，因此不存在"索引项比其所指的行活得更久"的窗口。

常规更新**优先修改当前行，历史信息进入 Undo**；不把每次更新的完整旧版本放在主堆，也**不采用 ASTORE 式版本组织，不以 LSM-Tree 作为主存储组织**。业务级多版本（记忆 revision、配置 revision 等）由**数据模型层**表达为额外的行/节点，存储层对其处理就是普通的插入与原地更新。

原地更新不意味着禁止迁移：行增长与跨页值使用**行片段、稳定入口和可恢复链接**。JSON 及高维向量可能超过单页容量，必须纳入跨页协议。

B+Tree 支持唯一、复合键和范围访问。索引候选**回表检查可见性**；索引项随事务维护。**已知行为**：RC 下索引扫描可能漏读语句开始后被并发删除的行——这是同类模型的既有取舍，须在接口文档与测试基线中显式记录。

资产文件是独立对象，不混入堆表页链。页面编码、检查器与损坏处理**必须先于完整 SQL 执行器交付**。

## 8 事务与崩溃恢复契约

首版采用 **Read Committed 语句快照**、多写事务、行锁、语句失败回滚、事务回滚与死锁检测。**Snapshot 使用提交序号，WAL 使用 LSN，两者不混用**。

修改顺序为：**写入恢复需要的 Undo 与日志描述，再修改受保护数据页**；**数据页持久化前对应 WAL 必须持久化**。**提交成功响应必须晚于提交日志的耐久确认**。网络断开时保留**结果未知**状态，客户端通过幂等请求或提交结果查询消除歧义，**不能盲目重试导致重复业务效果**。

采用 **steal 与 no-force** 缓存策略时，恢复需要已提交事务重做与未完成事务撤销。日志包含事务状态、`prevLSN`、结构变化与必要补偿记录；**重做与撤销应可重入**，恢复再次中断后仍能继续。部分页写入使用经评审的完整页映像或等效保护。

RC 锁等待后可能需要重新检查谓词或重启语句；必须防止重复修改同一行与 Halloween 问题。DDL 首版使用独立事务与对象锁。

所有索引、图表、记忆状态与配置引用遵守同一工作区事务。外部资产文件和异步派生索引另有协议，**不冒充与页日志同一原子存储**。跨私有区与 public 不支持写事务、外键或两阶段提交。

## 9 不可变外部资产协议

`ASSET_REF` 引用工作区内受管理文件；适用模型、算法包、文档、图片及其他大对象。**不提供库内 BLOB、CLOB 或原地文件更新**。已提交文件只允许读取、范围读取和删除；修改内容通过上传新对象并事务切换业务引用完成。

资产元数据包含 `asset_id`、工作区标识、大小、校验和、媒体类型、存储版本、创建时间、状态与引用信息。**用户不传任意服务器路径**；服务端生成对象位置。创建操作以 `idempotency_key` 识别重试，上传支持有界缓冲与中断恢复，**不把整文件装入内存**。不做跨用户文件去重。

上传流程为：预留额度 → 写 staging 文件 → 校验大小与校验和 → 同步内容 → 原子移动到最终位置 → 同步必要目录 → 提交数据库可见元数据。进程中断后未提交文件可成为孤立对象，后台根据状态与宽限期清理；**不得出现已成功提交的引用指向未持久化文件**。

删除先在事务中标记不可见；有业务引用时默认拒绝删除。文件回收还要等待旧快照与活动读取租约结束。删除前备份快照所需文件保留到清单完成。

## 10 中期与长期记忆模型

**中期记忆**围绕任务和会话：任务目标、检查点、阶段结论、工具结果引用、待办及恢复游标，通过 `task_id` 与 `session_id` 归集，设保留期限。**长期记忆**保存确认事实、偏好、经验、知识片段及实体关系，强调**来源、有效时间、版本和可遗忘性**。

| 对象 | 关键字段 | 使用目的 |
| --- | --- | --- |
| `memory` | memory_id、kind、state、revision、body、metadata | 记忆主体及活动版本 |
| `memory_version` | revision、source、valid_from、valid_to、hash | 历史与生效区间 |
| `task_checkpoint` | task_id、step、revision、payload、asset_refs | 中断恢复与条件更新 |
| `source_record` | source_id、source_kind、trace_id、model_version | 来源与证据追踪 |
| `derived_link` | source_id、derived_id、relation、revision | 摘要、分块、向量与图依赖 |

记忆更新**产生新业务 revision**，旧 revision 按保留策略留存；这是**应用版本，不等于 Undo 快照**。生成记忆与用户确认事实必须区分，**confidence 仅作为数据，不能自动代表正确性**。

事件时间、记录时间和事实生效区间分开保存。允许两条**冲突记忆并存**并建立 `conflicts_with` 关系，不能以最新写入覆盖所有历史。中期提升为长期由上层明确调用并提供来源，**数据库不运行 LLM 判断价值**。

检索默认排除 expired 与 deleted 状态。TTL 以**查询时可见性规则**生效，后台物理清理可以延迟。撤销记忆时同步阻止其派生物继续返回，再异步清理实体文件和索引。`public` 内容可共享但不自动可信；**检索内容不能改变认证、执行权限和系统指令**。

## 11 全文与混合检索

全文检索面向文档分块、参数名、错误码、SQL 标识符、模型名及实体名称。支持中文分词与精确词项字段，**固定分析器版本**；标识符不应仅依赖自然语言分词。索引文件**归属工作区**，不能跨用户构建全局词典与正文缓存。

混合检索输入包括查询文本、可选向量、类型与时间过滤、来源范围、`top_k` 和资源预算。分别产生词项与向量候选，在可见性校验后去重融合；建议先用 **RRF 等可解释的秩融合**，记录各路原始分数与排名，**不把不可比较的分数直接相加**。图扩展在候选之后以限定跳数和节点预算执行。

查询返回 `memory_id`、`revision`、`source`、检索方法、分数与必要证据片段。**public 与私有分开执行并显式融合**，不能在一个全用户索引中事后添加 `user_id` 过滤。

倒排和向量派生构建通过工作区内事务 outbox 产生任务，记录目标 revision 与提交水位。重复任务幂等，**旧任务不得覆盖新 revision**。查询可声明 freshness 模式：严格模式在预算内补查尚未入索引的已提交数据或返回尚未就绪；最终一致模式返回索引水位——**不得无说明地称为实时一致检索**。

## 12 向量类型与索引

**VECTOR 首版为固定维度 FLOAT32 数组**（列类型，非独立集合）。元数据记录 `embedding_model`、`model_revision`、`dimension`、`metric` 与 `normalization`。**同维度不同模型默认禁止混搜**，模型升级新建向量空间并切换活动引用。支持 L2、余弦与内积；定义零向量、NaN、无穷值与浮点计算误差。

| 路线 | 实施顺序 | 主要交付 |
| --- | --- | --- |
| 精确扫描 | P7 | 距离函数、过滤、TopK、召回基准 |
| HNSW | P8 | 增量构建、查询参数、删除与重建 |
| IVFFlat | P9 | 训练、列表、探测参数、重训练 |
| 量化或磁盘型 ANN | 后续 | 容量需求明确后立项 |

**ANN 索引为可重建的派生索引**，以工作区 generation、源提交水位与完整性清单控制激活。**索引必须走磁盘页结构**，不能假设向量常驻内存。每个候选回查源 revision、事务可见性、状态及过滤条件；高选择性过滤采用先过滤精确搜索、候选扩展或可解释回退。

**近似结果允许召回不足，但不允许越权、脏读或返回已撤销来源。** 验收以精确扫描计算 Recall@K，并报告参数、p95/p99、构建时间、内存与索引体积。

## 13 有限属性图

每工作区支持多个命名图，顶点保存 `vertex_id`、`label` 及 JSON 属性，边保存 `edge_id`、`label`、`src`、`dst` 及 JSON 属性。底层使用堆表与 B+Tree 出边、入边和选定属性索引；同一事务校验端点存在。**删除顶点默认拒绝存在关联边**，显式 detach 受事务与资源预算约束。

首版语言范围固定 `CREATE`、`MATCH`、`WHERE`、`RETURN`、`LIMIT` 与受控 `SET`、`DELETE` 子集；支持一跳与指定有限跳数的方向遍历。**不支持**无限变长路径、完整 Cypher、全图中心性或复杂分布式图算法。

限制最大跳数、扩展边数、结果数、内存及时间。**达到边界返回明确截断状态或资源错误，不能把截断结果当作完整答案。** 图更新、属性、端点约束与索引共享工作区事务，故障后图表无悬空边。

禁止跨私有工作区边、外键与可写联结；public 图只读。图属性的删除传播使用受管理依赖登记，**不靠扫描所有 JSON 猜测引用**。

## 14 SQL 引擎与模块接口

SQL 层参考 PostgreSQL 的原始解析与语义分析分离方法。**Raw AST 只记录语法与源码位置，不查询 Catalog**；Binder 解析对象与参数，形成带类型的 Bound Query；再生成逻辑表示、候选访问路径、物理计划与执行状态。阶段对象分离，**共享计划不可变**，参数、游标、哈希表与取消状态属于单次执行。

首版 SQL 包含建删表索引、CRUD、事务控制、表达式、参数绑定、INNER 与 LEFT JOIN、聚合、排序、LIMIT 及 JSON 路径和向量距离接口。图语言通过独立入口解析并转换为受控计划节点，资产写入通过流式 API。复杂重写、窗口函数、JIT 与单查询并行延后。

| 模块 | 核心接口 | 约束 |
| --- | --- | --- |
| WorkspaceContext | identity、quota、root_handle | 由认证和监督器生成，业务不可修改 |
| Catalog | resolve、type_descriptor、object_version | 只解析本人对象与显式 public 只读入口 |
| Transaction | begin、snapshot、commit、abort | 不跨工作区 |
| TableAccess | scan、fetch、insert、update、delete | 负责可见性，执行器不直接修改页 |
| AssetStore | upload、read_range、delete、status | 不接受任意本地路径 |
| Retrieval | text、vector、hybrid、index_watermark | 所有结果回查有效 revision |
| GraphAccess | create、match、expand、delete | 同事务及有界遍历 |

优化变换必须保持 NULL、异常、外连接与类型语义；图与 ANN 路径不绕过工作区与事务检查。计划缓存包含工作区、对象版本、类型版本、索引 generation 及相关配置版本。

## 15 多线程与访问协议

每工作进程设置有界执行池、WAL 刷盘线程、维护线程及索引任务池；**网络 I/O 不执行重型 SQL**。一个会话同时只执行一条命令，不跨会话共享可变事务对象。线程遵守明确锁序；**latch 仅保护内存结构，行锁保护事务冲突**；**持 latch 不等待事务、不执行文件 I/O 或阻塞网络**。解析器可重入，错误处理不跨线程 longjmp。所有请求有截止时间、取消检查和内存预算。取消后必须释放锁、页引用、文件与队列状态。

协议采用**版本化结构化请求**，先交付 Python SDK 和 CLI，再提供可选 HTTP/MCP 适配层。SQL 使用绑定参数；资产流独立传输。返回结果包含 `request_id`、事务状态、稳定错误码、重试建议与检索水位；**NUMBER 使用无损十进制编码**。

写 API 提供 `idempotency_key`，其结果记录与业务变化**同事务提交**；相同键不同内容拒绝。记忆、配置与检查点使用 `expected_revision` 执行 CAS。分页游标绑定工作区、查询和有效期，**不允许他人复用**；长时间工具执行期间**不保持数据库写事务**。

任务调度若提供租约，必须包含 `expires_at` 和单调 `fencing_token`，过期工作者不得覆盖新检查点。SDK 明确区分**可重试冲突、资源拒绝、已中止事务和提交结果未知**；自动重试只用于幂等操作。MCP 传入参数**不能覆写工作区身份**。

### 阶段验收要点

**P0** 固定身份、public 发布与只读、工作区生命周期、文件系统、数据类型、SQL 与图子集、资产删除、检索新鲜度及备份政策。完成更新、提交、回滚、资产发布和索引切换的**逐动作持久化表**，写明每个中断点的恢复结果。原型应证明跨页值、目录隔离和资产同步假设可行。

**P1** 以两个用户及 public 验证独立根目录、进程文件权限、启动恢复与资源拒绝。接入层**不能凭请求 `user_id` 路由**。至少 100 万次带种子页操作与参考模型比较；1 万次随机崩溃并验证恢复中再次中断。

**P4** 覆盖 2、8、32 客户端读写交错、热点、长快照和锁等待；至少 1 万组随机历史符合 RC 模型。索引至少 100 万键；TSan 无未解释竞态。

**P7** 至少 1 万条确定与生成过滤检索和可见性测试；固定业务集提供关键词与混合质量报告。上传文档到分块、索引任务、删除传播全过程可追溯。

**P11** 综合关系、JSON、记忆、全文、ANN、图及资产的故障，进行至少 72 小时混合长稳与至少 1 万次全栈随机中断。额外覆盖用户进程崩溃、public 服务失效、接入路由失败、磁盘满、慢 fsync、慢客户端、配额耗尽、租约过期和重复任务。

**P12** 由**未参与实现**人员在干净环境完成安装、建用户、public 发布、Agent 任务、恢复、备份、恢复校验和回退。**隔离、错误结果、成功提交丢失、不可恢复损坏和提前文件回收均为阻断缺陷。**

## 17 统一验收与场景集

所有门禁以**可判定的不变量和独立参考模型**为依据，**次数是执行下限而不是正确性证明**。结果集无排序时按**多重集**比较；ANN 按召回和过滤正确性**分别**评分。

| 维度 | 判定依据 | 必须证据 |
| --- | --- | --- |
| 用户隔离 | 授权矩阵、OS 文件边界 | 攻击输入、身份、访问与拒绝结果 |
| 事务恢复 | 持久化模型、外部确认历史 | 故障位置、WAL、恢复对照 |
| 类型及 SQL | 差分与独立模型 | 版本、NLS、查询、参数、结果 |
| 资产一致性 | 文件状态机与引用清单 | 文件校验、提交历史、回收记录 |
| 检索与 ANN | 精确基准、业务标准答案 | Recall、延迟、过滤、水位 |
| 图 | 邻接模型与事务历史 | 路径、端点、预算与中断结果 |
| 生命周期 | 状态机及依赖模型 | 修订、撤销、派生删除证据 |
| 资源公平性 | 冻结额度及负载 | 每用户 p99、RSS、排队与拒绝 |

Agent 场景集至少包含：多轮任务中断恢复、两个 Agent 竞争检查点、工具重试、长期事实纠正、相互矛盾记忆、TTL 到期、源文档撤销、嵌入模型升级、public 知识版本切换、恶意检索内容与用户注销。

**数据库失败与模型回答质量分开统计**——不以模型回答正确证明索引或权限正确。

## 18 运维、备份与可观测性

管理员只获得工作区状态、额度、进程健康与聚合性能，**不提供读取私有业务内容的 SQL 或文件接口**。默认**不记录**完整 SQL 参数、JSON 正文、文档片段与向量；审计记录身份、Agent、请求、对象 ID、动作、结果、版本和错误码。用户只能查看本人审计，public 发布审计独立保存。

指标覆盖提交及恢复、Undo 最老快照、锁等待、查询内存、临时文件、资产孤立与回收、outbox 积压、全文与 ANN 水位、召回评测、图扩展量、工作区启动延迟与 public 服务状态。必要诊断转储按用户单独生成，并由本人授权导出。

### 18.1 备份与恢复按数据分档

**能力来自 REDO 的存在**——归档日志保留连续的日志链，是**时间点恢复、在线备份与备库**三项能力的共同基础。

| 数据 | 是否受 REDO 保护 | 恢复能力 |
| --- | --- | --- |
| `logging = full` / `redo_only` 的表、图、配置、记忆 | **是** | **支持在线备份与时间点恢复** |
| `logging = none` 的表（会话表等） | 否 | **不参与**备份与恢复，视为**可丢失** |

> **必须显式声明**：时间点恢复**不覆盖**不记日志的表——它们恢复到任意状态，与目标时间点不一致。这是"选择不记日志"的必然代价，不是缺陷。用户不应以为 PITR 能把整库恢复到某一时刻。

**归档必须每工作区独立**：归档内容与 redo 一样**含用户数据**（行级修改描述），共享即泄漏。归档目标须落在该工作区的受控目录内。

**归档是前提而非可选**：若无归档，redo 组被循环覆盖时日志链即断，上表所列能力全部失效。

### 18.2 三种恢复路径不可混淆

| 路径 | 使用的日志 | 触发场景 |
| --- | --- | --- |
| **实例恢复** | **仅在线 redo** | 崩溃后自动执行，只需最近日志 |
| **介质恢复** | **需要归档日志** | 从备份恢复数据，需应用备份时间点到目标点的全部日志 |

已实现的崩溃恢复属**实例恢复**；在线备份与时间点恢复属**介质恢复**，两者是不同机制。

### 18.3 离线一致备份

暂停目标工作区写入 → 完成规定检查点和资产发布 → 固定资产清单 → 复制数据、控制、日志与资产 → 校验大小与哈希。备份属于原工作区并控制介质权限；恢复验证 owner、工作区标识、版本与完整引用。

### 18.4 离线迁移工具

用于**跨机迁移与版本升级**，覆盖**全部数据**——包括不记日志、不参与在线复制的表。

这是不记日志的数据**唯一**的保留途径；**新软件格式不支持时拒绝启动**，首版即以此工具完成升级。恢复到新目录但**保留相同身份**，不能将恢复功能作为数据转让。

### 18.5 性能基线

性能**不预先承诺任意 TPS**。P0 冻结基准机规格、实例总缓存预算、活跃工作区档位、资产规模和索引规模；记录 p50/p95/p99、吞吐、冷启动、构建、恢复及备份时间。P7 形成基线，后续相同条件**无未解释的超过 10% 回退**。

## 19 关键风险

| 风险 | 控制措施 |
| --- | --- |
| 隔离入口遗漏 | 工作区贯穿 + 攻击测试；隔离失败为发布阻断项 |
| 文件与元数据耐久性不一致 | 资产逐点故障注入 |
| Undo 及索引可见性错误 | 独立事务模型 + 随机历史对照 |
| ANN 滞后或删除传播不完整 | revision 与水位校验 |
| 图遍历失控 | 有界资源 + 扩展边数预算 |
| 局部正确而全局协议不闭合 | 规格先行、阶段门禁 |

**JSON、向量、图及资产进入同一产品，不意味着必须具有相同物理存储或同一更新机制。**
