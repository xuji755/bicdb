# 实例并发与启停恢复

## 1. 实例边界

一次部署只运行一个 `bicdb start` daemon。`public`、`personal` 和用户工作区是同一实例中的逻辑工作区，不是可独立启动的数据库服务。

实例级资源只有一份：全局控制文件、DB Cache、SQL worker 池、控制面和执行队列。工作区拥有目录视图、文件映射、undo 上下文、redo 组与恢复水位、配额和执行限额。服务装配使用一个共享 BufferPool、I/O 句柄空间、文件注册表和工作区 WAL 路由。当前 `Instance` 类型仍用作工作区引擎/字典的容器，但 BIND 不再为工作区分配另一个缓存或启动服务进程。工作区保留独立控制进度、redo 和 undo。

### 1.1 后台线程与资源归属

实例启动后构造一张工作区运行时表。每个已打开工作区拥有独立的 redo buffer、redo 组、undo 与检查点状态。LGWR 由实例线程池公平调度各工作区；CKPT 是实例全局协调者，按工作区跟踪检查点目标与完成水位。工作区运行时可延迟打开，但接收 SQL 前必须完成恢复门并注册后台调度。工作区日志故障应使对应工作区拒绝写入；全局控制文件或共享缓存一致性故障则必须封锁整个实例。

DB Cache 由整个实例共享，不按工作区重复创建。缓存按 KCBWDS 工作集分区，按页键 `(workspace_ref, rdba)` 分布到分区，同一工作区可使用多个分区；实例按 KCBWDS 分区数启动 DBWR，每个 DBWR 只扫描和写回自己分区中的脏页，写回前通过脏页所属工作区的 WAL guard 确保对应 `page_lsn` 已持久化。因而后台线程归属为：

| 资源/线程 | 数量与归属 |
|---|---|
| DB Cache | 实例一套 |
| KCBWDS | 实例配置的 N 个工作集分区 |
| DBWR | 每个 KCBWDS 分区一条；线程数随分区数确定 |
| redo buffer / redo groups | 每个工作区一套 |
| LGWR | 实例线程池，公平服务各工作区 |
| CKPT | 实例全局协调，维护各工作区检查点状态 |
| undo / 事务槽 /恢复水位 | 每个工作区一套 |

共享 BufferPool 必须按脏页的 `workspace_ref` 选择 WAL guard；不同工作区的 LSN 不能直接比较。不能在实例级 `redo_write` 闩锁内等待某一工作区的 fsync；注册表只短时查找并取得运行时引用，日志 I/O 串行化归对应工作区，防止一个工作区拖住所有 DBWR。

工作区关闭时先停止接收新事务并排空/回滚事务，由全局 CKPT 请求涉及的各分区 DBWR 写净该工作区，再完成日志刷盘、文件持久化和最终检查点。只有脏页、后台请求及持有引用均清空后，才能注销文件映射和 WAL guard。实例停机保持 LGWR、DBWR 和 CKPT 可用，直到所有工作区完成最终检查点，随后停止后台线程。

### 1.2 并发与持久化约束

1. **检查点水位按工作区存储。** 不设置全局 LSN；全局 CKPT 分别保证每个工作区的一致性，聚合该工作区所有缓存分区的完成回执。某工作区故障不阻止其他工作区启动。
2. **检查点必须覆盖正在发布的修改。** redo 已追加但页尚未标脏的修改也必须计入恢复下界；CKPT 不能仅看到“脏页为零”就推进到日志末端。需要修改发布屏障或在途修改水位。DBWR 冻结页镜像写盘后，必须比对修改序号；期间再修改的页继续保持脏状态。
3. **写成功不等于持久化。** 数据文件需完成对应 sync 后才能发布检查点；redo 复用许可与恢复起点通过可恢复的控制文件发布协议一同持久化。日志复用还须满足归档策略。
4. **提交必须经过耐久门。** 事务提交等待自身工作区目标 LSN 已持久化；后台超时或 I/O 错误不能返回提交成功。LGWR 调度限制每个工作区每轮的处理量，避免长期占用全部日志线程。
5. **工作区缓存最低保障为 2 GiB。** 实例共享缓存，按页分区并按工作区进行占用和保留额度核算；每个已激活工作区最低保障 2 GiB（131072 个 16 KiB 帧），空闲额度可借用，发生压力时归还。该值是容量保障，不要求启动时立即填满缓存。实例总缓存必须覆盖已激活工作区的最低保障之和；容量不足时拒绝激活新工作区并报告所需容量，不静默降低已有工作区保障。PUBLIC 计入保障额度。
6. **禁止跨工作区读写。** 每个会话/事务只能读写自身工作区；唯一例外是其他工作区可经授权只读访问 PUBLIC。禁止访问其他私有工作区，禁止经 PUBLIC 只读入口执行 DML、DDL、文件/图写入或有写副作用的函数。PUBLIC 的维护只能通过显式绑定 PUBLIC 的授权会话完成；应用角色还须满足对象写权限。PUBLIC 字典变更与新工作区文件供给采用可重入的创建/删除协议。
7. **行锁等待进入 enq 队列。** 按 `(workspace_ref, 稳定 ROWID)` 管理持有者与 FIFO 等待者；等待会话保存语句恢复状态，释放 worker、页 pin 和短期闩锁。登记等待和重新检查持有者须原子化，避免丢失唤醒。解锁后唤醒符合锁模式的等待者，回实例执行队列重新检查锁与谓词；支持超时、取消、断连清理和等待图死锁检测。COMMIT/ROLLBACK 保留执行名额，避免持锁事务被等待任务挤出。
8. **故障隔离有边界。** 独立日志流不代表共享磁盘带宽、缓存容量或全局元数据故障都已隔离。工作区缓存配额、后台 I/O 配额及故障状态需进入监控与调度。

共享缓存和工作区 WAL 路由已接入服务装配；实例级 LGWR、CKPT、Undo 修复线程池和按缓存分区的 DBWR 已接入。DBWR 已实现有界跳过与公平重试、异步通知 LGWR；缓存已按页多分区，工作区配额在实例统一核算。后台耐久性故障写入封锁已接入；enq 释放 worker 已完成服务层接入和内存验收，正式 daemon 运行验收与强制恢复仍待完成，不能视为整体架构已验收。

### 1.3 DBWR 临时跳过算法

每个 DBWR 维护本分区的临时跳过清单，键为 BufferKey，记录原因、所需日志流/LSN、重试次数与下次检查时间。清单不长期 pin 页，不保存可失效的裸帧引用，同一页只保留一项；每次回查重新定位当前页并检查其身份及日志水位。写回快照记录独立修改代次；页已变净或不再驻留时移除清单项。

1. 每轮冻结有界数量的候选页。遇到已 pin/写锁占用、redo 尚未耐久的页，加入清单后继续处理其他候选；不在扫描路径上等待日志 fsync。候选排序只在同一工作区 LSN 域内进行，工作区间轮转。
2. 对尚未耐久的 redo，按工作区合并最大的目标 LSN，向 LGWR 发出非阻塞刷盘请求；日志完成通知到达后唤醒对应 DBWR。页占用释放也可通知；定时复查作为兜底。
3. 完成本轮可写页后，以有界批次回查清单。重新定位页并核对帧代次与当前 page_lsn；只写满足条件的页，未满足者退避后保留。每轮兼顾新候选与旧清单，避免任一方饥饿。
4. 冻结可写页镜像后执行 I/O；落盘时若页被再次修改，原页继续为脏，新修改的恢复水位不得被清除。清单容量受分区容量约束；超过阈值则报告缓存/日志压力并限制该工作区新写入，不能丢弃脏页。
5. 日志或数据 I/O 硬错误进入工作区故障状态并单独报告，不作为“暂时不满足”无限重试。CKPT 包含跳过页和在途修改的恢复下界；清单未清空时不能宣告完全检查点成功。停机超时应报告未完成项并保留恢复信息。

## 2. 调度模型

实例使用共享 SQL worker 池和一条公平执行队列。调度器按工作区轮转，工作区不拥有独立线程池。以下参数均为重启生效：

- `service.worker_threads`：SQL worker 数；
- `service.execution_queue_capacity`：实例等待队列总容量；
- `service.max_active_per_workspace`：单工作区同时执行上限；
- `service.workspace_queue_capacity`：单工作区等待名额；
- `service.control_workers`：控制面预留并发数；
- `service.max_connections`：连接上限，不等同于 SQL 并发数。

`HELLO`、`STATUS` 等控制请求不进入 SQL 队列。行锁等待登记到 enq 队列并释放 SQL worker，不得阻塞控制面或耗尽 worker。锁被释放后，`UPDATE`/`DELETE` 必须重新扫描并重新计算谓词，不能复用等待前的行镜像或物理地址。

## 3. ROWID 与块更新

ROWID 是稳定的逻辑地址。行增长且原块无法容纳时，根槽改为 forwarding pointer，二级索引仍保存根 ROWID。迁移目标只是内部物理位置。多次迁移形成转发链，但根 ROWID 不变。

常见的小幅增长应在内存块副本中 compact 并保持原槽；只有块内重组后仍无法容纳时才迁移。`PCTFREE` 由 INSERT 保留，供已有行增长使用。

块更新的目标协议是：准备 undo 和行级 redo 空间，短时 pin 并写锁目标块，复制当前块，在私有副本中重组，校验后原子发布并标脏。不能在共享缓存块上逐段暴露半完成状态。现有 WAL 的 `page_diff` 是过渡物理差异格式；块重组会放大日志，后续格式升级应增加带版本的行级 redo，并保留旧格式恢复兼容。

## 4. 临时表空间

file 2 是独立 temp 文件：不进入 DB Cache、不生成 redo、不进入检查点和备份。初始化、每次启动及干净停机都重置其文件头和分配位图。崩溃后的临时内容直接丢弃，不参与恢复。

## 5. 启动恢复门

daemon 只能由 `bicdb start` 创建。服务发布 `READY` 前必须顺序完成：

1. 核对控制文件、数据文件身份和检查点位置；
2. 扫描 redo，执行 redo；
3. 修复已提交事务槽并回滚 loser；
4. 确认全部 undo 槽均不处于 `Active` 或 `PendingRollback`；
5. 重置 temp；
6. 完成恢复检查点，确认工作区脏块为零；
7. 注册工作区 WAL guard，并加入实例 LGWR/CKPT 调度；
8. 才允许路由到该工作区。

PUBLIC 保存关键系统元数据，必须完成一致性校验与恢复后才能开放实例；PUBLIC 不一致时必须修复或修补，不能通过强制启动绕过。其他工作区恢复失败不阻止整个实例启动。对能够提供一致读的工作区进入 `READ ONLY`；若 undo/页结构损坏导致无法重建一致读，则进入 `RECOVERY REQUIRED`，只开放状态诊断和恢复命令，避免只读查询暴露未提交数据。全局控制文件或实例共享结构损坏仍须拒绝实例开放。

管理命令已接入第一阶段：`ALTER WORKSPACE <name> OPEN READ ONLY`、`ALTER WORKSPACE <name> OPEN READ WRITE`、`ALTER WORKSPACE <name> OPEN READ WRITE FORCE`。它们只允许本机管理面身份在 PUBLIC 执行，SQL worker 必须同步收到 daemon 主控制器对“已恢复、已注册后台角色、已改变写准入”的确认才返回成功；离线/直连执行器不会伪造成功。普通读写打开必须通过恢复校验；显式 FORCE 可跳过窄范围且可精确分类的一致性检查并进入 `READ WRITE FORCED`。FORCE 不能绕过文件身份校验、越界校验及无法解析的结构；PUBLIC 始终禁止 FORCE。

## 6. 停机协议

`fast` 停机停止接收新请求并排空已接收队列，然后：

1. 显式回滚所有连接的未提交事务；
2. 确保回滚和提交 redo 已刷盘；
3. 由全局 CKPT 发起最终检查点，保持 LGWR 与 DBWR 工作，把各工作区 redo 刷到目标水位；
4. 由 KCBWDS 对应的 DBWR 写回所有工作区脏块；
5. 同步数据文件，再按工作区发布并刷盘完全检查点；
6. 验证各工作区脏块数为零；
7. 重置 temp；
8. 完成控制文件与数据文件头的一致性发布，停止实例 CKPT、DBWR、LGWR 并退出。

`immediate` 不执行干净关闭流程，下次启动必须经过完整恢复门。


## 7. 实例强制启动

```bash
bicdb start -p <bicdb.ini> --force
```

`--force` 是本次启动的显式选项，不作为参数文件中的永久默认值。其作用是允许非 PUBLIC 工作区在正常恢复失败后，跳过已识别的不一致数据/恢复项继续打开；正常恢复仍须先尝试，不因指定 FORCE 而直接省略恢复。

- **PUBLIC 是启动硬门。** 系统元数据、身份、权限、工作区注册表与文件映射必须一致。PUBLIC 或实例关键控制结构不一致时，启动失败，并报告需修复/修补的对象；`--force` 无权跳过。修复动作须显式执行，不能在强制启动时静默改写元数据。
- **其他工作区允许强制打开。** 单独收集恢复错误与受影响的页、对象、事务和日志范围，跳过可定位的不一致项，将工作区标记为 `READ WRITE FORCED`。正常工作区仍以普通读写状态打开，不因某个工作区失败而全部降级。
- **跳过必须落实到访问边界。** 已跳过的页/对象隔离并返回明确错误，不作为空数据静默返回，也不提供已验证的一致性保证。仅能定位到对象或工作区的故障按该范围隔离；无法解析的区域不能继续做普通读写。禁止将可疑页重新刷成“正常”页，或回收仍可能用于后续修复的 redo/undo。
- **异常范围必须持久记录。** 保存启动方式、操作者、错误、跳过项与日志/恢复位置；状态查询展示强制模式及受影响范围。下次普通启动不能自动清除这些记录，只有修复并校验通过才恢复正常状态。
- **权限和隔离继续生效。** FORCE 不绕过 PUBLIC 认证授权，不开放跨私有工作区访问，也不赋予其他工作区 PUBLIC 写权限。非 PUBLIC 强制打开失败不能拖住其他工作区；记录失败原因并继续实例启动。

单工作区的 `ALTER WORKSPACE ... OPEN READ WRITE FORCE` 与实例 `start --force` 使用同一套错误清单、隔离和审计机制。实例级强制启动仅批量应用于非 PUBLIC 工作区，不能生成一个忽略 PUBLIC 一致性的全局开关。

当前已实现 `bicdb start -p <bicdb.ini> --force` 的第一阶段窄范围：PUBLIC 始终先按普通模式恢复并作为 READY 硬门；私有工作区在后续 BIND 延迟打开时才收到本次启动的 FORCE 权限。代码从字典物理形状重新判断 PUBLIC，不能靠伪造路径绕过。FORCE 目前只允许跳过两类可精确描述的水位不一致：数据文件 `checkpoint_commit_scn` 超前于控制文件，以及 `file_scn` 超前于控制文件恢复位置。文件身份、参数事实、页/Undo/Redo 结构、恢复扫描、loser 回滚和恢复检查点仍全部执行，任何失败仍进入 `RECOVERY REQUIRED`。

只有实际跳过检查的私有工作区才记 `Forced` 审计，包含操作者入口、跳过项与恢复后日志位置，并显示 `READ_WRITE_FORCED` 和原因；指定 FORCE 但正常校验全部通过时仍记 `Verified`，不制造强制状态。管理员只读是独立的可逆运行时闸门，不伪装成耐久性故障，也不停止 DBWR/CKPT/Undo 维护；关系 DML/DDL、写 Cypher、索引维护和新事务在修改前被拒绝，查询和回滚保持可用。STATUS 显示 `READ_ONLY | READ_WRITE | READ_WRITE_FORCED | FAULT_READ_ONLY`及原因。

已打开工作区若存在粘滞耐久性故障，命令不会在原缓存上清除封锁；需先排空并重新走恢复打开边界。持久异常历史及结构化范围可通过 `recovery$` 查询；当前故障源只能可靠定位到工作区时按 `WORKSPACE` 记录。页/对象级执行隔离与在线/离线修复验证已在第 20–23 节完成；FORCE 仍不能覆盖任意损坏，也不得用于无法解析的结构错误。


## 8. 当前实现与参数

- 服务 `open_shared_with` 将所有已打开工作区连接到同一缓存；独立日志流经 WorkspaceWalRouter 满足页写前的 WAL 规则。
- 每激活一个工作区预留至少 131072 帧（2 GiB）；总缓存不足则拒绝新工作区激活。帧复用维护工作区驻留计数，超过最低额度的部分可以被其他工作区回收，最低额度内的页只能由本工作区替换。默认总缓存调整为 2 GiB；已有显式参数值不自动改写。
- `buffer.kcbwds=4` 指定缓存工作集分区数（1–64，必须为 2 的幂），每分区启动一个 DBWR。`buffer.pool_frames` 仍为实例总帧数，须整除分区数；每分区缓存策略按分配到的帧数计算，不把总缓存重复分配 N 份。
- 页按完整 `(workspace_ref, file_id, block_id)` 键稳定分布，同一工作区可以使用所有分区。`dirty_len`、`low_water`、工作区刷盘覆盖全部分区，工作区列表去重；检查点取该工作区各分区的最老脏页 LSN，不跨日志流比较。多块读仍保持一次连续文件 I/O，逐页装入对应缓存分区。
- 工作区最低额度及总驻留数由实例统一核算，不把 2 GiB 切成互不相干的分区配额。候选选择之后、摘链之前再次原子检查额度并扣减计数；多个分区同时淘汰也不能突破最低保障。空闲额度仍可借用，NUMA 的工作区首选分区仅用于亲和规划，不代替实际页分区。
- 前台腾帧优先写回申请工作区自己的可复用页，排除其他工作区最低保障内的页和已占用页；避免把有界写回批次花在刷净后仍不能借用的页上，随后错误返回缓存不足。候选排序不跨工作区比较 LSN。
- 后台参数均为重启生效：`wal.lgwr_threads=2`、`wal.lgwr_interval_ms=3000`；`checkpoint.checkpoint_threads=1`、`checkpoint.checkpoint_interval_ms=5000`；`undo.undo_threads=1`、`undo.undo_interval_ms=1000`；`buffer.dbwr_interval_ms=3000`。LGWR、CKPT、Undo 线程数均限制为 1–64；配置的是实例共享线程池规模，不随工作区数自动增加进程或线程。
- CKPT 与 Undo 按工作区分配任务，各线程轮转处理所分配工作区。SQL/WAL/undo 边界忙或已驻留 Undo 页忙时，非阻塞退让；元数据 fsync 仍可能受磁盘延迟影响，多个 CKPT 线程可减少一个工作区的 I/O 等待对其他工作区的影响。
- 运行期 CKPT 使用增量检查点，不修复 Undo 槽、不写脏块、不在缺少文件头缓存时触发腾帧写回。Undo 独立维护线程装入所需文件头并修复已提交事务槽，修复镜像标脏，交 DBWR 写出。CKPT 保留尚未耐久的修复所依赖的提交 WAL；修复记录按物理 `(usn, slot)` 而非 wrap 编号管理，旧代回滚不能删除新代提交记录。
- CKPT 冻结该工作区恢复下界，确认日志已耐久，持有净文件头的 pin，再 sync DBWR 曾写过的全部文件（包括其页已被淘汰的文件），之后发布控制文件进度和组降级，再更新并 sync 文件头的 checkpoint SCN / 恢复 LSN。写数据块发生在 DBWR；显式完全检查点 API 是停机/恢复协调入口，按 Undo 准备、redo flush、DBWR 排空、CKPT 元数据发布的顺序执行。
- 文件头旧 `file_scn` 位于 96..104，历史含义是恢复 LSN，保持不变；原 88..96 保留区新增 `checkpoint_commit_scn`，对应控制文件的 `checkpoint_commit_seq`。旧文件该字段为 0；文件大小、位图偏移和版本不变。文件增长读取最新头页，避免旧 DataFile 句柄覆盖 CKPT 元数据。
- 控制文件先于文件头发布，防止正常崩溃窗口产生“文件头超前于控制文件”的假不一致；部分文件头未更新或 sync 失败时保留重试状态，检查点调用报告失败，下一轮重试。启动拒绝文件头 SCN/LSN 超前于控制文件。滞后文件的介质恢复分类、损坏文件头修补和强制隔离仍需完善，不能把本轮元数据发布验收当作完整故障恢复验收。
- 空闲线程使用条件变量定时休眠；CKPT、Undo 不因无关 LGWR 通知提前醒来，停止通知可立即唤醒。LGWR 水位未推进不额外唤醒 DBWR，CKPT 空闲延期也不唤醒无脏页的 DBWR。检查点自身生成的元数据 redo 不触发无限新检查点；成功发布且水位未变化时不重复写文件头或 fsync。
- STATUS 显示实际 `lgwr_threads`、`checkpoint_threads`、`undo_threads`，并显示选定工作区的 `checkpoint_attempts`、`checkpoint_deferred`、`checkpoint_lsn`；不构造跨工作区全局 LSN。`background_failures` 汇总后台故障，不能把后台失败静默当成功。
- 完全停机先排空/回滚连接并完成各工作区检查点，再结束后台线程；immediate 不 join/收尾刷盘，重启走恢复门。
- DBWR 每轮分别处理最多 256 个新候选和 256 个到期重试项，工作区间轮转；游标为工作区编号，上一页刷净消失不影响轮转。旧重试按到期时间优先，反复占用的低地址页不会一直抢占批次。缓存候选扫描只在收到通知或扫描周期到期时进行，短间隔重试只重新定位清单页；候选快照有积压时连续处理后续批次，不等待新周期、不为每批重复全缓存扫描。依据实际脏页快照清理过期项，候选和跳过清单总量受分区帧数约束。
- pin、其他写回在途或对应工作区 redo 尚未耐久时立即跳过，退避从 10 ms 至 640 ms；线程等待取重试期限与配置周期的较小值。周期参数仍控制新脏页扫描兜底，清单重试无需等待整个周期。
- DBWR 按工作区合并最大的所需 LSN，通过 WorkspaceWalRouter 的实例通知钩子请求 LGWR；通知只登记目标并唤醒线程，不执行日志 I/O。LGWR 达到目标后唤醒 DBWR；不同工作区目标不进行全局比较。
- 同一缓存帧只允许一个页写回在途，I/O claim 持有短期 pin 防止帧复用；页镜像写盘时允许新修改。收尾持内容读锁核对独立 64 位修改代次与页头序号，修改序号回绕也不会误清脏状态。被跳过或再次修改的页保留首次变脏水位。
- STATUS 新增 `dbwr_passes`、`dbwr_pages_written`、`dbwr_failures`、`dbwr_deferred_pages`、`dbwr_pinned_pages`、`dbwr_in_flight_pages` 与 `dbwr_redo_pending_pages`，统计为实例级聚合快照。
- STATUS 的 `cache_partitions` 与 `dbwr_threads` 显示实际分区和写线程数量，二者一致；`cache_frames` 和 `cache_bytes` 显示实例总容量。
- 数据/WAL 硬错误与临时跳过分开处理：DBWR、LGWR、CKPT 或 Undo 维护发生后台耐久性错误时，将工作区写入封锁状态登记到共享缓存运行时。所有 DBWR 都停止写该工作区；事务开始、DML、行锁与提交、Undo 回收和 SQL DDL/DCL/写 Cypher 在业务修改前拒绝。故障状态保留第一条错误，普通重试或回滚不能清除，只有新缓存中的已验证恢复才可恢复写入。其他 DBWR 观察到封锁时同时移除该工作区的候选积压与延期项，保留脏页，避免在无可执行任务时连续空转。查询与显式回滚保持可用；故障后不再推进检查点或复用相关日志，保留脏页与恢复信息。
- 非 PUBLIC 故障不阻止其他工作区写入；正式 PUBLIC 注册为关键元数据工作区，发生故障后封锁整个实例的业务写入。该范围判定由正式 PUBLIC 根目录装配；独立内存测试可显式登记关键工作区。STATUS 增加 `workspace_write_state=READ_WRITE|FAULT_READ_ONLY` 和首个 `workspace_fault`。正常无故障路径只检查原子标志，不争用故障表锁。
- 缓存缺帧或页忙仍是暂时延期，不能误当耐久性硬错误。读操作发生故障时继续按原有页身份/校验处理，不把损坏页伪装为有效数据。运行时封锁状态保存在进程内，首次故障同时异步追加到持久恢复审计并可由 `recovery$` 查询；工作区完整恢复状态机、元数据 I/O 超时控制和停机超时清单仍待实现。

## 9. enq 非阻塞接口推进

事务引擎已提供 `enqueue_row_wait` / `poll_row_wait` / `load_row_wait_header` 与拥有式 `RowOwnerWait`。等待票据不持页 pin、WAL/undo 锁、游标或操作系统线程；轮询只读驻留 Undo 头镜像，不取 WAL/undo mutex，不触发文件 I/O。缺页通过 `needs_header` 告知执行层，由短任务显式装入；忙页延期。等待计时使用单调时钟与实际截止时间，取消、超时、死锁及请求丢弃均清理对应登记，事务此前持锁与修改继续由语句/事务边界负责。

WaitGate 的每次登记有独立代次；旧请求清理、旧通知不能取消新的登记。同一事务在注册表中只能等待一个持锁者/行，换目标时移除旧边。持锁者结束按登记次序输出唤醒清单；通知保留到轮询消费，登记前已结束的持锁者可通过驻留槽检查发现。唤醒只允许重新扫描与校验谓词，不移交锁，也不改变稳定根 ROWID。死锁检测新增驻留槽查询接口，保持既有牺牲者策略。

现有同步 `wait_for_row_owner` 已复用该票据接口。**服务中的 SQL 语句仍走同步等待，尚未释放 SQL worker。** 下一步必须让 SQL 保存回滚后的事务、原语句/参数及批次位置，将票据交实例等待集合，释放执行名额；唤醒后重新入公平队列并重新绑定/扫描原语句，同时实现等待名额、事务结束预留、断连/超时清理。不能以本轮事务接口测试替代整个服务 enq 验收。

## 10. 后台空闲休眠补充

LGWR、DBWR、CKPT 和 Undo 修复线程无任务时通过条件变量定时阻塞，停止通知可立即唤醒，不使用忙轮询。默认周期分别为 3000、3000、5000、1000 毫秒，可通过 `wal.lgwr_interval_ms`、`buffer.dbwr_interval_ms`、`checkpoint.checkpoint_interval_ms`、`undo.undo_interval_ms` 配置；参数拒绝零值。独立 LGWR/DBWR 构造接口同样拒绝零间隔，等待谓词忽略未携带任务的伪唤醒，保持原定超时。DBWR 对被 pin、在途或等待 redo 的页保留 10–640 毫秒退避清单；有可执行批次时继续处理，无可执行任务则休眠。

新增内存测试反复发送无任务通知，确认 LGWR 不执行 flush、DBWR 不执行扫描，并验证停机通知无需等待 5 秒周期即结束线程。没有启动、重启或创建数据库实例。

## 11. 服务层合作式行锁等待接入

第 9、10 节描述的是当时的阶段状态；当前 SQL worker 已改用 `SqlRequest` / `SqlStep`。等待前回滚本语句的局部修改，保存原 AST、参数、批次位置和事务状态，将 `RowOwnerWait` 交控制器的等待集合。未向客户端提前回复，未为等待者创建独立执行线程；活跃执行名额释放给其他请求。唤醒后恢复同一连接的状态，重新绑定/扫描原语句，批次已完成语句不重放。

等待集合消耗 `execution_queue_capacity` 与 `workspace_queue_capacity`，不消耗 `worker_threads` 或 `max_active_per_workspace`。唤醒、取消、超时和停机清理复用已预留的等待名额，不需要重新申请普通队列名额。等待名额不足时仍保留当前 worker 的活跃计数，将语句取消交 worker 清理；不能遗失事务状态。只有显式事务中的单条 COMMIT/ROLLBACK 使用结束事务预留队列，其总量受 `max_connections` 参数约束；不会因普通队列被等待者填满而拒绝释放锁。结束事务命令仍计入实际活跃线程与工作区活跃上限。

控制器只执行非阻塞驻留槽检查，冷 Undo 头页装入交短 worker 任务。事件循环空闲阻塞最多 100 毫秒；后台仍按第 10 节休眠。等待者按同一引擎的注册次序重新入队，而不是按连接号排序；通知允许重试，不是行锁移交。STATUS 增加 `execution_parked`，`execution_queued` 表示已就绪队列，二者分别报告。

连接在等待 SQL 回复时，每 100 毫秒检查 socket 是否断开；使用安全的非阻塞 PEEK，不消耗下一帧内容，不改变 socket 阻塞模式。连接断开设置共享取消标志；排队但未执行的 SQL 拒绝业务执行并回滚已有事务。已挂起请求复用等待名额进行清理。fast 停机取消所有挂起等待并等清理完成后才进入原有检查点/停机阶段；immediate 保持恢复语义。尚未提供通用的执行中 SQL 中断协议，不能将本轮断连排队清理等同于所有长语句的即时取消。

新增内存文件系统验收使用真实 catalog、WAL、Undo、Session 和 SQL worker，不启动 daemon 或磁盘实例：

- 单 worker、普通等待容量仅 1：等待者挂起后，持锁者通过预留 COMMIT 释放锁；原批次恢复，先前 INSERT 只执行一次。
- 等待名额不足不错误释放活跃计数；外部调度器不能消费其他调度器的等待票据。
- 待回复客户端断开可及时报告 Closed；PEEK 不消耗流水输入。
- 断连的排队 `COMMIT; INSERT` 不执行，未提交修改回滚。
- fast 停止清理挂起自动事务，归还全部名额，之后相同行更新无遗留锁。

## 12. 干净停机失败门补充

工作区 `shutdown` 不再忽略事务回滚错误：失败时保留句柄、登记故障写入封锁并返回错误，不推进最终检查点或清空 temp。服务停止先回滚连接事务，随后关闭全部已打开普通工作区与 PUBLIC；LGWR、DBWR、CKPT 和 Undo 线程直到这些步骤成功后才停止。PUBLIC 最终检查点错误向上传播，不再只写日志后返回成功。

新增独立 `checkpoint_shutdown` / `shutdown_checkpoint`，在持有工作区 writer 与 undo-chain 锁的边界，检查修复已知提交记录后的私有 Undo 头镜像。存在 Active 或 PendingRollback 槽时拒绝干净关闭，报告槽号和状态，不追加检查点、不发布控制进度、不复用 redo。只有验证完成才进入已有 redo flush、DBWR 排空、文件 sync、CF/文件头发布流程。运行期 `checkpoint_full` 保留可包含活跃事务的原有语义，不能用运行期检查点代替干净关闭验证。

immediate 路径不再遍历连接回滚事务，不执行最终检查点、后台 join 或 temp 清理；进程退出后的恢复门仍负责 redo 和 loser 回滚。本轮不执行运行实例停机测试。完整的停机超时与持久失败清单仍待完成。

另修复同步排空在遇到其他 DBWR 的在途 I/O claim 时持续 `yield_now` 的 CPU 空转，改为 1–32 毫秒指数退避休眠。后台 DBWR 的独立 10–640 毫秒清单退避保持不变。

## 13. 持久恢复审计基础接入

存储层新增 `RecoveryJournal`，每个工作区根目录保存独立 `recovery.audit`，不进入 DB Cache 或 redo。每项使用固定 16 KiB 帧，包含格式标识、工作区身份、独立审计顺序号、时间、工作区日志位置、状态、子系统/操作者及错误/验证详情；CRC32C 覆盖完整帧。事件追加后执行 fdatasync，新文件先 fsync 文件与父目录。不截断、覆盖或静默清空历史。记录中的日志位置只属于该工作区；恢复开始/失败尚未取得有效进度时为 0，详情明确说明起点待校验。

正常打开已接入审计：控制文件提供工作区身份后，先验证既有审计并持久化 Recovering；随后执行已有文件核对、redo/undo、loser 回滚和耐久检查点。只有这些步骤全部完成且 Verified 事件持久化成功，才能返回可供业务路由的工作区。失败记录包含原始错误；错误过长按 UTF-8 字符边界限制至 4096 字节。审计持久化也失败时同时报告两类错误，不报告开放成功。实例锁保留到审计结果发布之后。

既有无审计文件的工作区按上述恢复门生成首份记录；存在残缺尾部、校验错误、身份错误、非法状态或顺序错误则拒绝普通开放，不把损坏审计当作无历史。事件写入或 sync 失败后，该句柄禁止继续追加，必须重新打开/修补；防止后续成功状态覆盖部分写入的故障记录。并发旧句柄通过文件长度核对拒绝覆盖，但跨进程所有权仍由实例锁保证。审计上限为 4096 项（64 MiB），到达上限时拒绝继续追加并报告需显式归档；停机归档命令已在第 23 节实现。本版不在运行期自动改写恢复审计，避免与故障写线程竞争。

Recovering、Verified、Failed、RuntimeFault、Forced 的格式在本阶段定义；后续第 14、17、19、20 节已经接入运行期故障、FORCE、只读隔离和 SQL 查询。PUBLIC 审计不一致仍是启动硬门；私有工作区审计失败使该工作区无法绑定，不阻止已通过恢复门的 PUBLIC。不能仅凭审计末项 Verified 跳过完整恢复检查。

新增内存故障注入验证保留历史、外部身份拒绝、撕裂尾部拒绝、完整帧损坏拒绝、sync 失败后禁止伪成功、旧句柄覆盖拒绝、UTF-8/长度/保留位/顺序的结构校验与父目录同步失败。未创建、启动或重启数据库实例。

## 14. daemon 运行期故障异步审计

共享 BufferPool 新增一次性非阻塞故障通知口。先登记首次故障和写入封锁，再将事件交审计 sink；不在缓存故障表、通知口或页内容锁内执行回调。安装通知口时重放已有首因；新旧通知竞态由 sink 去重。回调只登记事件，不执行文件 I/O，也不等待审计写线程。

daemon 在 PUBLIC 验证恢复后启动一条 `bicdb-fault-audit` 线程，所有逻辑工作区注册各自 `recovery.audit` 路径后再进入后台调度。每个已注册工作区只允许首个故障处于 Pending；重复故障不扩大队列或覆盖首因。写线程取出任务后释放调度 mutex，再追加 RuntimeFault 并 fdatasync。空闲时以条件变量无限阻塞，不设周期扫描；伪唤醒只重检任务谓词。记录日志位置暂为 0（未提供已校验的故障位置），故障范围为整个工作区；精确页/对象/redo 范围仍待补充。

审计失败保留 Failed 状态并报告，禁止用普通重试清除首因；其他工作区事件继续处理。未注册或停止后送达的新故障记为明确投递失败，不报告已持久化。状态为 Healthy、Pending、Persisted、Failed，通过无磁盘访问的 sink 快照提供；STATUS 增加 `fault_audit_failures` 与当前绑定工作区的 `fault_audit_state`。它不取代 `workspace_fault` 写入封锁，审计成功不能恢复业务写权限。

正常停止先排空 SQL、完成各工作区停机检查点，再停止 LGWR/DBWR/CKPT/Undo 这些故障来源，最后排空已接收的审计事件并 join；审计失败不返回干净停机成功。immediate 不排空或 join 审计线程，下一次仍执行完整恢复门。独立直连实例也持有自己的异步审计 writer：创建或恢复验证成功后登记工作区并安装同一非 I/O 回调；正常 shutdown 在数据收尾后排空 writer，结构字段顺序保证异常 Drop 也先结束 writer 再释放实例锁。审计 I/O 的超时与中断仍需完善。

内存测试验证：首次故障去重并保留原始原因；一个工作区同步失败仍允许其他工作区成功持久化；未注册投递不能伪报成功；通知回调可重入查询故障状态，证明回调不持故障表锁；审计线程被文件 I/O 门阻塞时，其他故障登记和 STATUS 快照仍能完成；空闲及伪唤醒不触发文件 I/O，真实任务随后正常落盘。不启动、重启或创建数据库实例。

## 15. daemon 文件句柄生命周期修复

现场 daemon 在约 2.5 小时内打开 1,048,575 个文件句柄并达到进程硬上限。`/proc/<pid>/fd` 抽样显示绝大多数重复指向各工作区的 `*_meta` 字典文件，另有重复的控制文件。根因是 `FileIo` 使用显式句柄表：丢弃 `Catalog` 或 `ControlFile` Rust 对象不会自动从表中移除句柄；服务却为每个 SQL 打开请求级 Catalog，固定表查询还打开两份控制文件，完成请求后均未显式关闭。请求级 `CliFixedTables` 同时通过 `Box::leak` 永久保留，造成独立的内存泄漏。

服务 worker 现在在 Session 释放借用后显式关闭请求 Catalog，挂起、成功与错误完成路径统一执行；固定表在生成内存行后关闭两份控制文件；启动 PUBLIC 校验和私有认证的全局控制文件也覆盖成功及错误路径关闭。请求级固定表提供者改为栈生命周期，不再泄漏。`FileIo` 增加只读句柄计数，STATUS 返回并由 `bicdb status` 显示 `文件句柄`，便于直接监测回归。

新增回归连续执行 64 轮真实 worker SQL，每轮都断言句柄数回到固定基线。CLI 单元 40 项、catalog 69 项及 workspace 契约测试通过；另有既存图唯一性回滚测试仍报告 `RegionOccupied`，与本次句柄改动无交集，未以该失败掩盖句柄验收。

修复版已按标准 release 流程发布并完成 fast 停机/启动。运行实例 PID 3253174 启动时服务内部句柄为 18、OS 句柄为 23；连续执行 100 次真实 SQL 后仍分别为 18 和 23，证明请求路径不再累积句柄。DB Cache 保持 6144 MiB，实例从检查点干净打开且无 redo 重放或事务回滚。

## 16. 页重组与 Undo 旧像保留

图唯一性事务回归暴露 `Rollback(RegionOccupied)`：同一事务先删除一行，随后另一行增长触发 `replace_row` 页内重组；旧实现只复制活动槽，删除行虽然保留 Free 槽及原偏移，其字节旧像却被重组丢弃。回滚删除时原偏移已落入新的连续行区，无法安全恢复。这违反“Undo 可达旧像在回收水位前不得释放”的基本约束。

`can_replace_row`、`replace_row` 和 `defrag` 现在将所有已分配槽纳入空间核算和复制，包括 Free 槽的行旧像。Free 仍保持逻辑不可见，但物理字节随页副本一起重排，槽偏移同步更新，Undo 仍能按稳定 ROWID 找回旧像。当前没有实现逐槽 Undo-retention 水位，因此保守地不回收删除空间；后续只有证明相关 Undo 已越过保留水位时才允许物理释放。

专项验收覆盖删除旧像经过页重组仍可事务回滚、图唯一性失败语句后继续写并完整回滚，以及 Free 槽重组后的页校验。原失败的 `sql_unique_persistent_candidates_cover_ghosts_swaps_scope_relationships_and_rollback` 与 heap 10 项测试均通过。

## 17. 工作区恢复失败隔离与打开期资源收尾

PUBLIC 仍在发布 READY 前完成恢复，失败即拒绝整个实例启动。私有工作区延迟打开失败后，daemon 现在把第一条原因登记为实例内 `RECOVERY REQUIRED`；后续 BIND 直接返回同一原因，不重复执行恢复、不重复追加 Failed 审计，也不影响已打开的 PUBLIC 和其他私有工作区。STATUS 增加 `recovery_required_workspaces` 计数。显式修复、重试和 FORCE 管理命令仍需接入，普通登录不能清除此状态。

启动路径同时补齐临时资源关闭：工作区身份、创建参数、恢复扫描使用的控制文件只读句柄，以及恢复所选在线 redo 组句柄，都在成功与错误路径关闭；建区登记文件大小时的临时 DataFile 也显式关闭。PUBLIC 实测常驻 FileIo 句柄由 18 降为 7，OS 文件句柄由 23 降为 12，连续 100 次 SQL 后保持不变。

## 18. 控制文件句柄 RAII 与二次泄漏修复

运行验收又发现句柄从 37 增长到 55，`/proc/<pid>/fd` 显示新增项全部指向实例级 `control01.ctl` / `control02.ctl`。直接原因是 `route_owned_workspace()` 的全局注册表读取未显式关闭；结构性原因是 `CfCore` 持有的 `FileIo` 句柄不是 OS RAII 文件对象，Rust 对象离开作用域不会自动从显式句柄表移除。仅修一个调用点无法覆盖早退和后续新路径。

`CfCore` 现在逐副本记录句柄存活状态：显式 `close()` 仍向上报关闭 I/O 错误，`Drop` 作为所有读取和早退路径的最后安全网，且不会重复关闭已成功释放的副本。建立或打开第二副本失败时，立即关闭已打开的第一副本；新文件打开后预置长度失败也立即关闭该句柄。副本校验、自愈及结构拒绝期间的任何错误由同一所有者收尾。这一层同时覆盖全局控制文件和各工作区控制文件。

回归验证对未显式关闭的双副本对象、“第二副本打开失败”及“新文件预置长度失败”分别检查句柄回到零；ROUTE 成功和失败路径连续 50 次后回到固定基线。storage 239 项、CLI 单元 42 项、真服务认证 5 项通过。修复版已 release 发布并 fast 重启；最终 daemon PID 4140375 启动时服务内部句柄为 7、OS 句柄为 12，全局控制文件只保留两个必要的常驻副本句柄。安装的 `bicdb` 与 release 产物 SHA-256 一致。

## 19. 工作区 OPEN 管理命令第一阶段

SQL 语法已形成闭集：`ALTER WORKSPACE <引用> OPEN READ ONLY`、`OPEN READ WRITE`、`OPEN READ WRITE FORCE`；`FORCE` 只能修饰 `READ WRITE`。语句要求 PUBLIC 本机管理面身份，并通过 SQL worker → daemon 主控制器的同步管理事件执行。控制器核对 PUBLIC 注册路径、工作区身份、目标活动 SQL 数和共享缓存配额；未打开的私有工作区先走正常或窄范围 FORCE 恢复，成功后注册故障审计、LGWR/CKPT/Undo/DBWR 路由并加入实例工作区表，最后才改变访问闸门。离线执行器缺少控制器时明确拒绝，不能只改字典后返回假成功。

管理员只读状态与耐久性故障隔离分开保存。只读闸门可逆，允许查询、显式回滚和后台耐久性维护；事务开始、提交、关系 DML/DDL、图写和全文索引维护在修改前拒绝。`OPEN READ WRITE` 只清除管理员只读闸门，不清除 DBWR/LGWR/CKPT/Undo 硬错误形成的粘滞隔离。PUBLIC 可进入/退出管理员只读状态，但 `OPEN READ WRITE FORCE` 永久拒绝。目标工作区有其他正在执行的 SQL 时 OPEN 拒绝，避免在语句修改中途改变准入状态。

私有工作区的 `OPEN READ ONLY` 也是不一致工作区的隔离开放入口：普通恢复先执行；仅遇到 FORCE 已定义的窄范围文件水位不一致时，允许带审计完成恢复并立即关闭写闸门。它不跳过结构、校验、redo、undo 或 loser 回滚错误。此类工作区保留 `forced_recovery` 原因；随后普通 `OPEN READ WRITE` 被拒，必须由管理员明确执行 `OPEN READ WRITE FORCE`，防止一次只读救援在后续命令中无意变成读写。PUBLIC 不进入这条路径。

真实 daemon 回归建立 PUBLIC、两个用户和两个私有工作区：管理员将 w1 打开为 READ ONLY 后，alice 经 AUTH+BIND 仍可查询，DDL 被拒，STATUS 返回 `workspace_write_state=READ_ONLY`；管理员恢复 READ WRITE 后，alice 重新绑定并成功建表，STATUS 返回 READ_WRITE。回归同时验证 PUBLIC 只读后普通 DDL 被拒、OPEN 命令本身可恢复 PUBLIC 读写，以及 PUBLIC FORCE 被拒。storage 239 项、SQL 解析 26 项、SQL 计划/执行 20 项、CLI 单元 42 项和真实认证/路由 6 项通过。release 已发布，安装 `bicdb` 与构建产物 SHA-256 一致；正式实例 fast 重启为 PID 257942，启动句柄 7、待恢复工作区 0、DB Cache 6144 MiB。

## 20. SQL 恢复审计查询

每个工作区新增只读固定表 `recovery$`，基础列为 `sequence`、`state`、`timestamp_ms`、`recovery_lsn`、`actor` 和 `detail`。结构化范围列为 `scope_kind`、`scope_file`、`scope_block`、`scope_object`、`scope_txn`、`scope_lsn_start`、`scope_lsn_end`；不适用的列为 NULL。范围类型支持 `WORKSPACE`、`PAGE`、`OBJECT`、`TRANSACTION` 和 `REDO_RANGE`，反向 redo 区间在落盘前拒绝。它逐次读取并完整校验当前工作区的 `recovery.audit`，行顺序保持审计序号；状态显示为 `RECOVERING`、`VERIFIED`、`FAILED`、`RUNTIME_FAULT` 或 `FORCED`。该表没有字典对象和 SQL 写入口，`SHOW TABLES` 仅在当前工作区存在且可验证该数据源时将其列为 `FIXED`。

查询路径只以只读方式打开既有审计文件。文件缺失时不会创建，损坏、身份不符、残缺尾部和关闭失败均不能伪装为空结果；所有成功和失败路径都会释放文件句柄。PUBLIC 的 `file$` 与 `recovery$` 只向本机管理员可见，普通用户绑定自己的私有工作区后可以查看本工作区的恢复记录。

审计格式 v2 写入结构化范围，并继续逐页读取现场已有的 v1 记录；v1 记录显示为 `WORKSPACE` 范围。当前启动和运行时故障源尚只能可靠定位到工作区时，就必须记录 `WORKSPACE`，不得从错误文本猜测页或对象。后续故障源提供经过校验的页、对象、事务或 redo 范围后通过同一追加接口记录。显式修复/归档命令及修复后验证闭环仍需完成，不能通过直接修改 `recovery$` 清除异常。

## 21. 持久页/对象隔离执行边界

实例打开时按审计顺序重放 v2 结构化范围。`FAILED`、`RUNTIME_FAULT`、`FORCED` 及未完成的 `RECOVERING` 增加隔离；相同范围的 `VERIFIED` 才清除隔离。工作区级 `VERIFIED` 不会顺带清除页或对象范围，避免一次普通启动把仍待修复的细粒度异常误判为已修复。

- `PAGE` 范围按完整 `(workspace_ref,file_id,block_id)` 登记。缓存命中、未命中、新页安装和非阻塞驻留访问均越不过闸门；常规访问返回包含文件号、块号和审计原因的明确错误，不把隔离页伪装为不存在或空页。
- `OBJECT` 范围在 SQL 绑定捕获对象和索引版本后、执行前检查，覆盖查询、关系 DML 及索引引用；命名图、图索引、全文存储和 Cypher 的直接解析路径也在访问物理存储前检查。
- `TRANSACTION` 与 `REDO_RANGE` 暂无安全的局部读取边界，恢复为整个私有工作区只读，而不是猜测相关页面。PUBLIC 出现任何未清除的结构化范围均拒绝开放；不能把关键系统元数据降级为局部可疑后继续服务。
- `STATUS` 报告当前连接工作区的 `quarantined_pages` 与 `quarantined_objects` 数量；逐项事实仍以只读 `recovery$` 为准。

隔离清单随新实例从审计恢复，不提供进程内“清空”捷径。显式修复命令必须先验证实际介质/对象，再追加同范围 `VERIFIED`；该命令和审计归档仍是后续工作。

## 22. fast 停机排空超时诊断

fast 停机收到请求后停止接收新业务，取消并清理可挂起的行锁等待，等待已接受的活动、就绪和挂起请求全部离开调度器，随后才执行连接事务回滚、各工作区最终检查点、临时表空间清理和后台线程收尾。达到 `service.stop_wait_s` 后不会伪报干净关闭，也不会自行升级为 immediate；daemon 在日志中一次性记录 `active`、`queued`、`parked` 未完成计数并继续保留内存、redo、undo 和恢复审计。管理员可继续等待，或显式选择 immediate 让下次启动走恢复。

停机排空期间 STATUS 仍可用，返回 `shutdown_state=DRAINING`、`shutdown_elapsed_ms` 及同一组执行队列计数；正常服务为 `RUNNING`。命令行 `bicdb status` 同步显示这些字段。客户端 `bicdb stop -w` 的等待上限只约束客户端等待时间，不冒充 daemon 已退出；超时后可再查询 STATUS 或日志判断具体未完成项。

## 23. 细粒度恢复验证闭环

在 PUBLIC 本机管理会话中提供两个闭集命令：

```sql
ALTER WORKSPACE <workspace> VERIFY RECOVERY PAGE <file_id> <block_id>;
ALTER WORKSPACE <workspace> VERIFY RECOVERY OBJECT <object_id>;
```

目标必须是已经 `OPEN READ ONLY` 的私有工作区，没有正在执行的业务 SQL，且 DB Cache 中没有该工作区的脏页。命令只接受已在持久恢复清单中的精确范围，不提供工作区级“全部清除”或直接修改 `recovery$` 的捷径。

PAGE 验证绕过正常缓存准入，从已注册的数据文件直接读取持久页，核对完整页校验、文件号、块号和工作区标识，不把待验证页装入 DB Cache。OBJECT 验证重新解析活动目录对象与 `seg$` 映射，核对段头的 `obj#`/`dataobj#`，并逐页读取段头和高水位/追加位置范围内的数据页，任一页的校验、身份或访问失败都终止命令。

验证通过后，daemon 把同范围 `Verified` 任务交给实例唯一恢复审计写线程；只有追加、文件同步完成并收到确认后，才删除运行时的那一个页或对象隔离项。介质验证失败、审计落盘失败或运行时状态竞态都保持隔离；审计已落盘但内存项意外不存在时，命令明确要求重启重放审计，不报告静默成功。

PUBLIC 存在结构化隔离时会在 READY 前被拒绝，因此在线命令明确拒绝 PUBLIC，不开一条绕过启动一致性门的后门。PUBLIC 及其他无法在线打开的工作区使用离线入口：

```text
bicdb recovery verify -p <参数文件> page <file_id> <block_id>
bicdb recovery verify -p <参数文件> object <object_id>
```

离线入口首先取实例独占锁；daemon 或直连会话仍在运行时立即拒绝。它从控制文件活动文件清单定位 PAGE，拒绝 temp，并用数据文件头和页头双重身份校验；OBJECT 则以离线目录、段头和逐页读取验证。只能验证审计中当前未清除的精确范围，成功后追加 `bicdb/offline-admin` 的同范围 `Verified`。定向验收证明 PAGE 验证不会顺带清除 OBJECT，最后一个范围验证完成后重启才会解除全部相应隔离。

审计到达容量上限前可在停机状态执行 `bicdb recovery archive -p <参数文件>`。命令先取实例独占锁并校验全部原审计，再以 `create_new` 生成带最后序号的字节级完整归档，同步归档和父目录。当前审计只重建每个精确范围的最后状态，已 `Verified` 范围不再占容量，未验证的 PAGE、OBJECT、TRANSACTION、REDO_RANGE 或 WORKSPACE 按原状态、LSN、actor 和原序号引用保留。新文件先单独构建并同步，最后原子 rename 覆盖当前审计并同步目录；中途失败保留旧审计和已落盘归档，不会只剩一份半成品。
