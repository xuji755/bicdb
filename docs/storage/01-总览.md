## 1 总览

### 1.1 层次结构

```text
实例
├── 全局控制文件（2 份）            管控的文件清单 + 文件系统池
├── 缓冲池（实例级共享）            分区为工作集，每分区绑一个写线程（§5.10、§11.7）
├── 文件系统池                      一组挂载点（§2.8）
│
└── 工作区（互不干扰；故障域亦在此收敛，§11.8）
    │
    ├── 主位置（池中某一文件系统上）
    │   ├── 控制文件（2 份）        该工作区的恢复锚点
    │   ├── redo（2 组 × 2 成员）   组大小创建工作区时指定
    │   └── data/
    │       ├── file 0   元数据（**数据字典**，结构与普通表通用）
    │       ├── file 1   Undo
    │       ├── file 2   Temp（不持久化；打开工作区时重置）
    │       └── file 3+  数据段
    │           └── 段 ── 区（8 页 = 128KB）── 页（16KB）
    │               段有 **LIVE / DEAD** 两态：删除先失效，空间惰性回收（§4.7）
    │
    └── 池中散布的部分（可落在不同文件系统上）
        ├── 数据文件（file 3+）     每个独立放置；可自动扩展、可 MOVE（§3.3、§3.4）
        ├── assets/<v>/…            **外部对象**（模型、文档、图片）——
        │                           按 **16 个卷**分布，路径由资产 ID 推导（§2.9、§2.10）
        └── staging/                上传暂存——须与其 assets 卷同一文件系统（§2.9）
```

> **工作区不是一个物理目录**，而是一个**跨文件系统的命名空间**——
> 它的容量上限因此是**整个池**，而不是池中最大的那个盘（§2.10）。

### 1.2 三条贯穿全局的原则

| 原则 | 含义 | 影响 |
| --- | --- | --- |
| **一个引擎 + 表选项** | ROWID、文件布局、控制文件、WAL 基础设施与**页头**全部统一；表间差异收敛为**表级选项**。**页体按页类型自定义**（§5.1——格式服务于访问模式） | 备份、恢复、检查器、配额、诊断只做一套 |
| **存储层不承载版本与事务语义** | 行内无版本号、无时间戳、无事务 ID；可见性由 Undo + 快照判定 | 行更紧凑；业务多版本由数据模型层用额外的行/节点表达 |
| **渲染隔离在文件层** | 每工作区独立文件，不共享、不硬链接、不跨用户去重 | 隔离失败属发布阻断项 |

### 1.3 规模约束（驱动全部容量决策）

| 维度 | 范围 |
| --- | --- |
| 单工作区节点数 | **1 万 ~ 1000 万**（跨 3 个数量级） |
| 边数 | ≤ 10 × 节点数（平均度 ≤ 10） |
| 向量 | **部分节点有，可能一个都没有** |
| 页大小 | **16KB**，实例内固定 |

**由规模推出的两条硬约束**：

1. **向量必须是可选列**——某工作区无向量时不得有任何向量相关文件、索引或内存占用。
2. **ANN 索引必须磁盘型**——极端场景向量达 60GB，装不进 32GB 基准机内存。
