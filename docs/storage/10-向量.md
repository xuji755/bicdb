## 10 向量

**向量在本设计中是"列 + 索引"，不是独立体系**——本节是**索引**，
实体分散在后面各节，这里把它们汇总。

### 10.1 结论

- **列类型**（pgvector 式），不是独立集合：`VECTOR(n)`，维度写在类型里。
- **只能是可选列**——无向量的工作区零开销。
- 距离度量由**索引的操作数**决定（L2 / 余弦 / 内积），与 pgvector 一致。
- 模型元数据（`embedding_model`、`model_revision`）挂**列级**，用于阻止跨模型混搜
  （pgvector 本身不跟踪模型）。
- `halfvec`（半精度）保留为后续扩展的优化项，不作 V1.0 必选。

### 10.2 实体在哪一节

| 内容 | 在哪 |
| --- | --- |
| 列的物理编码（连续 **IEEE 754 FLOAT32**，小端，无头部）——**与标量列 `FLOAT32` 不是一回事** | §6.6 |
| 维度写在类型里 → 列宽因此固定 | `col$.length`（§3.1.3） |
| **超长向量的存储**——一页放不下时走行片段链 | §6.8 |
| **ANN 索引页的页体**（element / neighbor 定长槽） | §5.11 |
| **ANN 的物理参数**（`m` / `ef` / 距离度量 / 维度 / 入口点） | **段头页的类型扩展区**（§5.11） |
| 索引种类的标记 | `ind$.type#`（§3.1.3） |
| 检索语义（召回要求、混搜禁止、零向量 / NaN / 浮点误差） | **RET 规格域**（未展开） |

### 10.3 两处与 pgvector 的关键差异

**① 我们不把 ANN 的元数据放在索引的第 0 页**，而是**并入段头页的类型扩展区**（§5.11）。
理由与"段自描述"是同一条：**打开段即可分派行为，不必回查目录**（§4.2）。
pgvector 的 metapage 是独立的一页；我们的段头页**本来就是段的第 0 页**（§4.2）——
不必再加一页。

**② 边与向量的"定长"是两种定长**。邻接页的边是**变长**的（带 `label`），
ANN 的槽是**定长**的（由维度与 `m` 决定）。**同一个"定长槽"的骨架，两种约束**（§5.11）——
这与 §5.1"页体按类型各自定义"是同一件事：骨架可以共用，约束不必强求一致。
