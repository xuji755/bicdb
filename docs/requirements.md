# bicdb 需求文档

版本 1.0　状态：需求基线，P0 冻结前可能调整

> 本文定义 bicdb 在 V1.0 范围内必须满足的需求，作为设计评审、任务拆分与验收判据的共同基线。
> 总体设计见 [design.md](design.md)，存储层阶段设计见 [storage.md](storage.md)。

## 0 文档约定

**编号**：`REQ-<域>-<三位序号>`。**优先级**采用 RFC 2119 语义：

| 级别 | 含义 |
| --- | --- |
| **必须** | V1.0 不满足即为发布阻断项 |
| **应当** | 应当满足；不满足需给出理由并记入已知限制 |

**定位**：本文只回答"必须做到什么、如何判定做到了"，不描述实现方案。本文与 [design.md](design.md) 冲突时以本文为准。

## 1 产品定位与工作负载画像

### 1.1 定位

bicdb **不是**通用关系型数据库。其服务对象是 AI Agent，核心用途为：

| 用途 | 说明 |
| --- | --- |
| **知识** | 文档、片段、事实及其来源与派生关系 |
| **记忆** | 中期任务状态与长期事实/偏好，含版本与生命周期 |
| **配置** | 版本化配置、提示模板、工具参数、模型配置 |
| **拓扑** | 实体关系、依赖结构，支持有界遍历与关联查询 |
| **资产** | 不可变大对象（模型、文档、图片） |

与典型 RDBMS 的差异：

| 维度 | 典型 RDBMS | bicdb |
| --- | --- | --- |
| 主要负载 | 混合，写占比高 | **读占绝对多数** |
| 写入并发 | 高，热点争用常见 | **有限并发，争用低** |
| 数据模型 | 关系为主 | **多模型**：关系 + JSON + 向量 + 图 + 外部资产 |
| 写入形态（存储层） | 原地更新 + Undo | **同为原地更新 + Undo**（与此项**无差异**） |
| 多版本表达 | 通常由应用自行设计 | **由数据模型层表达**，非存储层特性 |
| 事务形态 | 长短混合 | **短事务**，无长事务、无跨工作区事务 |
| 查询形态 | 复杂多表 JOIN | **点查 + 语义检索 + 范围扫描 + 有界图遍历** |
| 隔离模型 | 角色/授权体系 | **工作区硬隔离**，不支持跨用户授权 |
| 生命周期 | 用户自行管理 | **内建 TTL、撤销、派生依赖传播** |

> **⚠ 层次边界：多版本在哪一层**
>
> - **存储层只做原地更新 + Undo**，与典型 RDBMS 一致。**不采用 ASTORE 式堆内多版本**，不以 LSM-Tree 作主存储，主堆中不保留每次更新的完整旧版本。
> - **"多版本"是数据模型层的表达**。记忆 revision、配置 revision 等在实现上是**额外的行/节点**。对存储引擎而言，这只是普通的插入与原地更新，**不存在"版本追加"这种存储机制**。
> - 认为"记忆是版本化的，所以底层要版本化存储"是**错误推导**，会导致堆内版本膨胀、Undo 与回收语义混乱、恢复协议复杂化。

### 1.2 工作负载画像

| 特征 | 描述 | 对设计的含义 |
| --- | --- | --- |
| 读:写比例 | 读占绝对多数 | 读路径是优化重点；写路径以正确性为先 |
| 写并发 | 有限，无高频热点行争用 | 保留多写者正确性，但**不必**为热点争用做复杂优化 |
| 读并发 | 高 | 读必须无锁、可并发、可缓存 |
| 事务时长 | 短，无长事务 | 快照注册与 Undo 回收压力可控 |
| 单次写入量 | 小；偶有大向量/JSON | 跨页协议必须支持，但非主路径 |
| 数据规模 | 单工作区中等规模 | 索引可常驻内存的比例高 |
| 读延迟 | 敏感 | p99 读延迟是核心指标 |
| 写延迟 | 不敏感 | 以耐久性优先 |

### 1.3 由此确定的四条取向

1. **读路径无锁化**：读不获取行锁、不阻塞写、不依赖写路径进展。见 REQ-TXN-005。
2. **写路径正确性不降级**：并发低不等于可以放松持久化、隔离与恢复要求。
3. **不为不存在的负载付费**：不实现针对高争用热点的复杂机制。见 REQ-TXN-009。
4. **版本化留在数据模型层**：存储层只做原地更新 + Undo。见 REQ-STO-014。

## 2 用户、角色与工作区

| 主体 | 本人私有区 | 他人私有区 | public 区 |
| --- | --- | --- | --- |
| 用户及其 Agent 凭证 | 按凭证范围读写 | **所有访问禁止** | 只读 |
| public 发布身份 | 无用户私有读取能力 | 禁止 | 发布、删除、版本管理 |
| 运维管理员 | 管理健康、容量与启停 | **不提供业务内容接口** | 管理运行状态 |

## 3 功能需求

### 3.1 用户隔离与工作区（ISO）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-ISO-001 | 每个用户具有独立工作区，私有数据、索引、日志、临时文件与资产不得与其他工作区混放 | 必须 |
| REQ-ISO-002 | 用户标识必须来自认证结果，不得以请求体中的 `user_id` 作为可信身份 | 必须 |
| REQ-ISO-003 | 不得提供任何跨用户授权、所有权转移、代理读取或共享链接能力 | 必须 |
| REQ-ISO-004 | 只有 public 工作区向所有用户只读共享；public 是保留工作区与数据所有者，不是 PUBLIC 角色 | 必须 |
| REQ-ISO-005 | owner 不可变；不提供跨工作区外键、可写联结或级联关系 | 必须 |
| REQ-ISO-006 | 普通用户不能判断另一用户的对象是否存在；拒绝响应不得泄露名称、内容或精确规模 | 必须 |
| REQ-ISO-007 | 文件操作必须检查路径穿越、符号链接与检查使用间竞态 | 必须 |
| REQ-ISO-008 | 工作区根目录使用服务端生成的不透明 ID，不得直接拼接用户输入 | 必须 |
| REQ-ISO-009 | 备份恢复必须校验工作区标识与格式版本，不得把用户 A 的备份导入用户 B 的工作区 | 必须 |
| REQ-ISO-010 | 隔离失败属于发布阻断项，不得以概率或平均成功率验收 | 必须 |
| REQ-ISO-011 | 私有工作区之间不使用硬链接、不共用资产目录、不做跨用户内容去重 | 必须 |
| REQ-ISO-012 | 克隆**不得作为跨用户数据转让通道**——只能在同一 owner 的范围内执行 | 必须 |

### 3.2 数据类型（TYP）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-TYP-001 | 提供 CHAR、VARCHAR2、NUMBER、INTEGER、DATE、TIMESTAMP 六类标量，行为与参考环境兼容 | 必须 |
| REQ-TYP-002 | NUMBER 不得以 double 承载；裸 NUMBER 不得归一为 NUMBER(38,0) | 必须 |
| REQ-TYP-003 | INTEGER 语义为 NUMBER(38,0)，不得退化为 32/64 位机器整数 | 必须 |
| REQ-TYP-004 | 类型兼容是声明、取值、赋值、转换、比较与客户端往返的**行为契约**，不要求内部字节编码相同 | 必须 |
| REQ-TYP-005 | SQL 空字符串按字符规则处理；JSON 空字符串保持其文档语义 | 必须 |
| REQ-TYP-006 | 提供扩展类型 BOOLEAN、UUID、FLOAT32、FLOAT64、TIMESTAMP_TZ、JSON、VECTOR、ASSET_REF | 必须 |
| REQ-TYP-007 | 时间事件统一保存 UTC 时刻，需要时保留原始时区；DATE/TIMESTAMP 仍按无时区处理 | 必须 |
| REQ-TYP-008 | 合计不少于 1 万条生成用例，记录版本、NLS、SQL、绑定与结果 | 应当 |
| REQ-TYP-009 | 完整 PL/SQL、DDL 隐式提交不由类型兼容要求推导 | 必须 |

### 3.3 存储与页式结构（STO）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-STO-001 | 以工作区内表空间、段、区、**16KB** 块与槽位堆表组织数据 | 必须 |
| REQ-STO-002 | 数据页包含格式版本、页类型、工作区受校验映射、文件号、块号、日志位置、校验和、空闲区与槽位目录 | 必须 |
| REQ-STO-003 | ROWID 稳定表示记录身份。删除在行头打删除标记，索引项随事务维护；提交后槽位即可复用。**ROWID 不含代次** | 必须 |
| REQ-STO-004 | 常规更新优先修改当前行，历史信息进入 Undo；**不得采用 ASTORE 式堆内多版本**，不得以 LSM-Tree 作为主存储组织 | 必须 |
| REQ-STO-005 | 行增长与跨页值必须通过行片段、稳定入口与可恢复链接支持；超出单页容量的 JSON 与高维向量必须纳入跨页协议 | 必须 |
| REQ-STO-006 | BufferPool 提供 pin、latch、脏页与日志位置管理；PageGuard 控制引用生命期，**不得向 SQL 层返回裸页面指针** | 必须 |
| REQ-STO-007 | 持 latch 期间不得等待事务、不得执行文件 I/O、不得阻塞网络 | 必须 |
| REQ-STO-008 | 提供 B+Tree 索引，支持唯一键、复合键与范围访问 | 必须 |
| REQ-STO-009 | 索引候选回表时必须检查可见性。索引项随删除/键更新事务一并维护；延迟回收的是堆空间与 Undo，**不是索引项** | 必须 |
| REQ-STO-010 | 页分裂使用单独审查的系统操作与恢复协议，不得把分裂错误当作业务事务失败简单忽略 | 必须 |
| REQ-STO-011 | 空闲页分配、初始化、位图与控制元数据均受 WAL 保护 | 必须 |
| REQ-STO-012 | 页面编码、检查器与损坏处理**必须先于完整 SQL 执行器交付** | 必须 |
| REQ-STO-013 | 资产文件是独立对象，不得混入堆表页链 | 必须 |
| REQ-STO-014 | **存储层不得实现版本化存储**。多版本必须由数据模型层表达为额外的行/节点 | 必须 |
| REQ-STO-015 | 任何"因业务需要多版本"而要求存储层保留旧版本的提案，必须先经 ADR 评审 | 必须 |
| REQ-STO-016 | **已知行为**：RC 下语句开始后被并发删除的行，索引扫描可能漏读。此为同类模型的既有取舍，**不是缺陷**，须在测试基线中显式记录 | 必须 |

### 3.4 事务、并发与恢复（TXN）

**写并发模型：多写者、低争用。** 保留多写者正确性，不针对高争用热点做复杂优化。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-TXN-001 | 首版隔离级别为 Read Committed 语句快照 | 必须 |
| REQ-TXN-002 | 支持多写事务与行锁 | 必须 |
| REQ-TXN-003 | 支持语句失败回滚、事务回滚与死锁检测 | 必须 |
| REQ-TXN-004 | Snapshot 使用提交序号，WAL 使用 LSN；**两者不得混用** | 必须 |
| REQ-TXN-005 | **读路径不得获取行锁、不得阻塞写、不得依赖写路径进展** | 必须 |
| REQ-TXN-006 | Undo 必须同时保存回滚所需信息与旧快照重建信息 | 必须 |
| REQ-TXN-007 | 修改顺序：先写 Undo 与日志描述，再修改受保护数据页 | 必须 |
| REQ-TXN-008 | 数据页持久化前，对应 WAL 必须已持久化 | 必须 |
| REQ-TXN-009 | 不实现针对高争用热点的复杂优化（锁分区、早释放细化等） | 必须 |
| REQ-TXN-010 | 提交成功响应必须晚于提交日志的耐久确认 | 必须 |
| REQ-TXN-011 | 网络断开时保留"结果未知"状态，客户端可通过幂等请求或提交结果查询消除歧义 | 必须 |
| REQ-TXN-012 | 采用 steal + no-force 缓存策略时，恢复必须能重做已提交事务、撤销未完成事务 | 必须 |
| REQ-TXN-013 | 日志包含事务状态、`prevLSN`、结构变化与必要补偿记录；重做与撤销必须可重入 | 必须 |
| REQ-TXN-014 | 部分页写入必须使用经评审的完整页映像或等效保护 | 必须 |
| REQ-TXN-015 | RC 锁等待后必须重新检查谓词或重启语句；必须防止重复修改同一行与 Halloween 问题 | 必须 |
| REQ-TXN-016 | DDL 首版使用独立事务与对象锁，禁止在未完成用户事务中混用 | 必须 |
| REQ-TXN-017 | 长期快照、Undo 耗尽与超时必须返回明确错误，不得覆盖仍被需要的旧版本 | 必须 |
| REQ-TXN-018 | 外部资产文件与异步派生索引另有协议，不得冒充与页日志同一原子存储 | 必须 |
| REQ-TXN-019 | 跨私有区与 public 不支持写事务、外键或两阶段提交 | 必须 |

### 3.5 JSON 与配置版本（CFG）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-CFG-001 | JSON 采用可校验的内部文档表示，支持对象、数组、字符串、精确数值、布尔与 null | 必须 |
| REQ-CFG-002 | 必须明确区分字段缺失、JSON null 与 SQL NULL | 必须 |
| REQ-CFG-003 | 数字不得在 SDK 往返时静默转为有损浮点数 | 必须 |
| REQ-CFG-004 | P0 冻结重复键策略，并定义 Unicode、数值范围、最大深度、节点数及文档字节限制 | 必须 |
| REQ-CFG-005 | 提供路径取值、存在判断、标量比较、有限数组访问、完整替换与受控局部修改 | 必须 |
| REQ-CFG-006 | 局部修改在数据库事务内完成；不要求原地修改 JSON 编码，允许重新编码并使用跨页行 | 必须 |
| REQ-CFG-007 | 索引先采用选定路径的表达式 B+Tree，后实现受限倒排索引；不默认支持任意复杂 JSONPath | 应当 |
| REQ-CFG-008 | 配置记录包含 `config_id`、`revision`、`schema_id`、`payload`、`content_hash`、`created_at` 及 active 状态 | 必须 |
| REQ-CFG-009 | 配置修订不可变；以预期 revision 执行条件切换；旧版本保留，回滚只切换活动引用 | 必须 |
| REQ-CFG-010 | 配置中的密钥使用密钥引用，不得保存到普通 JSON 正文与日志 | 必须 |
| REQ-CFG-011 | 工作流、工具参数、提示模板与模型配置仅作为数据保存；数据库不得据此自动加载代码或执行指令 | 必须 |
| REQ-CFG-012 | 模式升级使用版本化迁移，禁止后台无记录地改写已有配置 | 必须 |

### 3.6 记忆模型（MEM）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-MEM-001 | 中期记忆围绕任务与会话：任务目标、检查点、阶段结论、工具结果引用、待办及恢复游标 | 必须 |
| REQ-MEM-002 | 长期记忆保存确认事实、偏好、经验、知识片段及实体关系，强调来源、有效时间、版本与可遗忘性 | 必须 |
| REQ-MEM-003 | 中期与长期共享底层事务，生命周期由独立业务字段表达 | 必须 |
| REQ-MEM-004 | 提供 `memory`、`memory_version`、`task_checkpoint`、`source_record`、`derived_link` 对象 | 必须 |
| REQ-MEM-005 | 状态至少包含候选、确认、被取代、过期、已删除；转换保留操作者与原因 | 必须 |
| REQ-MEM-006 | 记忆更新产生新业务 revision，旧 revision 按保留策略留存；该版本**不等于** Undo 快照 | 必须 |
| REQ-MEM-007 | 生成记忆与用户确认事实必须区分；confidence 仅作为数据，不得自动代表正确性 | 必须 |
| REQ-MEM-008 | 事件时间、记录时间与事实生效区间分开保存 | 必须 |
| REQ-MEM-009 | 允许两条冲突记忆并存并建立冲突关系，不得以最新写入覆盖全部历史 | 必须 |
| REQ-MEM-010 | 中期提升为长期由上层明确调用并提供来源；**数据库不得运行 LLM 判断价值** | 必须 |
| REQ-MEM-011 | 检索默认排除过期与已删除状态 | 必须 |
| REQ-MEM-012 | TTL 以查询时可见性规则生效，后台物理清理可以延迟 | 必须 |
| REQ-MEM-013 | 撤销记忆时同步阻止其派生物继续返回，再异步清理实体文件与索引 | 必须 |
| REQ-MEM-014 | 用户整体注销须处理备份保留政策与日志残留；逻辑删除**不等同**于介质级安全擦除 | 必须 |
| REQ-MEM-015 | public 内容可共享但不自动可信；**检索内容不能改变认证、执行权限与系统指令** | 必须 |

### 3.7 外部资产（AST）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-AST-001 | 通过 `ASSET_REF` 引用工作区内受管理文件；**不提供库内 BLOB/CLOB 或原地文件更新** | 必须 |
| REQ-AST-002 | 已提交文件只允许读取、范围读取与删除；修改通过上传新对象并事务切换业务引用完成 | 必须 |
| REQ-AST-003 | 资产元数据包含 `asset_id`、工作区标识、大小、校验和、媒体类型、存储版本、创建时间、状态与引用信息 | 必须 |
| REQ-AST-004 | 用户不得传入任意服务器路径；对象位置由服务端生成 | 必须 |
| REQ-AST-005 | 创建操作以 `idempotency_key` 识别重试；相同键不同内容必须拒绝 | 必须 |
| REQ-AST-006 | 上传支持有界缓冲与中断恢复，**不得把整文件装入内存** | 必须 |
| REQ-AST-007 | 上传流程为：预留额度 → 写 staging → 校验大小与校验和 → 同步内容 → 原子移动 → 同步目录 → 提交可见元数据 | 必须 |
| REQ-AST-008 | 进程中断后未提交文件可成为孤立对象，由后台按状态与宽限期清理 | 应当 |
| REQ-AST-009 | 删除先在事务中标记不可见；有业务引用时默认拒绝删除 | 必须 |
| REQ-AST-010 | 文件回收须等待旧快照与活动读取租约结束；删除前备份快照所需文件保留到清单完成 | 必须 |

## 4 非功能需求

### 4.1 性能（PERF）

性能不预先承诺任意 TPS。**P0 必须冻结基准机规格**与下列档位。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REQ-PERF-001 | P0 冻结基准机规格、实例总缓存预算、活跃工作区档位、资产规模与索引规模 | 必须 |
| REQ-PERF-002 | 记录 p50/p95/p99、吞吐、冷启动、构建、恢复及备份时间 | 必须 |
| REQ-PERF-003 | **读延迟是核心指标**：读路径 p99 作为首要性能门禁 | 必须 |
| REQ-PERF-004 | 形成性能基线后，相同条件无未解释的超过 10% 回退 | 必须 |
| REQ-PERF-005 | 绝对业务目标不足时缩小范围或继续优化，**不得删除质量门禁** | 必须 |
| REQ-PERF-006 | 冷启动与工作区唤醒耗时纳入性能指标 | 应当 |
| REQ-PERF-007 | 按需进程不得让每个用户固定占用大额缓存；监督器以总预算分配 | 必须 |
| REQ-PERF-008 | 读吞吐应随执行线程数近似线性扩展至冻结的并发档位；读路径不得存在全局串行点 | 必须 |
| REQ-PERF-009 | 读操作不得因并发写入量增加而出现无界延迟增长 | 必须 |

> **适用范围限定**：REQ-PERF-008 在 **ANN 向量检索路径上不成立**——该路径受磁盘 I/O 限制，而磁盘是共享瓶颈。向量场景需单列指标。

| 库内模型执行 / LLM 调用 | 记忆提炼与推理由上层承担 |
| 复杂 LSM 主存储 | 明确不采用 |
| **ASTORE 式堆内多版本、存储层版本化** | 明确不采用；多版本由数据模型层表达 |
| 库内 LOB（BLOB/CLOB） | 资产走外部文件协议 |
| **分支合并**（把克隆/分支的改动并回主线） | 克隆与分支**支持**，但不提供合并——需比对两个工作区的数据与日志并定义冲突语义，与"存储层不做版本化"的边界冲突 |
| 备库部署（高可用） | 受 REDO 保护的数据在能力上已可复制，但备库进程、日志传输与切换协议为独立工程，不在 V1.0 |
| 复杂查询重写、窗口函数、JIT、单查询并行 | 延后 |
| 无限变长路径、完整 Cypher、图算法 | 仅有限子集与有界遍历 |
| 量化向量、磁盘型 ANN | 容量需求明确后另立项 |
| **跨用户授权、所有权转移、共享链接** | **永久不做**（产品约束，非版本约束） |
| 为高争用热点做的复杂并发优化 | 由工作负载画像决定 |
