# bicdb 客户端协议 v0.1（本机）

适用版本：**bicdb v0.3.0**，协议号 `wire=1`。

本文件是**驱动与客户端实现的唯一规格**：Rust 驱动（`crates/client`，`bicdb-client`）、
Python 驱动（`drivers/python/bicdb`）、`bicdbcli`、`bicdb start|stop|status`
都是它的实现。字节级示例见 §7，**冻结在测试里**（Rust：`crates/net/tests/wire_v01_frozen.rs`；
Python：`drivers/python/tests/test_wire.py`）——两边的示例字面量必须逐字节一致。

---

## 0 边界（这份规格是什么、不是什么）

| 是 | 不是 |
| --- | --- |
| **本机**（Unix 域套接字）客户端协议：连上、**认证**、执行 SQL、取结果、管理实例 | 网络/多机（TCP 承载）、**授权矩阵** |
| 长度前缀的**二进制安全**载荷（字节串无损） | 设计里的**版本化请求协议**全量（封套、幂等与 CAS、ACK/对账、游标分页）——那是独立切片 |
| 同步、一问一答（一条连接上只有一个未决请求） | 流水线/多路复用（PG 15 的 `H` 式的 pipelining） |
| **口令认证（本机）**：主体名 + 口令，服务端与 `user$.passwd` 的 PBKDF2-SHA512 比对（§4.3） | **网络承载**上的认证（通道绑定 / SCRAM 式挑战-应答）——本机套接字由文件权限保护，够这一层用 |
| **身份是连接的属性**（`REQ-ISO-002`：只来自认证结果） | 会话引用 / 断连对账 / 游标（`REQ-API-014/015/009`——独立切片） |

**记档**：设计中的 `bicdb-net` 覆盖上表右列；本规格是它的**本机第一切片**，
将来扩全时 **`wire` 号 +1**，而不是在原号上"兼容地"改语义。
**认证这一格是本切片新进的左列**：网络承载 + 通道绑定仍是右列（届时 `wire` +1）。

（`doc/` 是内部文档集，**不随公开镜像发布**；文内对它的引用只是出处标注。）

**与 `doc/spec/API.md` REQ-API-015 的对应**：那里写的是
`hello（无身份）` → `open_session {登录名, 凭证}`；本协议的 `HELLO` = 前者，
**`AUTH` = 后者的认证一步**（会话 = 连接，没有单独的"建会话"帧）。

**一处继承的边界**：`DESCRIBE` 与 SQL 走同一条连接、同一个会话（显式事务里
`DESC` 也不丢事务状态）；但结果集**不带二进制类型**（`type_code` 只在
`DESCRIBE` 里有真值）——结果列的形态由 `kind` 给出（见 §3.3）。

## 1 传输与寻址

**传输**：Unix 域套接字（`SOCK_STREAM`）。套接字文件由服务在
`[service] socket` 指定的位置创建（默认 `<db_root>/bicdb.sock`），**随服务退出清理**。

**客户端寻址**（与 `bicdb` 命令行**同一口径**；见使用手册 §2）：

| 顺序 | 位置 |
| --- | --- |
| 1 | 显式给出：`-p <参数文件\|根区目录>` |
| 2 | 环境变量 `BICDB_INI` |
| 3 | 当前目录的 `./bicdb.ini` |

客户端从参数文件里**只读两项**：`[instance] db_root`（相对套接字的解析基准）
与 `[service] socket`（相对项按 `db_root` 拼绝对路径）。**权威解析在服务端**
（`bicdb-cli` 的 `config` 模块：闭集校验、取值类型、建区期核对）；客户端
**不做**那些校验，也不该复制它们——否则两份实现必然漂移。

## 2 帧（所有动词共用）

```text
请求： <动词> \n <载荷字节数> \n <载荷字节…>
应答： OK|ERR \n <载荷字节数> \n <载荷字节…>
```

- 首行 = 动词（请求）或 `OK`/`ERR`（应答），ASCII，**≤ 1024 字节**；
- 载荷字节数 = **十进制**，`0…67108864`（64 MiB，服务端与客户端同额）；
- 载荷是**任意字节**（可以有换行、可以不是 UTF-8）——**长度是权威**。

**读侧纪律（照 MySQL 包序号错乱的教训）**：

1. **读满**声明的字节数（`read_exact` 语义）；读到一半就是对端出错，
   **报错连接**，绝不"按行补读"——那会让后续帧整体错位，而且**看不出错**；
2. 长度超上限 ⇒ 报错并断开（坏对端不该让对方分配无界内存）；
3. 首次应答之前，`OK`/`ERR` 之外的任何首行都是协议错。

## 3 值模型

线上的值**不认识引擎的类型**，只有四种形态。

### 3.1 值单元

```text
<标记><载荷字节数> \n <载荷字节…> \n
```

| 标记 | 含义 | 载荷 |
| --- | --- | --- |
| `-` | `NULL` | 恒为 0 字节 |
| `n` | 数值 | **十进制文本**（保持精度；`NUMBER` 任意精度，文本是唯一不丢精度的形态） |
| `o` | 布尔 | `0` 或 `1` |
| `b` | 字节串 | **小写十六进制**（原字节，无损） |

**为什么字节串走十六进制**：文本/二进制同形，ASCII 安全，不像"统一转字符串"
那样把非 UTF-8 的字节悄悄毁掉。**为什么数值走文本**：转成原生类型是
**驱动侧**的事（Python `Decimal`/`int`/`float`、Rust `i64`/`f64`）——协议不替它们选。

### 3.2 定长字段

| 形态 | 例 | 含义 |
| --- | --- | --- |
| `<标记> <数>` | `P 1` | 标记 + 计数（头行） |
| `<标记> <字节数>\n<字节>\n` | `Q 38\nSELECT …\n` | 标记 + 字节前缀字段 |
| `<标记>` | `A 3` | 见下 |

所有**头行以单个 ASCII 字母开头**；认不出的字母 ⇒ 具名报错（不是"跳过"）。

### 3.3 列形态（`kind`）

| `kind` | 引擎形态 | 驱动应给的原生类型（建议） |
| --- | --- | --- |
| `n` | `NUMBER` | Python `Decimal` / Rust `String`（`as_i64`/`as_f64` 便捷取） |
| `b` | 字节串（`CHAR`/`VARCHAR2`/`RAW`/`DATE`/…） | Python `bytes`（文本列自行 `decode`）/ Rust `Vec<u8>` |
| `o` | `BOOLEAN` | Python `bool` / Rust `bool` |

**注**：`kind` 是**形态**不是**类型**。想区分 `VARCHAR2(32)` 与 `RAW(16)` 要用
`DESCRIBE`（它给 `type_code` + `type_name`）。

## 4 动词（闭集）

| 动词 | 请求载荷 | 应答载荷 | 备注 |
| --- | --- | --- | --- |
| `HELLO` | 空 | §4.1 | **连接上必须的第一帧** |
| `AUTH` | §4.3 | §4.3 | **可选**：认主体；必须是**第一个业务请求** |
| `STATUS` | 空 | §4.2 | 服务自述 |
| `SQL` | §5.1 | §5.2 | 执行（可多条语句） |
| `DESCRIBE` | 对象名（UTF-8） | §6 | 列定义 |
| `SHUTDOWN` | `fast` \| `immediate` | 一行文本 | 服务收尾退出 |

未知动词 ⇒ `ERR` + 具名文本（**不断连**——客户端可以继续用这条连接）。

### 4.1 `HELLO`

```text
wire=1
version=0.3.0
instance=/data/bicdb
```

**版本协商**：客户端在**第一帧**发 `HELLO`，比对 `wire`：
不等 ⇒ **拒绝连**（客户端关闭连接并报"协议版本不兼容：服务端 X，客户端 Y"）。
不"尽力解释"——语义不同版本的载荷无法安全混用。

### 4.2 `STATUS`

`key=value` 若干行（含尾随换行），当前是：

```text
instance=<根区目录>
version=<服务/引擎版本>
pid=<服务进程号>
uptime_s=<服务已运行秒数>
served=<已服务请求数>
seq=<会话当前提交序号>
mode=service
wire=1
```

**未知键是允许的**（客户端忽略不认识的键——加键不升版本）。

认证之后，`STATUS` 里的 `identity=` 会说清这条连接是谁
（`管理面（本机/OS 身份）` 或某个主体名）。

### 4.3 `AUTH`（认证）

```text
U <主体名字节数> \n <主体名字节…> \n
S <口令字节数>   \n <口令字节…>   \n
```

应答（`OK`）：

```text
user=<主体名>
user_id=<主体号>
status=active|expired
```

**什么时候发**：`HELLO` 之后、任何业务请求（`SQL`/`DESCRIBE`）之前。**可选**——
不发就是"本机/OS 身份"（见下）。

**两条硬规则**：

1. **`AUTH` 必须是本连接上的第一个业务请求**。跑过 `SQL`/`DESCRIBE` 之后再发
   `AUTH` ⇒ `ERR`（"先以管理面身份做事、再冒名"这条路要堵死）；
2. **载荷里没有"用户号"**：只有主体名与口令，`user_id` 由服务端从目录解析
   （`REQ-ISO-002`：身份只来自认证结果，绝不接受请求体里的 `user_id`）。

**身份从哪来**（两条路，服务端定，客户端选）：

| 连接 | 身份 | 依据 |
| --- | --- | --- |
| **不认证** | **管理面身份**（本机/OS） | 控制套接字的文件权限——谁能连上谁就是它 |
| `AUTH` 成功 | **具名主体** | `public.user$` 的散列比对 |

**只在 `PUBLIC` 工作区上提供**：`user$` 在那里；普通工作区实例发 `AUTH` ⇒ `ERR`
（"本实例不是 PUBLIC 工作区 ⇒ 不做口令认证"）。

**失败语义**（`ERR` + 文本；**错误文本是契约的一部分**，驱动原样呈现）：

| 情形 | 文本要点 | 依据 |
| --- | --- | --- |
| 主体不存在 **或** 口令不对 | **同一条**"主体名或口令不对"；且两者**代价相同**（不存在的也跑一次同迭代数的 PBKDF2） | 防用户名枚举（PG 的 mock authentication：假盐 + 假迭代数、统一返回失败） |
| 主体已 `PAUSE` | "已暂停"——**拒绝新会话**；已开的会话**不掐断** | 照 Oracle `ACCOUNT LOCK` 的准入。**口令校验在先**：口令错时看到的仍是"就不对"，不泄露"这个名字存在且被停用" |
| 主体已 `EXPIRE` | **`OK` + `status=expired`**：连接建立但**受限**——除本人改密之外一律拒绝 | MySQL 的"新客户端密码过期后受限登录模式"（老客户端才直接报错） |
| 已认证过 | "重认证请重连" | 身份是**连接**的属性，不是请求的 |

**`status=expired` 的会话**：除
`ALTER USER <自己> IDENTIFIED BY '<新口令>' REPLACE '<旧口令>'`
之外任何语句都回 `ERR`（"受限会话"）；**改密成功即就地解除**（不用重连——
`user$` 的状态同时转回 `ACTIVE`）。

**口令的过线纪律**：口令是明文发的——它走的是**文件权限保护的本机套接字**。
服务端读它只为了跑一次 PBKDF2 比对：**不进日志、不进回执、不进诊断**
（服务日志只记"谁在什么时候认证成功/失败"）。
网络承载上的认证（通道绑定 / SCRAM 式）属"对外协议"切片——届时 `wire` +1。

## 5 `SQL`

### 5.1 请求载荷

```text
P <参数数> \n
  N <名字节数> \n <名字节…> \n      × 参数数
  V <值单元>                        （值单元自成一行，见 §3.1）
Q <SQL字节数> \n <SQL字节…> \n
```

- 参数是**具名**的（SQL 里写 `:名字`）；服务端按名字摆位（`Session::place_params`），
  缺失、多给、形态不符都是**具名错误**；
- SQL 可以含多条语句（`;` 分隔）——应答就是**语句结果序列**，一对多；
- 名字与 SQL 都是 UTF-8 文本（名字按字节数读，即使含换行也不错位）。

### 5.2 应答载荷（语句结果序列）

按顺序拼接，每项：

| 项 | 形态 |
| --- | --- |
| 结果集 | `R <列数> <行数>\n` + 列记录 ×列数 + 值单元 ×(列数×行数) |
| 影响行数 | `A <数>\n` |
| DDL 回执 | `D <字节数>\n<文本>\n` |
| 事务回执 | `T <字节数>\n<文本>\n` |

**列记录**（结果集与 `DESCRIBE` 同形）：

```text
C <kind> <可空> <类型码> <长度> <名字节数> <类型名字节数> \n
<名字节…> \n <类型名字节…> \n
```

结果集里 `可空`/`类型码`/`长度`/`类型名` 分别是 `1`/`0`/`0`/空（引擎按值给形态）；
`DESCRIBE` 里是目录里的真值。

**语句失败**：整个应答是 `ERR` + 错误文本（**不是**"部分结果 + 错误"）。
已经执行成功的语句**仍然生效**（多条语句是一个接一个执行的，不做整体回滚——
要整体性请自己用 `BEGIN … COMMIT`）。

## 6 `DESCRIBE`

请求载荷 = 对象名（UTF-8 字节，**不带长度前缀**——帧长度就是界）。

应答载荷：

```text
C <列数> \n
  <列记录> ×列数          （同 §5.2，带全量元数据）
```

对象不存在 ⇒ `ERR` + `目录：…` 的具名错误。

## 7 字节级示例（冻结）

`sql` = `SELECT id, name FROM t WHERE id = :id;`，参数 `id` = `7`（数值）。

### 7.1 请求（`SQL` 帧，60 字节载荷）

```text
P 1\n
N 2\nid\n
n1\n7\n
Q 38\nSELECT id, name FROM t WHERE id = :id;\n
```

（`\n` 是真实换行；`Q 38` 里的 38 是 SQL 文本的**字节数**。）

### 7.2 应答（结果集，85 字节载荷）

```text
R 2 2\n
C n 1 0 0 2 0\nID\n\n
C b 1 0 0 4 0\nNAME\n\n
n1\n7\n
b10\n616c706861\n
-0\n\n
b12\ne6b189e5ad97\n
```

即：两列 `ID`（数值）、`NAME`（字节串）；两行 —— `(7, "alpha")` 与 `(NULL, "汉字")`
（`汉字` 的 UTF-8 是 `e6 b1 89 e5 ad 97`，十进制文本过线时按十六进制无损传）。

---

### 7.3 认证请求（`AUTH` 帧，21 字节载荷；协议 §4.3）

主体 `alice`，口令 `s3cr3t`：

```text
U 5\nalice\n
S 6\ns3cr3t\n
```

### 7.4 认证应答（`AUTH` 的 `OK`，35 字节载荷）

```text
user=alice\n
user_id=7\n
status=active\n
```

（口令已过期时最后一行是 `status=expired` —— 受限会话，见 §4.3。）

## 8 会话与事务语义

- **一条连接 = 一个会话**。连接上的语句共享事务状态：`BEGIN` 之后的语句
  直到 `COMMIT`/`ROLLBACK` 都在同一个事务里（`SQL` 的载荷可以一次带多条语句，
  也可以分多次请求发）；
- **身份也是连接的属性**（§4.3）：认证一次、全程有效；语句载荷里没有
  "身份"或"工作区"这样的字段——**路由是身份的函数，不是请求参数的函数**；
- 连接**断开**（含客户端崩溃）⇒ 服务端**回滚**该连接未提交的显式事务
  （服务端在连接收尾时 `Drop` 会话）；
- **一条连接同时只能有一个未决请求**（同步一问一答；服务端不并发处理
  同一连接的请求）。要并发就用多条连接；
- **`COMMIT`/`ROLLBACK` 的应答是 `T <字节数>\n<文本>\n`**（事务回执），
  不是 `A`/`R`；驱动不该把"没有结果集"当成失败。

## 9 错误语义

| 层 | 表现 | 客户端该做什么 |
| --- | --- | --- |
| 连接（`ECONNREFUSED`/`ENOENT`） | 连不上 | 报"实例没在跑/套接字不存在"，附路径 |
| 帧 | 半帧、长度越界、超时 | **断开并用**——这条连接上的字节流已不可信 |
| 版本 | `HELLO` 的 `wire` 不等 | 拒绝连，报两端版本 |
| 服务（`ERR` + 文本） | 语句错、未知动词、载荷非法 | **原样呈现给用户**（文本是给人看的具名错误），连接**可继续用**（除 `SHUTDOWN`） |
| 认证（`AUTH` 的 `ERR`） | 主体名或口令不对 / 已暂停 / 非 PUBLIC / 已认证 | 原样呈现；**不要**据此判断"主体是否存在"（§4.3 的防枚举口径）；连接**可继续用**（仍未认证） |

**错误文本是契约的一部分**：服务的错误一律具名（哪个对象、哪个参数、哪一行），
驱动**不该**改写或翻译它，也不该只取首行。

## 10 驱动该实现的（两侧一致）

| 能力 | 说明 |
| --- | --- |
| `connect(目标)` | 按 §1 寻址；连上先 `HELLO` 核版本 |
| `connect(目标, user, password)` | 可选：连上后 `AUTH`（§4.3）；失败原文透传，**不要**从文本反推"名字是否存在" |
| `query(sql, params)` | 返回**结果集**（列 + 行）；最后一条不是结果集 ⇒ 具名错误 |
| `execute(sql, params)` | 返回影响行数（DDL/事务回执记 0） |
| `describe(对象)` | 列定义（名/可空/类型码/长度/类型名/形态） |
| `server_version()` | `HELLO` 的 `version` |
| trace（可选） | 每帧的动词与字节数打到 stderr（照 PG `PQTRACE` 的做法：排障不用抓包） |

值转原生类型是**驱动侧**的事；驱动**不得**把非 UTF-8 的字节串替换成 `�`
（要么原字节，要么显式报错）。

## 11 版本纪律

- `wire` 号随**不能兼容的**载荷变化 +1；**加字段/加键/加动词不升号**
  （认不出的动词回 `ERR` 具名错误，不是静默）；
- 本版 `wire=1` 的动词闭集 = §4 表（`AUTH` 是 2026-10-07 加入的**新增动词**：老服务端收到它回"未知动词"，语义不含糊）；
- 老客户端连新服务：`HELLO` 版本不等即拒绝（**明确失败**优于"多半能跑"）；
- 本规格的实现在仓库里有两份（Rust / Python），**示例字节冻结在测试里**：
  改协议要**先**改本文件与 `wire` 号，**再**改两份实现与两份冻结测试。
