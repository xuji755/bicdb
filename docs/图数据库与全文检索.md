# bicdb 图数据库与全文检索

适用版本：**v0.3.0**。本文只说明已经接入 SQL、原生存储、事务与恢复的能力。bicdb 参考 AGE/openCypher 的语言形态，但不运行 PostgreSQL AGE 插件，也不宣称兼容 Neo4j 的全部 Cypher 或它的二进制格式。

## 1. 当前能力

| 领域 | 已实现 | 主要边界 |
| --- | --- | --- |
| 存储 | 多标签节点、独立关系身份、平行边、自环、JSON 属性 | 默认图文本预算 100 MiB；仍需大图性能验收 |
| 物理访问 | 节点目录、正/反向邻接 B-tree、按快照读取 | 旧格式可能退回完整验证 |
| 事务 | Undo、WAL、崩溃恢复、语句回滚、多连接隔离 | 请求在单实例执行器上串行调度 |
| Cypher | `MATCH`、`OPTIONAL MATCH`、`WHERE`、`WITH`、`UNWIND`、`RETURN`、聚合、有界路径、`shortestPath` | 不支持无界遍历和完整 Cypher 25 |
| 写入 | `CREATE`、`MERGE`、`ON CREATE/ON MATCH`、`SET/REMOVE`、`DELETE/DETACH DELETE` | `DETACH` 受每语句关联边预算保护 |
| 属性索引 | 标量、组合字段、JSON 对象路径、范围、唯一约束 | 每图最多 64 个，每索引最多 8 个字段 |
| SQL 联查 | `GRAPH_TABLE`、标量列、瞬态 `GRAPH_ELEMENT`、JOIN/聚合/`INSERT SELECT` | 不支持 LATERAL；图元素句柄不能持久化到普通列 |
| 全文 | 节点/关系、BM25、terms/phrase/exact、JSON 固定路径、strict/eventual | 不兼容 Lucene 查询语言或分数 |
| 全文维护 | manual/batch、定时维护、变更队列、PAUSE/RESUME/SYNC/WAIT | 重建后旧物理段回收尚未完成 |

## 2. 创建图和数据

```sql
CREATE GRAPH knowledge;

CYPHER knowledge '
  CREATE (a:Entity {db_type:"mariadb",name:"IO使用率高",config:{question:"如何排查IO"}}),
         (b:Solution {db_type:"mariadb",name:"检查慢SQL与刷盘"}),
         (a)-[:HAS_SOLUTION {weight:10}]->(b)
';

CYPHER knowledge '
  MATCH (n:Entity)-[r:HAS_SOLUTION]->(s:Solution)
  WHERE n.db_type="mariadb"
  RETURN n.name,s.name,r.weight
';
```

未引号的 SQL 标识符折叠为小写；Cypher 的标签、关系类型和属性名区分大小写。可使用 `SHOW GRAPHS`、`DROP GRAPH`和 `ALTER GRAPH ... REBUILD ACCESS/STORAGE` 管理图与派生访问结构。

## 3. 属性索引

```sql
CREATE GRAPH INDEX domain_name ON knowledge
  NODES LABEL "Entity" (db_type,name);

CREATE UNIQUE GRAPH INDEX solution_name ON knowledge
  NODES LABEL "Solution" (name);

CREATE GRAPH INDEX relation_weight ON knowledge
  RELATIONSHIPS TYPE "HAS_SOLUTION" (weight);

SHOW GRAPH INDEXES ON knowledge;

PROFILE CYPHER knowledge '
  MATCH (n:Entity)
  WHERE n.db_type=$domain AND n.name=$name
  RETURN n
' PARAMETERS '{"domain":"mariadb","name":"IO使用率高"}';
```

组合索引遵循最左前缀。命中索引后仍会根据当前快照复核实体、标签/类型、属性和谓词，因此陈旧索引项不会成为结果。`ALTER GRAPH INDEX ... REBUILD` 可清理陈旧项。

## 4. 全文索引

```sql
CREATE FULLTEXT GRAPH INDEX answers ON knowledge
  NODES LABEL ("Entity", "Solution")
  (name,config.question)
  OPTIONS '{"update":"batch","interval_ms":5000,"batch_rows":256}';

SEARCH FULLTEXT GRAPH INDEX answers ON knowledge FOR 'IO 排查'
  OPTIONS '{
    "db_type":"mariadb",
    "channel":"terms",
    "consistency":"eventual",
    "limit":20
  }';

SHOW FULLTEXT GRAPH INDEXES ON knowledge;
ALTER FULLTEXT GRAPH INDEX answers ON knowledge WAIT
  OPTIONS '{"timeout_ms":30000}';
```

关系全文索引使用 `RELATIONSHIPS TYPE (...)`。每个全文索引至少一个、最多 16 个字段；支持固定 JSON 对象路径和数组下标，不支持通配符字段或动态下标。

`eventual` 读取已发布 generation，复核当前源修订，不返回已失效的旧结果；尚未维护的新内容可能暂时缺失。`strict` 包含当前语句和本事务未提交的源变化，当前实现可能执行有界全源构建。

## 5. Cypher 全文过程与多索引融合

```sql
CYPHER knowledge '
  CALL db.index.fulltext.queryNodes(
    "answers","IO 排查",
    {db_type:"mariadb",consistency:"eventual"})
  YIELD node AS n,score,complete
  WHERE score>0
  MATCH (n)-[:HAS_SOLUTION]->(s)
  RETURN n.name,s.name,score,complete
';

CYPHER knowledge '
  CALL bicdb.searchNodes(
    "IO 排查",
    {db_type:"mariadb",indexes:"auto",fields:["name","config.question"],limit:20})
  YIELD node,rank,mode
  RETURN node.name,rank,mode
';
```

`queryRelationships` 返回关系命中。`bicdb.searchNodes` 可显式指定多个索引，或用 `indexes:"auto"` 按字段和标签覆盖选择索引，然后按每路独立排名轮转去重。

## 6. 与关系 SQL 联查

```sql
SELECT g.name,o.owner
FROM GRAPH_TABLE(
  knowledge,
  'MATCH (n:Entity) WHERE n.db_type=$domain RETURN n.name,n'
  PARAMETERS '{"domain":"mariadb"}'
  COLUMNS (name VARCHAR2(128), element GRAPH_ELEMENT)
) g
LEFT JOIN owners o ON g.name=o.entity_name
ORDER BY g.name;
```

`GRAPH_ELEMENT` 只携带图对象、元素类型和局部 ID，可比较、排序、JOIN 和 DISTINCT，但不是属性快照，也不能写入普通表列。

## 7. 延迟维护与配置

```ini
[graph]
max_nodes = 100000
max_edges = 500000
max_rows = 10000
max_expansions = 100000
max_edge_expansions = 100000
max_elapsed_ms = 60000
max_depth = 16
max_text_bytes = 104857600
detach_edge_limit = 10000

[fulltext]
fulltext_interval_ms = 5000
fulltext_batch_rows = 256
```

batch 模式的源写入只在同一事务记录变更 ID/修订，不在前台路径分词。服务在请求间隙、空闲期和输入等待期间消费队列。活动用户事务会跳过后台维护；失败批次不确认事件，可重试。

## 8. 已知边界

- 不支持 APOC、GDS、任意用户过程/函数、无界路径或完整 Cypher 25。
- 图属性尚未接入 Neo4j 等价的日期、空间和向量索引。
- 全文不兼容 Lucene 查询语法、分词器或分数；不提供字段通配符。
- 语句仍由单实例执行器串行调度；多连接已隔离，但不代表并行图执行已完成。
- 旧全文格式首次维护需完整升级到 v4；`REBUILD` 仍是完整构建。
- 属性/全文重建的退役物理段尚未回收，反复重建会增加文件占用。
- 已有合成功能与恢复测试，但尚未完成生产规模知识图谱的 P95/P99 延迟、吞吐、RSS、磁盘和恢复时间验收。

所以，当前版本可用于知识图谱功能接入和受控试运行，但不应在没有代表性负载验证时宣称已达到 Neo4j 的完整功能和大图性能。
